Part 01

Computer Science: Pipeline Interception Topology & Pure ASGI

A critical design decision when integrating rate limiting into a web framework is where to place the enforcement check in the request lifecycle.

Many developers place rate limiting inside route controllers using FastAPI dependencies: @router.post("/items", dependencies=[Depends(rate_limit)]). In production, this introduces a catastrophic security vulnerability: The CPU Starvation Exploit.

FastAPI Request Ingestion Topology: Edge Interception vs. Route Dependency
1. Route Dependency (Depends) Vulnerable

Request enters server → executes entire web pipeline before rate check:

1. Reads 10MB JSON body from TCP socket
2. Parses JSON tokens in Python / Rust
3. Validates complex Pydantic models (CPU Heavy!)
4. Checks out DB connection from pool via Depends()
5. FINALLY checks rate limit → Rejects with 429!

✗ The Vulnerability: An attacker sends 1,000 invalid requests per second. Your server spends 99% of its CPU parsing payloads and checking out database sockets for requests you reject anyway!

2. Outermost Pure ASGI Middleware Defensive Standard

Request hits ASGI entrypoint → rate limit checked immediately:

1. Inspects raw ASGI 'scope' dict (path, method, IP)
2. Resolves YAML policy regex in 0.1ms
3. Checks Redis Lua script in 1ms
4. If throttled → Short-circuits with raw HTTP 429!
5. Zero JSON parsing • Zero DB sockets checked out!

✓ The Guarantee: The request body is never read into memory. Your database and CPU cores remain 100% idle while dropping malicious surges.

⚠️ Why Senior Engineers Avoid Starlette's BaseHTTPMiddleware for Rate Limiters

Starlette provides BaseHTTPMiddleware to make writing middleware easy via the call_next pattern. However, the official Starlette documentation explicitly notes its limitations:

  • Memory Buffering: BaseHTTPMiddleware buffers the response stream in memory to construct a high-level response object. If an endpoint streams a 500MB export, it can add memory pressure and delay chunk transmission.
  • ContextVar Quirks: Under high concurrency, asynchronous task contexts managed inside call_next can leak or drop context state across coroutines.

The Solution: Write a Pure ASGI Middleware implementing async def __call__(self, scope, receive, send). It operates with zero memory buffering, minimal CPU overhead, and full streaming compatibility.

Part 02

Standards Compliance: The IETF RateLimit Header Specification

Historically, tech giants invented ad-hoc headers: GitHub used X-RateLimit-Limit, Twitter used X-Rate-Limit-Remaining, and others used custom prefixes. This fragmentation forced frontend engineers and mobile SDK developers to write bespoke rate-handling logic for every vendor.

The IETF (Internet Engineering Task Force) HTTP Working Group formalized the **RateLimit Header Fields for HTTP** draft. SentinelFlow strictly enforces these standards:

RateLimit-Limit Quota Units

The maximum number of quota units permitted within the active time window (e.g. 100).

RateLimit-Remaining Available Quota

The number of quota units remaining in the current window. Drops to 0 when throttled.

RateLimit-Reset Delta Seconds

The number of seconds until the current quota window resets and fresh quota units become available (e.g. 18).

Retry-After RFC 6585 Mandate

Included strictly on HTTP 429 responses. Instructs automated clients and SDKs how long to sleep before retrying.

Part 03

Pure ASGI Mechanics: Intercepting the send Callable

In the ASGI specification, an application receives three arguments: scope (a dictionary of request metadata), receive (an async channel for streaming request body chunks), and send (an async channel for streaming response frames).

To inject RateLimit-* headers into successful 200 OK responses without buffering the response body in memory, we wrap the downstream send callable:

The Pure ASGI Send Wrapper Execution Flow
1. Downstream Controller Emits type: "http.response.start"
→ intercepts →
2. Wrapped send(message) Appends (b"ratelimit-remaining", b"42") to raw headers list
→ dispatches →
3. ASGI Server (Uvicorn) Writes bytes to TCP socket with zero memory buffering!
Zero Memory Overhead:

Subsequent message frames (type: "http.response.body") pass through the wrapper untouched. Whether the response is a 20-byte JSON object or a 5-gigabyte streaming video, memory consumption remains constant at ~0 bytes!

1. Pure ASGI Middleware: src/sentinelflow/middleware/pure_asgi.py Zero-Buffering Interceptor 
# ==============================================================================
# SentinelFlow Middleware - Pure ASGI Rate Limiter (Milestone 07)
# ==============================================================================

import json
from typing import Callable, Any, Dict, List, Tuple
from sentinelflow.config.watcher import PolicyWatcher
from sentinelflow.core.key_extractor import KeyExtractor
from sentinelflow.core.models import RateLimitResult
from sentinelflow.storage.resilient_redis import ResilientRateLimiter

class SentinelFlowMiddleware:
    """
    HIGH-PERFORMANCE PURE ASGI RATE LIMITING MIDDLEWARE:
    Intercepts traffic at the outermost network boundary.
    Rejects throttled clients with RFC 6585 JSON before request bodies are read.
    Wraps 'send' to inject IETF headers with zero response memory buffering.
    """
    def __init__(
        self,
        app: Callable,
        policy_watcher: PolicyWatcher,
        rate_limiter: ResilientRateLimiter,
        key_extractor: KeyExtractor
    ):
        self.app = app
        self.policy_watcher = policy_watcher
        self.rate_limiter = rate_limiter
        self.key_extractor = key_extractor

    async def __call__(self, scope: Dict[str, Any], receive: Callable, send: Callable) -> None:
        # 1. Pass through non-HTTP connections (WebSockets, Lifespan) untouched
        if scope["type"] != "http":
            await self.app(scope, receive, send)
            return

        path = scope.get("path", "/")
        method = scope.get("method", "GET").upper()

        engine = self.policy_watcher.engine

        # 2. Check Exemption Patterns (/health, /metrics)
        if engine.is_exempt(path):
            await self.app(scope, receive, send)
            return

        # 3. Extract Headers for Client Identity & Tiering
        raw_headers: List[Tuple[bytes, bytes]] = scope.get("headers", [])
        headers_dict = {k.decode("latin1").lower(): v.decode("latin1") for k, v in raw_headers}

        direct_ip = scope.get("client", ("127.0.0.1", 0))[0]
        client_ip = self.key_extractor.extract_client_ip(
            direct_ip=direct_ip,
            x_forwarded_for=headers_dict.get("x-forwarded-for")
        )

        # Resolve Tier from API Key or Bearer Token (defaults to anonymous)
        api_key = headers_dict.get("x-api-key")
        client_tier = "enterprise" if api_key == "secret_enterprise_key" else "anonymous"
        client_identifier = api_key if api_key else client_ip

        # 4. Resolve Rate Policy via Precompiled Regex
        parsed_rate, cost = engine.resolve(path=path, method=method, client_tier=client_tier)

        # Format composite storage key
        storage_key = f"{client_tier}:{client_identifier}:{method}:{path}"

        # 5. Execute Storage Rate Limit Check (Redis Lua or Local Fallback)
        rate_result: RateLimitResult = await self.rate_limiter.acquire_with_fallback(
            key=storage_key,
            limit=parsed_rate.limit,
            window_seconds=parsed_rate.window_seconds,
        )

        # ----------------------------------------------------------------------
        # 6. DEFENSIVE SHORT-CIRCUIT: Drop throttled requests immediately!
        # ----------------------------------------------------------------------
        if not rate_result.allowed:
            await self._send_429_response(send, rate_result)
            return

        # ----------------------------------------------------------------------
        # 7. WRAP SEND CALLABLE: Inject IETF headers on 200 OK without buffering!
        # ----------------------------------------------------------------------
        async def send_with_rate_limit_headers(message: Dict[str, Any]) -> None:
            if message["type"] == "http.response.start":
                headers = list(message.get("headers", []))
                for hk, hv in rate_result.to_headers().items():
                    headers.append((hk.lower().encode("latin1"), hv.encode("latin1")))
                message["headers"] = headers

            await send(message)

        await self.app(scope, receive, send_with_rate_limit_headers)

    async def _send_429_response(self, send: Callable, result: RateLimitResult) -> None:
        """Emits raw HTTP 429 Too Many Requests response frames directly over ASGI."""
        error_body = json.dumps({
            "error": "TooManyRequests",
            "message": f"Rate limit exceeded. Quota resets in {result.reset_after_seconds:.1f}s",
            "limit": result.limit,
            "retry_after_seconds": int(result.reset_after_seconds)
        }).encode("utf-8")

        headers = [
            (b"content-type", b"application/json"),
            (b"content-length", str(len(error_body)).encode("latin1")),
        ]
        for hk, hv in result.to_headers().items():
            headers.append((hk.lower().encode("latin1"), hv.encode("latin1")))

        await send({
            "type": "http.response.start",
            "status": 429,
            "headers": headers
        })
        await send({
            "type": "http.response.body",
            "body": error_body
        })

# ==============================================================================
# SentinelFlow Web - FastAPI Gateway Microservice (Milestone 07)
# ==============================================================================

from contextlib import asynccontextmanager
from pathlib import Path
from fastapi import FastAPI, status
from pydantic import BaseModel

from sentinelflow.config.watcher import PolicyWatcher
from sentinelflow.core.key_extractor import KeyExtractor
from sentinelflow.storage.redis_manager import RedisRateLimiter
from sentinelflow.storage.resilient_redis import ResilientRateLimiter
from sentinelflow.middleware.pure_asgi import SentinelFlowMiddleware

CONFIG_PATH = Path("config/rate_limits.yml")

@asynccontextmanager
async def lifespan(app: FastAPI):
    # Boot: Initialize Redis connection pools & load Lua scripts
    redis_limiter = RedisRateLimiter()
    try:
        await redis_limiter.initialize()
    except Exception:
        pass  # Resilient wrapper falls back to in-memory on local boot

    app.state.redis_limiter = redis_limiter
    yield
    await redis_limiter.close()

app = FastAPI(title="SentinelFlow Gateway", lifespan=lifespan)

# Instantiate components
policy_watcher = PolicyWatcher(config_path=CONFIG_PATH)
redis_limiter = RedisRateLimiter()
resilient_storage = ResilientRateLimiter(redis_limiter=redis_limiter)
key_extractor = KeyExtractor()

# Mount Pure ASGI Middleware as outermost interceptor!
app.add_middleware(
    SentinelFlowMiddleware,
    policy_watcher=policy_watcher,
    rate_limiter=resilient_storage,
    key_extractor=key_extractor
)

class LoginPayload(BaseModel):
    username: str
    password: str

@app.get("/health", tags=["System"])
async def health_probe():
    """Exempt from rate limits: Orchestrators can poll infinitely."""
    return {"status": "healthy"}

@app.post("/api/v1/auth/login", status_code=status.HTTP_200_OK, tags=["Auth"])
async def login(payload: LoginPayload):
    """Protected by strict auth_login YAML route policy (5/minute default)."""
    return {"message": f"Authenticated {payload.username}"}

@app.get("/api/v1/items", tags=["Data"])
async def list_items():
    """Protected by global client tier quotas."""
    return [{"id": 1, "name": "Item Alpha"}]

    """Verifies pure ASGI interception, IETF header injection, and 429 short-circuits."""

    async def test_health_probe_is_completely_exempt_from_headers(self, client: httpx.AsyncClient):
        response = await client.get("/health")
        assert response.status_code == 200
        # Exempt endpoints must not leak rate limit headers
        assert "ratelimit-limit" not in response.headers

    async def test_successful_request_injects_ietf_ratelimit_headers(self, client: httpx.AsyncClient):
        response = await client.get("/api/v1/items")
        assert response.status_code == 200
        
        # Mandatory IETF Headers verified
        assert "ratelimit-limit" in response.headers
        assert "ratelimit-remaining" in response.headers
        assert "ratelimit-reset" in response.headers

    async def test_rate_limit_exhaustion_short_circuits_with_429(self, client: httpx.AsyncClient):
        # POST /api/v1/auth/login has default limit of 5 per minute
        for _ in range(5):
            res = await client.post("/api/v1/auth/login", json={"username": "admin", "password": "p"})
            assert res.status_code == 200

        # 6th request MUST be short-circuited with HTTP 429 Too Many Requests
        blocked_res = await client.post("/api/v1/auth/login", json={"username": "admin", "password": "p"})
        assert blocked_res.status_code == 429

        # Verify RFC 6585 JSON Error payload and Retry-After header
        data = blocked_res.json()
        assert data["error"] == "TooManyRequests"
        assert "retry-after" in blocked_res.headers
        assert int(blocked_res.headers["retry-after"]) >= 1
Warning Track

Beginner Pitfalls & Architectural Anti-Patterns

❌ Rate Limiting Inside Route Handlers

Placing rate-limit checks inside controller logic: @app.post("/items") async def create(db=Depends(get_db)): check_rate().

Why this causes server crashes: Placing the rate limiter inside the route allows the request to pass through JSON body parsing, Pydantic validation, and database connection checkout before getting blocked. Under a DDoS attack, your database connection pool is completely exhausted by malicious requests that you reject anyway! Always rate limit at the outermost ASGI middleware layer.

❌ Omitting Headers on 200 OK Responses

Returning RateLimit-* headers only when returning HTTP 429.

Why this harms clients: If a server returns headers only upon failure, legitimate client SDKs cannot tell how close they are to their limit. They must blindly fire requests until they crash into a 429 error! Stamping headers on successful 200 responses allows clients to throttle themselves proactively.
