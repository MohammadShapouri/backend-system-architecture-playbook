Part 01

Computer Science: The Container Runtime Interface (CRI) Logging Pipeline

When an application inside a Kubernetes Pod writes bytes to sys.stdout, Kubernetes itself does not read the socket. Instead, the underlying Container Runtime Interface (CRI)—such as containerd or CRI-O—intercepts the stream and writes formatted text files to the Linux worker node host filesystem.

The CRI structures all pod output on the host node according to a deterministic directory hierarchy:

/var/log/pods/<namespace>_<pod_name>_<pod_uid>/<container_name>/<restart_count>.log

For legacy tooling backwards-compatibility, the runtime creates corresponding symlinks inside /var/log/containers/ pointing to the canonical /var/log/pods/ files:

The Kubernetes Node Logging & kubectl logs Dataflow
1. PulsePay Pod App writes JSON string to stdout (FD 1)
→ CRI intercepts →
2. containerd CRI Appends timestamp & stream tag to /var/log/pods/...
→ Kubelet serves →
3. Kubelet (Port 10250) Streams raw file contents to API Server & kubectl
The Raw CRI Log Line Format on Node Disk:
2026-11-10T04:12:01.890123456Z stdout F {"level":"INFO","action":"PAYMENT_SETTLE","amount":"50.0000"}

The CRI prefixes every raw stdout line with three tokens: [RFC3339 Timestamp], [Stream: stdout|stderr], and [Log Tag: F=Full line, P=Partial line if > 16KB]. Node log forwarders (Fluent Bit/Vector) must parse and strip this CRI prefix before processing your application's JSON payload.

Part 02

Architectural Topologies: DaemonSet vs. Sidecar vs. Direct Push

How should logs travel from pods to your central telemetry cluster? Kubernetes supports three architectural patterns, each with distinct resource, security, and operational trade-offs:

1. Node DaemonSet Senior Choice

Runs exactly one logging agent pod per worker node (e.g. Fluent Bit or Vector). Mounts the host node's /var/log/pods/ directory directly via a hostPath volume.

Why it wins: Minimal resource overhead (1 forwarder serves 50 pods on the node); zero application invasion; pod crashes never affect the logging daemon.

Maximum Efficiency • Lowest CPU & RAM
2. Streaming Sidecar Legacy Migration

Used when an unalterable legacy third-party binary writes logs strictly to an internal disk file (/var/log/app.log).

A secondary sidecar container shares an emptyDir volume with the app and runs tail -n+1 -F /var/log/app.log, streaming it into the sidecar's stdout!

Doubles Container Count • File-bridge only
3. Direct-from-App Push Anti-Pattern

Application pods open direct HTTP or gRPC network sockets to an external Elasticsearch or Loki cluster, bypassing stdout and node disk completely.

The Danger: If the logging cluster slows down, network threads inside every pod block. Bypasses kubectl logs entirely!

Network Fragile • Breaks kubectl logs
Part 03

Kubelet Disk Governance & Preventing DiskPressure Eviction Storms

In Kubernetes worker nodes, container logs stored under /var/log/pods/ reside on the worker node's root filesystem (or dedicated root disk mount).

If an application enters an infinite error loop and floods standard output, what prevents the node disk from reaching 100% capacity? The **Kubelet** daemon manages container log rotation through parameters configured in /var/lib/kubelet/config.yaml:

Node Configuration

Kubelet Log Rotation Settings

Configured in the cluster node Kubelet specification: 

# In /var/lib/kubelet/config.yaml:
containerLogMaxSize: "10Mi"
containerLogMaxFiles: 5

The Kubelet checks file sizes periodically. When a container log reaches 10MB, the Kubelet compresses and rotates it, keeping a maximum of 5 historical files (50MB cap per container).

The Cluster Outage Trap

The DiskPressure Eviction Cascade

If Kubelet log limits are misconfigured or unmanaged, the root disk breaches the Kubelet eviction threshold (default: 85% disk usage).

Disk > 85% → Node sets Condition: DiskPressure → Kubelet starts evicting Pods → PulsePay payments drop across the entire cluster!
Emergency Diagnostics: /dev/termination-log

When a container crashes before the logging agent can scrape its output (e.g. fatal segmentation fault, invalid environment variable, or startup panic), Kubernetes inspects the container's terminationMessagePath (default: /dev/termination-log). By writing critical failure reasons directly to this file, the error message is preserved in kubectl describe pod even if all container logs are wiped!

            - containerPort: 8000

2. Production Fluent Bit DaemonSet: k8s/fluentbit-daemonset.yaml Node-Level Telemetry Forwarder 
# ==============================================================================
# PulsePay Kubernetes - Fluent Bit Node-Level DaemonSet (Milestone 07)
# ==============================================================================

apiVersion: v1
kind: ConfigMap
metadata:
  name: fluent-bit-config
  namespace: kube-system
data:
  fluent-bit.conf: |
    [SERVICE]
        Flush         1
        Log_Level     info
        Daemon        off
        Parsers_File  parsers.conf

    [INPUT]
        Name              tail
        Tag               kube.*
        Path              /var/log/containers/*.log
        Parser            docker
        DB                /var/log/flb_kube.db
        Mem_Buf_Limit     50MB
        Skip_Long_Lines   On
        Refresh_Interval  5

    [FILTER]
        Name                kubernetes
        Match               kube.*
        Kube_URL            https://kubernetes.default.svc:443
        Kube_CA_File        /var/run/secrets/kubernetes.io/serviceaccount/ca.crt
        Kube_Token_File     /var/run/secrets/kubernetes.io/serviceaccount/token
        Kube_Tag_Prefix     kube.var.log.containers.
        Merge_Log           On
        Merge_Log_Key       log_processed
        Keep_Log            Off
        K8S-Logging.Parser  On
        K8S-Logging.Exclude On

    [OUTPUT]
        Name   stdout
        Match  kube.*
---
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: fluent-bit
  namespace: kube-system
spec:
  selector:
    matchLabels:
      k8s-app: fluent-bit-logging
  template:
    metadata:
      labels:
        k8s-app: fluent-bit-logging
    spec:
      tolerations:
        - key: node-role.kubernetes.io/master
          operator: Exists
          effect: NoSchedule
      containers:
        - name: fluent-bit
          image: fluent/fluent-bit:2.2
          volumeMounts:
            - name: varlog
              mountPath: /var/log
            - name: varlibdockercontainers
              mountPath: /var/lib/docker/containers
              readOnly: true
            - name: config
              mountPath: /fluent-bit/etc/
      volumes:
        - name: varlog
          hostPath:
            path: /var/log
        - name: varlibdockercontainers
          hostPath:
            path: /var/lib/docker/containers
        - name: config
          configMap:
            name: fluent-bit-config
3. Streaming Sidecar Pattern: k8s/legacy-clearing-sidecar.yaml File-to-Stdout Streaming Bridge 
# ==============================================================================
# PulsePay Kubernetes - Streaming Sidecar Pattern for Legacy Files (Milestone 07)
# ==============================================================================

apiVersion: v1
kind: Pod
metadata:
  name: pulsepay-legacy-clearing
  namespace: pulsepay-production
spec:
  containers:
    # Container 1: The Legacy Binary that ONLY writes to an internal log file
    - name: legacy-bank-clearing-app
      image: busybox:1.36
      args:
        - /bin/sh
        - -c
        - >
          while true; do
            echo "{\"timestamp\":\"$$(date -u +%FT%TZ)\",\"action\":\"ACH_SETTLE_BATCH\",\"records\":120}" >> /var/log/legacy/clearing.log;
            sleep 5;
          done
      volumeMounts:
        - name: shared-log-volume
          mountPath: /var/log/legacy

    # Container 2: THE STREAMING SIDECAR (Tails the shared file to container stdout!)
    - name: clearing-stream-sidecar
      image: busybox:1.36
      args: ["/bin/sh", "-c", "tail -n+1 -F /var/log/legacy/clearing.log"]
      volumeMounts:
        - name: shared-log-volume
          mountPath: /var/log/legacy

  # Shared in-memory or ephemeral disk volume linking both containers
  volumes:
    - name: shared-log-volume
      emptyDir: {}
Warning Track

Beginner Pitfalls & Architectural Anti-Patterns

❌ The "Kubelet Node Eviction Storm" Disaster

Failing to configure Kubelet containerLogMaxSize on worker nodes.

Why this crashes clusters: When an unrotated container spews gigabytes of error logs, the node filesystem reaches 85% capacity. The Kubelet immediately sets the DiskPressure taint and starts preemptively evicting pods across the node, causing an availability cascade.

❌ The "High-Cardinality Pod Label" etcd Bloat

Injecting transactional dynamic data (like transaction_id or user_email) into Kubernetes Pod labels.

Why this destroys control planes: Kubernetes stores all Pod metadata in etcd. High-cardinality labels balloon etcd database sizes, degrade the Kubernetes API server, and slow down kube-scheduler reconciliation loops. Dynamic transaction context belongs inside the log payload, never in Kubernetes Pod labels!

kubectl exec -it -n kube-system ds/fluent-bit -- ls -l /var/log/containers/ | grep pulsepay
Notice symlinks: Confirms node forwarders scrape directly from host files without interacting with the application process!
