A Index

Abstract Base Class (ABC)

Contract • Ch. 04

A class that inherits from the built-in abc.ABC module. It serves as a strict structural contract defining what methods must exist. Python prevents direct instantiation of an ABC if any of its methods are decorated with @abstractmethod.

@abstractmethod

Decorator • Ch. 04

A decorator that marks a method as incomplete. When applied inside an Abstract Base Class, Python sets the __isabstractmethod__ = True flag. Any concrete subclass must override this method, or it too will be blocked from instantiation.

Aggregation ("Has-a")

Relationship • Ch. 03

A structural relationship where one class holds a reference to another, but both maintain independent lifecycles. For example, an Order references a Customer, but deleting the order does not delete the customer.

C Index

Class (Blueprint)

Concept • Ch. 01

The template or architectural blueprint that defines the structure (attributes) and behavior (methods) of an object. It exists exactly once in memory and spawns multiple isolated instances.

Class Attribute

State • Ch. 01

A variable defined directly inside the class body, outside of any methods. It is shared by all instances. Assigning a mutable object (like a list) to a class attribute is a famous Python anti-pattern that leads to cross-instance state pollution.

@classmethod

Decorator • Ch. 03

A decorator that transforms a method to receive the class itself (cls) as the first argument rather than the instance (self). Heavily used for creating clean Factory Methods or alternative constructors (e.g., Order.create_empty()).

Composition ("Contains-a")

Relationship • Ch. 03

The tightest form of object association where an owner completely manages the lifecycle of nested internal entities (e.g., an Order composes OrderItems). The children have no logical existence outside the parent.

D Index

Defensive Copying

Architecture • Ch. 03

The practice of returning a shallow copy (e.g., self._items.copy()) instead of a direct reference to an object's internal mutable collections. Protects against external callers silently altering private state and bypassing validation logic.

Dependency Injection (DI)

Design Pattern • Ch. 06

Passing required component instances (like a StripeGateway) into a class via its constructor (__init__), rather than hardcoding the instantiation inside the class. Enables easy unit testing and strategy swapping.

Duck Typing

Polymorphism • Ch. 05

"If it walks like a duck and quacks like a duck, it's a duck." Python's philosophy that evaluates an object's suitability based on the presence of specific methods (like process_payment) rather than its strict inheritance lineage.

Dynamic Dispatch

Concept • Ch. 05

The runtime process where Python determines which version of an overridden method to execute by inspecting the actual object loaded in memory, bypassing the need for static if/elif type ladders.

E Index

Encapsulation

Concept • Ch. 02

The bundling of data state with the methods that operate on that state, restricting direct unauthorized tampering. In Python, this is achieved smoothly via @property and protected conventions (_var).

F Index

Fragile Base Class

Anti-Pattern • Ch. 03

An architectural vulnerability caused by overuse of inheritance. Seemingly benign changes in a base parent class cause unexpected, silent bugs cascading down through distant child classes. A primary reason to favor Composition.

G Index

God Class (The Blob)

Anti-Pattern • Ch. 03

A massive monolithic class (often born from bad inheritance like class Order(Customer, Address)) that attempts to know too much and do too much, violating the Single Responsibility Principle.

I Index

Inheritance ("Is-a")

Concept • Ch. 03

The tightest form of coupling where a subclass derives attributes and methods from a parent. Highly prone to the "Gorilla/Banana problem" (you want a banana, but you inherit the entire jungle).

__init__(self, ...)

Dunder • Ch. 01

The instance initializer dunder. Called automatically after memory allocation. Used to bind distinct state arguments directly to the self pointer, securing instance isolation.

Instance (Object)

Concept • Ch. 01

A physical object constructed from a class blueprint. Resides in RAM with its own distinct, isolated state dictionary, completely independent from other instances of the same class.

N Index

Name Mangling

CPython • Ch. 02

Prefixing an attribute with double underscores (__secret) instructs CPython to dynamically rename it to _ClassName__secret. Used to avoid subclass namespace collisions, not for true security.

P Index

Polymorphism

Concept • Ch. 05

The ability of different object classes (e.g., Stripe, PayPal) to respond to the exact same method interface. It replaces brittle if/else type checks with smooth dynamic dispatch.

@property

Decorator • Ch. 02

Python's built-in decorator for getters and setters. Allows you to intercept attribute access and mutations (obj.val = 5) to run background validation while preserving a simple dot-notation API.

R Index

__repr__(self)

Dunder • Ch. 01

The primary diagnostic string representation. It must be unambiguous and, ideally, look like valid Python code to recreate the object. Appears in log files, tracebacks, and lists. Python falls back to this if __str__ is missing.

S Index

self

Keyword • Ch. 01

The explicit first parameter in standard Python class methods. It acts as a memory pointer referring directly to the specific instance currently executing the method, enabling state isolation.

Strategy Pattern

Design Pattern • Ch. 05

A behavioral design pattern where algorithms (like tax calculation or payment gateways) are encapsulated in standalone objects. By relying on polymorphism, the main system can swap strategies at runtime without modifying core logic.

__str__(self)

Dunder • Ch. 01

The user-facing string representation. Invoked by print(obj) or f"{obj}". Should prioritize clean, readable formatting, omitting heavy technical diagnostics.

U Index

Uniform Access Principle

Architecture • Ch. 02

The software design principle stating that clients should not care if a value is implemented as a simple memory attribute or dynamically computed via a method. Python fulfills this via the @property decorator.
