Part 01

Computer Science: Interfaces and Enforced Contracts

Abstraction is the process of hiding complex background details and exposing only a clean, simple interface. In software architecture, an Interface (or Abstract Base Class) acts as a strict legal contract between your core application and external plugins.

If you tell your team, "Make a payment processor," someone might write a class with a method called pay(), another might write charge_card(), and a third might write execute_transaction(). Your checkout system would crash trying to guess the method names. An Abstract Base Class forces everyone to use the exact same method signature: process_payment(amount).

Architectural Boundary: The Interface vs. The Implementation
The Contract Abstract

Defines WHAT must be done. Contains zero actual logic.

PaymentGateway
- process_payment()
- authenticate()
The Implementations Concrete

Defines HOW it is done. Contains the actual network API calls. Must strictly obey the Contract.

StripeGateway
+ process_payment() {
requests.post('stripe.com')
}
PayPalGateway
+ process_payment() {
paypal_sdk.charge()
}
Part 02

Under the Hood: How CPython Blocks Instantiation

If an interface has empty methods, what happens if a developer accidentally tries to instantiate it directly? (gateway = PaymentGateway()). It would create a useless object that does nothing!

Python prevents this using the abc (Abstract Base Classes) module. When you decorate a method with @abstractmethod, CPython flags that method internally.

// CPython's Abstract Guard Pipeline

1. The Flag: @abstractmethod sets an internal flag on the function: func.__isabstractmethod__ = True.

2. Class Creation: When Python builds the class (using abc.ABCMeta), it collects all methods with this flag into a hidden set called cls.__abstractmethods__.

3. The Block: The moment someone writes obj = MyClass(), Python checks that set. If the set is not empty, Python immediately raises a TypeError: Can't instantiate abstract class and refuses to allocate memory!

The Fix: A subclass must override every single abstract method. When it does, the child method no longer has the flag, the __abstractmethods__ set becomes empty, and Python finally permits instantiation.

1. Abstract Contract: src/orderforge/domain/gateway.py Abstract Base Classes 
# ==============================================================================
# OrderForge Domain - Abstraction & Enforced Contracts (Milestone 04)
# ==============================================================================

from abc import ABC, abstractmethod

class PaymentGateway(ABC):
    """
    INTERFACE / CONTRACT:
    By inheriting from ABC, this class cannot be instantiated on its own.
    It dictates the exact method signatures that any concrete payment processor 
    (like Stripe or PayPal) MUST implement to be accepted by the checkout engine.
    """

    @abstractmethod
    def authenticate(self) -> bool:
        """
        Verifies API keys, tokens, or network credentials.
        Returns True if successful, False otherwise.
        """
        pass  # No logic required in the interface!

    @abstractmethod
    def process_payment(self, amount: float) -> str:
        """
        Executes the financial transaction.
        Must return a unique transaction receipt/ID string.
        """
        pass
2. Unit Test Battery: tests/test_gateway.py Testing Instantiation Blocks 
# ==============================================================================
# OrderForge Test Suite - Abstract Contract Verification (Milestone 04)
# ==============================================================================

import pytest
from orderforge.domain.gateway import PaymentGateway


class TestPaymentGatewayContract:
    """Unit tests asserting that Python blocks invalid interface usage."""

    def test_cannot_instantiate_abstract_base_class(self):
        # Attempting to create the interface directly MUST crash!
        with pytest.raises(TypeError, match=r"Can't instantiate abstract class PaymentGateway"):
            gateway = PaymentGateway()

    def test_subclass_must_implement_all_abstract_methods(self):
        # Define a broken subclass that misses 'process_payment'
        class BrokenGateway(PaymentGateway):
            def authenticate(self) -> bool:
                return True

        # Python catches the missing method exactly at instantiation time!
        with pytest.raises(TypeError, match=r"abstract method.*process_payment"):
            gateway = BrokenGateway()

    def test_valid_subclass_instantiates_cleanly(self):
        # Define a correct subclass
        class MockGateway(PaymentGateway):
            def authenticate(self) -> bool:
                return True
            def process_payment(self, amount: float) -> str:
                return "TXN_SUCCESS"

        # Instantiation succeeds seamlessly
        gateway = MockGateway()
        assert gateway.authenticate() is True
        assert gateway.process_payment(100.0) == "TXN_SUCCESS"
Warning Track

Beginner Pitfalls & Architectural Anti-Patterns

❌ The NotImplementedError Trap

Skipping abc entirely and writing def process_payment(self): raise NotImplementedError() in a standard parent class.

Why this causes production crashes: If you use NotImplementedError without ABC, Python allows the developer to instantiate the broken subclass perfectly fine. The app will boot up, run for days, and only crash with an error at the exact moment a customer tries to pay! ABC moves the crash to **startup time**, protecting your production environment.

❌ Forgetting to inherit from ABC

Using the @abstractmethod decorator, but forgetting to write class PaymentGateway(ABC):.

Why this fails silently: The @abstractmethod decorator simply puts a sticky note on the method saying "I am abstract". However, only the `ABCMeta` metaclass (which you get by inheriting from `ABC`) actually reads those sticky notes! If you forget `(ABC)`, Python ignores the decorators and lets you instantiate the empty class.
