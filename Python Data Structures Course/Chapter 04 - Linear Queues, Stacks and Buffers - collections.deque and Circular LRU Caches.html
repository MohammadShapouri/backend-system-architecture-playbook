Part 01

Computer Science: The Memory Shifting Flaw & CPython Block Anatomy

When developers implement a FIFO (First-In, First-Out) Queue or a sliding buffer in Python, a pervasive design mistake is using a standard list. While appending to the right side of a list is amortized $O(1)$, popping from the front (list.pop(0)) forces the operating system to physically shift every remaining pointer leftward in memory via the C standard library's memmove().

If your queue handles $500,000$ messages, processing them with list.pop(0) shifts 125 billion memory pointers, saturating CPU caches and transforming a linear pipeline into an $O(n^2)$ performance catastrophe.

The 64-Element Block Invariant:

In CPython's Modules/_collectionsmodule.c, a dequeobject is implemented as a doubly-linked list of fixed-size blocks, where each block contains exactly BLOCKLEN = 64 element slots.

  • O(1) Head & Tail Operations: Pushing or popping on either end merely shifts the internal leftindex or rightindex within the edge block. Zero elements are ever shifted!
  • Cache Locality: Iterating through elements inside a 64-pointer block benefits from CPU cache line pre-fetching, avoiding the cache-miss penalties of traditional single-node linked lists.
  • Trade-Off (Random Access Penalty): Finding an element at index $i$ requires traversing the block chain, taking $O(n)$ time. Never use a deque for random indexed searches like d[50000].
Concurrency & Mutexes

Thread-Safety Guarantees in CPython

Under CPython's Global Interpreter Lock (GIL), the four mutating edge methods of a deque (append, appendleft, pop, and popleft) are atomic operations. This means you can safely use a deque as a lock-free Single-Producer Single-Consumer (SPSC) queue between threads without wrapping edge calls in an explicit threading.Lock.

# Thread-safe in CPython without locks:
worker_queue.append(task)      # Atomic producer push
current_task = worker_queue.popleft() # Atomic consumer pull

Part 03

Algorithmic Design: Least Recently Used (LRU) Buffer Pools

Operating systems and database engines manage memory using Cache Replacement Policies. When the buffer pool fills to capacity and a new storage page must be loaded from disk or network, the engine must decide which page to evict.

The most widely applied heuristic is LRU (Least Recently Used): discard the item that has not been accessed for the longest duration.

Structural Duality

Why LRU Requires Two Data Structures

An optimal LRU cache must achieve three invariants simultaneously in $O(1)$ time:

  • O(1) Key Lookup: Handled by a Hash Map (dict).
  • O(1) Recency Tracking: Moving a queried item to the "Most Recently Used" position.
  • O(1) Eviction: Removing the item from the "Least Recently Used" position.

A hash map alone cannot track temporal sequence; a linear queue alone takes $O(n)$ to locate arbitrary keys. Combining a hash map with a double-ended pointer structure yields true $O(1)$ cache operations!

Database Mechanics

Buffer Pools & Page Pinning

In storage engines like PostgreSQL, InnoDB, or SQLite, simple LRU is dangerous during active transactions:

  • The Pinning Invariant: If worker thread A is currently reading or writing to Page 104, that page is pinned (pin_count > 0).
  • Eviction Guard: The cache eviction worker must skip all pinned pages even if they are the oldest in the queue!
  • Unpinning: When the query completes, the pin count decrements, allowing the page to be recycled once all active readers release it.

1. Production Cache Engine: src/memforge/cache/lru_cache.py LRU Buffer Pool Implementation 
# ==============================================================================
# MemForge Cache - LRU Buffer Pool with Page Pinning (Milestone 04)
# ==============================================================================

from collections import deque
from dataclasses import dataclass
from typing import Any, Dict, Optional


class BufferPoolFullError(Exception):
    """Raised when the buffer pool cannot evict any page because all pages are pinned."""
    pass


@dataclass
class PageFrame:
    """In-memory representation of a cached storage page descriptor."""
    page_id: int
    data: Any
    pin_count: int = 0
    is_dirty: bool = False


class LRUBufferPool:
    """
    PRODUCTION LRU BUFFER POOL:
    Combines an O(1) hash map directory with a collections.deque
    recency pipeline, augmented with transactional page-pinning guards.
    """
    def __init__(self, capacity_pages: int = 128):
        # Maximum storage pages allowed concurrently in RAM
        self._capacity = capacity_pages
        # Directory map: page_id -> PageFrame
        self._page_table: Dict[int, PageFrame] = {}
        # Temporal deque: tail = most recently used, head = least recently used
        self._recency_queue: deque[int] = deque()
        # Operational metric counters
        self.hits: int = 0
        self.misses: int = 0
        self.evictions: int = 0

    def __len__(self) -> int:
        """Returns total active cached pages currently residing in RAM."""
        return len(self._page_table)

    def _touch_recency(self, page_id: int) -> None:
        """Moves accessed page_id to the tail of the deque (Most Recently Used)."""
        # Remove old reference and append to tail (O(n) scan inside deque, optimal for buffers)
        try:
            self._recency_queue.remove(page_id)
        except ValueError:
            pass
        self._recency_queue.append(page_id)

    def get_page(self, page_id: int, pin: bool = False) -> Optional[Any]:
        """
        Retrieves a page by ID.
        If pin=True, increments the page's pin_count to prevent eviction.
        """
        if page_id in self._page_table:
            self.hits += 1
            frame = self._page_table[page_id]
            if pin:
                frame.pin_count += 1
            self._touch_recency(page_id)
            return frame.data

        self.misses += 1
        return None

    def put_page(self, page_id: int, data: Any, pin: bool = False) -> None:
        """
        Loads a page into the buffer pool.
        Triggers eviction if the pool is full.
        """
        if page_id in self._page_table:
            # In-place update
            frame = self._page_table[page_id]
            frame.data = data
            if pin:
                frame.pin_count += 1
            self._touch_recency(page_id)
            return

        # Evict if pool reached capacity
        if len(self._page_table) >= self._capacity:
            self._evict_least_recent()

        # Insert new frame
        pin_init = 1 if pin else 0
        new_frame = PageFrame(page_id=page_id, data=data, pin_count=pin_init)
        self._page_table[page_id] = new_frame
        self._recency_queue.append(page_id)

    def unpin_page(self, page_id: int) -> None:
        """Decrements pin_count, allowing page to be evicted when necessary."""
        if page_id in self._page_table:
            frame = self._page_table[page_id]
            if frame.pin_count > 0:
                frame.pin_count -= 1

    def _evict_least_recent(self) -> int:
        """
        Scans from head of deque (oldest) to find first unpinned page.
        Raises BufferPoolFullError if all cached pages are pinned!
        """
        examined_count = 0
        total_in_queue = len(self._recency_queue)

        while examined_count < total_in_queue:
            candidate_id = self._recency_queue.popleft()
            candidate_frame = self._page_table.get(candidate_id)

            if candidate_frame and candidate_frame.pin_count == 0:
                # Successfully found unpinned cold page: execute eviction!
                del self._page_table[candidate_id]
                self.evictions += 1
                return candidate_id

            # Page is pinned! Re-insert at tail and continue scan
            self._recency_queue.append(candidate_id)
            examined_count += 1

        raise BufferPoolFullError(
            f"Buffer pool deadlock: All {self._capacity} pages are currently pinned."
        )

# ==============================================================================
# MemForge Test Suite - LRU Buffer Pool Verification (Milestone 04)
# ==============================================================================

import pytest
from memforge.cache.lru_cache import LRUBufferPool, BufferPoolFullError

class TestLRUBufferPool:
    """Unit tests asserting capacity limits, LRU eviction order, and page pinning."""

    def test_basic_put_get_and_hit_miss_counters(self):
        pool = LRUBufferPool(capacity_pages=3)
        pool.put_page(101, b"PAGE_DATA_101")
        pool.put_page(102, b"PAGE_DATA_102")

        assert pool.get_page(101) == b"PAGE_DATA_101"
        assert pool.hits == 1

        assert pool.get_page(999) is None
        assert pool.misses == 1

    def test_lru_eviction_discards_oldest_item(self):
        # Capacity = 3
        pool = LRUBufferPool(capacity_pages=3)
        pool.put_page(1, "A")
        pool.put_page(2, "B")
        pool.put_page(3, "C")

        # Access page 1 -> moves Page 1 to Most Recently Used (tail)
        pool.get_page(1)  # Recency order: 2 (oldest), 3, 1 (newest)

        # Insert Page 4 -> must trigger eviction of Page 2!
        pool.put_page(4, "D")

        assert len(pool) == 3
        assert pool.evictions == 1
        assert pool.get_page(2) is None  # Page 2 was evicted!
        assert pool.get_page(1) == "A"    # Page 1 preserved!
        assert pool.get_page(3) == "C"
        assert pool.get_page(4) == "D"

    def test_pinned_pages_are_protected_from_eviction(self):
        pool = LRUBufferPool(capacity_pages=2)
        # Page 1 is pinned!
        pool.put_page(1, "PINNED_PAGE", pin=True)
        pool.put_page(2, "UNPINNED_PAGE")

        # Page 1 is oldest, but it is PINNED. Inserting Page 3 must evict Page 2!
        pool.put_page(3, "NEW_PAGE")

        assert pool.get_page(1) == "PINNED_PAGE"  # Protected!
        assert pool.get_page(2) is None           # Evicted!
        assert pool.get_page(3) == "NEW_PAGE"

    def test_pool_deadlock_when_all_pages_are_pinned(self):
        pool = LRUBufferPool(capacity_pages=2)
        pool.put_page(1, "A", pin=True)
        pool.put_page(2, "B", pin=True)

        # All pages pinned -> cannot evict -> raises BufferPoolFullError
        with pytest.raises(BufferPoolFullError):
            pool.put_page(3, "C")

        # Unpin page 1 and retry
        pool.unpin_page(1)
        pool.put_page(3, "C")  # Succeeds: evicts page 1!
        assert pool.get_page(1) is None
        assert pool.get_page(3) == "C"
Warning Track

Beginner Pitfalls & Architectural Anti-Patterns

❌ The extendleft() Order Reversal Surprise

Executing d.extendleft([1, 2, 3]) expecting [1, 2, 3, ...] on the left.

Why this causes bugs: extendleft iterates forward and calls appendleft() on each item. 1 is prepended, then 2 is prepended in front of 1, then 3 in front of 2! The deque becomes [3, 2, 1, ...]! Fix: Reverse the iterable explicitly: d.extendleft(reversed([1, 2, 3])).

❌ Middle-Index Slicing on a Deque

Writing val = d[len(d) // 2] or attempting slice operations d[10:20].

Why this kills throughput: Unlike lists which use contiguous arrays with instant $O(1)$ pointer math, deque does not support slicing and middle-index queries take $O(n)$ by walking 64-element block pointers. Fix: If your algorithm requires frequent random access or slicing, use a standard list.

❌ Unbounded Worker Queues (OOM Crashes)

Instantiating a producer queue without setting a bound: q = deque().

Why this causes Out-Of-Memory crashes: If producers generate events faster than consumers process them, an unbounded queue grows indefinitely, consuming all server RAM until the OS kills the process. Fix: Always bound queues with deque(maxlen=10000) or use queue.Queue(maxsize=10000) to apply backpressure.

❌ Using queue.Queue for Single-Threaded Code

Importing from queue import Queue for an in-memory algorithm running in a single thread.

Why this wastes CPU cycles: Python's queue.Queue wraps operations in heavy threading synchronization primitives (threading.Condition, threading.Lock). In single-threaded execution, it is up to 15x slower than collections.deque!
