Part 01

Computer Science: Hash Functions, SipHash-13 & The Hash Contract

At its mathematical core, a Hash Function maps arbitrary-sized data (such as a string, tuple, or binary payload) to a fixed-size integer. In Python on 64-bit systems, this is a signed 64-bit integer between $-2^{63}$ and $2^{63}-1$.

By the Pigeonhole Principle, because the domain of possible keys is infinitely larger than the finite set of 64-bit integers, collisions are mathematically inevitable ($h(k_1) = h(k_2)$ where $k_1 \neq k_2$). The performance of a hash table depends on two distinct factors: the quality of the hash function and the collision resolution strategy.

Security Architecture: SipHash-13 & Hash Flooding Defense

Why Python randomizes string hashing across process restarts

1. The Hash Flooding Exploit (DoS)

If an attacker knows the exact mathematical hash algorithm used by a server, they can craft thousands of distinct HTTP parameter keys that all hash to the exact same bucket slot. When inserted into a dictionary, every operation degenerates from $O(1)$ to a disastrous $O(n)$ linear scan, spiking CPU utilization to 100% and taking the backend offline.

2. Python's SipHash-13 Solution

Since Python 3.4 (PEP 456), CPython hashes strings, bytes, and memoryviews using SipHash-13, initialized with a cryptographically secure 128-bit secret seed randomly generated when the Python interpreter process boots. An attacker cannot predict collisions across processes, completely neutralizing algorithmic complexity attacks.

The Python Hashability Contract:

For an object to be usable as a dictionary key or set element, it must be hashable:

  1. It must implement __hash__() returning an integer that never changes during the object's lifetime.
  2. It must implement __eq__() to verify equality with other objects.
  3. The Invariant: If a == b is True, then hash(a) == hash(b) MUST be True. (The converse is not required due to collisions).
  4. Mutable containers (such as list, dict, set) are unhashable because their contents mutate, which would displace them from their bucket position and corrupt the table.

CPython Internals: The Compact Dictionary Architecture

Prior to Python 3.6, CPython used a classic Sparse Table Layout. Every hash table was a large array of 24-byte structs (me_hash, me_key, me_value). Because a dictionary must maintain a load factor under $\approx 2/3$ to prevent collisions, at least one-third of this large table remained empty, wasting substantial memory and disrupting memory cache locality.

Python 3.6 introduced the Compact Dictionary Layout (proposed by Raymond Hettinger and adapted from PyPy). This architecture separates the lookup indices from the storage entries, slashing memory usage by 20% to 25% and providing a celebrated side effect: dictionaries preserve insertion order by default.

Memory Layout: Legacy Sparse Array vs. Modern Compact Dict
Legacy Layout (≤ Python 3.5)

Single large sparse array of 24-byte entries. Wastes memory on empty slots.

[0] -- EMPTY (24 bytes wasted) --
[1] hash | "user_id" | 991
[2] -- EMPTY (24 bytes wasted) --
[3] hash | "role" | "admin"
[4] -- EMPTY (24 bytes wasted) --
Modern Compact Layout (Python 3.6+)

Dense packed entries array + tiny sparse indices array (1 byte per slot).

// 1. Sparse Indices Array (int8: -1 means empty)
-1
0
-1
1
-1
// 2. Dense Entries Array (Packed in arrival order)
[Index 0] hash | "user_id" | 991
[Index 1] hash | "role" | "admin"

Why Insertion Order is Preserved: Because items are appended sequentially to the end of the entries array, iterating over keys, values, or items simply scans the dense entries table linearly from 0 to $N-1$.

Part 02

Under the Hood: Open Addressing, Perturbation & Tombstones

When two distinct keys produce the same initial index slot ($i = \text{hash}(k) \pmod{\text{size}}$), how does the table resolve the conflict? Two major paradigms exist in computer science:

Separate Chaining Java HashMap

Every bucket in the table stores a linked list (or balanced binary tree) of entries that collided on that slot.

  • Advantage: The table never fills up; deletions are simple linked-list pointer updates.
  • Disadvantage: Terrible cache locality. Allocates separate node objects on the heap, thrashing CPU cache lines with pointer chasing.
Open Addressing CPython Dict

All entries reside directly within the array. When a collision occurs, the algorithm checks another slot in the table following a deterministic probe sequence.

  • Advantage: Exceptional cache locality. No linked-list pointer overhead.
  • Disadvantage: Requires careful deletion handling (tombstones) and dynamic resizing when load factor exceeds 2/3.
// CPython's Perturbation Probing Sequence

Simple linear probing ($i = (i + 1) \pmod{\text{size}}$) suffers from primary clustering: contiguous blocks of occupied slots build up, causing long search times. To prevent this, CPython uses a recurrence relation that incorporates unconsumed bits of the key's full 64-bit hash code:

i = (hash) & mask
perturb = hash
while bucket is occupied and key != target:
i = (5 * i + 1 + perturb) & mask
perturb >>= 5

The factor 5 * i + 1 is mathematically guaranteed to visit every slot in any power-of-two table size. Shifting perturb >>= 5 systematically injects all bits of the original 64-bit hash, scattering search probes across disparate table regions.

The Probe Continuity Invariant

Why Deletions Require Tombstones

In an open-addressing hash table, search stops when it encounters an EMPTY slot. Suppose Key $A$ and Key $B$ both hash to bucket 2. Key $A$ is placed at bucket 2; Key $B$ collides and probes forward to bucket 5.

1. Insert A → Bucket 2
2. Insert B → Bucket 2 (Collision!) → Probes to Bucket 5
3. Delete A → If Bucket 2 is marked completely EMPTY:
4. Query for B → Checks Bucket 2 → Sees EMPTY → Fails with KeyError! (B is lost!)

To preserve probe chain continuity, deleted entries must be replaced with a special sentinel marker: a Tombstone (e.g. <DUMMY>). A search probe treats a tombstone as occupied and continues searching, whereas an insertion probe can reuse the tombstone slot to store a new key!

Exhaustive Native Function Reference: dict & set

Python provides two core built-in hash-based structures: dict (mapping keys to values) and set / frozenset (storing unique keys without values).

1. Python dict Native API

Associative key-value mapping with O(1) average-time complexity

2. Python set & frozenset Native API

Unordered collections of unique hashable elements

Set Algebra
Fundamental Operations
  • s.add(elem): $O(1)$ amortized insertion of hashable element.
  • s.remove(elem): $O(1)$ deletion. Raises KeyError if absent.
  • s.discard(elem): $O(1)$ silent deletion. Never raises errors.
  • s.pop(): $O(1)$ removes arbitrary element. Raises KeyError if empty.
Mathematical Set Algebra
  • s1 | s2 (union): $O(len(s1) + len(s2))$ elements in either set.
  • s1 & s2 (intersection): $O(\min(len(s1), len(s2)))$ elements in both sets.
  • s1 - s2 (difference): $O(len(s1))$ elements in s1 but not s2.
  • s1 ^ s2 (symmetric diff): $O(len(s1) + len(s2))$ elements in exactly one set.

MemForge Milestone 02: Building a Custom Hash Table Engine

To power MemForge's primary key record lookups, we now construct src/memforge/core/hash_map.py: an open-addressing hash table written completely from scratch.

Our custom hash table features:

  • Deterministic perturbation probing sequence identical to CPython ($i = (5i + 1 + \text{perturb}) \pmod{\text{size}}$).
  • Sentinel <DUMMY> tombstone handling to guarantee probe chain continuity across deletions.
  • Dynamic resizing (doubling capacity) when the load factor exceeds $\approx 0.66$ ($2/3$).
  • Full Python mapping protocol support: __getitem__, __setitem__, __delitem__, __contains__, and __len__.

1. Custom Hash Table Engine: src/memforge/core/hash_map.py Open-Addressing Implementation 
# ==============================================================================
# MemForge Core - Custom Open-Addressing Hash Map (Milestone 02)
# ==============================================================================

from dataclasses import dataclass
from typing import Any, Iterator, Optional, Tuple

# Sentinel token used to mark deleted bucket slots (Tombstones)
_DUMMY_TOMBSTONE = object()

@dataclass
class HashEntry:
    """Discrete storage bucket containing cached hash code, key, and value."""
    hash_code: int
    key: Any
    value: Any

class MemForgeHashMap:
    """
    PRODUCTION OPEN-ADDRESSING HASH MAP:
    Implements CPython's perturbation recurrence probe sequence:
    i = (5*i + 1 + perturb) & mask.
    Enforces a strict 2/3 (0.66) load factor threshold before dynamic resizing.
    """
    INITIAL_CAPACITY = 8  # Power-of-two table capacity
    LOAD_FACTOR_THRESHOLD = 0.66

    def __init__(self, initial_capacity: int = INITIAL_CAPACITY):
        # Capacity must be a power of two to allow bitwise masking: (capacity - 1)
        self._capacity = initial_capacity
        self._buckets: list[Optional[Any]] = [None] * self._capacity
        self._active_count = 0     # Count of real, active keys
        self._tombstone_count = 0  # Count of dead tombstone entries

    def __len__(self) -> int:
        """Returns total active key-value pairs stored in the table."""
        return self._active_count

    def _lookup_slot(self, key: Any, hash_code: int) -> Tuple[bool, int]:
        """
        Core probe search: Runs CPython perturbation sequence.
        Returns: (found_flag: bool, target_slot_index: int)
        """
        mask = self._capacity - 1
        i = hash_code & mask
        perturb = hash_code
        first_tombstone_idx: Optional[int] = None

        while self._buckets[i] is not None:
            bucket = self._buckets[i]
            if bucket is _DUMMY_TOMBSTONE:
                # Record the first available tombstone slot for potential reuse
                if first_tombstone_idx is None:
                    first_tombstone_idx = i
            elif bucket.hash_code == hash_code and bucket.key == key:
                # Exact key match found!
                return (True, i)

            # CPython Perturbation Recurrence Probing
            i = (5 * i + 1 + perturb) & mask
            perturb >>= 5

        # Key absent. If a tombstone was passed, reuse it; else return empty slot.
        free_slot = first_tombstone_idx if first_tombstone_idx is not None else i
        return (False, free_slot)

    def __setitem__(self, key: Any, value: Any) -> None:
        """Associates value with key, resizing table if load factor exceeded."""
        h = hash(key)
        found, slot = self._lookup_slot(key, h)

        if found:
            # In-place value update
            self._buckets[slot].value = value
            return

        # Slot is empty or tombstone
        if self._buckets[slot] is _DUMMY_TOMBSTONE:
            self._tombstone_count -= 1

        self._buckets[slot] = HashEntry(hash_code=h, key=key, value=value)
        self._active_count += 1

        # Calculate total occupied slots (active + dead tombstones)
        total_occupied = self._active_count + self._tombstone_count
        if (total_occupied / self._capacity) >= self.LOAD_FACTOR_THRESHOLD:
            self._resize(self._capacity * 2)

    def __getitem__(self, key: Any) -> Any:
        """Retrieves value for key. Raises KeyError if key does not exist."""
        found, slot = self._lookup_slot(key, hash(key))
        if not found:
            raise KeyError(f"Key '{key}' not found in MemForgeHashMap.")
        return self._buckets[slot].value

    def __delitem__(self, key: Any) -> None:
        """Deletes key and replaces bucket with tombstone marker to preserve probe chain."""
        found, slot = self._lookup_slot(key, hash(key))
        if not found:
            raise KeyError(f"Cannot delete nonexistent key '{key}'.")

        # Replace entry with tombstone sentinel
        self._buckets[slot] = _DUMMY_TOMBSTONE
        self._active_count -= 1
        self._tombstone_count += 1

    def __contains__(self, key: Any) -> bool:
        """Fast boolean membership test."""
        found, _ = self._lookup_slot(key, hash(key))
        return found

    def get(self, key: Any, default: Any = None) -> Any:
        """Safe query returning default value if key is missing."""
        found, slot = self._lookup_slot(key, hash(key))
        return self._buckets[slot].value if found else default

    def _resize(self, new_capacity: int) -> None:
        """Allocates a larger table, purging dead tombstones and re-inserting all active entries."""
        old_buckets = self._buckets
        self._capacity = new_capacity
        self._buckets = [None] * new_capacity
        self._active_count = 0
        self._tombstone_count = 0

        for bucket in old_buckets:
            if bucket is not None and bucket is not _DUMMY_TOMBSTONE:
                self[bucket.key] = bucket.value

# ==============================================================================
# MemForge Test Suite - Custom Hash Map Verification (Milestone 02)
# ==============================================================================

import pytest
from memforge.core.hash_map import MemForgeHashMap

class CollisionKey:
    """Helper key fixture designed to force identical hash codes and test collisions."""
    def __init__(self, value: str, forced_hash: int = 42):
        self.value = value
        self.forced_hash = forced_hash

    def __hash__(self) -> int:
        return self.forced_hash

    def __eq__(self, other: object) -> bool:
        return isinstance(other, CollisionKey) and self.value == other.value


class TestMemForgeHashMap:
    """Unit tests asserting insertion, collision probing, tombstones, and resizing."""

    def test_basic_crud_operations(self):
        hm = MemForgeHashMap()
        hm["user_id"] = 991
        hm["role"] = "admin"

        assert len(hm) == 2
        assert hm["user_id"] == 991
        assert hm["role"] == "admin"
        assert "user_id" in hm
        assert "missing" not in hm

        # Update
        hm["role"] = "superuser"
        assert hm["role"] == "superuser"
        assert len(hm) == 2

        # Delete
        del hm["user_id"]
        assert len(hm) == 1
        assert "user_id" not in hm
        with pytest.raises(KeyError):
            _ = hm["user_id"]

    def test_collision_resolution_and_probe_chain(self):
        hm = MemForgeHashMap(initial_capacity=8)
        k1 = CollisionKey("key_A", forced_hash=10)
        k2 = CollisionKey("key_B", forced_hash=10)
        k3 = CollisionKey("key_C", forced_hash=10)

        # All keys hash to the same bucket (10 % 8 = 2). Probing must place all 3 cleanly.
        hm[k1] = "val_A"
        hm[k2] = "val_B"
        hm[k3] = "val_C"

        assert len(hm) == 3
        assert hm[k1] == "val_A"
        assert hm[k2] == "val_B"
        assert hm[k3] == "val_C"

    def test_tombstone_preserves_probe_continuity_on_deletion(self):
        hm = MemForgeHashMap(initial_capacity=8)
        k1 = CollisionKey("key_A", forced_hash=10)
        k2 = CollisionKey("key_B", forced_hash=10)
        k3 = CollisionKey("key_C", forced_hash=10)

        hm[k1] = "val_A"
        hm[k2] = "val_B"
        hm[k3] = "val_C"

        # Delete middle key k2 (replaces with tombstone)
        del hm[k2]
        assert len(hm) == 2
        assert k2 not in hm

        # CRITICAL PROBE TEST: k3 must STILL be found past the tombstone of k2!
        assert hm[k3] == "val_C"

    def test_dynamic_resizing_on_exceeding_load_factor(self):
        hm = MemForgeHashMap(initial_capacity=8)
        # 8 * 0.66 = 5.28 → Inserting 6 items must trigger resize to capacity 16
        for i in range(6):
            hm[f"key_{i}"] = i * 10

        assert len(hm) == 6
        assert hm._capacity == 16  # Table doubled in size

        # Ensure all previously inserted keys remain accessible after rehashing
        for i in range(6):
            assert hm[f"key_{i}"] == i * 10
Warning Track

Beginner Pitfalls & Architectural Anti-Patterns

❌ Mutating a Dict/Set While Iterating

Writing for k in d: if condition: del d[k].

Why this crashes: Modifying table entries or triggering a resize alters the internal iteration dictionary view pointer, immediately raising RuntimeError: dictionary changed size during iteration. Fix: Iterate over a snapshot list: for k in list(d.keys()): del d[k].

❌ The Redundant Double-Lookup Trap

Writing if "key" in d: val = d["key"].

Why this hurts throughput: It hashes the key, traverses the probe sequence, and locates the slot twice. Fix: Execute a single lookup using val = d.get("key", default) or handle KeyError explicitly.

❌ The setdefault() Eager Evaluation Trap

Writing d.setdefault(k, expensive_computation()).

Why this wastes CPU: Python evaluates arguments before calling the function. Even if k already exists in the dictionary, expensive_computation() is executed on every call anyway! Fix: Use collections.defaultdict or standard if k not in d: guard blocks.

❌ Implementing __eq__ Without __hash__

Defining a custom domain class with def __eq__(self, other): without an accompanying def __hash__(self):.

Why this fails silently: In Python 3, if a class defines __eq__ but not __hash__, Python sets __hash__ = None, making the class immediately unhashable and raising TypeError: unhashable type if added to a set or dict.
