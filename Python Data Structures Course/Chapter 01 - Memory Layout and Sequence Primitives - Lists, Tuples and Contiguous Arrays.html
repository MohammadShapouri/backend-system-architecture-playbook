Part 01

Computer Science: CPython Memory Anatomy & Sequence Primitives

To master data structures in Python, one must abandon the illusion that a list is a flat block of values. In CPython (the standard C implementation of Python), all objects exist as heap-allocated C structures.

A Python list is technically a referential dynamic array. It does not store actual data inline; rather, it stores an array of 64-bit memory addresses (pointers) that reference other independent PyObject structures scattered throughout the heap.

// CPython Internals: Dynamic Array Resizing Mathematics

Why is appending to a Python list $O(1)$ amortized rather than $O(n)$? Because CPython does not allocate space for only one extra item on every append. When the underlying array is full, CPython invokes list_resize() in Objects/listobject.c. The over-allocation growth formula calculates:

new_allocated = ((size_t)newsize + (newsize >> 3) + (newsize < 9 ? 3 : 6)) & ~(size_t)3;

This formula expands capacity in discrete jumps ($0, 4, 8, 16, 24, 32, 40, 52, 64, \dots$). The geometric factor roughly approximates an expansion ratio of $1.125$ ($+12.5\%$), striking a mathematical balance between avoiding runaway RAM waste and minimizing expensive memory reallocation syscalls (`realloc`).

Python provides four core sequence primitives across the language and standard library. Understanding every native function, mutation semantic, and mechanical failure mode is non-negotiable for writing production software.

2. Python tuple Native API (Immutable Referential Array)

Fixed-size sequence with structural freelist caching and hashing guarantees

Immutable

Tuples lack mutating methods (.append, .pop, .sort). They possess only .count() and .index(). However, immutability provides three critical systems advantages:

  • Zero Over-Allocation: Tuples allocate memory for the exact number of elements specified at instantiation. A 3-item list takes 80+ bytes; a 3-item tuple takes 64 bytes.
  • CPython Freelist Optimization: When a tuple of size $\le 20$ is garbage collected, CPython does not free the memory block back to the OS; it preserves it in an internal array of freelists for instantaneous re-use.
  • Hashability & Dictionary Keys: If all items inside a tuple are immutable (e.g. ints, strings), the tuple is hashable via __hash__(), allowing it to act as a compound dictionary key.

3. array.array & bytearray (True Contiguous Primitives)

Uniform C-types packed directly into linear hardware memory

High Density
array.array(typecode, [initializer])

Requires a strict C-type format character (e.g. 'i' for 32-bit signed integer, 'd' for 64-bit double, 'Q' for 64-bit unsigned integer). Stores primitive scalar values without PyObject wrappers. 1,000,000 integers in a list require ~8MB of RAM; in an array('i'), they require exactly ~4MB.

bytearray([source]) & memoryview(obj)

A mutable array of bytes (integers $0 \le x \le 255$). Combined with memoryview(), it unlocks the Python Buffer Protocol: slicing a memoryview creates a pointer window over existing memory with zero copying overhead ($O(1)$ memory and time).

Part 03

Algorithmic Mechanics: Searching, Slicing & Timsort

How do we maximize the throughput of operations on sequence primitives? We must understand the algorithmic engines underlying Python's search and sort functions.

Sorting Engine

CPython Timsort Internals

Invented by Tim Peters in 2002 for CPython, Timsort is a hybrid, adaptive, stable sorting algorithm that blends Insertion Sort with Merge Sort:

  • Run Detection: Scans array to identify contiguous chunks that are already ascending or strictly descending. Descending runs are reversed in-place ($O(n)$).
  • Minrun Splitting: Short runs are padded to a minimum threshold ($\text{minrun} \in [32, 64]$) and sorted via high-speed Binary Insertion Sort.
  • Merge Collapse: Runs are merged together using a stack invariant to maintain balanced sub-tree depths, guaranteeing $O(n \log n)$ worst-case and $O(n)$ best-case on partially sorted data.
Searching & Slices

Search Cost & The Slicing Trap

Understanding computational boundaries prevents insidious bottlenecks:

  • Linear Scan (`in` / `.index`): Unsorted lists require inspecting every pointer sequentially: $O(n)$ average and worst case.
  • The Slicing Memory Trap: Executing sub = my_list[100:500000] allocates a brand new list and copies 499,900 object references ($O(k)$ time and space).
  • The Zero-Copy Fix: Use memoryview on bytes/bytearrays. Slicing a memoryview creates a new view descriptor without allocating or copying underlying payload bytes ($O(1)$).

1. Production Core: src/memforge/core/buffer.py Zero-Copy Memory & Index Buffer 
# ==============================================================================
# MemForge Storage Engine - Core Sequence & Memory Buffers (Milestone 01)
# ==============================================================================

import array
from typing import Iterator, Tuple

class BufferOverflowError(Exception):
    """Raised when writing data exceeds maximum pre-allocated buffer capacity."""
    pass

class RecordNotFoundError(Exception):
    """Raised when querying a record index beyond valid written bounds."""
    pass


class ContiguousBuffer:
    """
    ZERO-COPY BINARY RING BUFFER:
    Pre-allocates a contiguous bytearray block in memory.
    Utilizes Python memoryview to slice and read byte segments without
    incurring heap allocations or intermediate memory copies.
    """
    def __init__(self, capacity_bytes: int = 1024 * 1024):
        # Physical allocation: One single contiguous chunk in RAM
        self._capacity = capacity_bytes
        self._raw_buffer = bytearray(capacity_bytes)
        # Create root memoryview: Exposes C-level buffer protocol
        self._view = memoryview(self._raw_buffer)
        # Cursor tracking total valid payload bytes written
        self._write_cursor = 0

    @property
    def bytes_written(self) -> int:
        """Returns total bytes written to the buffer."""
        return self._write_cursor

    @property
    def remaining_capacity(self) -> int:
        """Returns remaining unoccupied memory slots in bytes."""
        return self._capacity - self._write_cursor

    def write(self, payload: bytes) -> Tuple[int, int]:
        """
        Writes a byte chunk into contiguous memory in-place.
        Returns: (start_offset, length) tuple for index tracking.
        Raises: BufferOverflowError if payload exceeds remaining space.
        """
        payload_len = len(payload)
        if payload_len > self.remaining_capacity:
            raise BufferOverflowError(
                f"Cannot write {payload_len} bytes; only {self.remaining_capacity} bytes available."
            )

        start = self._write_cursor
        end = start + payload_len

        # In-place slice mutation: writes directly into pre-allocated memory
        self._raw_buffer[start:end] = payload
        self._write_cursor = end

        return (start, payload_len)

    def read_zero_copy(self, start: int, length: int) -> memoryview:
        """
        ZERO-COPY READ:
        Returns a sliced memoryview referencing the exact underlying RAM slice.
        Zero memory copying takes place regardless of the requested slice size!
        """
        if start < 0 or (start + length) > self._write_cursor:
            raise RecordNotFoundError(f"Offset range [{start}:{start+length}] is out of written bounds.")

        return self._view[start : start + length]

    def clear(self) -> None:
        """
        Fast O(1) buffer reset:
        Resets cursor to zero without zeroing RAM, avoiding expensive memset cycles.
        """
        self._write_cursor = 0


class FixedRecordArray:
    """
    HIGH-DENSITY NUMERIC INDEX ARRAY:
    Stores 64-bit unsigned integer offsets ('Q' typecode) in compact C-arrays.
    Eliminates PyObject pointer overhead, consuming exactly 8 bytes per record.
    """
    def __init__(self):
        # 'Q' represents unsigned 64-bit integer (unsigned long long in C)
        self._index_offsets = array.array('Q')

    def append_offset(self, offset: int) -> int:
        """
        Appends an integer offset into the contiguous array.
        Returns: The unique auto-incrementing Record ID (index position).
        """
        if offset < 0:
            raise ValueError("Record offsets must be positive integers.")
        
        self._index_offsets.append(offset)
        return len(self._index_offsets) - 1

    def get_offset(self, record_id: int) -> int:
        """Fast O(1) random access direct read from the C-array buffer."""
        try:
            return self._index_offsets[record_id]
        except IndexError as err:
            raise RecordNotFoundError(f"Record ID {record_id} does not exist in index.") from err

    def __len__(self) -> int:
        return len(self._index_offsets)

    def __iter__(self) -> Iterator[int]:
        return iter(self._index_offsets)

# ==============================================================================
# MemForge Test Suite - Contiguous Buffer & Index Tests (Milestone 01)
# ==============================================================================

import pytest
from memforge.core.buffer import (
    ContiguousBuffer, 
    FixedRecordArray, 
    BufferOverflowError, 
    RecordNotFoundError
)

class TestContiguousBuffer:
    """Validates zero-copy slicing, cursor bounds, and overflow guards."""

    def test_write_and_zero_copy_read_cycle(self):
        buf = ContiguousBuffer(capacity_bytes=64)
        data = b"MEMFORGE_TXN_01:SET:user_id:991"
        
        offset, length = buf.write(data)
        assert offset == 0
        assert length == len(data)
        assert buf.bytes_written == len(data)

        # Read data back using zero-copy memoryview
        view_slice = buf.read_zero_copy(offset, length)
        assert isinstance(view_slice, memoryview)
        assert view_slice.tobytes() == data

    def test_consecutive_writes_increment_offsets_correctly(self):
        buf = ContiguousBuffer(capacity_bytes=128)
        off1, len1 = buf.write(b"RECORD_A")
        off2, len2 = buf.write(b"RECORD_B")

        assert off1 == 0
        assert len1 == 8
        assert off2 == 8
        assert len2 == 8
        assert buf.bytes_written == 16

        assert buf.read_zero_copy(off1, len1).tobytes() == b"RECORD_A"
        assert buf.read_zero_copy(off2, len2).tobytes() == b"RECORD_B"

    def test_writing_beyond_capacity_raises_overflow_error(self):
        buf = ContiguousBuffer(capacity_bytes=10)
        with pytest.raises(BufferOverflowError, match=r"Cannot write 15 bytes"):
            buf.write(b"0123456789ABCDE")

    def test_reading_out_of_bounds_raises_record_not_found(self):
        buf = ContiguousBuffer(capacity_bytes=32)
        buf.write(b"VALID_RECORD")
        with pytest.raises(RecordNotFoundError):
            buf.read_zero_copy(start=20, length=5)


class TestFixedRecordArray:
    """Validates 64-bit integer index offset array."""

    def test_append_and_random_access_indexing(self):
        idx = FixedRecordArray()
        rec_id_0 = idx.append_offset(0)
        rec_id_1 = idx.append_offset(256)
        rec_id_2 = idx.append_offset(1024)

        assert rec_id_0 == 0
        assert rec_id_1 == 1
        assert rec_id_2 == 2

        assert idx.get_offset(0) == 0
        assert idx.get_offset(1) == 256
        assert idx.get_offset(2) == 1024
        assert len(idx) == 3

    def test_out_of_bounds_record_id_raises_error(self):
        idx = FixedRecordArray()
        idx.append_offset(128)
        with pytest.raises(RecordNotFoundError):
            idx.get_offset(99)
Warning Track

Beginner Pitfalls & Architectural Anti-Patterns

❌ The O(n²) Left-Pop Queue Disaster

Using list.pop(0) inside a loop to process a queue of incoming tasks.

Why this destroys performance: When index 0 is removed, CPython executes memmove() to physically shift every remaining element left by one pointer slot. Popping $N$ items one-by-one from a list of $100,000$ elements forces 5 billion memory shifts, freezing your app for minutes! Fix: Use collections.deque for $O(1)$ bidirectional pops.

❌ The Shared Shallow Reference Trap

Initializing a multi-dimensional matrix using multiplication syntax: matrix = [[0] * 5] * 5.

Why this causes subtle bugs: The outer list does not create 5 distinct lists; it replicates the exact same inner list reference 5 times. Modifying matrix[0][0] = 1 mutates all 5 rows simultaneously! Fix: Use a list comprehension to allocate separate inner lists: [[0 for _ in range(5)] for _ in range(5)].

❌ Quadratic String Concatenation in Loops

Constructing a serialized payload via repeated concatenation: buffer = buffer + chunk inside a network loop.

Why this crashes throughput: Strings are immutable. Every + re-allocates a completely new string in memory and copies all previous characters, yielding $O(n^2)$ time. Fix: Collect chunks into a bytearray or append to a list and call b"".join(list).

❌ Ignoring sys.getsizeof() Pointer Overhead

Storing 10 million integers in a standard list for analytical processing.

Why this thrashes RAM: A 64-bit integer takes 28 bytes in Python, plus an 8-byte pointer inside the list ($36\text{ bytes per integer}$). 10 million integers eat 360MB! Fix: Use array.array('q') or NumPy, storing raw 8-byte scalars in contiguous memory, reducing RAM footprint to exactly 80MB.
