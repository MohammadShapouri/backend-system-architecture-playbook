Part 01

Computer Science: Contiguous Arrays vs. Disjoint Pointer Chacing

Up to this point, our data structures (lists, arrays, deques) have utilized contiguous or blocked memory buffers. In a dynamic array, elements sit at predictable numeric offsets ($i \times \text{element\_size}$), conferring two immense advantages: instant $O(1)$ random access indexing and hardware CPU cache line pre-fetching.

However, dynamic arrays exhibit severe architectural weaknesses when building dynamic transactional logs, free-memory allocators, and graph pipelines: inserting or deleting an element at an arbitrary midpoint requires an expensive $O(n)$ physical memory shift (memmove()), and dynamic arrays frequently suffer from capacity reallocation spikes.

Physical Memory Topologies: Contiguous Array vs. Disjoint Linked Nodes

Part 02

Architectural Elegance: Sentinel (Dummy) Boundary Nodes

When beginner developers implement linked lists, their code becomes littered with fragile conditional checks:

if self.head is None: ...
elif node_to_delete == self.head: ...
elif node_to_delete == self.tail: ...
else: ... # Vulnerable to null pointer exceptions!

Senior systems architects eliminate 100% of these edge cases using the Sentinel Node Pattern (also called Dummy Head and Dummy Tail).

Sentinel-Guarded Doubly Linked List Topology

Every real payload node is guaranteed to have non-null prev and next pointers

[SENTINEL HEAD]
prev = None
next → Node 1
⇔
Real Node 1 (Action A)
← prev: Sentinel Head
next: Real Node 2 →
⇔
Real Node 2 (Action B)
← prev: Real Node 1
next: Sentinel Tail →
⇔
[SENTINEL TAIL]
← prev: Node 2
next = None
The Sentinel Invariants:
  • An empty list is simply initialized with head.next = tail and tail.prev = head.
  • Zero Special Cases: Inserting a node before the tail or after the head executes the exact same pointer reassignment formula whether the list contains 0 items or 1,000,000 items.
  • Safe Deletion: Removing a known node N is universally achieved in two lines:
    N.prev.next = N.next
    N.next.prev = N.prev
Part 03

Algorithmic Mechanics: Floyd's Cycle Detection & CPython Cyclic GC

Pointer-based structures introduce two subtle runtime hazards: accidental pointer loops causing infinite iteration freezing, and circular reference memory leaks that bypass standard CPython reference counting.

Topology Auditing

Floyd's Cycle Algorithm (Tortoise & Hare)

To determine if a linked list contains an unintended cycle without allocating extra memory for a visited hash set:

  • Maintain two pointers: slow (advances 1 step) and fast (advances 2 steps).
  • If the list is acyclic, fast reaches the tail / None in $O(n)$ time.
  • If a cycle exists, the fast pointer loops around and catches up to the slow pointer from behind. The moment slow == fast, a cycle is mathematically proven!
  • Complexity: Time: $O(n)$ | Space: strictly $O(1)$ auxiliary memory.
Memory Management

Circular Reference Leaks & gc Module

CPython deallocates objects instantly when their reference counter drops to zero (ob_refcnt == 0).

  • The Doubly-Linked Trap: In a doubly linked list, Node A points to Node B (A.next = B) and Node B points back to Node A (B.prev = A).
  • Even if your program deletes the parent list reference, A and B still reference each other! Their reference count never drops to zero!
  • The Solution: They must wait for CPython's generational cyclic garbage collector (gc.collect()) to break the cycle. In production engines, always implement an explicit .clear() method that unlinks all nodes to free memory immediately!
Part 04

MemForge Milestone 07: Transaction Undo Log Implementation

We now assemble Milestone 07 of MemForge. We implement src/memforge/txn/undo_log.py: an ACID transactional rollback chain.

The undo log architecture enforces:

  • Sentinel-guarded doubly linked list nodes storing inverse compensating mutations (key, previous_value, action).
  • Instant $O(1)$ action appending to the tail of the active transaction chain.
  • Transactional Rollback: Iterates backwards from tail to head, reversing all mutations and restoring original data states upon query failure.
  • Savepoint Support: Allows rolling back partially to a designated savepoint node while preserving earlier operations.
  • Explicit cyclic reference unlinking on commit or discard to prevent garbage collector latency spikes.

1. Production Undo Log: src/memforge/txn/undo_log.py Sentinel Doubly Linked Pointer Engine 
# ==============================================================================
# MemForge Transaction Engine - Sentinel Doubly Linked Undo Log (Milestone 07)
# ==============================================================================

from dataclasses import dataclass
from typing import Any, Callable, Dict, Iterator, Optional


@dataclass
class UndoNode:
    """
    Discrete compensating action node in the doubly linked chain.
    action: 'RESTORE_VALUE' or 'DELETE_INSERTED'
    """
    action: str
    key: str
    previous_value: Any
    prev: Optional["UndoNode"] = None
    next: Optional["UndoNode"] = None


class TransactionUndoLog:
    """
    PRODUCTION SENTINEL DOUBLY LINKED LIST:
    Maintains fixed dummy head and dummy tail boundary nodes.
    Guarantees O(1) appending and rollback without null-pointer checks.
    """
    def __init__(self):
        # Allocate sentinel boundary nodes with dummy payload
        self._head = UndoNode(action="__SENTINEL_HEAD__", key="", previous_value=None)
        self._tail = UndoNode(action="__SENTINEL_TAIL__", key="", previous_value=None)

        # Invariant: Empty list links head directly to tail
        self._head.next = self._tail
        self._tail.prev = self._head
        self._length = 0

    def __len__(self) -> int:
        """Returns total active compensating actions in the undo log."""
        return self._length

    def append_undo_action(self, action: str, key: str, previous_value: Any) -> UndoNode:
        """
        Appends an undo action directly before the sentinel tail in O(1) time.
        Returns the created UndoNode to serve as a transaction savepoint handle.
        """
        new_node = UndoNode(action=action, key=key, previous_value=previous_value)
        predecessor = self._tail.prev

        # Splice pointers in 4 steps:
        new_node.prev = predecessor
        new_node.next = self._tail
        predecessor.next = new_node
        self._tail.prev = new_node

        self._length += 1
        return new_node

    def rollback_all(self, target_state_dict: Dict[str, Any]) -> int:
        """
        ROLLBACK TRANSACTION:
        Traverses backwards from tail to head, executing inverse actions
        directly onto the target state dictionary.
        Returns count of reverted actions.
        """
        return self.rollback_to_savepoint(savepoint_node=self._head, target_state_dict=target_state_dict)

    def rollback_to_savepoint(
        self,
        savepoint_node: UndoNode,
        target_state_dict: Dict[str, Any]
    ) -> int:
        """
        Rolls back actions backwards until reaching savepoint_node.
        Unlinks all reverted nodes to maintain clean pointer bounds.
        """
        reverted_count = 0
        current = self._tail.prev

        while current is not self._head and current is not savepoint_node:
            # Execute compensating action
            if current.action == "RESTORE_VALUE":
                target_state_dict[current.key] = current.previous_value
            elif current.action == "DELETE_INSERTED":
                target_state_dict.pop(current.key, None)

            reverted_count += 1
            current = current.prev

        # Unlink reverted tail chain: connect savepoint_node directly to tail
        savepoint_node.next = self._tail
        self._tail.prev = savepoint_node
        self._length -= reverted_count

        return reverted_count

    def clear(self) -> None:
        """
        EXPLICIT CYCLE-BREAKING PURGE:
        Breaks all circular node pointers to allow immediate reference count
        deallocation without burdening the cyclic garbage collector.
        """
        current = self._head.next
        while current is not self._tail and current is not None:
            next_node = current.next
            current.prev = None
            current.next = None
            current = next_node

        self._head.next = self._tail
        self._tail.prev = self._head
        self._length = 0

    def has_cycle(self) -> bool:
        """
        TOPOLOGY AUDITOR (Floyd's Tortoise & Hare Algorithm):
        Proves absence of unintended circular pointer loops in O(n) time and O(1) space.
        """
        slow = self._head
        fast = self._head

        while fast is not None and fast.next is not None:
            slow = slow.next
            fast = fast.next.next

            if slow is fast:
                return True

        return False

# MemForge Test Suite - Transaction Undo Log Verification (Milestone 07)

import pytest
from memforge.txn.undo_log import TransactionUndoLog

class TestTransactionUndoLog:
    """Unit tests asserting transactional state rollbacks, savepoint boundaries, and cycle detection."""

    def test_full_transaction_rollback_reverts_state(self):
        undo_log = TransactionUndoLog()
        state = {"balance_alice": 1000, "balance_bob": 500}

        # Transaction: Alice sends 200 to Bob
        # 1. Deduct from Alice
        undo_log.append_undo_action("RESTORE_VALUE", key="balance_alice", previous_value=1000)
        state["balance_alice"] = 800

        # 2. Add to Bob
        undo_log.append_undo_action("RESTORE_VALUE", key="balance_bob", previous_value=500)
        state["balance_bob"] = 700

        # 3. Create new audit row
        undo_log.append_undo_action("DELETE_INSERTED", key="audit_tx_99", previous_value=None)
        state["audit_tx_99"] = "COMPLETED"

        assert len(undo_log) == 3
        assert state["balance_alice"] == 800
        assert state["balance_bob"] == 700
        assert "audit_tx_99" in state

        # Simulate failure: Trigger full rollback!
        reverted = undo_log.rollback_all(target_state_dict=state)
        assert reverted == 3
        assert len(undo_log) == 0

        # State must be perfectly restored to initial conditions
        assert state["balance_alice"] == 1000
        assert state["balance_bob"] == 500
        assert "audit_tx_99" not in state

    def test_partial_rollback_to_savepoint(self):
        undo_log = TransactionUndoLog()
        state = {"step": 0}

        # Step 1: Baseline modification
        savepoint_1 = undo_log.append_undo_action("RESTORE_VALUE", "step", previous_value=0)
        state["step"] = 1

        # Step 2: Tentative operation
        undo_log.append_undo_action("RESTORE_VALUE", "step", previous_value=1)
        state["step"] = 2

        # Step 3: Tentative failure
        undo_log.append_undo_action("RESTORE_VALUE", "step", previous_value=2)
        state["step"] = 3

        assert state["step"] == 3
        assert len(undo_log) == 3

        # Roll back ONLY to savepoint_1 (reverting steps 2 and 3, preserving step 1)
        reverted = undo_log.rollback_to_savepoint(savepoint_node=savepoint_1, target_state_dict=state)
        assert reverted == 2
        assert len(undo_log) == 1
        assert state["step"] == 1

    def test_floyd_cycle_detector_identifies_accidental_loop(self):
        undo_log = TransactionUndoLog()
        n1 = undo_log.append_undo_action("RESTORE_VALUE", "a", 1)
        n2 = undo_log.append_undo_action("RESTORE_VALUE", "b", 2)
        n3 = undo_log.append_undo_action("RESTORE_VALUE", "c", 3)

        assert undo_log.has_cycle() is False

        # Intentionally corrupt the pointer structure by introducing an artificial loop
        n3.next = n1  # Loop: n1 → n2 → n3 → n1
        assert undo_log.has_cycle() is True

    def test_explicit_clear_unlinks_pointers_completely(self):
        undo_log = TransactionUndoLog()
        undo_log.append_undo_action("RESTORE_VALUE", "k1", 10)
        undo_log.append_undo_action("RESTORE_VALUE", "k2", 20)
        assert len(undo_log) == 2

        undo_log.clear()
        assert len(undo_log) == 0
        assert undo_log._head.next is undo_log._tail
        assert undo_log._tail.prev is undo_log._head
Warning Track

Beginner Pitfalls & Architectural Anti-Patterns

❌ The Orphaned Tail Pointer Catastrophe

Writing current.next = new_node before connecting new_node.next = current.next.

Why this causes memory leaks: In pointer structures, order of assignment is critical! Reassigning the forward pointer prematurely severs reference to the entire remaining chain, permanently orphaning thousands of nodes in memory. Rule: Always wire the new node's outgoing links first, before overwriting existing chain pointers.

❌ Treating Linked Lists Like Arrays

Iterating by index in a loop: for i in range(len(ll)): val = ll.get_at(i).

Why this causes O(n²) bottlenecks: Each call to get_at(i) walks the pointer chain from the head. Running this in a loop takes $1 + 2 + \dots + n = O(n^2)$ time! Fix: Implement Python's __iter__() protocol, yielding consecutive node values directly in a single $O(n)$ traversal.

❌ Spaghetti Null-Pointer Checks

Writing custom conditional branches for every insertion or deletion at the boundaries of a linked list.

Why this causes bugs: Any missed edge case yields AttributeError: 'NoneType' object has no attribute 'next' in production. Fix: Adopt the Sentinel Node Pattern: allocate dummy head and tail nodes so every real node is guaranteed non-null neighbors.

❌ Relying on CPython Refcounting for Cycles

Discarding a doubly linked list without an explicit unlinking method.

Why this thrashes RAM: Doubly linked nodes reference each other bidirectionally (next ⇔ prev), preventing immediate garbage collection upon leaving scope. Fix: Implement an explicit .clear() method that severs all pointers to free heap allocations immediately.
