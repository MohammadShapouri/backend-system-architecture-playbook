Part 01

Computer Science: Binary Tree Geometry in Flat Arrays

A Binary Heap is a complete binary tree that satisfies the Heap-Order Property. In a Min-Heap, for every node $i$ other than the root, the key of the parent is less than or equal to the key of $i$ ($\text{val}(\text{parent}) \le \text{val}(i)$). Thus, the minimal element always resides at the root.

Unlike general binary trees that allocate independent heap nodes linked together by explicit pointers, a Complete Binary Tree (where every level is completely filled except possibly the deepest, which is filled from left to right) can be packed directly into a contiguous zero-indexed flat array without wasting a single byte on child or parent pointers.

Mathematical Complexity Analysis

Floyd's Algorithm: Why heapify() is O(n) and Not O(n log n)

A frequent interview trap is assuming that transforming an arbitrary list of $n$ elements into a valid heap takes $O(n \log n)$ time because inserting $n$ elements one by one takes $n \times O(\log n)$.

Python's heapq.heapify() uses Floyd's Bottom-Up Heap Construction. Instead of sifting elements up from the top, it iterates backwards starting at the deepest non-leaf parent index $\lfloor n/2 \rfloor - 1$ down to the root 0, sifting elements downward.

// The Geometric Summation of Node Work:
In a complete binary tree of height $H = \lfloor\log_2 n\rfloor$:
• Half of all nodes ($n/2$) reside at the bottom leaf level → 0 swaps needed.
• A quarter of all nodes ($n/4$) reside 1 level above leaves → max 1 swap.
• An eighth of all nodes ($n/8$) reside 2 levels above leaves → max 2 swaps.
• Only 1 node (the root) can sift down $H$ levels.
Total Work = ∑h=0H (n / 2h+1) × O(h) = n × ∑h=0∞ (h / 2h+1) = n × 1 = O(n)

Because the vast majority of nodes reside near the bottom of the tree, the aggregate operations converge strictly to linear time $O(n)$, making batch heapification far more efficient than building a heap incrementally.

Exhaustive Native Function Reference: The heapq Module

In Python, heapq is not an object-oriented class; it is a module of algorithm functions that operate directly on standard Python lists in-place. All operations maintain a Min-Heap invariant.

Python heapq Module Functions

In-place Min-Heap algorithmic primitives backed by C acceleration (_heapq)

heapq Standard Library
Function Signature Time Complexity Mutation / Return CPython Mechanism & Operational Details
heappush(heap, item) O(log n) In-place • Returns None Appends item to the end of the list and executes sift-up to restore min-heap invariant.
heappop(heap) O(log n) In-place • Returns smallest item Swaps root with last item, pops last item, and executes sift-down on the new root. Raises IndexError if heap is empty.
heappushpop(heap, item) O(log n) In-place • Returns smallest item Compares item directly against root. If item is smaller, returns it immediately without modifying heap. Otherwise, replaces root with item and sifts down. Faster than separate push + pop.
heapreplace(heap, item) O(log n) In-place • Returns original root Pops root unconditionally and replaces it with item, then sifts down. More efficient than heappop() followed by heappush(). Raises IndexError if empty.
heapify(x) O(n) In-place • Returns None Transforms an arbitrary Python list into a valid min-heap in-place in linear time using Floyd's bottom-up sifting algorithm.
nlargest(n, iter, [key]) O(m log n) Returns list of size n Finds the $n$ largest elements using an internal Min-Heap of size $n$. Far faster than sorting entire collection of size $m$ when $n \ll m$.
nsmallest(n, iter, [key]) O(m log n) Returns list of size n Finds the $n$ smallest elements using an internal Max-Heap of size $n$.
merge(*iterables, [key]) O(N log K) Iterator Merges multiple pre-sorted inputs into a single sorted output stream using a $K$-way min-heap ($K = \text{number of streams}$). Never loads entire streams into memory.
Part 03

Production Architecture: Tie-Breaking & O(1) Tombstone Cancellation

When building production job queues, database schedulers, or network packet arbiters with heaps, engineers encounter two major architectural hurdles: comparison collision errors and updating priorities of items already in the heap.

The 3-Tuple Tie-Breaking Pattern Stability Guard

In Python, tuples compare lexicographically: element by element. If you store (priority, task) in a heap and two tasks share the same priority, Python evaluates task_a < task_b. If your task object is a dictionary or custom class lacking comparison operators, Python crashes:

TypeError: '<' not supported between instances of 'QueryTask'

The Solution: Insert a monotonically increasing sequence counter: (priority, sequence_id, task). Because sequence_id is always unique, Python never compares the task objects, guaranteeing stable FIFO ordering on priority ties!

O(1) Tombstone Cancellation Lazy Deletion

Binary heaps do not support efficient search. Finding an arbitrary task inside a heap list to delete or update its priority takes a linear scan $O(n)$, followed by $O(\log n)$ re-sifting.

The Production Solution: Maintain an external lookup map entry_finder: dict[task_id, entry].

  • Cancel: Mark the entry's task as a sentinel <REMOVED> in $O(1)$ time. Leave it in the heap!
  • Reprioritize: Mark the existing task as <REMOVED> and push a brand new 3-tuple with the updated priority in $O(\log n)$.
  • Dispatch: When heappop() extracts a task marked <REMOVED>, discard it and pop again.

1. Production Scheduler: src/memforge/scheduler/priority_queue.py Binary Heap Execution Engine 
# ==============================================================================
# MemForge Scheduler - Priority Query Queue with Tombstone Removal (Milestone 05)
# ==============================================================================

import heapq
import itertools
from dataclasses import dataclass
from typing import Any, Dict, List, Optional


class QueueEmptyError(Exception):
    """Raised when attempting to pop from an empty priority queue."""
    pass


@dataclass
class QueryTask:
    """Discrete database transaction payload submitted for execution."""
    task_id: str
    query_sql: str
    client_id: str


# Sentinel token marking cancelled tasks inside the heap
_REMOVED = "<REMOVED_TASK_TOMBSTONE>"


class PriorityQueryScheduler:
    """
    PRODUCTION QUERY SCHEDULER:
    Maintains a Min-Heap of [priority, sequence_id, task] entries.
    Provides O(log n) enqueue/dequeue, monotonic tie-breaking,
    and O(1) task cancellation/reprioritization via entry lookup mapping.
    """
    def __init__(self):
        # Underlying flat list array representing the complete binary min-heap
        self._heap: List[List[Any]] = []
        # Directory mapping task_id to its live heap entry: task_id -> [priority, seq, task]
        self._entry_finder: Dict[str, List[Any]] = {}
        # Monotonically increasing sequence generator to break comparison ties
        self._sequence_counter = itertools.count()
        # Number of active, non-cancelled tasks
        self._active_count = 0

    def __len__(self) -> int:
        """Returns total active (non-cancelled) tasks pending in the scheduler."""
        return self._active_count

    def push_query(self, task: QueryTask, priority: int = 2) -> None:
        """
        Enqueues a query task with a priority tier (lower number = higher priority).
        If task_id already exists, cancels the previous entry and updates.
        Complexity: O(log n)
        """
        if task.task_id in self._entry_finder:
            # Cancel existing task via tombstone
            self.cancel_query(task.task_id)

        seq = next(self._sequence_counter)
        # Entry layout: [priority, sequence_id, task]
        entry = [priority, seq, task]
        self._entry_finder[task.task_id] = entry
        heapq.heappush(self._heap, entry)
        self._active_count += 1

    def pop_next_query(self) -> QueryTask:
        """
        Extracts and returns the highest priority active query task.
        Automatically discards tombstoned (cancelled) tasks in O(log n) time.
        Raises QueueEmptyError if no active tasks remain.
        """
        while self._heap:
            priority, seq, task = heapq.heappop(self._heap)
            if task is not _REMOVED:
                del self._entry_finder[task.task_id]
                self._active_count -= 1
                return task

        raise QueueEmptyError("Cannot pop from an empty priority query scheduler.")

    def cancel_query(self, task_id: str) -> bool:
        """
        Cancels a task in O(1) time by marking its entry as a tombstone.
        Returns True if task was found and cancelled; False otherwise.
        """
        entry = self._entry_finder.pop(task_id, None)
        if entry is not None:
            # Replace task reference with tombstone sentinel
            entry[-1] = _REMOVED
            self._active_count -= 1
            return True
        return False

    def reprioritize_query(self, task_id: str, new_priority: int) -> bool:
        """
        Updates the priority of an active task in O(log n) time.
        Lazily cancels the old task and inserts the new priority entry.
        """
        entry = self._entry_finder.get(task_id)
        if entry is None:
            return False

        old_task: QueryTask = entry[-1]
        # Mark old entry as dead
        self.cancel_query(task_id)
        # Re-insert with new priority tier
        self.push_query(old_task, priority=new_priority)
        return True

    def peek_highest_priority(self) -> Optional[int]:
        """
        Inspects the priority number of the next active task without popping.
        Returns None if queue has no active tasks.
        """
        # Purge dead tombstones sitting at the root
        while self._heap and self._heap[0][-1] is _REMOVED:
            heapq.heappop(self._heap)

        if self._heap:
            return self._heap[0][0]
        return None

import pytest
from memforge.scheduler.priority_queue import (
    PriorityQueryScheduler, 
    QueryTask, 
    QueueEmptyError
)

class TestPriorityQueryScheduler:
    """Unit tests asserting priority dispatch, sequence tie-breaking, and cancellation."""

    def test_priority_tier_dispatch_order(self):
        scheduler = PriorityQueryScheduler()
        t_low = QueryTask("t1", "VACUUM FULL", "worker_bg")
        t_high = QueryTask("t2", "ALTER TABLE users DROP COLUMN pin", "admin")
        t_med = QueryTask("t3", "SELECT * FROM orders", "client_app")

        # Enqueue in randomized order
        scheduler.push_query(t_low, priority=3)   # Low
        scheduler.push_query(t_high, priority=0)  # Critical DDL
        scheduler.push_query(t_med, priority=2)   # Normal Read

        assert len(scheduler) == 3
        # Must pop highest priority first (0 → 2 → 3)
        assert scheduler.pop_next_query().task_id == "t2"
        assert scheduler.pop_next_query().task_id == "t3"
        assert scheduler.pop_next_query().task_id == "t1"
        assert len(scheduler) == 0

    def test_identical_priority_preserves_fifo_order(self):
        scheduler = PriorityQueryScheduler()
        # Three queries submitted with identical priority (1)
        t1 = QueryTask("q1", "INSERT A", "c1")
        t2 = QueryTask("q2", "INSERT B", "c2")
        t3 = QueryTask("q3", "INSERT C", "c3")

        scheduler.push_query(t1, priority=1)
        scheduler.push_query(t2, priority=1)
        scheduler.push_query(t3, priority=1)

        # Sequence counter must guarantee strict arrival order
        assert scheduler.pop_next_query().task_id == "q1"
        assert scheduler.pop_next_query().task_id == "q2"
        assert scheduler.pop_next_query().task_id == "q3"

    def test_tombstone_cancellation_skips_removed_tasks(self):
        scheduler = PriorityQueryScheduler()
        t1 = QueryTask("q1", "QUERY_1", "c1")
        t2 = QueryTask("q2", "QUERY_2", "c2")
        t3 = QueryTask("q3", "QUERY_3", "c3")

        scheduler.push_query(t1, priority=1)
        scheduler.push_query(t2, priority=0)  # Highest priority
        scheduler.push_query(t3, priority=2)

        # Cancel the highest priority query (q2) before execution
        assert scheduler.cancel_query("q2") is True
        assert len(scheduler) == 2

        # Scheduler must skip q2 cleanly
        assert scheduler.pop_next_query().task_id == "q1"
        assert scheduler.pop_next_query().task_id == "q3"

    def test_dynamic_reprioritization_updates_schedule(self):
        scheduler = PriorityQueryScheduler()
        t1 = QueryTask("q1", "BACKGROUND_JOB", "c1")
        t2 = QueryTask("q2", "REPORT_JOB", "c2")

        scheduler.push_query(t1, priority=3)  # Low
        scheduler.push_query(t2, priority=2)  # Normal

        # Promote q1 to Emergency Tier 0!
        scheduler.reprioritize_query("q1", new_priority=0)

        # q1 must execute before q2 now
        assert scheduler.pop_next_query().task_id == "q1"
        assert scheduler.pop_next_query().task_id == "q2"

    def test_empty_queue_raises_error(self):
        scheduler = PriorityQueryScheduler()
        with pytest.raises(QueueEmptyError):
            scheduler.pop_next_query()
Warning Track

Beginner Pitfalls & Architectural Anti-Patterns

❌ The 2-Tuple Heap Comparison Crash

Storing heapq.heappush(h, (priority, task_dict)) where task objects are uncomparable.

Why this crashes production: As soon as two tasks share the same priority number, Python attempts to compare the second element. Python dictionaries and arbitrary classes raise TypeError: '<' not supported, causing your scheduler to fail under concurrent load! Fix: Always insert an incrementing sequence counter as the second tuple element: (priority, seq_id, task).

❌ Slicing a Heap Expecting Sorted Order

Writing top_3 = heap[:3] to extract the three smallest elements.

Why this produces incorrect data: In a binary heap, only the root element at index 0 is guaranteed to be the absolute minimum. Children at indices 1 and 2 are smaller than their subtrees, but index 2 might easily be smaller than index 1! Fix: Use [heapq.heappop(heap) for _ in range(k)] or heapq.nsmallest(k, heap).

❌ Calling list.sort() on Every Insertion

Maintaining a priority queue by appending to a list and calling tasks.sort() on every incoming event.

Why this destroys performance: Sorting an entire list takes $O(n \log n)$ time per event. Over 100,000 tasks, this wastes billions of CPU cycles. A binary heap executes heappush in only $O(\log n)$ by sifting along tree height.

❌ Sequential heappop() Followed by heappush()

Writing val = heapq.heappop(h); heapq.heappush(h, new_val).

Why this is suboptimal: This performs two separate tree traversals ($2 \times O(\log n)$) and temporarily shrinks the list. Fix: Use heapq.heapreplace(h, new_val), which replaces the root and sifts down in a single pass ($1 \times O(\log n)$).
