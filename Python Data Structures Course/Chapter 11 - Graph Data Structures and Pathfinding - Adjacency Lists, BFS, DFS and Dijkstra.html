Part 01

Computer Science: Graph Topologies & Representation Mathematics

Formally, a Graph is an ordered pair $G = (V, E)$, where $V$ is a finite set of Vertices (or Nodes) representing entities, and $E \subseteq V \times V$ is a set of Edges representing relationships between them. Edges can be Directed (one-way relationships, like following an account or a foreign key reference) or Undirected (mutual symmetric connections, like network hardware peers).

When representing graphs in memory, software engineers face a critical architectural decision between two primary data structures:

Adjacency Matrix (Dense 2D Grid) vs. Adjacency List (Sparse Hash Mapping)

Evaluating space complexity, sparse graph allocations, and iteration costs

  • Neighbor Traversal: Iterating over outgoing edges of $u$ takes optimal $O(\text{degree}(u))$ time without touching disconnected entities.
  • The Industry Standard: Powering Neo4j, graph databases, social networks, and compiler dependency managers.
Part 02

Algorithmic Mechanics: BFS, DFS & Topological Sorting

Unlike trees (which are acyclic and possess a designated root), arbitrary graphs can contain cycles, disjoint islands (unconnected components), and complex branching. Graph traversals require systematic visited tracking to prevent infinite loops.

1. Breadth-First Search (BFS) Queue Driven

Explores neighbors layer-by-layer radiating outward from the source vertex using an in-memory queue (collections.deque).

  • Shortest Path Guarantee: On unweighted graphs, BFS is mathematically guaranteed to find the path with the minimum number of edge transitions.
  • Degrees of Separation: Ideal for finding immediate social circles (1st, 2nd, 3rd-degree network connections) and breadth-limited crawl operations.
  • Complexity: Time $O(|V| + |E|)$ | Space $O(|V|)$.
2. Depth-First Search (DFS) & Cycles Stack / Recursive

Explores along each branch to its maximum depth before backtracking.

  • 3-Color State Cycle Detection: Classifies vertices into three states: UNVISITED (0), VISITING (1, currently in the call stack), and VISITED (2, completed).
  • The Cycle Proof: If DFS encounters a neighbor that is currently in the VISITING state, a back-edge exists, proving an inescapable cycle!
  • Complexity: Time $O(|V| + |E|)$ | Space $O(|V|)$.
Topological Sorting (Kahn's Algorithm & In-Degree Processing) DAG Only

A Topological Sort of a Directed Acyclic Graph (DAG) is a linear ordering of vertices such that for every directed edge $u \to v$, vertex $u$ appears before vertex $v$ in the sequence.

// How Kahn's In-Degree Algorithm Resolves Migration Order:
  1. Calculate the in-degree (count of incoming edges) for every vertex in the graph.
  2. Initialize a queue with all vertices whose in-degree is exactly 0 (entities with zero dependencies).
  3. Pop vertex $u$ from the queue, append to execution order, and decrement the in-degree of all its neighbors $v$.
  4. If a neighbor's in-degree drops to 0, push it into the queue.
  5. Deadlock Invariant: If the final output length is less than $|V|$, the graph contains a cyclic dependency, making topological resolution impossible!
Part 03

Algorithmic Optimization: Heap-Backed Dijkstra Pathfinding

When edges carry variable positive costs or weights (such as network latency in milliseconds, physical distance, or query cost), Breadth-First Search fails because the path with the fewest edges is not necessarily the path with the lowest aggregate weight.

Invented by Edsger W. Dijkstra in 1956, Dijkstra's Algorithm computes the single-source shortest path across non-negative weighted graphs:

The Priority Queue Acceleration

Edge Relaxation & The Min-Heap Pipeline

Naive Dijkstra scans all unvisited nodes to locate the smallest tentative distance, running in $O(|V|^2)$ time. In production systems, we pair Dijkstra with Python's heapq (Chapter 05), accelerating execution to $O((|V| + |E|) \log |V|)$:

1. Initialize distances map: dist = {source: 0.0, all_others: ∞}
2. Min-Heap stores entries: (current_cumulative_distance, node_id, path_history)
3. While heap is non-empty:
a. Pop entry with smallest cumulative distance: (d, u, path)
b. If d > dist[u], discard as a stale lazy heap entry!
c. If u == target, termination reached! Return optimal cost and path.
d. For each neighbor $v$ of $u$ with weight $w$:
new_dist = d + w
if new_dist < dist[v]:
    dist[v] = new_dist
    heapq.heappush(heap, (new_dist, v, path + [v]))
Non-Negative Weight Constraint: Dijkstra relies on a greedy property: once a node is settled, its shortest path cannot be improved by exploring further edges. If a graph contains negative edge weights, Dijkstra breaks; you must use the Bellman-Ford algorithm ($O(|V| \cdot |E|)$) instead.

1. Production Graph Engine: src/memforge/graph/relationship.py Adjacency List & Traversal Algorithms 
# ==============================================================================
# MemForge Graph Engine - Entity Relationships & Pathfinding (Milestone 11)
# ==============================================================================

import heapq
from collections import deque
from typing import Dict, List, Optional, Set, Tuple


class CyclicDependencyError(Exception):
    """Raised when topological sorting detects an unresolvable cycle."""
    pass


class GraphRelationshipEngine:
    """
    PRODUCTION GRAPH RELATIONSHIP ENGINE:
    Maintains a weighted adjacency list: src_entity -> {dst_entity: weight}.
    Provides BFS degrees of separation, 3-color DFS cycle detection,
    Kahn's topological sorting, and heap-backed Dijkstra shortest path.
    """
    def __init__(self):
        # Sparse Adjacency List: node_id -> {neighbor_id: edge_weight}
        self._adj: Dict[str, Dict[str, float]] = {}

    def add_entity(self, entity_id: str) -> None:
        """Registers an entity node in the graph if not already present."""
        if entity_id not in self._adj:
            self._adj[entity_id] = {}

    def add_relationship(
        self,
        src: str,
        dst: str,
        weight: float = 1.0,
        bidirectional: bool = False
    ) -> None:
        """Adds a weighted directed edge from src to dst."""
        if weight < 0:
            raise ValueError("Edge weight must be non-negative for Dijkstra pathfinding.")

        self.add_entity(src)
        self.add_entity(dst)
        self._adj[src][dst] = weight

        if bidirectional:
            self._adj[dst][src] = weight

    def get_degrees_of_separation(self, start_id: str, max_depth: int = 2) -> Dict[str, int]:
        """
        BREADTH-FIRST SEARCH (BFS):
        Computes shortest unweighted hop distance from start_id up to max_depth.
        Returns mapping: entity_id -> hop_count.
        """
        if start_id not in self._adj:
            return {}

        visited: Dict[str, int] = {start_id: 0}
        queue: deque[Tuple[str, int]] = deque([(start_id, 0)])

        while queue:
            curr_node, depth = queue.popleft()

            if depth >= max_depth:
                continue

            for neighbor in self._adj[curr_node]:
                if neighbor not in visited:
                    visited[neighbor] = depth + 1
                    queue.append((neighbor, depth + 1))

        return visited

    def detect_cycle(self) -> bool:
        """
        3-COLOR DEPTH-FIRST SEARCH (DFS) CYCLE DETECTOR:
        0 = UNVISITED | 1 = VISITING (In active stack) | 2 = VISITED (Completed)
        Returns True if a directed cycle exists.
        """
        state: Dict[str, int] = {node: 0 for node in self._adj}

        def _has_cycle_dfs(u: str) -> bool:
            state[u] = 1  # Mark VISITING

            for v in self._adj[u]:
                if state[v] == 1:
                    # Found back-edge to a node currently in stack -> Cycle detected!
                    return True
                if state[v] == 0 and _has_cycle_dfs(v):
                    return True

            state[u] = 2  # Mark VISITED
            return False

        for node in self._adj:
            if state[node] == 0:
                if _has_cycle_dfs(node):
                    return True

        return False

    def resolve_execution_order(self) -> List[str]:
        """
        KAHN'S TOPOLOGICAL SORTING:
        Computes a valid linear execution order for dependencies in O(|V| + |E|) time.
        Raises CyclicDependencyError if circular deadlocks exist!
        """
        # 1. Compute in-degree for every vertex
        in_degree: Dict[str, int] = {node: 0 for node in self._adj}
        for u in self._adj:
            for v in self._adj[u]:
                in_degree[v] += 1

        # 2. Queue vertices with in-degree == 0 (zero dependencies)
        queue: deque[str] = deque([node for node, deg in in_degree.items() if deg == 0])
        order: List[str] = []

        while queue:
            u = queue.popleft()
            order.append(u)

            for v in self._adj[u]:
                in_degree[v] -= 1
                if in_degree[v] == 0:
                    queue.append(v)

        # 3. Deadlock validation
        if len(order) < len(self._adj):
            raise CyclicDependencyError("Graph contains cyclic dependencies; topological order impossible.")

        return order

    def shortest_path_dijkstra(self, src: str, dst: str) -> Tuple[float, List[str]]:
        """
        HEAP-ACCELERATED DIJKSTRA PATHFINDING:
        Finds the least-cost weighted path from src to dst.
        Complexity: O((|V| + |E|) log |V|) using heapq min-heap.
        Returns: (total_cost, [path_nodes])
        """
        if src not in self._adj or dst not in self._adj:
            return (float("inf"), [])

        # Distance directory: node -> lowest known cost
        distances: Dict[str, float] = {src: 0.0}
        # Min-Heap stores entries: (cumulative_cost, node_id, path_list)
        heap: List[Tuple[float, str, List[str]]] = [(0.0, src, [src])]

        while heap:
            curr_dist, u, path = heapq.heappop(heap)

            if u == dst:
                # Optimal destination reached!
                return (curr_dist, path)

            # Skip stale lazy heap entries
            if curr_dist > distances.get(u, float("inf")):
                continue

            for v, weight in self._adj[u].items():
                new_dist = curr_dist + weight
                if new_dist < distances.get(v, float("inf")):
                    distances[v] = new_dist
                    heapq.heappush(heap, (new_dist, v, path + [v]))

        # Destination unreachable
        return (float("inf"), [])
2. Unit Test Battery: tests/unit/test_graph.py BFS, DFS Cycles & Dijkstra Tests 
# ==============================================================================
# MemForge Test Suite - Graph Relationship Engine Tests (Milestone 11)
# ==============================================================================

import pytest
from memforge.graph.relationship import (
    GraphRelationshipEngine, 
    CyclicDependencyError
)

class TestGraphRelationshipEngine:
    """Unit tests asserting BFS degrees of separation, DFS cycles, and Dijkstra paths."""

    def test_bfs_degrees_of_separation(self):
        graph = GraphRelationshipEngine()
        # Network: Alice -> Bob -> Charlie -> Dave
        graph.add_relationship("Alice", "Bob")
        graph.add_relationship("Bob", "Charlie")
        graph.add_relationship("Charlie", "Dave")

        # Max depth 2 from Alice should reach Bob (depth 1) and Charlie (depth 2), NOT Dave
        degrees = graph.get_degrees_of_separation("Alice", max_depth=2)
        assert degrees["Alice"] == 0
        assert degrees["Bob"] == 1
        assert degrees["Charlie"] == 2
        assert "Dave" not in degrees

    def test_dfs_cycle_detection_in_dag(self):
        graph = GraphRelationshipEngine()
        graph.add_relationship("users", "orders")
        graph.add_relationship("orders", "invoices")

        # Acyclic DAG
        assert graph.detect_cycle() is False

        # Introduce cycle: invoices -> users
        graph.add_relationship("invoices", "users")
        assert graph.detect_cycle() is True

    def test_kahn_topological_sort_and_deadlock_detection(self):
        graph = GraphRelationshipEngine()
        # Dependencies: schema -> tables -> indexes -> app
        graph.add_relationship("schema", "tables")
        graph.add_relationship("tables", "indexes")
        graph.add_relationship("indexes", "app")

        order = graph.resolve_execution_order()
        assert order == ["schema", "tables", "indexes", "app"]

        # Add circular deadlock: app -> schema
        graph.add_relationship("app", "schema")
        with pytest.raises(CyclicDependencyError):
            graph.resolve_execution_order()

    def test_heap_dijkstra_shortest_weighted_path(self):
        graph = GraphRelationshipEngine()
        # Diamond Network:
        # A -> B (weight 4.0), A -> C (weight 1.0)
        # B -> D (weight 1.0), C -> D (weight 5.0)
        # Path A->B->D = 5.0 | Path A->C->D = 6.0
        graph.add_relationship("A", "B", weight=4.0)
        graph.add_relationship("A", "C", weight=1.0)
        graph.add_relationship("B", "D", weight=1.0)
        graph.add_relationship("C", "D", weight=5.0)

        cost, path = graph.shortest_path_dijkstra("A", "D")
        assert cost == 5.0
        assert path == ["A", "B", "D"]
Warning Track

Beginner Pitfalls & Architectural Anti-Patterns

❌ Forgetting the Visited Set in BFS/DFS

Writing for neighbor in adj[u]: queue.append(neighbor) without tracking visited vertices.

Why this freezes production: In any graph with cycles (or bidirectional edges), a traversal without a visited: set() bounces infinitely back and forth between vertices (A → B → A → B), running until memory runs out or the process freezes!

❌ Running Dijkstra on Negative Weights

Applying shortest_path_dijkstra() to graphs containing negative edge weights.

Why this yields incorrect results: Dijkstra is a greedy algorithm based on the assumption that accumulating edge weights is monotonically non-decreasing. A negative edge breaks this invariant, causing Dijkstra to finalize sub-optimal paths. Use Bellman-Ford when negative weights exist!

❌ Adjacency Matrix Memory Blowup

Instantiating a 2D matrix [[0] * V for _ in range(V)] for sparse social or transactional networks.

Why this causes OOM crashes: For 100,000 entities, a matrix requires allocating 10,000,000,000 slots. A nested dictionary adjacency list (dict[str, dict]) consumes space strictly proportional to real edges ($O(V + E)$), taking mere megabytes.

❌ Recursive DFS Stack Overflow

Using naive recursive functions to traverse deep graphs with thousands of sequential edges.

Why this crashes: In linear topologies, recursive DFS exceeds Python's default 1,000-frame recursion limit, raising RecursionError. For deep graphs, use an explicit iterative loop with a Python list acting as a stack.
