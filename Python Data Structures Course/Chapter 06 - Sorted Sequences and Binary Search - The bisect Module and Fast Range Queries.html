Part 01

Computer Science: Bisection Mathematics & Logarithmic Search

When searching an unsorted array of size $n$, an algorithm has no mathematical advantage; in the worst and average cases, it must inspect every memory address sequentially, yielding linear complexity $O(n)$.

If the sequence maintains a sorted invariant ($a[i] \le a[i+1]$), we gain a powerful mathematical property: evaluating the median element at index $\text{mid} = \lfloor(\text{low} + \text{high}) / 2\rfloor$ instantly eliminates half of all remaining candidates. After $k$ iterations, the search space reduces to $n / 2^k$. Setting $n / 2^k = 1$ demonstrates that search terminates in at most $k = \lceil\log_2 n\rceil$ steps.

CPython C-Acceleration Note (_bisectmodule.c):

Python's standard library implements the bisect algorithms directly in optimized C. The midpoint is computed as mid = ((size_t)lo + hi) >> 1. In pure C/Java, (lo + hi) / 2 risks signed 32-bit integer overflow; in CPython, the bit-shift on unsigned pointers guarantees memory safety and lightning-fast execution directly in CPU registers.

Part 02

Under the Hood: The Boundary Duality of bisect_left and bisect_right

If an array contains unique elements, binary search trivially locates the target value. However, real-world database records frequently contain duplicate keys (e.g. thousands of records sharing the same timestamp, status code, or foreign key ID).

Python provides two core bisection primitives to define exact mathematical insertion and range boundaries around duplicates:

Partitions the array such that all elements to the left are strictly less than $x$ ($e < x$), and all elements to the right are greater than or equal to $x$ ($e \ge x$). Returns the index of the first occurrence.

bisect_right(a, x=25) → Index 5

Partitions the array such that all elements to the left are less than or equal to $x$ ($e \le x$), and all elements to the right are strictly greater than $x$ ($e > x$). Returns the insertion slot following the final occurrence.

Query Formulation

The 4 Interval Query Permutations

Database query engines express interval constraints in four mathematical forms. By combining bisect_left and bisect_right, you can calculate the exact slice indices in $O(\log n)$ time without post-filtering:

Mathematical Interval SQL Semantics Bisect Slice Formulation Boundary Mechanics
[v_min, v_max) v >= min AND v < max a[bisect_left(a, min) : bisect_left(a, max)] Standard Python half-open slice. Includes lower bound; stops before upper bound.
[v_min, v_max] v BETWEEN min AND max a[bisect_left(a, min) : bisect_right(a, max)] Fully closed interval. Includes both extremes and all duplicate occurrences of max.
(v_min, v_max] v > min AND v <= max a[bisect_right(a, min) : bisect_right(a, max)] Excludes lower bound duplicates; includes upper bound matches.
(v_min, v_max) v > min AND v < max a[bisect_right(a, min) : bisect_left(a, max)] Strict open interval. Excludes matching boundaries on both sides.

// Classic Production Pattern: Numeric Range Grading & SLA Classification
from bisect import bisect_right

# SLA Tier Cutoffs (in milliseconds):
# 0 - 50ms: PLATINUM | 51 - 200ms: GOLD | 201 - 1000ms: SILVER | > 1000ms: BREACH
LATENCY_BREAKPOINTS = [50, 200, 1000]
SLA_TIERS = ["PLATINUM", "GOLD", "SILVER", "SLA_BREACH"]

def classify_query_sla(latency_ms: float) -> str:
    """Maps continuous latency values to discrete SLA buckets in O(log k) time."""
    bucket_index = bisect_right(LATENCY_BREAKPOINTS, latency_ms)
    return SLA_TIERS[bucket_index]

# classify_query_sla(25.0)  → "PLATINUM" (index 0)
# classify_query_sla(50.0)  → "PLATINUM" (index 0 because 50 is not > 50)
# classify_query_sla(50.1)  → "GOLD"     (index 1)
# classify_query_sla(2500)  → "SLA_BREACH" (index 3)

MemForge Milestone 06: Sorted Numeric Range Index Implementation

We now assemble Milestone 06 of MemForge. We implement src/memforge/index/sorted_index.py: a secondary index designed to execute sub-millisecond range scans across stored record values (such as transaction amounts, timestamps, or latency metrics).

The sorted index features:

  • Batch initialization via build_from_records() using $O(n \log n)$ Timsort, avoiding the quadratic $O(n^2)$ penalty of repeated insertions.
  • Incremental insertion using bisect_right.
  • Exact point matching returning all matching record IDs in $O(\log n)$ time.
  • Universal range filtering (range_scan) supporting closed $[a, b]$, half-open $[a, b)$, and open $(a, b)$ intervals.

1. Production Range Index: src/memforge/index/sorted_index.py Bisect Range Engine 
# ==============================================================================
# MemForge Index - Secondary Sorted Range Index (Milestone 06)
# ==============================================================================

from bisect import bisect_left, bisect_right
from dataclasses import dataclass
from typing import Any, Iterator, List, Optional, Tuple


@dataclass(frozen=True)
class IndexEntry:
    """Discrete secondary index pointer linking a numeric indexed value to a record ID."""
    value: float
    record_id: int


class SortedNumericIndex:
    """
    PRODUCTION SORTED RANGE INDEX:
    Maintains entries in strict ascending order by value.
    Provides O(log n) point searches and sub-millisecond range queries
    over millions of indexed numerical records using bisect algorithms.
    """
    def __init__(self):
        # Parallel arrays or entries list projected by value
        self._entries: List[IndexEntry] = []

    def __len__(self) -> int:
        """Returns total indexed entries."""
        return len(self._entries)

    def build_from_records(self, records: List[Tuple[float, int]]) -> None:
        """
        BATCH BUILD INVARIANT:
        Constructs index in O(n log n) time using Timsort.
        Avoids the O(n^2) catastrophe of calling insort in a loop!
        """
        raw_entries = [IndexEntry(value=val, record_id=rid) for val, rid in records]
        # Sort in-place using value as primary key, record_id as secondary key
        raw_entries.sort(key=lambda e: (e.value, e.record_id))
        self._entries = raw_entries

    def insert(self, value: float, record_id: int) -> None:
        """
        Incremental insertion: Uses bisect_right on value projection.
        Complexity: O(log n) search + O(n) pointer shift.
        """
        new_entry = IndexEntry(value=value, record_id=record_id)
        # Python 3.10+ key-based bisect: projects entry to its scalar value
        idx = bisect_right(self._entries, value, key=lambda e: e.value)
        self._entries.insert(idx, new_entry)

    def find_exact(self, value: float) -> List[int]:
        """
        POINT QUERY:
        Returns all record IDs matching value exactly in O(log n + k) time,
        where k is the count of duplicates.
        """
        left = bisect_left(self._entries, value, key=lambda e: e.value)
        right = bisect_right(self._entries, value, key=lambda e: e.value)
        return [self._entries[i].record_id for i in range(left, right)]

    def range_scan(
        self,
        min_val: Optional[float] = None,
        max_val: Optional[float] = None,
        include_min: bool = True,
        include_max: bool = False
    ) -> List[int]:
        """
        RANGE QUERY ENGINE:
        Executes logarithmic range slicing across closed, half-open, or open intervals.
        Returns: Matching list of record IDs.
        """
        # 1. Determine lower index boundary
        if min_val is None:
            start_idx = 0
        elif include_min:
            start_idx = bisect_left(self._entries, min_val, key=lambda e: e.value)
        else:
            start_idx = bisect_right(self._entries, min_val, key=lambda e: e.value)

        # 2. Determine upper index boundary
        if max_val is None:
            end_idx = len(self._entries)
        elif include_max:
            end_idx = bisect_right(self._entries, max_val, key=lambda e: e.value)
        else:
            end_idx = bisect_left(self._entries, max_val, key=lambda e: e.value)

        # Slices are zero-copy references to record_ids
        return [self._entries[i].record_id for i in range(start_idx, end_idx)]

import pytest
from memforge.index.sorted_index import SortedNumericIndex

class TestSortedNumericIndex:
    """Unit tests asserting point lookups, duplicate partitions, and range scan bounds."""

    def test_batch_build_and_point_query_with_duplicates(self):
        index = SortedNumericIndex()
        # Sample data with duplicates: 3 entries with value 25.0
        records = [
            (50.0, 501),
            (25.0, 201),
            (10.0, 101),
            (25.0, 202),
            (100.0, 999),
            (25.0, 203)
        ]
        index.build_from_records(records)
        assert len(index) == 6

        # Point search for 25.0 must locate all 3 records
        matches_25 = index.find_exact(25.0)
        assert sorted(matches_25) == [201, 202, 203]

        # Point search for missing value
        assert index.find_exact(99.0) == []

    def test_half_open_range_scan(self):
        index = SortedNumericIndex()
        # Setup values: 10, 20, 30, 40, 50
        records = [(float(i * 10), i) for i in range(1, 6)]
        index.build_from_records(records)

        # Standard half-open: [20.0, 40.0) -> values 20, 30
        results = index.range_scan(min_val=20.0, max_val=40.0, include_min=True, include_max=False)
        assert results == [2, 3]

    def test_closed_interval_range_scan(self):
        index = SortedNumericIndex()
        records = [(float(i * 10), i) for i in range(1, 6)]
        index.build_from_records(records)

        # Fully closed interval: [20.0, 40.0] -> values 20, 30, 40
        results = index.range_scan(min_val=20.0, max_val=40.0, include_min=True, include_max=True)
        assert results == [2, 3, 4]

    def test_strict_open_interval_range_scan(self):
        index = SortedNumericIndex()
        records = [(float(i * 10), i) for i in range(1, 6)]
        index.build_from_records(records)

        # Strict open: (20.0, 40.0) -> value 30 only
        results = index.range_scan(min_val=20.0, max_val=40.0, include_min=False, include_max=False)
        assert results == [3]

    def test_unbounded_range_scans(self):
        index = SortedNumericIndex()
        records = [(float(i * 10), i) for i in range(1, 6)]
        index.build_from_records(records)

        # Unbounded upper: >= 30.0 -> values 30, 40, 50
        res_upper = index.range_scan(min_val=30.0, max_val=None, include_min=True)
        assert res_upper == [3, 4, 5]

        # Unbounded lower: < 30.0 -> values 10, 20
        res_lower = index.range_scan(min_val=None, max_val=30.0, include_max=False)
        assert res_lower == [1, 2]

    def test_incremental_insertion_maintains_sort_order(self):
        index = SortedNumericIndex()
        index.build_from_records([(10.0, 1), (30.0, 3)])
        
        # Incremental insert of 20.0
        index.insert(20.0, 2)
        assert len(index) == 3

        results = index.range_scan(min_val=5.0, max_val=35.0, include_min=True, include_max=True)
        assert results == [1, 2, 3]
Warning Track

Beginner Pitfalls & Architectural Anti-Patterns

❌ Calling bisect on an Unsorted List

Running bisect_left(raw_unsorted_list, val).

Why this fails silently: The bisect module does NOT validate whether the sequence is sorted (checking sorting would take $O(n)$ time, destroying the $O(\log n)$ advantage). Executing binary search on an unsorted list returns meaningless, incorrect indices without raising any exceptions! Fix: Ensure the list is sorted via a.sort() before executing bisect queries.

❌ The Repeated insort() O(n²) Trap

Populating an index of 100,000 items by calling bisect.insort() in a loop.

Why this destroys performance: While insort finds the position in $O(\log n)$, inserting into a Python list forces an $O(n)$ memory shift of all following elements. 100,000 calls to insort costs $O(n^2)$ → 5 billion memory shifts! Fix: Collect items with .append() and call .sort() once in $O(n \log n)$.

❌ Off-by-One Boundary Inversion

Using bisect_right for a lower bound or bisect_left for a closed upper bound.

Why this drops data: If you query WHERE age >= 21 using bisect_right(ages, 21), you jump past all 21-year-olds! Conversely, querying WHERE age <= 21 with bisect_left excludes all 21-year-olds! Rule: Use bisect_left to include lower bounds; use bisect_right to include upper bounds.

❌ Memory-Heavy Intermediate Slicing

Writing sub_records = large_sorted_list[lo:hi] to count matches.

Why this thrashes RAM: In Python, slicing a list allocates a completely new list and copies all pointers. If the range matches 500,000 items, you copy 500,000 pointers (4MB RAM) just to count them! Fix: To get count, subtract indices directly: count = hi - lo ($O(1)$ time and zero memory).
