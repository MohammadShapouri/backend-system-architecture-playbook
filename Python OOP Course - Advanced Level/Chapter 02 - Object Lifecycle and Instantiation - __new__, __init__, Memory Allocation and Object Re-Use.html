Part 01

Computer Science: The Two-Phase Instantiation Protocol

Most developers assume that writing obj = MyClass(*args) directly calls __init__. This is fundamentally inaccurate.

In CPython, calling a class invokes the metaclass's call operator (type.__call__). This coordinates a strict two-phase construction protocol separating raw heap memory allocation from state assignment:

Under the Hood: The CPython type.__call__ Orchestration Pipeline
Step 1: Allocation (__new__)
Invokes cls.__new__(cls, *args, **kw)

A static allocator method. Calls the C runtime allocator to carve out heap memory and returns a brand new, uninitialized instance of cls.

Step 2: Type Invariant Check
isinstance(instance, cls)

CPython Rule: If __new__ returns an instance of cls (or its subclasses), proceed to Step 3. If it returns an existing object or different type, __init__ is skipped!

Step 3: Initialization (__init__)
Invokes instance.__init__(*args, **kw)

An initializer method. Receives the allocated instance as self and assigns state attributes to self.__dict__. Must return strictly None!

Equivalent Python Implementation of type.__call__: 
def type_call(cls, *args, **kwargs):
    # 1. Allocate raw object in memory
    instance = cls.__new__(cls, *args, **kwargs)

    # 2. CPython Type Invariant Guard: Only initialize if instance matches cls!
    if isinstance(instance, cls):
        init_result = instance.__init__(*args, **kwargs)
        if init_result is not None:
            raise TypeError("__init__() should return None, not '{type(init_result).__name__}'")

    return instance
Part 02

Under the Hood: Subclassing Immutable Types & The Flyweight Pattern

Why does Python have both __new__ and __init__?

The primary architectural reason is immutable types. Built-in types such as int, float, str, and tuple cannot have their contents mutated after creation. By the time __init__ executes, the underlying C-struct is already frozen. Therefore, custom subclasses of immutable types must customize their values inside __new__ before allocation finishes.

Memory Freezing

Subclassing Immutable Built-ins

If you subclass str to enforce uppercase domain codes, attempting to alter the value in __init__ fails because the string buffer is immutable. You must intercept the string in __new__: 

class CurrencyCode(str):
    def __new__(cls, value: str):
        # Transform and allocate memory in Phase 1:
        normalized = value.strip().upper()
        return super().__new__(cls, normalized)
Object Pooling

The Flyweight Pattern (Instance Deduplication)

In high-throughput systems, instantiating millions of identical value objects thrashes memory. Using __new__, we inspect an internal cache dictionary: if an instance with matching parameters exists, we return the cached pointer immediately with zero heap allocation: 

class StatusPool:
    _cache: dict[str, Self] = {}
    def __new__(cls, name: str):
        if name not in cls._cache:
            cls._cache[name] = super().__new__(cls)
        return cls._cache[name]
Part 03

Lifecycle Termination: Reference Counting & The Traps of `__del__`

When an object's lifetime concludes, CPython deallocates its heap memory. Beginners frequently reach for __del__() (the finalizer dunder) under the false assumption that it behaves like a C++ destructor.

In production Python, relying on __del__ for critical resource cleanup is an architectural anti-pattern.

Why __del__ is Hazardous in Production
  • No Guarantee of Execution: When a Python process exits or crashes, CPython does not guarantee that __del__ will be called for all objects remaining in memory.
  • Exceptions are Ignored: If an exception occurs inside __del__, it cannot be caught by application try-except blocks; Python simply writes a silent warning to sys.stderr and moves on.
  • The Zombie Resurrection Trap: If code inside __del__ assigns self to an external global variable, the object is resurrected while CPython's internal deallocator is mid-execution, corrupting runtime state!
The Clean Production Alternative

Never bind resource deallocation (closing files, releasing database connections, dropping locks) to garbage collection.

The Production Standard: Implement the Context Manager Protocol (__enter__ and __exit__, detailed in Chapter 07) or provide an explicit .close() method. This guarantees deterministic cleanup at the exact line of execution, regardless of garbage collector timing.

Part 04

Dunder Method Matrix: When to Override vs. When NOT to Override

Senior developers know not just how to override dunder methods, but more importantly, when NOT to override them:

Dunder Method Signature When to Override (✓) When NOT to Override (✗)
__new__ __new__(cls, *args, **kw) → instance Subclassing immutable types (tuple, str, int); implementing Flyweight instance pooling; dynamically returning different subclass instances based on arguments. Standard mutable domain models where state assignment belongs in __init__. Overriding it needlessly introduces metaclass bugs and initialization leaks.
__init__ __init__(self, *args, **kw) → None Standard instance initialization: assigning state attributes to self, setting up connections, and dependency injection. When implementing Singleton or Flyweight patterns via __new__ (because Python re-executes __init__ every time the class is called, wiping existing instance state!).
__del__ __del__(self) → None Low-level C-extension bindings or emergency logging warnings when a developer forgot to explicitly close a resource. Avoid in high-level application code. Never rely on it for database transaction rollbacks, file closing, or lock releasing. Use context managers (with) instead.

1. Production Lifecycle Engine: src/entityforge/core/lifecycle.py Flyweight Caching & Subclass Routing 
# ==============================================================================
# EntityForge Core - Lifecycle, Instantiation & Flyweight Pooling (Milestone 02)
# ==============================================================================

from __future__ import annotations
from typing import Any, Dict, Optional, Self, final, override
from entityforge.core.entity import BaseEntity, EntityIdentity


class FlyweightStatus(str):
    """
    IMMUTABLE FLYWEIGHT STATUS VALUE OBJECT:
    Subclasses built-in 'str'. Overrides __new__ to enforce uppercase
    normalization and deduplicate instances via a class-level cache pool.
    Guarantees that FlyweightStatus('ACTIVE') is FlyweightStatus('ACTIVE') is True!
    """
    _pool: Dict[str, Self] = {}

    def __new__(cls, value: str) -> Self:
        # 1. Normalize value before memory allocation
        normalized = value.strip().upper()

        # 2. Check if instance already exists in memory pool
        if normalized in cls._pool:
            # Returns existing pointer: Zero new heap memory allocated!
            return cls._pool[normalized]

        # 3. First time seen: Allocate memory via str.__new__
        instance = super().__new__(cls, normalized)
        cls._pool[normalized] = instance
        return instance

    @classmethod
    def pool_size(cls) -> int:
        """Returns total cached flyweight instances currently in memory."""
        return len(cls._pool)

    @classmethod
    def clear_pool(cls) -> None:
        """Clears the flyweight instance cache."""
        cls._pool.clear()


class DynamicEntityRouter:
    """
    POLYMORPHIC ROUTING VIA __new__:
    Demonstrates how __new__ can inspect parameters and dynamically
    instantiate and return a concrete subclass instance.
    """
    def __new__(cls, entity_type: str, *args, **kwargs) -> Any:
        if entity_type == "user":
            return super().__new__(UserPayloadEntity)
        elif entity_type == "audit":
            return super().__new__(AuditPayloadEntity)
        else:
            raise ValueError(f"Unknown entity type: '{entity_type}'")


class UserPayloadEntity(BaseEntity):
    def __init__(self, entity_type: str, entity_id: EntityIdentity, username: str) -> None:
        super().__init__(entity_id=entity_id, username=username)
        self.username = username


class AuditPayloadEntity(BaseEntity):
    def __init__(self, entity_type: str, entity_id: EntityIdentity, action: str) -> None:
        super().__init__(entity_id=entity_id, action=action)
        self.action = action


class SafeResourceGuard:
    """
    DETERMINISTIC CLEANUP INVARIANT:
    Replaces the hazards of __del__ by implementing the Context Manager Protocol.
    Guarantees immediate cleanup upon exiting scope.
    """
    def __init__(self, resource_name: str) -> None:
        self.resource_name = resource_name
        self.is_open: bool = False

    def open(self) -> Self:
        self.is_open = True
        return self

    def close(self) -> None:
        self.is_open = False

    def __enter__(self) -> Self:
        return self.open()

    def __exit__(self, exc_type, exc_val, exc_tb) -> None:
        self.close()

import pytest
from entityforge.core.entity import EntityIdentity
from entityforge.core.lifecycle import (

    DynamicEntityRouter,

    AuditPayloadEntity,

class TestObjectLifecycle:
    """Unit tests asserting Flyweight deduplication, __new__ subclass routing, and cleanup."""

    def setup_method(self):
        # Ensure cache pool is clean before each test run
        FlyweightStatus.clear_pool()

    def test_flyweight_instance_deduplication_and_identity(self):
        # 1. Create two separate calls with identical string values
        s1 = FlyweightStatus("active")
        s2 = FlyweightStatus("  ACTIVE  ")

        # 2. Assert values are normalized to uppercase
        assert s1 == "ACTIVE"
        assert s2 == "ACTIVE"

        # 3. CRITICAL FLYWEIGHT INVARIANT:
        # Both variables MUST point to the EXACT same memory pointer!
        assert s1 is s2
        assert id(s1) == id(s2)

        # 4. Assert pool size contains exactly 1 unique instance
        assert FlyweightStatus.pool_size() == 1

        # 5. Distinct status creates a second instance
        s3 = FlyweightStatus("SUSPENDED")
        assert s1 is not s3
        assert FlyweightStatus.pool_size() == 2

    def test_dynamic_subclass_routing_via_new(self):
        ident = EntityIdentity.generate()

        # Instantiating the router with "user" must return a UserPayloadEntity
        user = DynamicEntityRouter("user", entity_id=ident, username="alice")
        assert isinstance(user, UserPayloadEntity)
        assert user.username == "alice"

        # Instantiating the router with "audit" must return an AuditPayloadEntity
        audit = DynamicEntityRouter("audit", entity_id=ident, action="LOGIN")
        assert isinstance(audit, AuditPayloadEntity)
        assert audit.action == "LOGIN"

        # Unknown type raises ValueError inside __new__
        with pytest.raises(ValueError, match=r"Unknown entity type"):
            _ = DynamicEntityRouter("invalid_type")

    def test_safe_resource_guard_context_manager(self):
        # Context manager guarantees deterministic closing without relying on __del__
        guard = SafeResourceGuard("database_tx_conn")
        assert guard.is_open is False

        with guard as resource:
            assert resource.is_open is True

        # Scope exit triggers __exit__ immediately
        assert guard.is_open is False
Warning Track

Beginner Pitfalls & Architectural Anti-Patterns

❌ The Singleton __init__ Re-Execution Trap

Implementing a Singleton by caching an instance in __new__ while keeping state initialization in __init__.

Why this causes subtle data bugs: type.__call__ unconditionally calls __init__ on whatever instance __new__ returns. Every time a caller writes s = MySingleton("new_config"), __init__ re-runs on the existing instance, silently overwriting its active state! Fix: Guard __init__ with an if not hasattr(self, '_initialized'): check or initialize strictly in __new__.

❌ Relying on __del__ for Resource Cleanup

Writing def __del__(self): self.db_connection.close().

Why this causes connection leaks: Python's garbage collector does not run on a deterministic schedule. If an object is part of a circular reference, its finalizer might not run until interpreter shutdown (or not at all if the process terminates abruptly). Exhausts database connection pools and file handles! Fix: Use context managers (with blocks) or an explicit .close() method.

❌ Attempting State Assignment in __init__ on Immutable Types

Subclassing tuple or str and writing def __init__(self, val): self = val.upper().

Why this fails: By the time __init__ runs, the immutable C memory structure has already been allocated and sealed by str.__new__. Reassigning self merely alters a local variable in the method scope, leaving the actual instance untouched! Fix: Transform and allocate the value inside __new__ using super().__new__(cls, val.upper()).

❌ Returning Non-None from __init__

Writing def __init__(self): return self.

Why this raises an immediate TypeError: CPython's type.__call__ expects __init__ to return strictly None. Returning any object (even self) raises TypeError: __init__() should return None! If you need to return a specific instance, override __new__ instead.
