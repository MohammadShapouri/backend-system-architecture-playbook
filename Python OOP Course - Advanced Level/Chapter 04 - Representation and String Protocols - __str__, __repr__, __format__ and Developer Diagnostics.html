Part 01

Computer Science: The Duality of Object Representation

In object-oriented design, text representation serves two distinct, mutually conflicting audiences: end-users (who demand clean, internationalized, visually palatable text) and software engineers/debuggers (who require raw, unambiguous, mathematically precise state diagnostics).

CPython formally separates these two concerns through two dedicated slots in the C-level PyTypeObject: tp_str and tp_repr.

The Representation Duality Matrix: __repr__ vs. __str__
1. __repr__(self) → str For Developers
  • Primary Goal: Unambiguity above all else. Must explicitly reveal the type, state, and critical identifiers of the instance.
  • The Eval Invariant: Whenever feasible, the output should mirror valid Python code that recreates the instance: eval(repr(obj)) == obj.
  • Invocation Triggers: Interactive REPL, log aggregators, exception tracebacks, and nested inside containers (e.g., printing a list[obj]).
UserEntity(id=UUID('...'), name='Alice', balance=150.0)
2. __str__(self) → str For End Users
  • Primary Goal: Readability. Designed for display in terminal banners, reports, notifications, or graphical user interfaces.
  • Formatting Focus: Can omit technical metadata (like memory addresses or internal IDs) in favor of localized, clean business representations.
  • Invocation Triggers: print(obj), str(obj), and bare f-strings: f"{obj}".
Alice (Balance: $150.00)
// CPython Runtime Fallback Cascade:

If a class defines __repr__ but omits __str__, CPython automatically falls back to __repr__ when str(obj) is called. However, the reverse is NOT true: if you only implement __str__, inspecting the object in debuggers or lists still displays the useless default: <MyClass object at 0x...>!

The Production Invariant: Always implement __repr__ first. Implement __str__ only when end-user formatting diverges from diagnostic representation.
Part 02

Under the Hood: The Format Protocol & Mini-Languages

Modern Python relies heavily on formatted string literals (f-strings). When you write f"{value:spec}", CPython delegates execution directly to value.__format__(spec).

By default, user-defined classes inherit object.__format__, which simply calls str(self) if the format specification is empty, but raises a fatal TypeError if any formatting specification string is passed!

Format Mechanics

The Spec String Handshake

The string following the colon in an f-string is passed unparsed into __format__(self, format_spec). Python places zero constraints on what format_spec contains; it is an entirely custom mini-language defined by the domain model:

# Caller specifies domain-specific formatting flags:
f"{account:currency,compact}" # → "$1.5M"
f"{account:audit,masked}" # → "ACCT-***-991"
f"{account:json}" # → '{"id": "..."}'
Low-Level Wire Encoding

Binary Wire Encoding with __bytes__

When domain entities must be transmitted across raw TCP sockets, packed into binary database WAL buffers (such as MemForge's ContiguousBuffer), or cryptographically hashed, Python provides __bytes__(self):

# Invoked via bytes(entity):
def __bytes__(self) -> bytes:
# Pack struct or serialize binary wire payload
return struct.pack("!QI", self.id, self.code)
Part 03

Dunder Method Matrix: Representation & Diagnostic Protocols

Implementing string protocols carelessly leaks sensitive secrets into production logs or incurs severe performance penalties:

Dunder Method Return Type When to Override (✓) When NOT to Override (✗)
__repr__ str (mandatory) Mandatory on every domain class. Return unambiguous diagnostics containing class name, primary key, and core state. Mask secrets (passwords, tokens, API keys). Never write an interactive multi-line graphical presentation here. Never allow raw unmasked credentials into the returned string.
__str__ str (mandatory) When end-user, localized, or UI-facing presentation diverges from raw debugging diagnostics. When the output of __repr__ is already clean and user-friendly (avoid redundant duplicate implementations).
__format__ str (mandatory) Financial, datetime, scientific, or domain value types requiring customized mini-languages (e.g., currency rounding, date masking, compact SI units). Standard service or controller classes where f-string interpolation is never used with format specifications.
__bytes__ bytes (mandatory) Low-level network packets, cryptographic primitives, hardware interfaces, or high-throughput storage engines (e.g. WAL serialization). Standard business models where JSON or Protobuf string serialization is handled by dedicated service layers.

1. Production Diagnostics Core: src/entityforge/core/diagnostics.py Representation Protocols & Format Specs 
# ==============================================================================
# EntityForge Core - Diagnostic Representations & String Protocols (Milestone 04)
# ==============================================================================

from __future__ import annotations
import json
from typing import Any, ClassVar, Dict, Set


class DiagnosticRendererMixin:
    """
    REUSABLE DIAGNOSTIC REPRESENTATION MIXIN:
    Provides unambiguous __repr__, human-readable __str__, and custom
    __format__ mini-languages. Automatically masks fields listed in __sensitive_fields__.
    """
    # Class-level declaration of attributes requiring redaction in logs/diagnostics
    __sensitive_fields__: ClassVar[Set[str]] = {"password", "api_key", "secret", "token"}

    def _extract_renderable_attributes(self, mask_sensitive: bool = True) -> Dict[str, Any]:
        """Extracts state attributes across both slotted and dynamic instances."""
        data: Dict[str, Any] = {}
        
        # Inspect slots or __dict__
        if hasattr(self, "__slots__"):
            for slot in self.__slots__:
                clean_name = slot.lstrip("_")
                if hasattr(self, slot):
                    val = getattr(self, slot)
                    if mask_sensitive and clean_name.lower() in self.__sensitive_fields__:
                        data[clean_name] = "********"
                    else:
                        data[clean_name] = val
        elif hasattr(self, "__dict__"):
            for key, val in self.__dict__.items():
                clean_name = key.lstrip("_")
                if mask_sensitive and clean_name.lower() in self.__sensitive_fields__:
                    data[clean_name] = "********"
                else:
                    data[clean_name] = val

        return data

    def __repr__(self) -> str:
        """
        UNAMBIGUOUS DEVELOPER DIAGNOSTIC:
        Emits valid constructor-like syntax while redacting sensitive credentials.
        """
        attrs = self._extract_renderable_attributes(mask_sensitive=True)
        rendered_params = ", ".join(f"{k}={repr(v)}" for k, v in attrs.items())
        return f"{self.__class__.__name__}({rendered_params})"

    def __str__(self) -> str:
        """
        HUMAN-READABLE PRESENTATION:
        Emits clean business identifier and main descriptor.
        """
        ident = getattr(self, "id", "unknown")
        name = getattr(self, "name", getattr(self, "_name", self.__class__.__name__))
        return f"[{self.__class__.__name__}:{ident}] {name}"

    def __format__(self, format_spec: str) -> str:
        """
        CUSTOM DOMAIN FORMAT SPECIFICATION MINI-LANGUAGE:
        - '' or 's': Default to __str__()
        - 'r': Call __repr__()
        - 'json': Emit compact JSON string
        - 'compact' or 'short': Emit brief [Class:ID] tag
        - 'masked': Force full redaction
        """
        if not format_spec or format_spec == "s":
            return str(self)
        elif format_spec == "r":
            return repr(self)
        elif format_spec == "compact" or format_spec == "short":
            ident = getattr(self, "id", "N/A")
            return f"<{self.__class__.__name__}:{str(ident)[:8]}>"
        elif format_spec == "json":
            raw_data = self._extract_renderable_attributes(mask_sensitive=True)
            # Convert non-serializable objects (UUIDs) to string
            clean_json_data = {k: str(v) for k, v in raw_data.items()}
            return json.dumps(clean_json_data, sort_keys=True)
        elif format_spec == "masked":
            attrs = self._extract_renderable_attributes(mask_sensitive=True)
            return f"{self.__class__.__name__}(MASKED: {len(attrs)} fields)"
        else:
            raise ValueError(
                f"Unsupported format specification '{format_spec}' for {self.__class__.__name__}"
            )


class SecureAccountRecord(DiagnosticRendererMixin):
    """Domain entity combining slotted state with diagnostic rendering protocols."""
    __slots__ = ("_id", "_name", "_balance", "_api_key")

    def __init__(self, account_id: str, name: str, balance: float, api_key: str) -> None:
        self._id = account_id
        self._name = name
        self._balance = balance
        self._api_key = api_key

    @property
    def id(self) -> str:
        return self._id

    @property
    def name(self) -> str:
        return self._name

    @property
    def balance(self) -> float:
        return self._balance

    def __bytes__(self) -> bytes:
        """Serializes state to UTF-8 encoded wire format for binary WAL ingestion."""
        payload = f"{self._id}|{self._name}|{self._balance}"
        return payload.encode("utf-8")

import json
import pytest
from entityforge.core.diagnostics import SecureAccountRecord


class TestDiagnosticProtocols:
    """Unit tests asserting __repr__, __str__, __format__ mini-languages, and __bytes__."""

    def test_repr_masks_sensitive_credentials_automatically(self):
        account = SecureAccountRecord(
            account_id="ACC-99182",
            name="Enterprise Liquidity Pool",
            balance=1500000.50,
            api_key="secret_live_tok_99182a8bf2"
        )

        repr_str = repr(account)

        # 1. Assert class name and business fields are fully present
        assert "SecureAccountRecord" in repr_str
        assert "ACC-99182" in repr_str
        assert "Enterprise Liquidity Pool" in repr_str

        # 2. CRITICAL SECURITY INVARIANT: Secret API key MUST be redacted!
        assert "secret_live_tok_99182a8bf2" not in repr_str
        assert "api_key='********'" in repr_str

    def test_str_provides_human_readable_presentation(self):
        account = SecureAccountRecord(
            account_id="ACC-101",
            name="Alice Operator",
            balance=50.0,
            api_key="key_123"
        )

        # __str__ output formatted for UI display
        assert str(account) == "[SecureAccountRecord:ACC-101] Alice Operator"

    def test_custom_format_spec_mini_language(self):
        account = SecureAccountRecord(
            account_id="ACC-88291039",
            name="Settlement Reserve",
            balance=25000.0,
            api_key="super_secret"
        )

        # 1. Empty or 's' spec delegates to __str__
        assert f"{account}" == str(account)
        assert f"{account:s}" == str(account)

        # 2. 'r' spec delegates to __repr__
        assert f"{account:r}" == repr(account)

        # 3. 'compact' spec renders short tag
        assert f"{account:compact}" == "<SecureAccountRecord:ACC-8829>"

        # 4. 'json' spec emits valid serialized JSON with masked fields
        json_output = f"{account:json}"
        parsed = json.loads(json_output)
        assert parsed["id"] == "ACC-88291039"
        assert parsed["api_key"] == "********"

        # 5. Invalid spec raises ValueError
        with pytest.raises(ValueError, match=r"Unsupported format specification"):
            _ = f"{account:unsupported_flag}"

    def test_bytes_serialization_protocol(self):
        account = SecureAccountRecord(
            account_id="ACC-001",
            name="BufferNode",
            balance=100.0,
            api_key="key"
        )

        wire_bytes = bytes(account)
        assert isinstance(wire_bytes, bytes)
        assert wire_bytes == b"ACC-001|BufferNode|100.0"
Warning Track

Beginner Pitfalls & Architectural Anti-Patterns

❌ Implementing __str__ While Omitting __repr__

Writing def __str__(self): return self.name without implementing __repr__.

Why this destroys debugging UX: When your objects are stored inside a collection (such as list, dict, or tuple), Python prints elements using their __repr__, completely ignoring __str__! Inspecting print([user1, user2]) outputs useless pointers: [<User object at 0x...>, ...]. Always implement __repr__ first!

❌ Leaking Plaintext Credentials in Tracebacks

Writing def __repr__(self): return f"User(token='{self.api_key}')".

Why this causes compliance & security breaches: Any unhandled exception or log line dumps repr(obj) directly into logging pipelines (Datadog, CloudWatch, Sentry), permanently exposing raw authentication secrets in plaintext. Always mask or redact sensitive credentials inside representation dunders!

❌ Throwing Exceptions Inside __repr__

Accessing uninitialized or remote attributes inside __repr__ that can raise an error.

Why this breaks debuggers: When an active exception is being formatted by the runtime, Python calls __repr__ on local variables to print the traceback. If __repr__ raises an exception, the original exception is masked by a secondary crash, completely blinding developers during production triage!

❌ Returning Non-String Types from String Dunders

Writing def __str__(self): return self.raw_id where raw_id is an integer or UUID.

Why this raises an immediate TypeError: CPython's tp_str and tp_repr slots strictly require returning a Python str object. Returning an int, UUID, or None raises TypeError: __str__ returned non-string (type int). Always wrap non-strings in str(...).
