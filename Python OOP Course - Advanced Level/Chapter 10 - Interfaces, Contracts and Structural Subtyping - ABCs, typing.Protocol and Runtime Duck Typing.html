Part 01

Computer Science: Nominal Subtyping vs. Structural Subtyping

In type systems, an Interface defines a contract: a specification of methods, arguments, and return types that an implementing class must provide. In software architecture, there are two distinct ways a type checker or runtime verifies that a class satisfies an interface:

Interface Topologies: Nominal Subtyping vs. Structural Subtyping (Duck Typing)

Comparing explicit inheritance trees against shape-based protocol compatibility

1. Nominal Subtyping (abc.ABC) Explicit Heritage
class EventDispatcher(ABC): @abstractmethod def publish(...)
must explicitly subclass
class RedisDispatcher(EventDispatcher): Implements .publish()
  • Explicit Lineage: A class is recognized as a subtype if and only if it explicitly inherits from the base class in its definition.
  • Coupling Cost: The third-party or adapter class is tightly coupled to your framework's module imports.
  • Runtime Enforcement: CPython blocks class instantiation at runtime if any @abstractmethod is missing!
2. Structural Subtyping (typing.Protocol) Static Duck Typing
class Repository(Protocol): def save(entity: T) -> None: ...
zero inheritance required!
class SQLiteStorage: Defines matching .save() method
  • Shape-Based Equivalence: "If it walks like a duck and quacks like a duck, it's a duck." Compatibility is proven purely by method names and type signatures.
  • Zero Coupling: The concrete storage class does not import, inherit, or even know about Repository!
  • Compile-Time Verification: Static analyzers (mypy, pyright) verify protocol conformance prior to deployment.
Part 02

Under the Hood: ABCMeta & Instantiation Blocking

How does Python physically prevent you from instantiating an abstract class? In Python, functions are first-class objects. Decorating a method with @abstractmethod does not raise an error at definition time; it sets an internal boolean flag: func.__isabstractmethod__ = True.

When a class inherits from abc.ABC (which uses the metaclass abc.ABCMeta), CPython inspects the class dictionary during type construction:

// CPython's Abstract Instantiation Guard Pipeline
1. Class Creation: ABCMeta.__new__ scans the class and its MRO ancestors.
2. Set Calculation: It collects every method where __isabstractmethod__ == True that has not been overridden by a concrete implementation.
3. Frozenset Population: It stores these names in cls.__abstractmethods__ = frozenset({'save', 'delete', ...}).
4. Instantiation Interception: When caller writes repo = BaseRepository(), CPython's type.__call__ checks:
if cls.__abstractmethods__:
    raise TypeError(f"Can't instantiate abstract class {cls.__name__} with abstract methods {cls.__abstractmethods__}")
Virtual Subclassing

The __subclasshook__ Magic Protocol

How does isinstance([], collections.abc.Sequence) return True when built-in list does not inherit from Sequence?

ABCs can define a classmethod called __subclasshook__(cls, subclass). When isinstance(obj, MyABC) or issubclass(Candidate, MyABC) is evaluated, CPython calls this hook, allowing the ABC to dynamically inspect the candidate's MRO attributes: 

class SizedContract(ABC):
    @classmethod
    def __subclasshook__(cls, C: type) -> bool:
        if cls is SizedContract:
            # Return True if any class in the candidate's MRO defines '__len__'
            if any("__len__" in B.__dict__ for B in C.__mro__):
                return True
        return NotImplemented
Part 03

Architecture Invariant: Strict Decorator Stacking Order

When combining @abstractmethod with other built-in decorators (such as @classmethod, @staticmethod, or @property), the order of decorator application is critical.

✓ Correct Decorator Stacking CPython Rule 
# 1. Abstract Classmethod:
@classmethod
@abstractmethod
def factory(cls, config: dict) -> Self: ...

# 2. Abstract Read-Only Property:
@property
@abstractmethod
def connection_string(self) -> str: ...

The Rule: @abstractmethod must sit as the innermost decorator, immediately adjacent to the function definition (def).

✗ Fatal Inverted Stacking Broken Lookup 
# FATAL: @classmethod wraps outside @abstractmethod
@abstractmethod
@classmethod
def broken_factory(cls, config: dict): ...

Why this fails silently: @classmethod returns a descriptor object. If @abstractmethod wraps on the outside, it attempts to set __isabstractmethod__ on the descriptor instead of the function, which older CPython versions ignore, allowing subclasses to instantiate without implementing the method!

Part 04

Architectural Decision Matrix: ABC vs. Protocol vs. Concrete Class

Senior architects choose the exact typing mechanism that minimizes coupling while maximizing static safety:

Mechanism Typing Paradigm Coupling Level Ideal Architectural Use Case
typing.Protocol (PEP 544) Structural (Static Duck Typing) Zero Coupling Default choice for interfaces. Adapters, database repositories, pluggable drivers, serializers where you want consumers to satisfy contracts without subclassing.
@runtime_checkable Protocol Structural + Runtime Check Zero Coupling When you need structural typing, but also need to perform runtime isinstance(adapter, Protocol) checks at system initialization boundaries.
abc.ABC + @abstractmethod Nominal Subtyping Tight Coupling Framework base classes where you provide partial shared implementation alongside abstract methods (Template Method Pattern).

1. Production Contracts Core: src/entityforge/core/contracts.py Protocols & Abstract Contracts 
# ==============================================================================
# EntityForge Core - Interfaces, Protocols & Structural Subtyping (Milestone 10)
# ==============================================================================

from __future__ import annotations
from abc import ABC, abstractmethod
from typing import Any, Dict, Generic, List, Optional, Protocol, TypeVar, runtime_checkable
from entityforge.core.entity import BaseEntity

T = TypeVar("T", bound=BaseEntity)


@runtime_checkable
class RepositoryProtocol(Protocol[T]):
    """
    PEP 544 STRUCTURAL SUBTYPING PROTOCOL:
    Defines the persistence contract for domain entities.
    Any class implementing save, get_by_id, and delete satisfies this protocol
    WITHOUT needing to inherit from RepositoryProtocol!
    """
    def save(self, entity: T) -> None:
        """Persists an entity into storage."""
        ...

    def get_by_id(self, entity_id: str) -> Optional[T]:
        """Retrieves an entity by its string UUID, or None if absent."""
        ...

    def delete(self, entity_id: str) -> bool:
        """Deletes entity by ID, returning True on success."""
        ...


class EventDispatcherContract(ABC):
    """
    NOMINAL ABSTRACT BASE CLASS (ABC):
    Enforces implementation of domain event publication across concrete adapters.
    CPython will block instantiation of any subclass omitting @abstractmethod!
    """
    @abstractmethod
    def publish(self, event_type: str, payload: Dict[str, Any]) -> None:
        """Publishes a structured domain event to message brokers or listeners."""
        pass


class InMemoryEntityRepository(Generic[T]):
    """
    CONCRETE STORAGE ADAPTER (Pure Structural Duck Typing):
    Notice: Does NOT inherit from RepositoryProtocol!
    Satisfies RepositoryProtocol purely by matching method signatures.
    """
    def __init__(self) -> None:
        self._storage: Dict[str, T] = {}

    def save(self, entity: T) -> None:
        self._storage[str(entity.id)] = entity

    def get_by_id(self, entity_id: str) -> Optional[T]:
        return self._storage.get(entity_id)

    def delete(self, entity_id: str) -> bool:
        if entity_id in self._storage:
            del self._storage[entity_id]
            return True
        return False

    def count(self) -> int:
        return len(self._storage)


class InMemoryEventDispatcher(EventDispatcherContract):
    """
    CONCRETE DISPATCHER ADAPTER (Nominal Inheritance):
    Explicitly subclasses EventDispatcherContract, fulfilling abstract methods.
    """
    def __init__(self) -> None:
        self.dispatched_events: List[Dict[str, Any]] = []

    def publish(self, event_type: str, payload: Dict[str, Any]) -> None:
        self.dispatched_events.append({"type": event_type, "payload": payload})


class DomainEntityService(Generic[T]):
    """
    DEPENDENCY INVERSION PRINCIPLE (DIP):
    High-level business service depends strictly on abstractions (Protocols & ABCs),
    never on concrete database or message broker implementations!
    """
    def __init__(
        self,
        repository: RepositoryProtocol[T],
        dispatcher: EventDispatcherContract
    ) -> None:
        self._repo = repository
        self._dispatcher = dispatcher

    def register_entity(self, entity: T) -> None:
        """Executes business workflow: Persists entity and broadcasts domain event."""
        self._repo.save(entity)
        self._dispatcher.publish(
            event_type="ENTITY_REGISTERED",
            payload={"id": str(entity.id), "class": entity.__class__.__name__}
        )

class TestContractsAndProtocols:
    """Unit tests asserting structural typing, ABC instantiation guards, and IoC orchestration."""

    def test_structural_duck_typing_protocol_satisfaction(self):
        repo = InMemoryEntityRepository[SampleUser]()

        # 1. Structural Subtyping Invariant:
        # InMemoryEntityRepository does NOT inherit from RepositoryProtocol,
        # but satisfies it structurally!
        assert isinstance(repo, RepositoryProtocol)

    def test_abc_blocks_instantiation_when_abstract_methods_unimplemented(self):
        # CPython ABCMeta MUST block instantiation of incomplete subclasses!
        with pytest.raises(TypeError, match=r"Can't instantiate abstract class"):
            _ = IncompleteDispatcher()

    def test_complete_dispatcher_instantiates_and_fulfills_contract(self):
        dispatcher = InMemoryEventDispatcher()
        assert isinstance(dispatcher, EventDispatcherContract)

        dispatcher.publish("TEST_EVENT", {"status": "OK"})
        assert len(dispatcher.dispatched_events) == 1
        assert dispatcher.dispatched_events[0]["type"] == "TEST_EVENT"

    def test_dependency_inversion_orchestration_service(self):
        # Decoupled components wired together via Dependency Injection
        repo = InMemoryEntityRepository[SampleUser]()
        dispatcher = InMemoryEventDispatcher()

        assert retrieved.username == "alice_contract"

        # 2. Verify event published
        assert len(dispatcher.dispatched_events) == 1
        assert dispatcher.dispatched_events[0]["payload"]["id"] == str(user.id)
Warning Track

Beginner Pitfalls & Architectural Anti-Patterns

❌ The 'I' Prefix Anti-Pattern

Naming interfaces IRepository, IUserService, or IEventDispatcher.

Why this is unpythonic: The I prefix is a Hungarian notation relic from C# and Java. In Python, interfaces should be named for what they represent (Repository) or suffixed with their mechanism (RepositoryProtocol, EventDispatcherContract), while concrete classes are qualified by their implementation (PostgresRepository).

❌ Over-Inheriting from ABCs

Creating monolithic abstract base classes with 25 abstract methods that every adapter must inherit.

Why this violates Interface Segregation (ISP): It couples all adapters to a rigid nominal hierarchy. If an adapter only needs to support read operations, forcing it to inherit and implement 20 write methods violates clean code. Use lean, focused typing.Protocol definitions instead!

❌ Inverted Abstract Decorator Stacking

Placing @abstractmethod on the outside: @abstractmethod @classmethod.

Why this breaks runtime checks: @abstractmethod must wrap the underlying function directly. If inverted, it sets __isabstractmethod__ on the descriptor object, which CPython ignores, allowing subclasses to instantiate without fulfilling the contract! Always make @abstractmethod the innermost decorator.

❌ Assuming @runtime_checkable Validates Signatures

Assuming isinstance(obj, MyProtocol) verifies method parameter types at runtime.

Why this creates false confidence: At runtime, @runtime_checkable only verifies that the method or attribute name exists on the class! It does not check argument counts, parameter types, or return types at runtime! Full type safety requires running static type checkers (mypy / pyright).
