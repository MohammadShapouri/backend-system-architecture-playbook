Part 01

Computer Science: The Class of Classes & Dynamic Synthesis

In object-oriented programming, an object is an instance of a class. In Python, because classes are also objects, every class must itself be an instance of something.

That "something" is a Metaclass. A metaclass is simply the class of a class. By default, every class in Python is an instance of the built-in metaclass type.

Runtime Synthesis

Dynamic Class Creation: The 3-Argument type() Call

When the Python interpreter evaluates a class statement, it compiles the body into a bytecode block and executes the 3-argument form of type(name, bases, namespace):

# 1. Standard declarative syntax:
class User(BaseEntity):
    role = "admin"
    def get_role(self): return self.role
# 2. What CPython evaluates dynamically under the hood:
User = type(
    "User",
    (BaseEntity,),
    {"role": "admin", "get_role": lambda self: self.role}
)

By providing a custom metaclass subclassing type, you intercept this creation process, allowing you to rewrite class attributes, validate schemas, inject methods, and register classes before they ever exist in your module!

Part 02

Under the Hood: The 4-Phase Class Creation Lifecycle

When CPython parses a class Model(metaclass=ModelMeta): block, it executes a rigorous 4-phase construction pipeline:

The CPython 4-Phase Class Construction Pipeline
Phase 1: Metaclass Selection & Base Inspection CPython inspects the metaclass= keyword argument and the metaclasses of all base classes to resolve the most derived metaclass.
Phase 1: Selection
Phase 2: Namespace Preparation (__prepare__) CPython calls metaclass.__prepare__(name, bases, **kwargs). Returns an empty mapping (e.g. dict or custom map) to serve as the local execution namespace.
Phase 2: Namespace
Phase 3: Class Body Bytecode Execution The statements inside the class body are executed line by line inside the namespace mapping returned in Phase 2. Functions, descriptors, and variables populate the dictionary.
Phase 3: Populate
Phase 4: Metaclass Instantiation (__new__ & __init__) CPython invokes metaclass.__new__(mcls, name, bases, namespace, **kw), allocating the actual class object in heap RAM!
Phase 4: Allocation
// Why __prepare__ Was Introduced (PEP 3115):

In legacy Python, class attributes were evaluated into a standard unordered dictionary. By overriding __prepare__, a custom metaclass can return an OrderedDict or custom tracking mapping, capturing the exact line-by-line definition order of database columns or form fields!

Part 03

Modern Metaprogramming: PEP 487 `__init_subclass__`

Python core developer Tim Peters famously wrote:

"Metaclasses are deeper magic than 99% of users should ever worry about. If you wonder whether you need them, you don’t."

Why? Because custom metaclasses introduce complex inheritance conflicts (the Metaclass Conflict problem). In Python 3.6, PEP 487 introduced __init_subclass__. It allows parent classes to intercept subclass creation using simple, clean methods without writing a metaclass:

Legacy / Heavy Pattern

Custom Metaclass

Requires subclassing type, overriding __new__, and specifying metaclass=MyMeta in every root class: 

class LegacyMeta(type):
    def __new__(mcls, name, bases, ns):
        cls = super().__new__(mcls, name, bases, ns)
        registry[name] = cls
        return cls

class Model(metaclass=LegacyMeta):
    pass

Fails when inheriting from multiple classes with different metaclasses!

Modern Python Standard

PEP 487 __init_subclass__

A simple classmethod defined on the base class that receives newly created subclasses and keyword arguments: 

class BasePlugin:
    def __init_subclass__(cls, plugin_id: str, **kwargs):
        super().__init_subclass__(**kwargs)
        registry[plugin_id] = cls

class AuthPlugin(BasePlugin, plugin_id="auth_v1"):
    pass

Zero metaclasses, zero MRO conflicts, clean keyword arguments in class headers!

Part 04

Architectural Decision Matrix: Choosing the Right Metaprogramming Tool

Before writing a metaclass, consult this hierarchy of metaprogramming mechanisms:

Mechanism Complexity Execution Timing When to Use
Class Decorator Lowest After class creation Adding helper methods, wrapping classes, inspecting attributes without altering inheritance. (e.g. @dataclass).
PEP 487 __init_subclass__ Low During subclass initialization Default modern choice. Automatic plugin registration, validating subclass attributes, configuring base classes via header kwargs.
Custom Metaclass (type) Highest Before & during class creation When you must control namespace preparation (__prepare__), dynamically rewrite bases, or mutate class attributes before the class object is allocated.

1. Production Metaclass Core: src/entityforge/core/meta.py Metaclass Compiler & Schema Registry 
# ==============================================================================
# EntityForge Core - Metaclasses & Declarative Model Compiler (Milestone 12)
# ==============================================================================

from __future__ import annotations
from typing import Any, Dict, Optional, Tuple, Type
from entityforge.core.entity import BaseEntity, EntityIdentity
from entityforge.core.descriptors import Field


class ModelCatalog:
    """Global thread-safe registry tracking all active declarative domain models."""
    _registry: Dict[str, Type[DeclarativeEntity]] = {}

    @classmethod
    def register(cls, model_name: str, model_cls: Type[DeclarativeEntity]) -> None:
        cls._registry[model_name] = model_cls

    @classmethod
    def get(cls, model_name: str) -> Optional[Type[DeclarativeEntity]]:
        return cls._registry.get(model_name)

    @classmethod
    def clear(cls) -> None:
        cls._registry.clear()


class ModelMeta(type):
    """
    PRODUCTION METACLASS SCHEMA COMPILER:
    1. Intercepts class definition.
    2. Extracts all Field descriptors and compiles an immutable _fields table.
    3. Auto-registers concrete entity models in the global ModelCatalog.
    """
    def __new__(
        mcls,
        name: str,
        bases: Tuple[type, ...],
        namespace: Dict[str, Any],
        **kwargs: Any
    ) -> Type[Any]:
        # 1. Collect all Field descriptors declared in the class namespace
        fields: Dict[str, Field] = {}
        for attr_name, attr_val in list(namespace.items()):
            if isinstance(attr_val, Field):
                fields[attr_name] = attr_val

        # 2. Inherit fields from parent models in bases
        for base in reversed(bases):
            if hasattr(base, "_fields"):
                parent_fields = getattr(base, "_fields")
                fields = {**parent_fields, **fields}

        # 3. Attach compiled immutable fields dictionary to class namespace
        namespace["_fields"] = fields

        # 4. Allocate and construct the class object via type.__new__
        new_class = super().__new__(mcls, name, bases, namespace)

        # 5. Register concrete models in catalog (skip abstract base DeclarativeEntity)
        if name != "DeclarativeEntity":
            ModelCatalog.register(name, new_class)

        return new_class


class DeclarativeEntity(BaseEntity, metaclass=ModelMeta):
    """
    MASTER DECLARATIVE DOMAIN MODEL BASE:
    Combines ModelMeta schema compilation with PEP 487 __init_subclass__ configuration.
    """
    _table_name: str = ""

    def __init_subclass__(cls, table_name: Optional[str] = None, **kwargs: Any) -> None:
        """PEP 487 Hook: Allows declarative table_name configuration in class header."""
        super().__init_subclass__(**kwargs)
        cls._table_name = table_name or cls.__name__.lower() + "s"

    def __init__(self, entity_id: EntityIdentity, **kwargs: Any) -> None:
        super().__init__(entity_id=entity_id)
        
        # Assign attributes through descriptors to trigger validation
        fields: Dict[str, Field] = getattr(self.__class__, "_fields", {})
        for field_name, field_obj in fields.items():
            if field_name in kwargs:
                setattr(self, field_name, kwargs[field_name])
            elif field_obj.default is not None:
                setattr(self, field_name, field_obj.default)
            elif field_obj.required:
                raise ValueError(f"Missing mandatory field '{field_name}' on {self.__class__.__name__}")

class AccountModel(DeclarativeEntity, table_name="bank_accounts"):
    """Declarative entity model compiled by ModelMeta."""
    account_number = StringField(min_length=5)
    balance = IntegerField(min_value=0, default=0)


class PremiumAccountModel(AccountModel, table_name="premium_accounts"):
    """Subclass inheriting parent fields while adding its own."""
    tier = StringField(default="GOLD")


class TestMetaclassDeclarativeModels:
    """Unit tests asserting metaclass schema compilation, cataloging, and __init_subclass__."""

    def test_metaclass_compiles_fields_dictionary(self):
        # 1. ModelMeta must extract fields into _fields mapping
        assert "account_number" in AccountModel._fields
        assert "balance" in AccountModel._fields

        # 2. Subclasses must inherit parent fields and include new ones
        assert "account_number" in PremiumAccountModel._fields
        assert "balance" in PremiumAccountModel._fields
        assert "tier" in PremiumAccountModel._fields

    def test_model_catalog_automatic_registration(self):
        # ModelMeta must automatically register concrete subclasses in the global catalog
        assert ModelCatalog.get("AccountModel") is AccountModel
        assert ModelCatalog.get("PremiumAccountModel") is PremiumAccountModel

    def test_init_subclass_header_kwargs_configuration(self):
        # __init_subclass__ sets custom table names
        assert AccountModel._table_name == "bank_accounts"
        assert PremiumAccountModel._table_name == "premium_accounts"

    def test_declarative_instantiation_and_validation(self):
        ident = EntityIdentity.generate()
        account = AccountModel(entity_id=ident, account_number="ACC-99182")

        assert account.account_number == "ACC-99182"
        assert account.balance == 0  # Applied default

Warning Track

Beginner Pitfalls & Architectural Anti-Patterns

❌ The Metaclass Conflict Trap

Multiple-inheriting from two base classes that declare different custom metaclasses.

Why this fails at definition time: If BaseA uses MetaA and BaseB uses MetaB, writing class Child(BaseA, BaseB): fails with TypeError: metaclass conflict: the metaclass of a derived class must be a (non-strict) subclass of the metaclasses of all its bases! Use __init_subclass__ to avoid metaclass conflicts completely.

❌ Overusing Metaclasses for Simple Tasks

Writing a 30-line custom metaclass just to register subclasses in a list.

Why this is poor architecture: Metaclasses are heavy, difficult for team members to debug, and break easily. Since Python 3.6, subclass registration should be implemented in 3 lines using def __init_subclass__(cls): registry.append(cls)!

❌ Mutating Namespaces Unpredictably

Silently deleting or renaming methods inside metaclass.__new__ without documentation.

Why this violates clean code: If a developer writes a method in their class and the metaclass silently renames or deletes it, code inspection, linters, and IDE autocompletions break completely.

❌ Forgetting **kwargs in __init_subclass__

Defining def __init_subclass__(cls, table_name) without accepting **kwargs.

Why this breaks cooperative inheritance: Other mixins or parent classes in the hierarchy may declare header keyword arguments. If your hook doesn't forward **kwargs to super().__init_subclass__(**kwargs), Python raises an immediate TypeError!
