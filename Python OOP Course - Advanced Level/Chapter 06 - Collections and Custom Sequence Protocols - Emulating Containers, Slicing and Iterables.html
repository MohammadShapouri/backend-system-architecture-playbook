Part 01

Computer Science: The Collection Protocol Pyramid

Python does not rely on monolithic container interfaces. Instead, it decomposes collection behavior into small, composable Protocols defined by specific dunder methods. A class only needs to implement the exact protocols required for its domain semantics:

The Python Collection Protocol Hierarchy (collections.abc)
Sized
__len__(self) -> int

Allows len(c). Invariant: Must return a non-negative integer $\ge 0$. Governs truthiness if __bool__ is omitted.

Container
__contains__(self, item) -> bool

Enables the in operator. Provides $O(1)$ membership checks (e.g. hash lookups) bypassing linear $O(n)$ iteration scans.

Iterable
__iter__(self) -> Iterator

Permits for x in c:, list comprehensions, unpacking, and generator delegation. Returns an iterator satisfying __next__.

Composite Protocol: Sequence & MutableSequence collections.abc
Sequence (Read-Only):

Unites Sized + Container + Iterable + __getitem__. Provides mixin implementations of __reversed__(), .index(), and .count() automatically!

MutableSequence (Read-Write):

Adds __setitem__, __delitem__, and insert(). Synthesizes .append(), .reverse(), .extend(), .pop(), and .remove() for free!

// CPython Legacy Fallback: Iteration via __getitem__

If an object defines __getitem__ but omits __iter__, CPython automatically falls back to indexed iteration. When a loop executes for x in obj:, Python queries obj[0], obj[1], obj[2], ... sequentially until an IndexError is raised! In modern production code, always implement __iter__ explicitly to communicate architectural intent.

Part 02

Under the Hood: Slicing Geometry & `slice.indices()` Normalization

When bracket notation includes a colon (e.g. c[1:10:2]), Python does not pass integers into __getitem__. It constructs and passes an instance of the built-in slice class: slice(1, 10, 2).

Manually handling slice boundaries—accounting for negative indices (e.g. c[:-2]), omitted bounds (c[::-1]), and strides out of range—is a notorious source of off-by-one errors.

Python provides the definitive standard solution: the slice.indices(length) method.

Standard Library Method

slice.indices(length)

Given the total length of the sequence, indices() normalizes all negative offsets, clips bounds to $[0, \text{length}]$, and resolves negative step directions: 

s = slice(-5, None, -1)
start, stop, step = s.indices(10)
# Output: (5, -1, -1)
# Perfectly matches range(start, stop, step)!

You can immediately feed the normalized 3-tuple directly into range() with zero conditional logic.

Type Homogeneity

The Subtype Preservation Invariant

When slicing a custom domain collection, a common anti-pattern is returning a standard raw Python list:

sub = entity_collection[1:5] # Returns plain list! Breaks custom domain methods!

The Production Invariant: Slicing a custom sequence must return a new instance of the exact same collection type, preserving domain methods, custom observers, and validation rules down the processing chain!

Part 03

Architecture Warning: The Subclassing `list` Anti-Pattern

When developers need a custom list that enforces validation or emits events, their first instinct is to subclass Python's built-in list: class CustomList(list):.

In CPython, subclassing built-in collections directly is an architectural trap.

The C-Level Method Bypass Trap

In CPython, built-in types (list, dict) are implemented in optimized C. For performance reasons, C-level methods frequently bypass overridden Python methods:

  • If you override __setitem__ to validate incoming values, calling custom_list.extend([bad_data]) runs internal C code that inserts the data directly, completely skipping your overridden __setitem__!
  • Subclassing dict exhibits the exact same flaw: overriding __setitem__ is ignored by dict.update()!
The Production Standard: collections.abc

To build robust, production-grade custom sequences:

Inherit from collections.abc.MutableSequence (or wrap an internal list compositionally). When you implement the 5 core abstract methods (__getitem__, __setitem__, __delitem__, __len__, insert), all convenience methods (append, extend, pop, remove, __iadd__) are implemented as Python mixins that guarantee your validation hooks are always invoked!

Part 04

Dunder Method Matrix: Container & Sequence Protocols

The exact contract specifications for emulating Python collections:

Method Trigger Syntax When to Override (✓) When NOT to Override (✗)
__len__ len(c) Whenever instances act as sized collections. Invariant: Must return non-negative int $\ge 0$. Infinite streams, unbuffered generators, or database cursors where total count is unknown without consuming all rows.
__getitem__ c[i], c[start:stop] Index access and slicing. Must handle both int and slice objects. Raise IndexError on out-of-bounds indices. Simple data transfer objects or services that should not pretend to be arrays.
__setitem__ c[i] = val, c[s:e] = vals Mutable sequences and mappings. Validate types and emit change notifications. Immutable collections (raise TypeError or omit definition entirely).
__iter__ for x in c: Yielding items directly. Implement as a generator function with yield or delegate to iter(internal_collection). When the class is already an iterator (implements __next__ returning items). Iterators return self in __iter__.
__contains__ x in c Providing an optimized $O(1)$ membership check (e.g. by checking an internal set or index) bypassing linear iteration. When membership is already inherently $O(n)$ linear traversal (Python’s default fallback handles this automatically).

1. Production Sequence Core: src/entityforge/core/collections.py MutableSequence & Slicing Protocols 
# ==============================================================================
# EntityForge Core - Observable EntityCollection & Sequence Protocols (Milestone 06)
# ==============================================================================

from __future__ import annotations
from collections.abc import MutableSequence
from typing import Any, Callable, Generic, Iterable, Iterator, List, Optional, Set, TypeVar, Union, overload
from entityforge.core.entity import BaseEntity, EntityIdentity
from entityforge.core.diagnostics import DiagnosticRendererMixin

T = TypeVar("T", bound=BaseEntity)


class EntityCollection(MutableSequence[T], DiagnosticRendererMixin, Generic[T]):
    """
    PRODUCTION OBSERVABLE DOMAIN SEQUENCE:
    Subclasses collections.abc.MutableSequence to acquire mixin methods (.append, .pop, .extend)
    while strictly preserving subclass type homogeneity during slicing operations.
    """
    def __init__(self, initial_items: Optional[Iterable[T]] = None) -> None:
        self._items: List[T] = []
        # Secondary index set enabling O(1) membership checks by EntityIdentity UUID:
        self._identity_index: Set[EntityIdentity] = set()
        # Observer callback registry for mutation events:
        self._listeners: List[Callable[[str, Any], None]] = []

        if initial_items is not None:
            self.extend(initial_items)

    # ==========================================================================
    # Observer Registration & Dispatch
    # ==========================================================================
    def add_listener(self, callback: Callable[[str, Any], None]) -> None:
        """Registers an observer callback: callback(event_type: str, payload: Any)."""
        self._listeners.append(callback)

    def _notify(self, event_type: str, payload: Any) -> None:
        """Dispatches change notifications to all registered listeners."""
        for listener in self._listeners:
            listener(event_type, payload)

    # ==========================================================================
    # The 5 Core Abstract Methods of MutableSequence
    # ==========================================================================
    def __len__(self) -> int:
        """Returns total entity count in O(1) time."""
        return len(self._items)

    @overload
    def __getitem__(self, index: int) -> T: ...

    @overload
    def __getitem__(self, index: slice) -> EntityCollection[T]: ...

    def __getitem__(self, index: Union[int, slice]) -> Union[T, EntityCollection[T]]:
        """
        INDEX & SLICE RESOLUTION:
        1. If index is int → returns the single entity at that position.
        2. If index is slice → uses slice.indices() to return a new EntityCollection
           of the EXACT same class, preserving domain methods and type homogeneity!
        """
        if isinstance(index, slice):
            start, stop, step = index.indices(len(self._items))
            sliced_items = [self._items[i] for i in range(start, stop, step)]
            # Subtype preservation invariant: Return instance of self.__class__!
            new_collection = self.__class__(sliced_items)
            return new_collection
        return self._items[index]

    def __setitem__(self, index: Union[int, slice], value: Union[T, Iterable[T]]) -> None:
        """Updates item(s) at position, updating the identity index and notifying listeners."""
        if isinstance(index, slice):
            raise NotImplementedError("Batch slice assignment is restricted to maintain domain invariants.")

        if not isinstance(value, BaseEntity):
            raise TypeError(f"Expected BaseEntity instance, got '{type(value).__name__}'")

        old_item = self._items[index]
        self._identity_index.discard(old_item.id)
        self._items[index] = value
        self._identity_index.add(value.id)
        self._notify("SET", {"index": index, "old": old_item, "new": value})

    def __delitem__(self, index: Union[int, slice]) -> None:
        """Removes item(s) at position, updating identity set and notifying listeners."""
        if isinstance(index, slice):
            start, stop, step = index.indices(len(self._items))
            # Delete in reverse order to preserve valid index positions
            indices_to_delete = sorted(list(range(start, stop, step)), reverse=True)
            for i in indices_to_delete:
                del self[i]
            return

        item = self._items.pop(index)
        self._identity_index.discard(item.id)
        self._notify("DELETE", {"index": index, "item": item})

    def insert(self, index: int, value: T) -> None:
        """Inserts an entity at position, updating index and notifying listeners."""
        if not isinstance(value, BaseEntity):
            raise TypeError(f"Expected BaseEntity instance, got '{type(value).__name__}'")

        self._items.insert(index, value)
        self._identity_index.add(value.id)
        self._notify("INSERT", {"index": index, "item": value})

    # ==========================================================================
    # Optimized Protocol Overrides
    # ==========================================================================
    def __contains__(self, item: object) -> bool:
        """
        OPTIMIZED CONTAINER PROTOCOL:
        Leverages internal UUID identity set for O(1) membership check,
        bypassing O(n) sequential list traversal!
        """
        if isinstance(item, BaseEntity):
            return item.id in self._identity_index
        return False

    def __iter__(self) -> Iterator[T]:
        """Yields entities in sequential arrival order."""
        return iter(self._items)

    def find_by_id(self, entity_id: EntityIdentity | str) -> Optional[T]:
        """Domain query finding an entity by UUID in O(n) scan."""
        target_str = str(entity_id)
        for item in self._items:
            if str(item.id) == target_str:
                return item
        return None

import pytest
from entityforge.core.entity import BaseEntity
from entityforge.core.collections import EntityCollection


class DomainItem(BaseEntity):
    """Concrete entity subclass for collection testing."""
    pass


class TestEntityCollectionProtocols:
    """Unit tests asserting Sized, Iterable, Sequence slicing, and Observer notifications."""

    def test_sized_and_iterable_protocols(self):
        col = EntityCollection()
        assert len(col) == 0

        e1 = DomainItem.create_new(name="Item_1")
        e2 = DomainItem.create_new(name="Item_2")

        # Mixin append() provided by MutableSequence
        col.append(e1)
        col.append(e2)

        # Sized protocol
        assert len(col) == 2

        # Iterable protocol
        names = [item.name for item in col]
        assert names == ["Item_1", "Item_2"]

    def test_optimized_o1_membership_container_protocol(self):
        col = EntityCollection()
        e1 = DomainItem.create_new(name="Alpha")
        e2 = DomainItem.create_new(name="Beta")

        col.append(e1)
        assert e1 in col      # O(1) check against internal UUID set
        assert e2 not in col

        # Remove e1 -> index set must discard
        col.remove(e1)
        assert e1 not in col

    def test_slicing_preserves_subtype_homogeneity(self):
        col = EntityCollection([DomainItem.create_new(code=i) for i in range(10)])

        # 1. Single item indexing returns domain entity
        assert isinstance(col[0], DomainItem)
        assert col[0].code == 0

        # 2. SUBTYPE PRESERVATION INVARIANT:
        # Slicing MUST return a new EntityCollection instance, NOT a plain Python list!
        sub_slice = col[2:6]
        assert isinstance(sub_slice, EntityCollection)
        assert len(sub_slice) == 4
        assert [item.code for item in sub_slice] == [2, 3, 4, 5]

        # 3. Complex negative step slicing
        rev_slice = col[::-1]
        assert isinstance(rev_slice, EntityCollection)
        assert len(rev_slice) == 10
        assert rev_slice[0].code == 9

    def test_observer_listener_dispatches_mutation_events(self):
        col = EntityCollection()
        events = []

        # Register observer callback
        col.add_listener(lambda ev_type, payload: events.append((ev_type, payload)))

        e1 = DomainItem.create_new(name="Observed_A")
        col.append(e1)

        assert len(events) == 1
        assert events[0][0] == "INSERT"
        assert events[0][1]["item"] is e1

        # Delete triggers notification
        del col[0]
        assert len(events) == 2
        assert events[1][0] == "DELETE"
Warning Track

Beginner Pitfalls & Architectural Anti-Patterns

❌ Subclassing Built-in list Directly

Writing class MyList(list): and overriding __setitem__.

Why this causes silent security bugs: CPython's built-in list methods like extend() and C-level slice assignments bypass overridden Python methods for speed. Unvalidated items bypass your validation hooks! Always subclass collections.abc.MutableSequence or use collections.UserList.

❌ Slicing Returning a Raw list

Implementing __getitem__ slice branch as return self._items[idx].

Why this breaks domain pipelines: If a caller writes subset = my_collection[0:5], they expect subset to still be an instance of MyCollection with domain filtering and observer methods. Returning a raw list strips all custom methods and breaks method chaining. Always return self.__class__(self._items[idx]).

❌ Mutating Sequences During Iteration

Writing for item in collection: if condition: collection.remove(item).

Why this drops elements silently: Removing an element shifts all following elements leftward by one pointer. The internal iterator counter advances by one, causing the loop to completely skip the element immediately following the deleted item! Iterate over a slice snapshot: for item in list(collection):.

❌ Manual Slice Calculation Boilerplate

Writing custom if s.start < 0: ... elif s.step is None: ... logic.

Why this causes bugs: Hand-rolled boundary logic fails on negative steps ([::-1]) and negative bounds ([-3:-1]). Python already provides the battle-tested C-level method start, stop, step = slice_obj.indices(len(self)). Always use it!
