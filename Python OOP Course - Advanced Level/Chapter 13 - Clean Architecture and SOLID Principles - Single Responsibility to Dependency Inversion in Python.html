Part 01

Computer Science: The Clean Architecture Dependency Rule

In Clean Architecture (formulated by Robert C. Martin), software is structured into concentric circular layers. The foundational law governing this topology is the Dependency Rule:

Source code dependencies must point ONLY INWARD, toward higher-level policies.

Nothing in an inner circle can know anything about something in an outer circle. Domain Entities must never import database drivers, web frameworks (FastAPI/Django), or external network libraries.

The Clean Architecture Concentric Onion

Dependencies flow inwards; domain models remain isolated from frameworks

The Dependency Inversion Bridge:

How does an inner Use Case save an entity to a PostgreSQL database without importing PostgreSQL? By defining an abstract Protocol in the inner circle, and having the outer database adapter implement that protocol.

Part 02

Reinterpreting SOLID for Idiomatic Python

The SOLID principles were originally formulated in the context of static, compiled languages (C++, Java). Blindly porting Java patterns (like creating factories for factories or prefixing every file with I) leads to unpythonic bloat. Here is how senior architects apply SOLID in Python:

S • Single Responsibility Principle (SRP) One Reason to Change

A class should have one, and only one, actor to whom it is responsible. Python Application: A domain entity (OrderAggregate) manages business invariants and calculations. It must not contain code for saving itself to SQL (order.save_to_db()), formatting HTML emails (order.to_email()), or validating Stripe tokens. Those responsibilities belong in dedicated repositories, serializers, and gateway clients.

O • Open/Closed Principle (OCP) Open for Extension • Closed for Modification

You should be able to extend class behavior without modifying its source code. Python Application: Avoid branching if country == 'US': ... elif country == 'UK': ... ladders inside calculation methods. Instead, inject a pluggable TaxStrategy Protocol. Adding support for a new country simply requires creating a new strategy class, leaving existing domain services completely untouched!

L • Liskov Substitution Principle (LSP) Contractual Substitutability

Subtypes must be substitutable for their base types without altering system correctness. Python Application: If a base repository method returns a list of entities, a subclass must not return None or raise an unhandled CustomDatabaseError that callers don't catch. Preconditions cannot be tightened (e.g. demanding extra required arguments), and postconditions cannot be weakened.

I • Interface Segregation Principle (ISP) Lean Protocols

Clients should not be forced to depend on methods they do not use. Python Application: Do not create massive monolithic interfaces with 30 methods. Decompose interfaces into lean, client-specific typing.Protocol definitions (e.g. a read-only ReaderProtocol and a write-only WriterProtocol). A report generator only depends on the reader, leaving write dependencies isolated.

D • Dependency Inversion Principle (DIP) Invert Dependencies via Abstractions

High-level business policies should not import low-level database drivers or network clients. Both should depend on abstract protocols. Python Application: Pass dependencies into constructors (__init__) typed as Protocol. In unit tests, inject an in-memory mock repository; in production, inject the PostgreSQL adapter. The domain service never changes!

Warning Track

Architectural Anti-Patterns & Domain Code Smells

❌ The God Object (Monolith Class)

A single 2,500-line class (OrderManager) that validates inputs, calculates taxes, connects to PostgreSQL, charges credit cards via Stripe, sends emails, and generates PDF receipts.

The Fix: Decompose along business boundaries using SRP. Split into OrderAggregate (state & calculations), PaymentGateway, and NotificationService.

❌ The Anemic Domain Model

Treating entities as dumb data bags with zero logic (just plain dictionaries or empty dataclasses), while stuffing all business rules into procedural "Service" functions.

The Fix: Bring behavior back to the data! Business invariants (e.g. order.cancel(), order.add_line()) belong directly inside the entity.

❌ Primitive Obsession

Passing raw strings, floats, and tuples everywhere (def charge(amount: float, curr: str, email: str):) without domain validation.

The Fix: Wrap raw scalars into rich, self-validating Value Objects (Chapter 05): MonetaryAmount, EmailAddress.

❌ The isinstance() Type Ladder

Writing if isinstance(obj, CreditCard): ... elif isinstance(obj, PayPal): ....

The Fix: Violates OCP and Polymorphism! Use dynamic dispatch: define a PaymentProcessor Protocol and simply invoke processor.charge(amount) polymorphically.

Part 04

EntityForge Milestone 13: SOLID Refactoring Implementation

We now assemble Milestone 13 of EntityForge: implementing src/entityforge/core/solid_refactor.py.

We decompose a monolithic order checkout workflow into five cleanly separated, SOLID-compliant modules:

  • SRP: CleanOrderService coordinates order completion without executing payment math, database persistence, or email formatting directly.
  • OCP: Pluggable TaxStrategyProtocol allowing new tax calculations (US Sales Tax vs. EU VAT) to be added without modifying the core order processor.
  • LSP: Concrete payment adapters strictly fulfill the PaymentProcessorProtocol contract, returning consistent transaction IDs or raising domain-safe exceptions.
  • ISP: Separate, lean protocols for payment processing (PaymentProcessorProtocol) and notification emission (ReceiptNotifierProtocol).
  • DIP: CleanOrderService accepts its repository, tax strategy, payment processor, and notification dispatcher via Constructor Dependency Injection.

# EntityForge Core - Clean Architecture & SOLID Invariants (Milestone 13)

from __future__ import annotations
from decimal import Decimal
from typing import Dict, List, Optional, Protocol, runtime_checkable
from entityforge.core.value_object import MonetaryAmount
from entityforge.core.aggregate import OrderAggregate


# ==============================================================================
# 1. Interface Segregation Principle (ISP): Lean, Client-Specific Protocols
# ==============================================================================
@runtime_checkable
class TaxStrategyProtocol(Protocol):
    """Open/Closed Principle (OCP): Pluggable strategy computing order tax."""
    def calculate_tax(self, subtotal: MonetaryAmount) -> MonetaryAmount:
        ...


@runtime_checkable
class PaymentProcessorProtocol(Protocol):
    """Dependency Inversion (DIP): Contract for charging payment sources."""
    def charge(self, amount: MonetaryAmount, source_token: str) -> str:
        """Must return a unique transaction confirmation ID string."""
        ...


@runtime_checkable
class ReceiptNotifierProtocol(Protocol):
    """Single Responsibility (SRP): Decoupled receipt messaging contract."""
    def send_receipt(self, recipient_email: str, order_id: str, total: MonetaryAmount) -> bool:
        ...


# ==============================================================================
# 2. Open/Closed Principle (OCP): Swappable Strategy Implementations
# ==============================================================================
class ZeroTaxStrategy:
    """Tax-exempt strategy returning zero tax."""
    def calculate_tax(self, subtotal: MonetaryAmount) -> MonetaryAmount:
        return MonetaryAmount(amount=0, currency=subtotal.currency)


class FlatRateTaxStrategy:
    """Flat percentage tax strategy (e.g. 20% VAT)."""
    def __init__(self, rate: Decimal) -> None:
        if rate < Decimal("0.0"):
            raise ValueError("Tax rate cannot be negative.")
        self.rate = rate

    def calculate_tax(self, subtotal: MonetaryAmount) -> MonetaryAmount:
        tax_amount = subtotal.amount * self.rate
        return MonetaryAmount(amount=tax_amount, currency=subtotal.currency)


# ==============================================================================
# 3. Liskov Substitution Principle (LSP): Fully Compatible Payment Adapters
# ==============================================================================
class MockPaymentGateway:
    """Test adapter fulfilling PaymentProcessorProtocol contract cleanly."""
    def __init__(self) -> None:
        self.processed_transactions: List[Dict[str, Any]] = []

    def charge(self, amount: MonetaryAmount, source_token: str) -> str:
        if not source_token.startswith("tok_"):
            raise ValueError("Invalid payment token format.")
        
        tx_id = f"TXN_MOCK_{len(self.processed_transactions) + 1}"
        self.processed_transactions.append({"tx_id": tx_id, "amount": amount, "token": source_token})
        return tx_id


class MockReceiptNotifier:
    """Mock notifier fulfilling ReceiptNotifierProtocol."""
    def __init__(self) -> None:
        self.sent_receipts: List[Dict[str, Any]] = []

    def send_receipt(self, recipient_email: str, order_id: str, total: MonetaryAmount) -> bool:
        self.sent_receipts.append({"email": recipient_email, "order_id": order_id, "total": total})
        return True


# ==============================================================================
# 4. Dependency Inversion Principle (DIP) & Single Responsibility (SRP)
# ==============================================================================
class CleanOrderCheckoutService:
    """
    HIGH-LEVEL USE CASE SERVICE:
    Dependencies are injected via constructor typed strictly against Protocols.
    Zero coupling to concrete databases, Stripe APIs, or email daemons!
    """
    def __init__(
        self,
        tax_strategy: TaxStrategyProtocol,
        payment_processor: PaymentProcessorProtocol,
        notifier: ReceiptNotifierProtocol
    ) -> None:
        self._tax_strategy = tax_strategy
        self._payment_processor = payment_processor
        self._notifier = notifier

    def checkout_order(self, order: OrderAggregate, payment_token: str) -> Dict[str, Any]:
        """
        Coordinates the checkout workflow in pure business terms:
        1. Calculate subtotal & apply tax strategy.
        2. Charge payment source.
        3. Dispatch receipt notification.
        """
        subtotal = order.calculate_grand_total()
        tax = self._tax_strategy.calculate_tax(subtotal)
        grand_total = subtotal.add(tax)

        # Charge payment via abstract protocol
        tx_id = self._payment_processor.charge(amount=grand_total, source_token=payment_token)

        # Notify customer
        self._notifier.send_receipt(
            recipient_email=order.customer.email,
            order_id=str(order.id),
            total=grand_total
        )

        return {
            "order_id": str(order.id),
            "subtotal": subtotal,
            "tax": tax,
            "grand_total": grand_total,
            "transaction_id": tx_id
        }

# EntityForge Test Suite - SOLID Principles & Clean Refactoring (Milestone 13)
# ==============================================================================

from decimal import Decimal
import pytest
from entityforge.core.entity import EntityIdentity
from entityforge.core.value_object import MonetaryAmount
from entityforge.core.aggregate import Customer, OrderAggregate
from entityforge.core.solid_refactor import (
    CleanOrderCheckoutService,
    FlatRateTaxStrategy,
    ZeroTaxStrategy,
    MockPaymentGateway,
    MockReceiptNotifier,
    TaxStrategyProtocol,
    PaymentProcessorProtocol,
    ReceiptNotifierProtocol,
)


class TestSOLIDArchitecture:
    """Unit tests asserting Open/Closed strategies, Liskov substitution, and Dependency Injection."""

    def test_structural_protocol_conformance(self):
        # Verify ISP protocols are satisfied structurally without explicit inheritance
        tax_strat = ZeroTaxStrategy()
        assert isinstance(tax_strat, TaxStrategyProtocol)

        gateway = MockPaymentGateway()
        assert isinstance(gateway, PaymentProcessorProtocol)

        notifier = MockReceiptNotifier()
        assert isinstance(notifier, ReceiptNotifierProtocol)

    def test_open_closed_tax_strategy_swapping(self):
        # 1. Setup OrderAggregate ($100.00 subtotal)
        customer = Customer(entity_id=EntityIdentity.generate(), email="alice@solid.io")
        order = OrderAggregate(entity_id=EntityIdentity.generate(), customer=customer, currency="USD")
        order.add_line("SKU-ITEM", MonetaryAmount(100.00, "USD"), quantity=1)

        gateway = MockPaymentGateway()
        notifier = MockReceiptNotifier()

        # 2. Checkout with ZeroTaxStrategy (OCP extension 1)
        zero_tax_service = CleanOrderCheckoutService(
            tax_strategy=ZeroTaxStrategy(),
            payment_processor=gateway,
            notifier=notifier
        )
        res_zero = zero_tax_service.checkout_order(order, payment_token="tok_visa")
        assert res_zero["tax"] == MonetaryAmount(0.00, "USD")
        assert res_zero["grand_total"] == MonetaryAmount(100.00, "USD")

        # 3. Checkout with FlatRateTaxStrategy (20% VAT - OCP extension 2)
        # We extended tax behavior WITHOUT modifying a single line of CleanOrderCheckoutService!
        vat_service = CleanOrderCheckoutService(
            tax_strategy=FlatRateTaxStrategy(rate=Decimal("0.20")),
            payment_processor=gateway,
            notifier=notifier
        )
        res_vat = vat_service.checkout_order(order, payment_token="tok_mastercard")
        assert res_vat["tax"] == MonetaryAmount(20.00, "USD")
        assert res_vat["grand_total"] == MonetaryAmount(120.00, "USD")

    def test_dependency_injection_isolation(self):
        customer = Customer(entity_id=EntityIdentity.generate(), email="bob@solid.io")
        order = OrderAggregate(entity_id=EntityIdentity.generate(), customer=customer, currency="USD")
        order.add_line("SKU-TOOL", MonetaryAmount(50.00, "USD"), quantity=1)

        gateway = MockPaymentGateway()
        notifier = MockReceiptNotifier()
        service = CleanOrderCheckoutService(
            tax_strategy=ZeroTaxStrategy(),
            payment_processor=gateway,
            notifier=notifier
        )

        service.checkout_order(order, payment_token="tok_amex")

        # Injected adapters observed execution independently
        assert len(gateway.processed_transactions) == 1
        assert gateway.processed_transactions[0]["amount"] == MonetaryAmount(50.00, "USD")

        assert len(notifier.sent_receipts) == 1
        assert notifier.sent_receipts[0]["email"] == "bob@solid.io"
