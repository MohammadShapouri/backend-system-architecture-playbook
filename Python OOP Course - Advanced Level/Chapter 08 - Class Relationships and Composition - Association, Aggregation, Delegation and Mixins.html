Computer Science: The Class Relationship Taxonomy

In object-oriented modeling, junior developers often default to inheritance whenever two concepts appear related. This introduces severe coupling. Senior architects classify connections into three distinct structural relationships based on coupling intensity and lifecycle co-dependence:

Part 02

Architecture Invariant: Why "Composition Over Inheritance" is Law

Inheritance is the tightest form of coupling available in object-oriented programming. Subclasses inherit all private implementation quirks, memory layout choices, and internal bugs of their ancestors. In large enterprise systems, deep inheritance hierarchies inevitably run into two famous failure modes:

1. The Fragile Base Class Problem

A base class modifies an internal private method or changes how an attribute is calculated. Unbeknownst to the maintainer, a subclass four levels down in a distant module had overridden a helper method that the base class now relies on.

The entire downstream application breaks silently or crashes at runtime. Base classes cannot easily be modified without risking cascading regressions across every subclass in the codebase.

2. The Gorilla-Banana Problem

Coined by Erlang creator Joe Armstrong:

"The problem with object-oriented languages is they’ve got all this implicit environment that they carry around with them. You wanted a banana, but what you got was a gorilla holding the banana and the entire jungle."

Subclassing a class to reuse a single 10-line calculation method forces you to inherit its database connections, thread pools, file descriptors, and bloated state.

Design Pattern

Delegation & Dynamic Forwarding with __getattr__

Instead of inheriting from a class to gain its methods, encapsulate an instance of it inside your class and delegate calls to it. While explicit delegation (def method(self): return self._inner.method()) is standard, Python enables transparent dynamic delegation via the __getattr__ fallback hook: 

class AuditLoggingProxy:
    def __init__(self, target_service: Any) -> None:
        self._target = target_service  # Encapsulated instance (Composition)

    def __getattr__(self, name: str) -> Any:
        # Intercept attribute access only if not found on proxy:
        attr = getattr(self._target, name)
        if callable(attr):
            def logged_wrapper(*args, **kwargs):
                print(f"AUDIT: Invoking {name} on {self._target.__class__.__name__}")
                return attr(*args, **kwargs)
            return logged_wrapper
        return attr
Part 03

Clean Mixin Architecture: Behavioral Extension Without Coupling

If inheritance is so dangerous, why does Python support multiple inheritance? The answer is Mixins.

A Mixin is a specialized, lightweight class designed strictly to provide reusable behavioral methods across unrelated class hierarchies without representing an independent domain entity.

// The 4 Non-Negotiable Rules of Production Mixins
1. Must Be Strictly Stateless

A mixin should never define an __init__ that allocates new instance attributes. Introducing state variables inside a mixin risks colliding with host class variables!

2. Never Instantiated Standalone

A mixin has no standalone business meaning. You should never write m = AuditableMixin(). It exists exclusively to be mixed into concrete classes.

3. Standard Naming Convention

Always suffix the class name with Mixin (e.g. AuditableMixin, JSONSerializableMixin) to communicate architectural intent to other developers.

4. Cooperative Delegation

If a mixin must participate in lifecycle hooks, it must use super().__init__(**kwargs) with **kwargs propagation to avoid breaking the MRO chain (detailed in Chapter 09).

Part 04

Architectural Decision Matrix: Choosing the Right Relationship

When connecting classes, evaluate your requirements against this production decision matrix:

Pattern Coupling Degree Lifecycle Dependence When to Choose
Composition High (Internal) Strictly Co-Dependent DDD Aggregate Roots owning child entities (Order → LineItems). Child has no meaning without the parent.
Aggregation Medium (Reference) Independent Container referencing external entities (Order → Customer, Department → Employees).
Mixin Low (Behavioral) Stateless Hook Reusing pure cross-cutting behavioral methods (audit logging, JSON serialization, diagnostic dumps) across unrelated types.
Delegation Proxy Low (Encapsulated) Independent Wrapper Wrapping third-party services, transparent caching, access control, and dynamic protocol routing via __getattr__.
Subclass Inheritance Extreme (Tightest) Tightly Bound Strictly for Liskov-compliant subtype polymorphism or framework base classes (e.g. BaseEntity, MutableSequence). Avoid for simple code reuse!

# ==============================================================================
# EntityForge Core - Aggregate Roots, Composition & Mixins (Milestone 08)
# ==============================================================================

from __future__ import annotations
import time
from decimal import Decimal
from typing import Any, Dict, List, Optional
from entityforge.core.entity import BaseEntity, EntityIdentity
from entityforge.core.value_object import MonetaryAmount


class AuditableMixin:
    """
    CLEAN STATELESS MIXIN:
    Provides domain event logging behavior across unrelated classes.
    Rule: Never defines an __init__ assigning instance attributes to prevent state collisions!
    """
    def record_audit_event(self, event_name: str, metadata: Optional[Dict[str, Any]] = None) -> Dict[str, Any]:
        """Pure behavioral method formatting a standardized audit log entry."""
        entity_id = getattr(self, "id", "UNKNOWN")
        entry = {
            "entity_id": str(entity_id),
            "entity_class": self.__class__.__name__,
            "event": event_name,
            "timestamp": time.time(),
            "metadata": metadata or {}
        }
        return entry


class OrderLine(BaseEntity):
    """
    COMPOSITION TARGET (Child Entity):
    Holds item details and quantity. Lifecycle is strictly owned by OrderAggregate.
    """
    def __init__(
        self,
        entity_id: EntityIdentity,
        product_sku: str,
        unit_price: MonetaryAmount,
        quantity: int
    ) -> None:
        super().__init__(entity_id=entity_id)
        if quantity <= 0:
            raise ValueError("Quantity must be strictly positive.")
        self.product_sku = product_sku
        self.unit_price = unit_price
        self.quantity = quantity

    @property
    def total_price(self) -> MonetaryAmount:
        """Calculates total line cost: unit_price * quantity."""
        line_total = self.unit_price.amount * Decimal(self.quantity)
        return MonetaryAmount(amount=line_total, currency=self.unit_price.currency)


class Customer(BaseEntity):
    """
    AGGREGATION TARGET (Independent Entity):
    Exists completely independently of any specific order.
    """
    def __init__(self, entity_id: EntityIdentity, email: str) -> None:
        super().__init__(entity_id=entity_id, email=email)
        self.email = email


class OrderAggregate(BaseEntity, AuditableMixin):
    """
    DDD AGGREGATE ROOT:
    1. Composition: Owns the lifecycle of internal OrderLine entities (_lines).
    2. Aggregation: References an external Customer entity (_customer).
    3. Behavioral Extension: Mixes in AuditableMixin for audit generation.
    """
    def __init__(
        self,
        entity_id: EntityIdentity,
        customer: Customer,
        currency: str = "USD"
    ) -> None:
        super().__init__(entity_id=entity_id)
        # AGGREGATION: References existing external customer
        self._customer: Customer = customer
        self._currency: str = currency
        # COMPOSITION: Private child entity list owned exclusively by this root
        self._lines: List[OrderLine] = []
        self._is_cancelled: bool = False

    @property
    def customer(self) -> Customer:
        """Returns the aggregated customer reference."""
        return self._customer

    @property
    def lines(self) -> List[OrderLine]:
        """DEFENSIVE COPY: Prevents external callers from mutating _lines directly!"""
        return self._lines.copy()

    def add_line(self, product_sku: str, unit_price: MonetaryAmount, quantity: int) -> OrderLine:
        """
        COMPOSITION INVARIANT:
        The Aggregate Root alone controls the instantiation and attachment of child entities.
        """
        if self._is_cancelled:
            raise RuntimeError("Cannot add items to a cancelled order.")
        if unit_price.currency != self._currency:
            raise ValueError(f"Price currency '{unit_price.currency}' does not match order currency '{self._currency}'")

        line_id = EntityIdentity.generate()
        new_line = OrderLine(entity_id=line_id, product_sku=product_sku, unit_price=unit_price, quantity=quantity)
        self._lines.append(new_line)
        return new_line

    def calculate_grand_total(self) -> MonetaryAmount:
        """Calculates sum across all composed line items."""
        total = MonetaryAmount(amount=0, currency=self._currency)
        for line in self._lines:
            total = total.add(line.total_price)
        return total

    def cancel_order(self) -> None:
        """
        LIFECYCLE CASCADE:
        Cancelling the aggregate destroys/clears composed child line items.
        Notice that the aggregated Customer remains completely unharmed!
        """
        self._is_cancelled = True
        self._lines.clear()


class DelegatedRepositoryProxy:
    """
    DYNAMIC FORWARDING PROXY:
    Encapsulates an underlying repository instance via composition.
    Uses __getattr__ to dynamically delegate calls while auditing execution latency.
    """
    def __init__(self, repository: Any) -> None:
        self._repo = repository
        self.forwarded_call_count: int = 0

    def __getattr__(self, name: str) -> Any:
        """Dynamically intercepts and forwards missing methods to the internal repo."""
        target_attr = getattr(self._repo, name)
        if callable(target_attr):
            def proxy_wrapper(*args: Any, **kwargs: Any) -> Any:
                self.forwarded_call_count += 1
                return target_attr(*args, **kwargs)
            return proxy_wrapper
        return target_attr

class FakeDatabaseRepository:
    """Mock storage class used to test dynamic __getattr__ delegation."""
    def save_aggregate(self, agg_id: str) -> str:
        return f"SAVED_{agg_id}"

    def ping(self) -> bool:
        return True


class TestClassRelationshipsAndComposition:
    """Unit tests asserting composition lifecycle cascading, aggregation, and delegation."""

    def test_composition_lifecycle_cascades_on_order_cancel(self):
        # 1. Aggregation: Customer has independent existence
        cust_id = EntityIdentity.generate()
        customer = Customer(entity_id=cust_id, email="alice@example.com")

        # 2. Composition: OrderAggregate owns internal OrderLines
        order_id = EntityIdentity.generate()
        order = OrderAggregate(entity_id=order_id, customer=customer, currency="USD")

        order.add_line("SKU-PYTHON-BOOK", MonetaryAmount(50.00, "USD"), quantity=2)
        order.add_line("SKU-STICKER-PACK", MonetaryAmount(10.00, "USD"), quantity=5)

        assert len(order.lines) == 2
        assert order.calculate_grand_total() == MonetaryAmount(150.00, "USD")

        # 3. Cancel order: Composed lines are destroyed/cleared
        order.cancel_order()
        assert len(order.lines) == 0

        # 4. AGGREGATION INVARIANT:
        # The aggregated Customer remains completely intact and unaffected by order cancellation!
        assert customer.email == "alice@example.com"
        assert customer.id == cust_id

    def test_defensive_copy_protects_composition_encapsulation(self):
        customer = Customer(entity_id=EntityIdentity.generate(), email="bob@test.io")
        order = OrderAggregate(entity_id=EntityIdentity.generate(), customer=customer)
        order.add_line("SKU-A", MonetaryAmount(10.00, "USD"), 1)

        # External caller attempts to mutate internal lines via returned list
        leaked_lines = order.lines
        leaked_lines.clear()  # Mutates the returned copy!

        # Aggregate Root encapsulation holds firm!
        assert len(order.lines) == 1

    def test_stateless_mixin_behavior_injection(self):
        customer = Customer(entity_id=EntityIdentity.generate(), email="charlie@test.io")
        order = OrderAggregate(entity_id=EntityIdentity.generate(), customer=customer)

        # AuditableMixin method available directly on OrderAggregate
        audit = order.record_audit_event("ORDER_PLACED", metadata={"ip": "127.0.0.1"})

        assert audit["entity_class"] == "OrderAggregate"
        assert audit["event"] == "ORDER_PLACED"
        assert audit["metadata"]["ip"] == "127.0.0.1"

    def test_dynamic_delegation_proxy_forwarding(self):
        fake_db = FakeDatabaseRepository()
        proxy = DelegatedRepositoryProxy(repository=fake_db)
        assert proxy.forwarded_call_count == 0

        # Method call forwarded dynamically via __getattr__
        result = proxy.save_aggregate("AGG-101")
        assert result == "SAVED_AGG-101"
        assert proxy.forwarded_call_count == 1

        assert proxy.ping() is True
        assert proxy.forwarded_call_count == 2
Warning Track

Beginner Pitfalls & Architectural Anti-Patterns

❌ State Pollution in Mixins

Defining an __init__ inside a mixin that assigns self.data = [] or self.status = "INIT".

Why this causes bugs: If the host class (or another mixin) also uses the common attribute name self.data, the mixin silently overwrites the domain model's data during initialization! Mixins must remain strictly stateless behavioral extensions.

❌ Leaking Internal Composed References

Writing @property def lines(self): return self._lines returning the live internal list.

Why this breaks encapsulation: Returning the direct reference to an internal composed collection allows external callers to bypass aggregate root validation rules by running order.lines.append(invalid_item) directly. Always return a defensive shallow copy: return self._lines.copy().

❌ The "God Class" Deep Inheritance Hierarchy

Constructing trees like: Order → Entity → Model → DatabaseRecord → Serializable → Object.

Why this causes architectural gridlock: Deep inheritance trees ($> 3$ levels) couple domain models tightly to database drivers, serialization protocols, and validation frameworks. If one base class changes its method signatures, distant subclasses shatter. Refactor to composition: an Order has a repository, it is not a database record.

❌ Unconditional Delegation Loops in __getattr__

Writing def __getattr__(self, name): return getattr(self._target, name) when self._target was never initialized.

Why this triggers infinite recursion: If an exception occurs before self._target is assigned in __init__, evaluating self._target inside __getattr__ calls __getattr__ again to find _target, looping infinitely until Python crashes!
