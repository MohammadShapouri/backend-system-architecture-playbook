Part 01

Computer Science: CPython Type Geometry & The Type Pyramid

In many compiled languages (such as C++ or Java), classes are compile-time constructs that vanish or reduce to static metadata tables in the binary. In Python, classes are full first-class objects residing on the heap at runtime.

Every entity in Python—integers, functions, strings, custom instances, and even class definitions themselves—is allocated as a variation of the C struct PyObject. At the C level, every object contains at minimum two fields:

1. ob_refcnt (Reference Count) An 8-byte signed integer tracking how many references point to this object. Drives CPython's immediate memory deallocation when reaching 0.
2. ob_type (Type Pointer) An 8-byte pointer addressing the object's class (a PyTypeObject), which defines the object's methods, memory size, and behavior.

The Foundational Type Invariant:

Python's entire object model rests on a profound circularity: object is the root of the inheritance tree (every class inherits from object), while type is the root of the instance tree (every class is an instance of type). Crucially, type subclasses object, and object is an instance of type.

Part 02

Under the Hood: Namespaces & Descriptor Method Binding

When you write user.execute(), how does Python locate the method and pass user as the first argument (self)?

Methods are not stored inside instance dictionaries. They live as plain functions in the class dictionary (User.__dict__). Python uses the Descriptor Protocol to dynamically bind functions to instances at runtime:

Runtime Mechanics

The Descriptor Transformation of a Bound Method

In Python, every standard function object implements the descriptor method __get__(). When an attribute lookup retrieves a function through an instance, CPython executes:

# 1. Developer syntax:
user.execute(42)
# 2. What CPython evaluates under the hood:
func = User.__dict__["execute"]
bound_method = func.__get__(user, User) # Returns a PyMethodObject
bound_method(42) # In turn calls: func(user, 42)

A Bound Method is simply a lightweight wrapper storing two pointers: __self__ (pointing to the instance) and __func__ (pointing to the raw underlying function).

Method Varieties: Instance vs. Class vs. Static Methods

1. Instance Method def method(self, ...)

Binding: Automatically receives the instance as self.
Role: Inspects and mutates unique instance state (self.__dict__).
Use case: 90% of domain business logic.

2. @classmethod def factory(cls, ...)

Binding: Automatically receives the class object as cls.
Role: Alternative constructors and polymorphic factory patterns that correctly instantiate subclasses.
Use case: from_dict(), from_json().

3. @staticmethod def sanitize(...)

Binding: Strips automatic first-argument binding completely.
Role: Pure isolated utility logic grouped under the class namespace for logical cohesion.
Use case: Validation helpers, string formatting.

Part 03

Core Invariants: Identity (`is`) vs. Value Equality (`==`)

In Domain-Driven Design (DDD) and production object architecture, distinguishing between an Entity (defined by unique lifetime identity) and a Value Object (defined solely by its internal attribute values) is foundational.

Identity Comparison: is Pointer Equality

Evaluates whether two variables point to the exact same memory address in RAM:

a is b ⇔ id(a) == id(b)

Bypasses all method calls. In CPython, it compiles directly to the bytecode instruction COMPARE_OP (is), comparing two C pointers in a single CPU cycle.

Value Equality: == Semantic Equality

Evaluates whether two distinct objects share the same semantic state or value:

a == b ⇔ type(a).__eq__(a, b)

Delegates execution to the __eq__ dunder method. Two completely separate objects located at different memory addresses can evaluate as equal if their attributes match.

1. Production Core: src/entityforge/core/entity.py Domain Metamodel & Entity Identity 
# ==============================================================================
# EntityForge Core - Domain Metamodel & Entity Identity (Milestone 01)
# ==============================================================================

from __future__ import annotations
import uuid
import time
from dataclasses import dataclass
from typing import Any, Dict, Optional, Self, final, override


@dataclass(frozen=True)
class EntityIdentity:
    """
    IMMUTABLE VALUE OBJECT:
    Represents the unique domain identity of an entity.
    Equivalence is determined purely by the raw UUID value.
    """
    value: uuid.UUID
    created_at: float

    @classmethod
    def generate(cls) -> Self:
        """Alternative named constructor generating a fresh cryptographically secure UUIDv4."""
        return cls(value=uuid.uuid4(), created_at=time.time())

    @classmethod
    def from_string(cls, raw_uuid: str) -> Self:
        """Parses an existing UUID string into a strongly typed EntityIdentity."""
        parsed = uuid.UUID(raw_uuid)
        return cls(value=parsed, created_at=time.time())

    @override
    def __str__(self) -> str:
        return str(self.value)


class BaseEntity:
    """
    FOUNDATIONAL DOMAIN ENTITY METAMODEL:
    Governs entity identity, dual-namespace isolation, polymorphic factory
    constructors, and diagnostic representations across all domain models.
    """
    # Class-level schema attribute: Shared across all instances of this type
    __schema_version__: int = 1

    def __init__(self, entity_id: EntityIdentity, **attributes: Any) -> None:
        # Private identity pointer: Encapsulated and protected from accidental mutation
        self._entity_id: EntityIdentity = entity_id
        # Assign instance state: Injected directly into instance __dict__
        for key, val in attributes.items():
            setattr(self, key, val)

    @property
    @final
    def id(self) -> EntityIdentity:
        """
        PEP 591 @final Guard:
        Subclasses must NEVER override or tamper with the entity identity accessor!
        """
        return self._entity_id

    @classmethod
    def create_new(cls, **attributes: Any) -> Self:
        """
        FACTORY CONSTRUCTOR:
        Allocates a fresh UUID identity and instantiates cls polymorphically.
        Using cls(...) guarantees subclasses instantiate their own type, not BaseEntity!
        """
        fresh_id = EntityIdentity.generate()
        return cls(entity_id=fresh_id, **attributes)

    @classmethod
    def from_payload(cls, payload: Dict[str, Any]) -> Self:
        """Deserialization factory reconstructing an entity from a dictionary payload."""
        raw_id = payload.get("id")
        if not raw_id:
            raise ValueError("Payload must contain an 'id' attribute.")

        identity = EntityIdentity.from_string(str(raw_id))
        clean_attrs = {k: v for k, v in payload.items() if k != "id"}
        return cls(entity_id=identity, **clean_attrs)

    @staticmethod
    def sanitize_identifier(name: str) -> str:
        """
        STATIC UTILITY HELPER:
        Operates without 'self' or 'cls'. Scoped under BaseEntity for logical cohesion.
        Strips whitespace and enforces lowercase alphanumeric normalization.
        """
        if not isinstance(name, str):
            raise TypeError("Identifier must be a string.")
        cleaned = name.strip().lower()
        if not cleaned:
            raise ValueError("Identifier cannot be empty.")
        return cleaned

    @override
    def __eq__(self, other: object) -> bool:
        """
        DOMAIN ENTITY EQUALITY INVARIANT:
        Two entities are identical if and only if they share the exact same EntityIdentity,
        even if their mutable state attributes currently diverge!
        """
        if not isinstance(other, BaseEntity):
            return NotImplemented
        return self._entity_id == other._entity_id

    @override
    def __repr__(self) -> str:
        """Diagnostic representation displaying class name, ID, and schema version."""
        class_name = self.__class__.__name__
        return f"<{class_name} id={self._entity_id.value} schema_v={self.__schema_version__}>"
2. Unit Test Battery: tests/unit/test_entity.py Identity, Namespaces & Method Binding Assertions 
# ==============================================================================
# EntityForge Test Suite - Entity Metamodel & Identity Verification (Milestone 01)
# ==============================================================================

import uuid
import pytest
from entityforge.core.entity import BaseEntity, EntityIdentity


class UserEntity(BaseEntity):
    """Concrete domain entity subclass used to verify polymorphic instantiation."""
    __schema_version__: int = 2


class TestBaseEntityArchitecture:
    """Unit tests asserting identity contracts, dual namespaces, and method bindings."""

    def test_identity_equality_vs_pointer_identity(self):
        fixed_uuid = uuid.uuid4()
        id1 = EntityIdentity(value=fixed_uuid, created_at=100.0)
        id2 = EntityIdentity(value=fixed_uuid, created_at=200.0)

        # 1. id1 and id2 are separate objects in memory (different pointers)
        assert id1 is not id2

        # 2. But they evaluate as semantically equal because their UUID value matches
        assert id1 == id2

        # 3. Two separate entity instances sharing the same ID evaluate as equal (Entity Identity Invariant)
        user_a = UserEntity(entity_id=id1, username="alice", role="analyst")
        user_b = UserEntity(entity_id=id2, username="alice_mutated", role="admin")

        assert user_a is not user_b  # Distinct instances
        assert user_a == user_b      # Equal by domain entity identity!

    def test_dual_namespace_isolation(self):
        # Class attribute resides in Class.__dict__, NOT instance.__dict__
        user = UserEntity.create_new(username="bob")

        # Instance namespace holds instance state
        assert "username" in user.__dict__
        assert user.__dict__["username"] == "bob"

        # Class attribute is accessible via instance, but resides on UserEntity
        assert user.__schema_version__ == 2
        assert "__schema_version__" not in user.__dict__
        assert "__schema_version__" in UserEntity.__dict__

    def test_polymorphic_classmethod_constructor(self):
        # Factory method called on subclass must instantiate the subclass, NOT BaseEntity!
        user = UserEntity.create_new(username="charlie")

        assert isinstance(user, UserEntity)
        assert isinstance(user, BaseEntity)
        assert user.__class__ is UserEntity
        assert user.username == "charlie"
        assert isinstance(user.id, EntityIdentity)

    def test_classmethod_from_payload_deserialization(self):
        raw_uuid = str(uuid.uuid4())
        payload = {"id": raw_uuid, "username": "dave", "tier": "enterprise"}

        user = UserEntity.from_payload(payload)
        assert str(user.id) == raw_uuid
        assert user.username == "dave"
        assert user.tier == "enterprise"

    def test_staticmethod_sanitization_helper(self):
        cleaned = BaseEntity.sanitize_identifier("   Tenant_Alpha_99   ")
        assert cleaned == "tenant_alpha_99"

        with pytest.raises(TypeError):
            BaseEntity.sanitize_identifier(12345)

        with pytest.raises(ValueError):
            BaseEntity.sanitize_identifier("    ")
Warning Track

Beginner Pitfalls & Architectural Anti-Patterns

❌ Mutable Class Attribute State Leak

Declaring class User: roles = [] and appending via self.roles.append(r).

Why this causes severe bugs: roles is allocated once on the class dictionary. Mutating it modifies the list for every single instance across the entire system! User B will inherit User A's administrative permissions! Fix: Initialize mutable collections inside __init__(): self.roles = [].

❌ Conflating 'is' with '==' on Literals

Writing if status is "ACTIVE": ... or if count is 1000: ....

Why this fails intermittently: is compares memory pointers, not string or integer values. CPython interns small integers ($-5$ to $256$) and some strings, making is appear to work in trivial tests, but it fails silently on larger numbers or dynamically computed strings! Use == for values, reserving is strictly for None or sentinel checks.

❌ Hardcoding Concrete Class in @classmethod

Writing return BaseEntity(...) inside a @classmethod factory constructor.

Why this breaks polymorphism: If a downstream developer subclasses class User(BaseEntity): and calls User.create_new(), hardcoding BaseEntity(...) returns an instance of the base class, discarding all subclass methods! Always call cls(...).

❌ Overusing @staticmethod for Domain Logic

Packing an entire module of unrelated business procedures as static methods inside a dummy class: class Utils: @staticmethod ....

Why this is unpythonic: Python is not Java. Python files are already modules that serve as namespaces. If a function does not need access to self or cls and is used across multiple domains, write it as a clean, top-level function in a dedicated utility module.
