A Index

Active-Active vs. Active-Passive

High Availability • Ch. 6

Disaster recovery topologies. In Active-Active, all nodes or datacenters actively serve production traffic concurrently, requiring conflict resolution. In Active-Passive, a primary cluster serves traffic while a hot-standby node syncs state, activating only upon primary failure.

Anycast (BGP Anycast Routing)

Edge Networking • Ch. 4

A global routing technique where multiple physical edge Points of Presence (PoPs) broadcast the exact same IP address via BGP. Client packets are routed to the topologically nearest datacenter, minimizing RTT and naturally diluting volumetric DDoS floods.

Asyncio Event Loop

Concurrency • Ch. 14

A single-threaded, cooperative multitasking runtime that registers sockets with the OS kernel (via `epoll`/`kqueue`). Delivers 50,000+ concurrent I/O connections per node, but freezes entirely if blocking synchronous CPU tasks or `time.sleep()` are executed.

At-Least-Once Delivery

Messaging • Ch. 14, 15

A message delivery guarantee where the broker redelivers a record until an explicit positive acknowledgment (ACK) is received. Guarantees no data loss, but mandates that consumer processing logic be strictly idempotent to prevent duplicate execution.

Availability ($A$)

SRE • Ch. 6

The probability that a system is operational at a given point in time: $A = \frac{\text{MTTF}}{\text{MTTF} + \text{MTTR}}$. Measured in "Nines" (e.g. 99.9% permits 43.8 minutes of downtime/month; 99.999% permits only 26.3 seconds/month).

B Index

Backpressure

Queue Physics • Ch. 14

A flow-control mechanism where a downstream consumer signals an upstream producer to throttle, pause, or drop ingress when buffer capacity limits are breached, preventing out-of-memory (OOM) crashes.

Back-of-the-Envelope Estimation

Capacity Math • Ch. 2

Order-of-magnitude calculations used by system architects to size QPS, storage accrual, network bandwidth, and memory budgets before selecting specific database engines or provisioning clusters.

Blast Radius

Fault Isolation • Ch. 6

The maximum scope of functional damage or customer disruption that occurs when a specific component, zone, or poison pill fails. Minimized via Cell-Based Architectures and Shuffle Sharding.

Bloom Filter

Storage Physics • Ch. 9

A space-efficient probabilistic data structure that tests set membership. False positives are possible, but false negatives are mathematically impossible. Used in LSM-trees (RocksDB) to skip scanning SSTable files on disk for missing keys.

Brooker, Marc (Author / Engineer)

Seminal Author • Ch. 14

AWS Distinguished Engineer who published the definitive mathematical proof showing that Full Jitter ($T_{\text{sleep}} = \text{random}(0, \min(T_{\text{max}}, T_{\text{base}} \times 2^{\text{attempt}}))$ maximizes client spread and flattens thundering herd retry avalanches.

B-Tree (Balanced Tree Storage)

Storage Physics • Ch. 9

A self-balancing search tree organizing data into fixed-size pages (typically 4KB–16KB) on disk. Delivers $O(\log N)$ predictable reads, but incurs high Write Amplification Factors (WAF) due to random in-place page rewrites.

Bulkhead

Resilience • Ch. 14

A stability pattern that partitions execution resources into isolated pools or semaphores so that a failure or slowdown in one non-critical dependency (e.g. PDF generation) cannot exhaust thread pools needed by core workflows (e.g. order dispatch).

Burn Rate (Error Budget)

SRE • Ch. 6

The rate at which a service consumes its allowed error budget: $\text{Burn Rate} = \frac{\text{Observed Error Rate}}{\text{Allowed Error Rate}}$. A burn rate of 1.0 consumes 100% of the monthly budget in 30 days; a burn rate of 14.4x consumes 2% in 1 hour, triggering on-call escalation.

C Index

Cache-Aside (Lazy Loading)

Caching • Ch. 12

An architectural caching pattern where the application reads from cache first; upon a cache miss, it reads from the database, writes the entry to the cache, and returns. Writes modify the database and invalidate the cache key.

Cache Avalanche

Failure Mode • Ch. 12

A catastrophic failure mode occurring when thousands of cached keys share the exact same TTL and expire at the identical second, sending a massive traffic tsunami to the primary database. Mitigated by applying **TTL Jitter**.

Cache Penetration

Failure Mode • Ch. 12

A failure mode where queries for non-existent IDs (e.g. `user_id = -9999`) bypass the cache and hit the database every time because no cache entry exists. Defended via **Bloom Filters** or caching null sentinels with short TTLs.

Cache Stampede (Dogpiling)

Failure Mode • Ch. 12

When a heavily queried hot key expires, thousands of concurrent requests miss simultaneously and hammer the primary database to recompute it. Neutralized via **SingleFlight request coalescing** or the **XFetch probabilistic algorithm**.

CAP Theorem (Brewer's Theorem)

Distributed Theory • Ch. 1, 16

Formulated by Eric Brewer. States that a distributed data store can simultaneously provide at most two of three guarantees: Consistency (C), Availability (A), and Partition Tolerance (P). Because network partitions ($P$) cannot be avoided, systems must choose between $CP$ and $AP$.

Cell-Based Architecture

Resilience • Ch. 6

An enterprise scaling pattern where traffic is partitioned into self-contained, independent "cells" (complete micro-deployments of compute and storage). A catastrophic failure or poison pill inside Cell 42 bounds the blast radius to $1/N$ of the user fleet.

Change Data Capture (CDC)

Data Architecture • Ch. 11, 15

A pipeline (e.g. Debezium) tailing a database's Write-Ahead Log (WAL) to emit committed row changes as an event stream, enabling asynchronous fan-out to search indexes, caches, and analytics stores without dual-write race hazards.

Circuit Breaker

Resilience • Ch. 14

A finite state machine wrapper (`CLOSED` → `OPEN` → `HALF_OPEN`) intercepting calls to volatile remote dependencies. Upon reaching a failure threshold, it trips open to fail fast in 0.1ms without calling the network, granting the downstream service breathing room to recover.

ClickHouse (Columnar OLAP)

Database Engines • Ch. 9, 11

A column-oriented analytical database storing data in contiguous column arrays rather than row tuples. Leverages vectorized SIMD CPU instructions and aggressive LZ4/ZSTD compression to scan billions of rows per second for analytical dashboards and pricing heatmaps.

Connection Draining (Graceful Shutdown)

Ingress • Ch. 5

The process where a load balancer stops routing new requests to a decommissioning backend instance while granting in-flight requests a grace window (e.g. 30 seconds) to complete, preventing 502/504 errors during rolling software deployments.

Connection Pooling (PgBouncer / HikariCP)

Database Scaling • Ch. 10

A caching tier for database connections. Eliminates the expensive cost of forking OS processes on PostgreSQL. Pools are mathematically sized via: $\text{Pool} = (2 \times \text{Cores}) + \text{Disk Spindles}$.

Consistent Hashing

Sharding • Ch. 10

A distributed hashing algorithm mapping partition keys and server nodes to a 32-bit circular ring. When scaling the cluster, adding a shard moves only $K/N$ keys from its immediate neighbor, leaving the rest of the cluster untouched.

CQRS (Command Query Responsibility Segregation)

Data Architecture • Ch. 15

An architectural pattern that divides data access into separate Command (Write) models enforcing domain invariants and Query (Read) models serving denormalized views, allowing each to be scaled independently.

D Index

Dead Letter Queue (DLQ)

Messaging • Ch. 14

A secondary holding queue where messages that repeatedly fail processing (poison pills) are quarantined after exhausting max retry attempts, preventing crash loops from blocking healthy tasks.

Direct Server Return (DSR)

Networking • Ch. 5

An L4 load balancing optimization where incoming packets pass through the load balancer (which rewrites the destination MAC address), but backend servers route response packets directly back to the client, bypassing the load balancer on egress.

Distributed Lock

Coordination • Ch. 13

A synchronization primitive providing mutual exclusion across separate network processes. Must be paired with monotonic **Fencing Tokens** to prevent zombie clients from writing after a GC pause.

Distributed Tracing

Observability • Ch. 19

A telemetry method tracking the lifecycle of an execution request across multiple microservices via a Directed Acyclic Graph (DAG) of Spans linked by a unified `Trace-ID`.

Double-Entry Bookkeeping

Financial Systems • Ch. 17

An immutable accounting system where every transaction requires at least two balanced postings such that $\sum \text{Debits} - \sum \text{Credits} = 0$. Eliminates mutable single-column balances and ensures complete financial provenance.

Dual-Write Problem

Failure Mode • Ch. 11, 16

An architectural vulnerability where an application synchronously mutates two independent storage systems (e.g. PostgreSQL and Kafka). If an unhandled failure occurs between writes, the stores diverge permanently.

E Index

Envoy Proxy

Ingress • Ch. 5

A high-performance C++ distributed edge and service proxy created by Lyft. Features dynamic configuration (xDS APIs), passive outlier detection, and Peak-EWMA load balancing.

Error Budget

SRE • Ch. 6

The fraction of unreliability a service is allowed to tolerate over a rolling time window: $\text{Error Budget} = 1.0 - \text{SLO}$. Governs the balance between feature release velocity and reliability freezes.

Event Sourcing

Data Architecture • Ch. 15

An architectural pattern persisting the state of a business entity as an append-only log of immutable historical events rather than executing destructive updates. Entity state is rehydrated by replaying the event stream.

F Index

Fallacies of Distributed Computing

Theory • Ch. 14

A set of 8 false assumptions articulated by L. Peter Deutsch and James Gosling that junior engineers inevitably make: The network is reliable; Latency is zero; Bandwidth is infinite; The network is secure.

False Sharing

Hardware Physics • Ch. 3

A performance degradation occurring when two independent threads on different CPU cores modify distinct variables that happen to sit on the same 64-byte hardware cache line, forcing constant cache invalidation and bus ping-ponging.

Fencing Token

Coordination • Ch. 13

A monotonically increasing integer counter issued by a distributed lock manager. The storage layer rejects any write carrying a token lower than the highest token previously committed, neutralizing zombie client writes.

Four Golden Signals (Google SRE)

Observability • Ch. 19

The four essential metrics for monitoring user-facing systems: Latency (time to service requests), Traffic (demand placed on the system), Errors (rate of failed requests), and Saturation (how full the system is).

G Index

Graph Database (Index-Free Adjacency)

Database Engines • Ch. 11

A specialized storage engine where nodes contain direct memory pointers to neighboring nodes. Traversing relationships is $O(1)$ constant time per hop, outperforming SQL joins for multi-hop fraud detection.

H Index

Head-of-Line (HoL) Blocking

Failure Mode • Ch. 8, 14

A bottleneck where the first item in a sequence or single dropped packet stalls the processing or transmission of all subsequent items. Solved in networking via HTTP/3 (QUIC) and in queuing via Dead Letter Queues.

High Cardinality (Metrics Trap)

Observability • Ch. 19

The danger of adding high-entropy labels (such as `user_id` or `order_id`) to Prometheus metrics. Every unique combination allocates a separate time-series in RAM, leading to memory exhaustion.

I Index

Idempotency

API Design • Ch. 16, 17

The property of an operation whereby applying it multiple times produces the identical result as applying it once: $f(f(x)) = f(x)$. Enforced using persistent unique **Idempotency Keys** to prevent double-charging on network retries.

IOPS (I/O Operations Per Second)

Storage Hardware • Ch. 2, 9

The standard performance benchmark measuring how many distinct read or write operations a physical drive handles per second (HDD: ~100 IOPS; SATA SSD: ~80k IOPS; NVMe SSD: ~500k–1M+ IOPS).

J Index

Jeff Dean's Latency Numbers

Hardware Constants • Ch. 3

The classic baseline constants of computer hardware: L1 Cache ($0.5\text{ ns}$), RAM ($100\text{ ns}$), NVMe SSD ($1\text{ ms}$), Datacenter RTT ($0.5\text{ ms}$), Cross-Continental WAN RTT ($150\text{ ms}$).

Jitter (Full Jitter)

Resilience • Ch. 14

The introduction of randomness into exponential backoff calculations: $T_{\text{sleep}} = \text{random}(0, \text{backoff})$. Disperses retry waves across time to eliminate synchronized thundering herd spikes.

K Index

Kafka (Apache Kafka / KRaft)

Stream Processing • Ch. 15

A distributed, partitioned, replicated commit log service. Decouples producers and consumers, exploits the Linux Page Cache and `sendfile` zero-copy I/O, and coordinates via KRaft consensus.

Kleppmann, Martin (Author / Researcher)

Seminal Author • Ch. 13

Cambridge researcher and author of Designing Data-Intensive Applications (DDIA). Published the definitive critique of Redis Redlock, proving that distributed locks require monotonic **Fencing Tokens** at the storage layer.

Kreps, Jay (Author / Engineer)

Seminal Author • Ch. 15

Co-creator of Apache Kafka and CEO of Confluent. Author of "The Log: What every software engineer should know about real-time data's unifying abstraction", formalizing the distinction between destructive queues and immutable commit logs.

L Index

L4 vs. L7 Load Balancing

Ingress • Ch. 5

Layer 4 routes raw TCP/UDP packets based on IP/port without payload inspection (ultra-high Mpps throughput). Layer 7 terminates TLS, parses HTTP headers/paths/cookies, and manages content-based routing at higher CPU cost.

Little's Law ($L = \lambda \times W$)

Capacity Math • Ch. 2

A mathematical queuing theorem stating that the average number of concurrent requests in flight ($L$) equals the arrival rate ($\lambda$) multiplied by the average latency ($W$). Sizes active socket tables and thread pools.

LSM-Tree (Log-Structured Merge-Tree)

Storage Physics • Ch. 9

A write-optimized storage architecture buffering mutations into an in-memory sorted structure (MemTable) and sequential WAL, later flushed to immutable SSTable files on disk. Delivers 10x higher write throughput than B-Trees.

Long-Polling (Hanging GET)

Protocols • Ch. 8

A real-time fallback mechanism where a client sends an HTTP request that the server holds open until an event occurs or a timeout expires. The client immediately reconnects upon receiving data.

M Index

Maglev (Google L4 Director)

Load Balancing • Ch. 5

Google’s software-defined Layer 4 network load balancer deployed on commodity Linux servers. Utilizes a specialized consistent hashing lookup table and Direct Server Return (DSR) to route packets at wirespeed.

Modular Monolith

Architecture Evolution • Ch. 18

An architectural design pattern where code is structured into strictly bounded, encapsulated domain modules with private data access, deployed together as a single unified artifact. Delivers in-process call speed with clean team boundaries.

MTTR vs. MTTD

SRE • Ch. 19

Mean Time to Detect (MTTD) measures the duration between an outage starting and alerts firing. Mean Time to Repair (MTTR) measures the duration from alert triage to production mitigation.

N Index

N+1 Network Hop Trap (Chatty Services)

Anti-Pattern • Ch. 3

A distributed anti-pattern where servicing a single user request causes a service to execute $N$ sequential synchronous RPC calls over the network to fetch related items, compounding network latency ($N \times 15\text{ms}$).

Non-Functional Requirements (NFRs)

Requirements • Ch. 1

The quantitative criteria and quality attributes that govern system architecture (latency budgets, availability targets, durability guarantees, compliance constraints), as opposed to functional user features.

Nygard, Michael T. (Author)

Seminal Author • Ch. 14

Author of the industry-defining book Release It! Design and Deploy Production-Ready Software (2007). Established the **Circuit Breaker** and **Bulkhead** patterns to prevent cascading failures in distributed environments.

O Index

Offset Management

Streaming • Ch. 15

The tracking of a consumer group's read position within a commit log partition. Offsets are committed explicitly to allow worker crashes to resume execution without duplicate processing or data loss.

OmniRoute Project

Continuous Build • Ch. 1–20

The enterprise multi-region logistics, passenger ride-dispatch, and financial settlement platform engineered milestone by milestone across all 20 chapters of this curriculum.

OpenTelemetry (OTel)

Observability • Ch. 19

A vendor-neutral Cloud Native Computing Foundation (CNCF) observability framework providing standard APIs, SDKs, and tooling to generate and export metrics, logs, and distributed traces.

Origin Shield (CDN Intermediate Tier)

Edge Architecture • Ch. 4

A centralized caching layer positioned between edge PoPs and the primary origin server. Consolidates cache misses across 300+ edge locations into a single origin request, eliminating origin stampedes.

Outbox Pattern (Transactional Outbox)

Consistency • Ch. 11, 16

Guarantees dual-write immunity by committing domain state and an outbox event record within the identical local ACID database transaction, asynchronously relayed to message brokers via Change Data Capture (CDC).

Outlier Detection (Passive Health Checking)

Load Balancing • Ch. 5

A dynamic load balancing defense pioneered by Envoy Proxy: monitors live traffic and immediately ejects backend nodes that return consecutive 5xx errors from the routing pool for a cooldown period without waiting for synthetic probes.

P Index

PACELC Theorem

Distributed Theory • Ch. 1

Daniel Abadi’s extension of CAP: In case of **P**artition, trade off **A**vailability vs. **C**onsistency; **E**lse (normal operations), trade off **L**atency vs. **C**onsistency.

Paxos (Multi-Paxos)

Consensus • Ch. 13

Leslie Lamport's foundational consensus protocol enabling independent nodes to agree on a sequence of decisions over an unreliable network. Known for mathematical rigor and high real-world implementation difficulty.

Peak-EWMA (Moving Average Latency)

Routing Algorithms • Ch. 5

An adaptive load balancing metric tracking a decaying moving average of backend response times: $\text{EWMA}_t = \alpha \times \text{Latency} + (1 - \alpha) \times \text{EWMA}_{t-1}$. Naturally steers requests away from lagging or GC-paused instances.

Pivot Transaction

Saga Architecture • Ch. 16

The point of no return in a distributed Saga. Steps before the pivot are compensable. Once the pivot transaction commits, subsequent steps cannot be compensated and **must run to completion** via automated retries.

Poison Pill

Failure Mode • Ch. 14

A malformed or corrupted task payload that crashes workers repeatedly upon consumption, inducing infinite crash loops and starving healthy tasks unless quarantined in a Dead Letter Queue.

Polyglot Persistence

Database Theory • Ch. 11

The practice of utilizing different data storage technologies (relational, key-value, document, graph, columnar) tailored to specific access patterns within the same overarching application.

Power of Two Choices (P2C)

Algorithms • Ch. 5

Michael Mitzenmacher’s routing theorem: Picking two backend nodes at random and routing to the one with lower load/latency achieves an exponential reduction in queue length compared to round-robin, with strictly $O(1)$ computation overhead.

Q Index

Quorum Mathematics

Consensus • Ch. 13

The strict majority requirement in consensus clusters: $Q = \lfloor N/2 \rfloor + 1$. Guarantees that two conflicting quorums cannot exist simultaneously during a network partition, mandating odd node counts ($N=3, 5, 7$).

R Index

Raft (Consensus Algorithm)

Consensus • Ch. 13

A consensus algorithm designed by Ongaro & Ousterhout to provide equivalent safety to Multi-Paxos while being understandable. Manages leader election via randomized election timers and enforces strong leader log replication. Powers etcd.

Read-After-Write Consistency

Database Scaling • Ch. 10

A consistency guarantee ensuring that a user immediately observes updates they submitted. Defended by pinning a user's reads to the Primary database for a brief window (e.g. 2 seconds) post-write, bypassing lagging replicas.

Redlock (Redis Distributed Locking)

Coordination • Ch. 13

A multi-node Redis lock proposal by Salvatore Sanfilippo. Heavily critiqued by Martin Kleppmann for reliance on synchronized system clocks and vulnerability to GC-paused zombie clients without fencing tokens.

Redpanda

Streaming • Ch. 15

A modern C++ streaming engine drop-in compatible with the Kafka API. Built on the Seastar framework using thread-per-core hardware mapping and direct NVMe access (`io_uring`), eliminating JVM garbage collection pauses.

RUM Conjecture (Harvard Database Group)

Storage Physics • Ch. 9

A storage engine trilemma proving that an engine can optimize for at most two of three bounds: **R**ead overhead, **U**pdate overhead, and **M**emory/Space overhead. B-Trees optimize for Read/Space; LSM-Trees optimize for Update/Space.

S Index

Saga Pattern

Distributed Transactions • Ch. 16

A distributed transaction pattern executing a sequence of independent local ACID transactions across microservices. If any step fails before the pivot step, compensating transactions ($C_i$) execute in reverse order to unwind state.

Sendfile (Zero-Copy Syscall)

OS Physics • Ch. 15

A Linux kernel system call transferring bytes directly from OS Page Cache memory into the Network Interface Card (NIC) buffer via Direct Memory Access (DMA), avoiding user-space memory copies and context switches.

Server-Sent Events (SSE)

Protocols • Ch. 8

A unidirectional real-time streaming protocol over standard HTTP (`text/event-stream`). Multiplexes across HTTP/2 without extra socket overhead, features native browser reconnection, and supports `Last-Event-ID` resumption.

Sharding (Horizontal Partitioning)

Database Scaling • Ch. 10

Dividing a single database horizontally across independent database servers. Data is routed via a high-cardinality **Shard Key**. Co-locating related entity collections on the same shard eliminates distributed cross-shard joins.

Shuffle Sharding

Resilience • Ch. 6

An advanced multi-tenant isolation pattern pioneered by AWS: each customer is assigned a unique *virtual combination* of nodes (e.g. 2 nodes out of 8). Limits poison-pill outage impact to a tiny overlap of customers.

SLA / SLO / SLI Framework

SRE • Ch. 6

The SRE performance triad: SLI is the measured telemetry metric; SLO is the internal engineering availability target (e.g. 99.9%); SLA is the commercial contract carrying financial penalties if breached.

Sliding Window Counter (Rate Limiting)

Algorithms • Ch. 4

A memory-efficient rate limiting algorithm combining previous and current window counts with fractional time decay: $\text{Reqs} = \text{Count}_{\text{curr}} + \left(\text{Count}_{\text{prev}} \times \left(1 - \frac{\Delta t}{\text{Window}}\right)\right)$. Eliminates boundary burst spikes.

Slowloris Attack

Security • Ch. 4

A low-bandwidth Layer 7 denial-of-service attack where an attacker opens thousands of HTTP connections, trickling single header bytes every 10 seconds to keep reverse proxy connection threads tied up indefinitely.

SSTable (Sorted String Table)

Storage Physics • Ch. 9

An immutable, sequential on-disk file format storing sorted key-value pairs with an index block. Formed when a MemTable flushes to disk. Compaction merges multiple SSTables in the background.

Sticky Sessions (Session Affinity)

Ingress • Ch. 5, 7

A load balancing configuration pinning a client's requests to a specific server instance via cookies or IP hashing. A dangerous anti-pattern under Carrier-Grade NAT (CGNAT) where thousands of users share a single gateway IP.

Strangler Fig Pattern

Migration • Ch. 18

Martin Fowler's incremental refactoring pattern: intercepts traffic via an edge proxy, gradually routes traffic to newly extracted microservices or modular monolith components, and strangles the legacy system with zero downtime.

T Index

Tail Latency (p99 / p99.9)

Performance • Ch. 1, 3

The latency experienced by the slowest 1% or 0.1% of requests. At high scale (e.g. 100,000 QPS), a bad p99 impacts 1,000 users every second. Caused by GC pauses, disk lock contention, and network retransmissions.

TCP 3-Way Handshake

Networking • Ch. 3

The `SYN → SYN-ACK ← ACK` sequence required to establish a TCP stream before data transfer begins. Incurs 1 full round-trip time (RTT). Mitigated via HTTP persistent connections (Keep-Alive) and TCP Fast Open.

Token Bucket Algorithm

Algorithms • Ch. 4

A rate limiting algorithm where tokens are added to a bucket at a constant refill rate up to a max capacity. Requests consume tokens and are permitted if tokens exist, providing natural burst tolerance.

Two-Phase Commit (2PC / XA)

Distributed Theory • Ch. 16

An atomic commitment protocol coordinating distributed databases across a voting phase (Prepare) and a commitment phase. Holding row locks across remote network calls causes latency explosions and global deadlocks under load.

U Index

Unbounded Buffer Trap

Anti-Pattern • Ch. 14

An architectural vulnerability where an in-memory queue or channel has no maximum capacity limit (`maxsize=0`). Under traffic bursts, buffered tasks consume all available RAM until the OS terminates the container with `SIGKILL`.

V Index

Virtual Nodes (VNodes)

Sharding • Ch. 10

The technique of assigning multiple virtual tokens (e.g. 100 to 256) per physical shard on a consistent hashing ring. Ensures statistical uniformity in data distribution and prevents localized hot spots.

W Index

W3C Trace Context (`traceparent`)

Observability • Ch. 19

The official W3C specification standardizing cross-service context propagation via the `traceparent` HTTP header: `00-{trace_id_32_hex}-{parent_span_id_16_hex}-{flags_2_hex}`.

WebSockets (RFC 6455)

Protocols • Ch. 7, 8

A bidirectional, full-duplex TCP communication protocol initiated via an HTTP handshake. Features low framing overhead (2–14 bytes), ideal for real-time driver coordinate streams and multiplayer collaboration.

WebTransport (over HTTP/3 / QUIC)

Next-Gen Protocols • Ch. 8

An emerging real-time transport protocol built over HTTP/3 and QUIC (UDP). Supports bidirectional reliable streams alongside unreliable datagrams with zero head-of-line blocking and connection migration across networks.

Write-Ahead Log (WAL)

Storage Physics • Ch. 9

An append-only log on disk where modifications are written sequentially before being applied to in-memory pages or B-Trees, guaranteeing durability and crash recovery.

Write Amplification Factor (WAF)

Storage Physics • Ch. 9

The ratio of bytes written to physical storage relative to the logical payload bytes requested: $\text{WAF} = \frac{\text{Bytes Written to Storage}}{\text{Bytes Written by Application}}$. High in B-Trees (~50x–100x), low in LSM-Trees.

Write-Behind (Write-Back Caching)

Caching • Ch. 12

A caching pattern where the application writes to the cache in RAM and returns immediately. A background daemon asynchronously batches and flushes dirty records to the persistent database.

Write Skew Anomaly

Database Anomalies • Ch. 17

A concurrency anomaly under Snapshot Isolation where two concurrent transactions read overlapping data, verify a domain invariant independently, and commit non-overlapping writes that violate the global constraint. Neutralized via `SERIALIZABLE` isolation.

X Index

XFetch Algorithm (Probabilistic Early Expiration)

Algorithms • Ch. 12

An optimal cache stampede prevention algorithm (VLDB 2015) evaluating: $-\beta \times \Delta \times \ln(\text{rand}()) > \text{TTL}_{\text{remaining}}$. Probabilistically triggers exactly one background re-computation as expiration nears, ensuring hot keys never expire for active readers.

Z Index

Zero-Copy I/O

OS Architecture • Ch. 15

A computer systems technique avoiding CPU-mediated copying of data between kernel and user space memory buffers, moving data directly from storage cache to network drivers via Direct Memory Access (DMA).

Zipfian Distribution (Power-Law Caching)

Capacity Math • Ch. 2

A statistical power-law distribution where item frequency is inversely proportional to its rank: $P(r) \propto 1/r^s$. Explains the 80/20 rule of caching: caching the top 20% of content satisfies 80%+ of incoming queries.

Zombie Socket (Half-Open TCP)

Networking • Ch. 7

A persistent TCP connection where one endpoint has terminated (e.g. mobile device lost power or entered an elevator) without sending a TCP `FIN` packet. The server retains the socket indefinitely unless purged by application-level heartbeats.
