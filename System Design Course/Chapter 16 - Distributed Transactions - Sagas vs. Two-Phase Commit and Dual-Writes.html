Distributed Systems Theory

The Death of Local ACID: Why 2PC Collapses in the Cloud

In single-node monolithic databases, achieving **Atomicity, Consistency, Isolation, and Durability (ACID)** is straightforward: the storage engine locks modified rows in memory and writes modifications to a local Write-Ahead Log (WAL). If anything fails, calling ROLLBACK instantly reverts uncommitted pages.

In microservices, the **Database-per-Service** pattern is mandatory to maintain team autonomy and loose coupling. A single business transaction must now execute across multiple independent databases over an unreliable network.

Two-Phase Commit (2PC / XA) • Cloud Trap Blocking / Fragile

A central coordinator asks all databases: "Can you commit?" (Phase 1: Prepare). Nodes acquire row locks and reply YES. The coordinator then sends "Commit!" (Phase 2).

• Latency: Locks held across multiple network roundtrips!
• Single Point of Failure: If coordinator crashes, nodes hold locks forever!
• Scalability: Throughput plummets to the slowest node in the network.
✗ Cloud Reality: 2PC availability approaches zero as services scale.
The Saga Pattern • Cloud Standard BASE Consistency

Formalized by Hector Garcia-Molina in 1987. Breaks a distributed transaction into a sequence of **independent local ACID transactions**.

• Lock Duration: Sub-millisecond! Locks released immediately per step.
• Fault Tolerance: If Step $N$ fails, compensating transactions ($C_{N-1} \dots C_1$) unwind state.
• Availability: Unlocked high-concurrency throughput across services.
✓ Production Standard: Embraces Eventual Consistency safely.

💡 The Real-World Metaphor (Plain English)

Imagine booking a complete summer vacation: Step 1: Reserve Flight → Step 2: Reserve Hotel → Step 3: Rent Car.

Under **Two-Phase Commit (2PC)**, the travel website calls the airline, the hotel, and the car agency and says: "Hold these exact seats and rooms on freeze, and don't let anyone else book them or hang up the phone while I finish." If the rental car agent's computer freezes, the airline and hotel remain trapped on the phone for 20 minutes with empty rooms locked!

Under a **Saga**, you pay for the flight immediately (Local ACID). You then book the hotel room immediately (Local ACID). If the rental car turns out to be sold out, you do not panic: you trigger **Compensating Actions** in reverse order! You cancel the hotel reservation (issuing a full refund) and cancel the flight ticket (issuing a refund). The trip is unwound safely without holding global locks.

Saga Architecture

Choreography vs. Orchestration: Selecting the Coordination Topology

Decentralized Event Mesh vs. Centralized State Machine Coordinator

There are two architectural paradigms for coordinating a distributed Saga:

1. Choreography (Event-Driven Mesh)

Services listen to event topics on Kafka/RabbitMQ and execute local transactions in response to events. There is no central controller.

Pros: Highly decoupled for simple 2-step workflows.
Cons: "Spaghetti choreography" at scale. Difficult to understand the global transaction state, detect timeouts, or debug rollbacks when 10 services emit circular events.

2. Orchestration (Central State Machine)

A dedicated Saga Orchestrator class commands participants to execute steps via point-to-point RPC or command messages.

Pros: Complete observability. The orchestrator persists a clear state machine, tracks timeouts, and handles compensations deterministically.
Cons: Requires building and maintaining the orchestrator state engine.

The OmniRoute Trip Booking Saga Orchestrator Pipeline
// 1. Normal Forward Execution Flow (All Steps Commit Locally)
Step 1: Wallet Service Deducts $50 hold locally
→
Step 2: Fleet Service Locks driver capacity locally
→
Step 3: Dispatch (PIVOT) Creates legal trip record
// 2. Failure at Step 2 → Automatic Compensating Rollback in Reverse!
Compensate 1: Refund Hold Releases $50 back to passenger
← unwinds ←
Step 2 FAILS! Driver cancelled / unreachable
← skipped ←
Step 3 (Never Reached) Zero state modified
The Pivot Step Principle:

Every Saga has a Pivot Transaction. It is the point of no return. Steps before the pivot are compensable. Once the pivot transaction commits, subsequent steps MUST NEVER FAIL; they are retryable until success! Placing irreversible actions (e.g. sending SMS notifications or pushing funds to external banking rails) after the pivot guarantees system integrity.

Consistency Anomalies

The Lack of Isolation in Sagas: Taming Semantic Anomalies

Dirty Reads • Lost Updates • Semantic Locking Countermeasures

The greatest challenge of the Saga Pattern is **the lack of ACID Isolation**. Because each local transaction commits immediately, intermediate states are visible to other concurrent transactions before the entire Saga finishes:

1. The Dirty Read Anomaly

Saga 1 reserves $50 from a passenger's wallet. Before Saga 1 finishes Step 2, the passenger checks their balance on mobile and sees $0. Saga 1 subsequently fails Step 2 and refunds the $50. The passenger witnessed a temporary phantom balance!

✓ Remedy: Semantic Locking. Instead of directly deducting balance, set `status = "PENDING_HOLD"`.

2. The Lost Update Anomaly

Saga 1 reads driver capacity and sets it to BUSY. Before Saga 1 commits, Saga 2 overwrites the driver status to AVAILABLE, ignoring Saga 1's ongoing reservation.

✓ Remedy: Optimistic Concurrency Control (OCC) with version numbers or monotonic fencing tokens.

import datetime
import uuid
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column
from sqlalchemy import String, Float, DateTime, Enum as SAEnum
import enum


class Base(DeclarativeBase):
    pass


class SagaStatus(str, enum.Enum):
    STARTED = "STARTED"
    EXECUTING = "EXECUTING"
    COMPENSATING = "COMPENSATING"
    COMPLETED = "COMPLETED"
    ROLLED_BACK = "ROLLED_BACK"
    FAILED = "FAILED"


class SagaInstanceModel(Base):
    """
    PERSISTENT SAGA STATE MACHINE LOG:
    Tracks distributed transaction status, current step, and error reasons.
    """
    __tablename__ = "saga_instances"

    id: Mapped[str] = mapped_column(String(36), primary_key=True, default=lambda: str(uuid.uuid4()))
    saga_type: Mapped[str] = mapped_column(String(50), nullable=False)
    status: Mapped[SagaStatus] = mapped_column(SAEnum(SagaStatus), default=SagaStatus.STARTED, nullable=False)
    payload_json: Mapped[str] = mapped_column(String, nullable=False)
    error_reason: Mapped[str] = mapped_column(String, nullable=True)
    created_at: Mapped[datetime.datetime] = mapped_column(
        DateTime, default=datetime.datetime.utcnow, nullable=False
    )
    updated_at: Mapped[datetime.datetime] = mapped_column(
        DateTime, default=datetime.datetime.utcnow, onupdate=datetime.datetime.utcnow, nullable=False
    )


class PassengerWalletModel(Base):
    """Simulates the Passenger Wallet Service database table."""
    __tablename__ = "passenger_wallets"

    user_id: Mapped[str] = mapped_column(String(50), primary_key=True)

2. Saga Orchestrator & Step Definitions: src/omniroute/transactions/saga_orchestrator.py State Machine & Compensations 
# ==============================================================================
# OmniRoute Transactions - Distributed Saga Orchestrator
# ==============================================================================

from abc import ABC, abstractmethod
from typing import List, Dict, Any
from sqlalchemy.ext.asyncio import AsyncSession
from sqlalchemy import select

from omniroute.transactions.models import (
    SagaInstanceModel, SagaStatus, PassengerWalletModel
)


class ISagaStep(ABC):
    """Saga Step Contract: Must define forward action and idempotent compensation."""
    @property
    @abstractmethod
    def name(self) -> str: ...

    @abstractmethod
    async def execute(self, context: Dict[str, Any], session: AsyncSession) -> bool: ...

    @abstractmethod
    async def compensate(self, context: Dict[str, Any], session: AsyncSession) -> bool: ...


# ------------------------------------------------------------------------------
# STEP 1: Reserve Passenger Funds
# ------------------------------------------------------------------------------
class ReserveFundsStep(ISagaStep):
    name = "ReservePassengerFunds"

    async def execute(self, context: Dict[str, Any], session: AsyncSession) -> bool:
        user_id = context["user_id"]
        amount = context["amount"]

        stmt = select(PassengerWalletModel).where(PassengerWalletModel.user_id == user_id)
        res = await session.execute(stmt)
        wallet = res.scalar_one_or_none()

        if not wallet or (wallet.balance - wallet.reserved_hold) < amount:
            return False  # Insufficient funds

        wallet.reserved_hold += amount
        context["funds_held"] = True
        return True

    async def compensate(self, context: Dict[str, Any], session: AsyncSession) -> bool:
        if not context.get("funds_held"):
            return True  # Idempotent no-op if step never executed

        user_id = context["user_id"]
        amount = context["amount"]

        stmt = select(PassengerWalletModel).where(PassengerWalletModel.user_id == user_id)
        res = await session.execute(stmt)
        wallet = res.scalar_one_or_none()

        if wallet:
            wallet.reserved_hold = max(0.0, wallet.reserved_hold - amount)

        context["funds_held"] = False
        return True


# ------------------------------------------------------------------------------
# STEP 2: Lock Driver Capacity
# ------------------------------------------------------------------------------
class LockDriverCapacityStep(ISagaStep):
    name = "LockDriverCapacity"

    async def execute(self, context: Dict[str, Any], session: AsyncSession) -> bool:
        driver_id = context["driver_id"]
        # Simulate checking driver availability
        if driver_id == "driver_offline_error":
            return False  # Simulates failure at Step 2!

        context["driver_locked"] = True
        return True

    async def compensate(self, context: Dict[str, Any], session: AsyncSession) -> bool:
        context["driver_locked"] = False
        return True


# ------------------------------------------------------------------------------
# STEP 3: Confirm Dispatch Agreement (THE PIVOT STEP)
# ------------------------------------------------------------------------------
class ConfirmDispatchPivotStep(ISagaStep):
    name = "ConfirmDispatchPivot"

    async def execute(self, context: Dict[str, Any], session: AsyncSession) -> bool:
        # THE PIVOT TRANSACTION: Once this executes, the ride is legally created.
        context["dispatch_confirmed"] = True
        return True

    async def compensate(self, context: Dict[str, Any], session: AsyncSession) -> bool:
        # Pivot step is irreversible! Must return True or require human intervention.
        return True


# ------------------------------------------------------------------------------
# SAGA ORCHESTRATOR ENGINE
# ------------------------------------------------------------------------------
class SagaOrchestrator:
    """
    DISTRIBUTED SAGA ORCHESTRATOR:
    Coordinates forward step execution. If any step fails, triggers
    compensating actions in strict reverse (LIFO) order!
    """
    def __init__(self, steps: List[ISagaStep]):
        self.steps = steps

    async def run(
        self, saga_instance: SagaInstanceModel, context: Dict[str, Any], session: AsyncSession
    ) -> bool:
        saga_instance.status = SagaStatus.EXECUTING
        executed_steps: List[ISagaStep] = []

        for step in self.steps:
            try:
                success = await step.execute(context, session)
                if success:
                    executed_steps.append(step)
                else:
                    # Step reported domain failure → Rollback
                    saga_instance.error_reason = f"Step failed: {step.name}"
                    await self._compensate(executed_steps, context, saga_instance, session)
                    return False
            except Exception as exc:
                saga_instance.error_reason = f"Step exception in {step.name}: {str(exc)}"
                await self._compensate(executed_steps, context, saga_instance, session)
                return False

        saga_instance.status = SagaStatus.COMPLETED
        await session.commit()
        return True

    async def _compensate(
        self,
        executed_steps: List[ISagaStep],
        context: Dict[str, Any],
        saga_instance: SagaInstanceModel,
        session: AsyncSession
    ) -> None:
        saga_instance.status = SagaStatus.COMPENSATING
        # Reverse LIFO order compensation:
        for step in reversed(executed_steps):
            try:
                await step.compensate(context, session)
            except Exception as comp_exc:
                saga_instance.status = SagaStatus.FAILED
                await session.commit()
                raise comp_exc

        saga_instance.status = SagaStatus.ROLLED_BACK
        await session.commit()
3. Saga Trip Booking Router: src/omniroute/transactions/router.py FastAPI & Async Database Reporting 
import json
from fastapi import APIRouter, Depends, status, HTTPException
from pydantic import BaseModel, Field
from sqlalchemy.ext.asyncio import AsyncSession
from typing import AsyncGenerator

from omniroute.transactions.models import SagaInstanceModel, SagaStatus
from omniroute.transactions.saga_orchestrator import (
    SagaOrchestrator, ReserveFundsStep, LockDriverCapacityStep, ConfirmDispatchPivotStep
)

router = APIRouter(prefix="/api/v1/sagas", tags=["Saga Transactions"])

# Instantiated trip booking saga definition
trip_booking_orchestrator = SagaOrchestrator([
    ReserveFundsStep(),
    LockDriverCapacityStep(),
    ConfirmDispatchPivotStep()
])


class BookTripRequestDTO(BaseModel):
    user_id: str
    driver_id: str
    amount: float = Field(..., gt=0.0)


async def get_session() -> AsyncGenerator[AsyncSession, None]:
    raise NotImplementedError


@router.post(
    "/trip/book",
    status_code=status.HTTP_200_OK,
    summary="Execute Distributed Trip Booking Saga"
)
async def book_trip_saga(
    dto: BookTripRequestDTO,
    db: AsyncSession = Depends(get_session)
):
    saga_record = SagaInstanceModel(
        saga_type="TRIP_BOOKING_SAGA",
        payload_json=json.dumps(dto.model_dump())
    )
    db.add(saga_record)
    await db.commit()
    await db.refresh(saga_record)

    context = dto.model_dump()
    success = await trip_booking_orchestrator.run(saga_record, context, db)

    return {
        "saga_id": saga_record.id,
        "status": saga_record.status.value,
        "success": success,
        "error_reason": saga_record.error_reason
    }

Warning Track

Beginner Pitfalls & Distributed Transaction Anti-Patterns

❌ Placing Irreversible Actions Before the Pivot Step

Executing non-compensable actions (such as sending a customer push notification or triggering an un-cancellable bank wire transfer) before all compensable reservation steps have succeeded.

Why this causes disasters: If the saga fails on a subsequent step, you cannot mathematically un-send a push notification or un-ring a physical bell! You leave customers bewildered and balances corrupted. Irreversible actions must occur strictly AFTER the Pivot Step!

❌ Non-Idempotent Compensations

Writing compensating actions that blindly refund amounts without checking whether the step actually succeeded or if a refund was already processed.

Why this bleeds money: When a network partition drops the acknowledgment of a compensation, the orchestrator retries. If the compensation is non-idempotent, it credits the customer's wallet a second and third time! Compensations must be strictly idempotent.
