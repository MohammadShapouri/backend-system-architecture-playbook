The Real-Time Spectrum: Evolution from Polling to WebTransport

The World Wide Web was architected around a strict request-response paradigm: the client sends a request, the server returns a response, and the connection closes. Over the last 25 years, engineers have developed five progressive generations of real-time communication to bypass this limitation:

1. Short Polling (Timer-Based) Anti-Pattern at Scale

Client sends an HTTP GET request every $N$ seconds (setInterval(poll, 2000)) regardless of whether new data exists.

• Overhead: Full HTTP/1.1 headers (~800 bytes) on every poll
• Waste: 98% of responses return empty data ({})
• Mobile: Forces cellular radio into high-power state continuously
2. Long Polling (Hanging GET) Universal Fallback

Client requests data. The server holds the request open until an event occurs or a timeout expires. The client reconnects immediately upon receiving a response.

• Latency: Near instantaneous event delivery
• Drawback: Reconnection overhead after every event
• Use Case: Critical fallback when WebSockets/SSE are blocked
3. Server-Sent Events (SSE) Unidirectional Streaming

Standard HTTP connection with content-type text/event-stream. Server streams chunks indefinitely down the open HTTP channel.

• Transport: Standard HTTP (Multiplexable over HTTP/2)
• Features: Native browser auto-reconnect & Last-Event-ID
• Use Case: Stock tickers, rider map car movements, LLM token streaming
4. WebSockets (RFC 6455) Bidirectional Full-Duplex

Upgrades an HTTP connection to a persistent, bidirectional TCP stream with minimal framing overhead (2 to 14 bytes per frame).

• Direction: Full-Duplex (Both sides send anytime)
• Drawback: Requires custom heartbeats, load balancer bypasses
• Use Case: Chat, collaborative editing, driver coordinate uploads
5. WebTransport (over HTTP/3 / QUIC) • The Next Generation UDP-Based Multiplexing

Operating on top of QUIC (UDP), WebTransport combines the bidirectional capabilities of WebSockets with the multiplexing powers of HTTP/3:

No Head-of-Line Blocking

A dropped packet on Stream A does not stall Stream B! Independent streams flow unimpeded.

Unreliable Datagrams

Send high-frequency GPS coordinate updates over raw UDP datagrams without TCP retransmission latency!

Connection Migration

When a driver switches from Wi-Fi to 5G cellular, the connection survives with ZERO reconnection handshake!

Hardware & Telecom Physics

Mobile Battery Drain: The Radio Resource Control (RRC) Machine

Cellular Modem States • Tail Time Waste • Battery Sapping Short Polling

Why does polling kill mobile phones? A smartphone’s 4G/5G cellular modem does not stay powered on continuously; doing so would drain the lithium-ion battery in under 3 hours. Instead, the telecommunications tower coordinates the device using the Radio Resource Control (RRC) State Machine:

The Cellular Radio Resource Control (RRC) Power Cycle
1. RRC_IDLE
Radio powered off
Current: ~5 to 10 mW
→ Packet sent →
2. RRC_CONNECTED
Full power transmission
Current: ~1,500 to 2,500 mW!
→ Inactivity timer →
3. TAIL TIME (Warm)
Awaits more packets
Lingers for 10 to 15 seconds!
The Short Polling Battery Trap:

If a rider app polls every 10 seconds, the cellular radio enters RRC_CONNECTED to send the request, finishes in 100ms, and enters the 10-second TAIL TIME. Just as the radio prepares to sleep, the next poll fires! The cellular modem NEVER enters deep sleep. In contrast, SSE streams events down an already-open connection, allowing packets to be coalesced into efficient bursts.

2. SSE Broadcaster & Long-Poll Hub: src/omniroute/protocols/sse_hub.py Asynchronous Stream Multiplexer 
# ==============================================================================
# OmniRoute Protocols - Real-Time SSE Broadcaster & Long-Polling Engine
# ==============================================================================

import asyncio
import json
import time
from typing import AsyncGenerator, Dict, Optional, List


class RealtimeProtocolHub:
    """
    MULTI-PROTOCOL DISPATCH ENGINE:
    Coordinates SSE event streaming and Long-Polling hanging GET queues.
    Maintains an in-memory historical event buffer to support 'Last-Event-ID' resumption.
    """
    def __init__(self, max_history_size: int = 100):
        self.max_history_size = max_history_size
        # History buffer: list of (event_id, payload_dict)
        self._event_history: List[tuple[int, dict]] = []
        self._current_sequence_id: int = 0
        # Long-polling client queues: client_id -> asyncio.Queue
        self._long_poll_queues: Dict[str, asyncio.Queue] = {}
        self._lock = asyncio.Lock()

    async def publish_telemetry(self, payload: dict) -> int:
        """Broadcasts coordinate update to both SSE history and active long-poll clients."""
        async with self._lock:
            self._current_sequence_id += 1
            seq = self._current_sequence_id
            self._event_history.append((seq, payload))

            if len(self._event_history) > self.max_history_size:
                self._event_history.pop(0)

            # Wake up all hanging long-poll clients
            for queue in self._long_poll_queues.values():
                await queue.put((seq, payload))

            return seq

    async def subscribe_sse(
        self, last_event_id: Optional[int] = None
    ) -> AsyncGenerator[str, None]:
        """
        SSE STREAM GENERATOR (RFC 8895 Compliance):
        1. Resends any missed events occurring after 'Last-Event-ID'.
        2. Streams new incoming events as formatted 'data: ...\n\n' chunks.
        """
        local_seq = last_event_id or self._current_sequence_id

        # 1. Replay missed history
        async with self._lock:
            missed_events = [e for e in self._event_history if e[0] > local_seq]

        for seq_id, event_data in missed_events:
            yield f"id: {seq_id}\nevent: gps_telemetry\ndata: {json.dumps(event_data)}\n\n"
            local_seq = seq_id

        # 2. Continuous real-time stream
        poll_queue: asyncio.Queue = asyncio.Queue()
        client_key = f"sse_client_{time.time()}_{id(poll_queue)}"
        async with self._lock:
            self._long_poll_queues[client_key] = poll_queue

        try:
            while True:
                seq_id, event_data = await poll_queue.get()
                if seq_id > local_seq:
                    yield f"id: {seq_id}\nevent: gps_telemetry\ndata: {json.dumps(event_data)}\n\n"
                    local_seq = seq_id
        finally:
            async with self._lock:
                self._long_poll_queues.pop(client_key, None)

    async def await_long_poll(
        self, client_id: str, timeout_sec: float = 15.0
    ) -> Optional[dict]:
        """Hanging GET handler: awaits an event or returns None upon timeout."""
        queue: asyncio.Queue = asyncio.Queue()
        async with self._lock:
            self._long_poll_queues[client_id] = queue

        try:
            seq_id, data = await asyncio.wait_for(queue.get(), timeout=timeout_sec)
            return {"sequence_id": seq_id, "payload": data}
        except asyncio.TimeoutError:
            return None  # Normal timeout: client will immediately poll again
        finally:
            async with self._lock:
                self._long_poll_queues.pop(client_id, None)
3. Multi-Protocol FastAPI Controller: src/omniroute/protocols/router.py FastAPI & StreamingResponse 
from fastapi import APIRouter, WebSocket, WebSocketDisconnect, Header, status, Depends
from fastapi.responses import StreamingResponse
from pydantic import BaseModel
from typing import Optional

from omniroute.protocols.sse_hub import RealtimeProtocolHub

router = APIRouter(prefix="/api/v1/stream", tags=["Protocol Streaming"])
hub = RealtimeProtocolHub()


class TelemetryBroadcastDTO(BaseModel):
    driver_id: str
    lat: float
    lng: float
    bearing: float


@router.post("/broadcast", status_code=status.HTTP_202_ACCEPTED)
async def broadcast_driver_telemetry(dto: TelemetryBroadcastDTO):
    """Ingests driver coordinates and broadcasts across all connected protocols."""
    seq = await hub.publish_telemetry(dto.model_dump())
    return {"status": "PUBLISHED", "sequence_id": seq}


@router.get("/sse")
async def stream_sse_telemetry(last_event_id: Optional[int] = Header(None, alias="Last-Event-ID")):
    """
    SERVER-SENT EVENTS (SSE) ENDPOINT:
    Streams driver location updates to rider apps using text/event-stream.
    Supports HTTP/2 multiplexing and automated client reconnection resumption.
    """
    generator = hub.subscribe_sse(last_event_id=last_event_id)
    return StreamingResponse(
        generator,
        media_type="text/event-stream",
        headers={
            "Cache-Control": "no-cache",
            "Connection": "keep-alive",
            "X-Accel-Buffering": "no"  # Disables proxy buffering in Nginx/Envoy
        }
    )


@router.get("/long-poll/{client_id}")
async def long_poll_telemetry(client_id: str):
    """Hanging GET Long-Polling fallback endpoint for restrictive corporate proxies."""
    result = await hub.await_long_poll(client_id, timeout_sec=2.0)
    if result is None:
        return {"status": "TIMEOUT", "data": None}
    return {"status": "EVENT_RECEIVED", "data": result}


@router.websocket("/ws/driver/{driver_id}")
async def driver_websocket_telemetry(websocket: WebSocket, driver_id: str):
    """Bidirectional WebSocket pipeline for active driver location ingestion."""
    await websocket.accept()
    try:
        while True:
            payload = await websocket.receive_json()
            await hub.publish_telemetry({"driver_id": driver_id, **payload})
            await websocket.send_json({"ack": True})
    except WebSocketDisconnect:
        pass

import asyncio
import pytest
from fastapi import FastAPI
from httpx import AsyncClient, ASGITransport

from omniroute.protocols.sse_hub import RealtimeProtocolHub
from omniroute.protocols.router import router


class TestRealtimeProtocolsSuite:
    """Verifies SSE streaming resumption, Long-Polling timeouts, and broadcast coordination."""

    @pytest.mark.asyncio
    async def test_sse_resumption_with_last_event_id(self):
        hub = RealtimeProtocolHub()

        # Publish 3 historical events
        await hub.publish_telemetry({"step": 1})
        await hub.publish_telemetry({"step": 2})
        await hub.publish_telemetry({"step": 3})

        # Client reconnects asserting it already saw Event #1
        sse_stream = hub.subscribe_sse(last_event_id=1)

        # Stream must immediately replay missed events #2 and #3
        chunk_2 = await anext(sse_stream)
        assert "id: 2" in chunk_2
        assert '"step": 2' in chunk_2

        chunk_3 = await anext(sse_stream)
        assert "id: 3" in chunk_3
        assert '"step": 3' in chunk_3

    @pytest.mark.asyncio
    async def test_long_polling_receives_broadcast_instantaneously(self):
        hub = RealtimeProtocolHub()

        async def delayed_broadcast():
            await asyncio.sleep(0.05)
            await hub.publish_telemetry({"lat": 37.77})

        asyncio.create_task(delayed_broadcast())

        # Hanging long-poll client awaits event
        res = await hub.await_long_poll(client_id="rider_1", timeout_sec=1.0)
        assert res is not None
        assert res["payload"]["lat"] == 37.77

    @pytest.mark.asyncio
    async def test_long_polling_timeout_safety(self):
        hub = RealtimeProtocolHub()
        # Zero events published → timeout cleanly in 0.05s
        res = await hub.await_long_poll(client_id="rider_timeout", timeout_sec=0.05)
        assert res is None

    @pytest.mark.asyncio
    async def test_protocol_rest_integration(self):
        app = FastAPI()
        app.include_router(router)

        transport = ASGITransport(app=app)
        async with AsyncClient(transport=transport, base_url="http://test") as client:
            res = await client.post("/api/v1/stream/broadcast", json={
                "driver_id": "drv_10",
                "lat": 40.7128,
                "lng": -74.0060,
                "bearing": 180.0
            })
            assert res.status_code == 202
            assert res.json()["status"] == "PUBLISHED"
Warning Track

Beginner Pitfalls & Real-Time Protocol Anti-Patterns

❌ The "WebSockets for Everything" Dogma

Using WebSockets for simple, read-only feeds (such as stock prices, notification alerts, or LLM token streaming).

Why this causes architectural failure: WebSockets bypass HTTP/2 multiplexing, preventing your app from sharing a single TCP connection with normal web assets. They bypass edge CDN caching layers, require custom ping/pong heartbeats, and demand stateful cluster mesh backplanes. If communication is strictly one-way (Server → Client), always prefer Server-Sent Events (SSE)!

❌ The HTTP/1.1 Six-Connection Ceiling on SSE

Serving Server-Sent Events over HTTP/1.1 without enabling HTTP/2 on reverse proxies.

Why this freezes client browsers: Modern browsers enforce a strict limit of 6 concurrent HTTP/1.1 connections per domain. If a user opens 6 tabs with an open SSE connection, opening a 7th tab completely freezes all image and API loading for the entire website! Always terminate SSE over **HTTP/2 or HTTP/3**, where multiple streams multiplex over a single connection!
