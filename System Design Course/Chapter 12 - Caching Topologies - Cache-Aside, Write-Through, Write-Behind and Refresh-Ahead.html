Caching Systems Architecture

The 4 Canonical Caching Patterns: Mechanics, Latencies & Trade-Offs

As Phil Karlton famously declared: "There are only two hard things in Computer Science: cache invalidation and naming things."

A cache is not merely an in-memory dictionary. Where it sits in the data pipeline, how it synchronizes with the database, and whether writes pass through it synchronously determine your system's data durability, read latency, and write throughput.

1. Cache-Aside (Lazy Loading) Industry Default

The application orchestrates both cache and database directly.

Read: Check Cache → Hit: Return → Miss: Read DB & Populate Cache
Write: Write to Database → Invalidate/Evict Cache Key
✓ Pros: Resilient to cache death; only requested data is cached.
✗ Cons: Cache miss latency spike; potential stale reads before invalidation.
2. Write-Through Synchronous Integrity

The application treats the cache as the main data store.

Write: App writes to Cache → Cache synchronously writes to DB before return
Read: Always served from cache (guaranteed 100% fresh)
✓ Pros: Zero stale data; reads are always sub-millisecond.
✗ Cons: Double write penalty (latency = Cache Write + DB Write).
3. Write-Behind (Write-Back) High Write Throughput

Application writes to cache only. Cache asynchronously flushes writes to DB.

Write: App writes to Cache → Returns instantly (sub-1ms)
Async: Background daemon coalesces & batches writes to DB in chunks
✓ Pros: Massive write speed; absorbs heavy bursts; batches DB writes.
✗ Cons: Data loss risk if cache crashes before flushing dirty pages.
4. Refresh-Ahead Predictive Pre-Warm

Cache automatically reloads keys before expiration based on access frequency.

Behavior: If key accessed frequently & TTL expires soon → Async DB reload
Read: Users NEVER experience a cache-miss latency penalty!
✓ Pros: Eliminates p99 read latency spikes on hot keys.
✗ Cons: Mispredicted keys waste database CPU cycles.

💡 The Real-World Metaphor (Plain English)

Imagine the difference between a student doing homework with sticky notes versus a formal filing cabinet.

In Cache-Aside, the student looks at their desk. If the formula isn't on a sticky note, they walk to the filing cabinet, look it up, and write it on a sticky note for next time.

In Write-Behind, when the teacher assigns new math problems, the student jots down the answers on their desk scratchpad and continues playing video games immediately (Instant return). At 9:00 PM, they sit down and copy all the answers neatly into their formal binder in one single batch (Async batch flush). It's fast, but if their puppy chews up the scratchpad before 9:00 PM, their homework is lost!

Failure Physics & Algorithms

The 3 Deadly Cache Catastrophes & The XFetch Algorithm

Stampedes • Penetration • Avalanches • Optimal Probabilistic Early Expiration

When systems operate at high traffic volumes (>100,000 QPS), caches encounter three fatal failure modes:

1. Cache Stampede (Dogpiling)

A heavily queried key expires. 10,000 concurrent requests miss simultaneously and hammer the primary database at the exact same millisecond to recompute it.

Cure: The XFetch Algorithm
2. Cache Penetration

Queries for non-existent IDs (e.g., `driver_id = -9999`) miss the cache. The request falls through to the database every time, creating a targeted vector for DDoS attacks.

Cure: Bloom Filters & Null-Caching
3. Cache Avalanche

Thousands of keys populated during a server restart share the exact same 300s TTL. All keys expire at second 300, sending a massive traffic tsunami to the database.

Cure: Randomized TTL Jitter
The XFetch Optimal Probabilistic Early Expiration Algorithm
Vattani, Chierichetti, Lowenstein (VLDB 2015 Research Award Winner)
-\beta \times \Delta \times \ln(\text{rand}()) > \text{TTL}_{\text{remaining}}

Where $\Delta$ is the computation time taken to fetch data from the database, $\beta > 0$ is an aggressiveness tuning multiplier (standard $\beta = 1.0$), and $\text{rand}() \in (0, 1]$ is a uniform random float.

Why XFetch is Superior to Mutex Locking:

Traditional stampede defense uses distributed locks (SingleFlight / Redlock). If the lock-holding thread dies or lags, thousands of incoming client requests hang and time out.

The Probabilistic Physics:

As the key approaches expiration, the probability that an incoming read request triggers a background re-computation increases continuously. Exactly ONE request probabilistically re-fetches the database early, refreshing the cache before it ever reaches zero TTL. The key never truly expires for users!

2. XFetch & Write-Behind Caching Engine: src/omniroute/caching/cache_engine.py Stampede & Buffer Physics 
# ==============================================================================
# OmniRoute Caching - XFetch Early Expiration & Write-Behind Buffer
# ==============================================================================

import math
import random
import time
import asyncio
from dataclasses import dataclass
from typing import Any, Callable, Dict, Optional, Tuple, Awaitable
from sqlalchemy.ext.asyncio import AsyncSession
from sqlalchemy import select

from omniroute.caching.models import DriverRatingAggregationModel


@dataclass
class CacheEntry:
    value: Any
    delta_computation_time_sec: float
    expiration_timestamp: float


class DistributedCacheEngine:
    """
    DISTRIBUTED CACHING ENGINE:
    1. Cache-Aside with XFetch Probabilistic Early Expiration (Stampede defense).
    2. Null Object Caching (Penetration defense).
    3. Write-Behind In-Memory Buffer with asynchronous database flusher.
    """
    NULL_SENTINEL = "__NULL_OBJECT_SENTINEL__"

    def __init__(self, beta: float = 1.0):
        self.beta = beta
        self._memory_cache: Dict[str, CacheEntry] = {}
        # Write-Behind buffer: driver_id -> (points_accumulated, count_accumulated)
        self._write_behind_buffer: Dict[str, Tuple[float, int]] = {}
        self._lock = asyncio.Lock()

    def _should_recompute_xfetch(self, entry: CacheEntry) -> bool:
        """
        XFETCH ALGORITHM:
        -beta * delta * ln(random()) > TTL_remaining
        """
        ttl_remaining = entry.expiration_timestamp - time.time()
        if ttl_remaining <= 0:
            return True

        rand_val = random.uniform(0.0001, 1.0)
        early_recompute_threshold = -self.beta * entry.delta_computation_time_sec * math.log(rand_val)
        return early_recompute_threshold > ttl_remaining

    async def get_with_xfetch(
        self,
        key: str,
        fetch_db_fn: Callable[[], Awaitable[Any]],
        ttl_sec: float = 60.0
    ) -> Any:
        entry = self._memory_cache.get(key)
        now = time.time()

        # Cache Hit & XFetch Check
        if entry and not self._should_recompute_xfetch(entry):
            if entry.value == self.NULL_SENTINEL:
                return None
            return entry.value

        # Cache Miss OR XFetch Probabilistic Trigger
        t0 = time.perf_counter()
        computed_value = await fetch_db_fn()
        delta = time.perf_counter() - t0

        # Cache Penetration Defense: If DB returns None, cache NULL_SENTINEL with short 5s TTL
        if computed_value is None:
            val_to_cache = self.NULL_SENTINEL
            actual_ttl = 5.0
        else:
            val_to_cache = computed_value
            actual_ttl = ttl_sec

        async with self._lock:
            self._memory_cache[key] = CacheEntry(
                value=val_to_cache,
                delta_computation_time_sec=max(delta, 0.001),
                expiration_timestamp=now + actual_ttl
            )

        return computed_value

    async def record_write_behind(self, driver_id: str, rating_score: float) -> None:
        """WRITE-BEHIND: Buffers rating update in RAM. Returns immediately in sub-1ms!"""
        async with self._lock:
            points, count = self._write_behind_buffer.get(driver_id, (0.0, 0))
            self._write_behind_buffer[driver_id] = (points + rating_score, count + 1)

    async def flush_write_behind_buffer(self, session: AsyncSession) -> int:
        """Background worker: Flushes and coalesces dirty rating metrics to DB."""
        async with self._lock:
            if not self._write_behind_buffer:
                return 0
            items_to_flush = dict(self._write_behind_buffer)
            self._write_behind_buffer.clear()

        flushed_count = len(items_to_flush)
        for driver_id, (points, count) in items_to_flush.items():
            stmt = select(DriverRatingAggregationModel).where(DriverRatingAggregationModel.driver_id == driver_id)
            res = await session.execute(stmt)
            model = res.scalar_one_or_none()

            if not model:
                model = DriverRatingAggregationModel(
                    driver_id=driver_id,
                    total_rating_points=points,
                    rating_count=count
                )
                session.add(model)
            else:
                model.total_rating_points += points
                model.rating_count += count

        await session.commit()
        return flushed_count
3. Caching FastAPI Controller: src/omniroute/caching/router.py FastAPI & Async Database Reporting 
from fastapi import APIRouter, Depends, status, HTTPException
from pydantic import BaseModel, Field
from sqlalchemy.ext.asyncio import AsyncSession
from sqlalchemy import select
from typing import AsyncGenerator

from omniroute.caching.cache_engine import DistributedCacheEngine
from omniroute.caching.models import CitySurgePricingModel

router = APIRouter(prefix="/api/v1/cache", tags=["Caching Engine"])
cache_engine = DistributedCacheEngine(beta=1.0)


class DriverRatingWriteDTO(BaseModel):
    driver_id: str
    rating_score: float = Field(..., ge=1.0, le=5.0)


async def get_session() -> AsyncGenerator[AsyncSession, None]:
    raise NotImplementedError


@router.get("/surge/{city_code}")
async def get_city_surge_pricing(
    city_code: str,
    db: AsyncSession = Depends(get_session)
):
    """
    CACHE-ASIDE WITH XFETCH:
    Serves surge multiplier from memory. If key is close to expiration,
    probabilistically recomputes via DB before cache miss occurs!
    """
    city_key = city_code.upper().strip()

    async def db_fallback_fetch():
        stmt = select(CitySurgePricingModel).where(CitySurgePricingModel.city_code == city_key)
        res = await db.execute(stmt)
        record = res.scalar_one_or_none()
        if not record:
            return None
        return {"city_code": record.city_code, "surge_multiplier": record.surge_multiplier}

    result = await cache_engine.get_with_xfetch(f"surge:{city_key}", db_fallback_fetch, ttl_sec=30.0)
    if not result:
        raise HTTPException(status_code=404, detail="City not found in surge registry.")

    return result


@router.post("/ratings/submit", status_code=status.HTTP_202_ACCEPTED)
async def submit_driver_rating_write_behind(dto: DriverRatingWriteDTO):
    """
    WRITE-BEHIND BUFFER:
    Buffers rating in memory without taking database write locks.
    Returns in <1ms to client.
    """
    await cache_engine.record_write_behind(dto.driver_id, dto.rating_score)
    return {"status": "BUFFERED_IN_MEMORY", "driver_id": dto.driver_id}

import asyncio
import pytest
import pytest_asyncio
from sqlalchemy.ext.asyncio import create_async_engine, async_sessionmaker, AsyncSession
from sqlalchemy import select

from omniroute.caching.models import Base, CitySurgePricingModel, DriverRatingAggregationModel
from omniroute.caching.cache_engine import DistributedCacheEngine


@pytest_asyncio.fixture
async def in_memory_db():
    engine = create_async_engine("sqlite+aiosqlite:///:memory:", echo=False)
    async with engine.begin() as conn:
        await conn.run_sync(Base.metadata.create_all)

    session_factory = async_sessionmaker(engine, expire_on_commit=False, class_=AsyncSession)
    yield session_factory
    await engine.dispose()


class TestCachingTopologiesSuite:
    """Verifies XFetch early expiration, Write-Behind batch flushing, and null caching."""

    @pytest.mark.asyncio
    async def test_xfetch_cache_hit_and_penetration_null_defense(self):
        cache = DistributedCacheEngine(beta=1.0)
        db_invocations = 0

        async def mock_db_call():
            nonlocal db_invocations
            db_invocations += 1
            return {"surge": 1.5}

        # Initial Call → Cache Miss, reads DB
        res1 = await cache.get_with_xfetch("surge:NYC", mock_db_call, ttl_sec=60.0)
        assert res1["surge"] == 1.5
        assert db_invocations == 1

        # Second Call → Immediate Cache Hit! Zero DB query
        res2 = await cache.get_with_xfetch("surge:NYC", mock_db_call, ttl_sec=60.0)
        assert res2["surge"] == 1.5
        assert db_invocations == 1

        # Test Cache Penetration (Null Object Caching)
        async def null_db_call():
            nonlocal db_invocations
            db_invocations += 1
            return None

        null_res1 = await cache.get_with_xfetch("surge:NON_EXISTENT", null_db_call, ttl_sec=60.0)
        assert null_res1 is None
        assert db_invocations == 2

        # Penetration query repeated → Serves cached NULL without querying DB!
        null_res2 = await cache.get_with_xfetch("surge:NON_EXISTENT", null_db_call, ttl_sec=60.0)
        assert null_res2 is None
        assert db_invocations == 2

    @pytest.mark.asyncio
    async def test_write_behind_buffer_batches_database_commits(self, in_memory_db):
        cache = DistributedCacheEngine()

        # Buffer 3 rating updates for Driver 42 in memory
        await cache.record_write_behind("driver_42", 5.0)
        await cache.record_write_behind("driver_42", 4.0)
        await cache.record_write_behind("driver_99", 5.0)

        async with in_memory_db() as session:
            # Background flusher runs
            flushed = await cache.flush_write_behind_buffer(session)
            assert flushed == 2  # Coalesced into 2 drivers

            # Verify DB holds coalesced points
            stmt = select(DriverRatingAggregationModel).where(DriverRatingAggregationModel.driver_id == "driver_42")
            res = await session.execute(stmt)
            model = res.scalar_one()

            assert model.total_rating_points == 9.0  # 5.0 + 4.0
            assert model.rating_count == 2
Warning Track

Beginner Pitfalls & Caching Anti-Patterns

❌ The Synchronous Distributed Cache Lock

Attempting to prevent cache stampedes by forcing 10,000 incoming web threads to acquire a distributed Redis lock on cache miss.

Why this causes latency collapse: If the single thread holding the lock lags or hits a GC pause, thousands of web requests block and exhaust thread pools, creating widespread HTTP 504 timeouts! Always prefer probabilistic early re-computation (XFetch): it allows requests to recompute early in the background while still serving active cache to callers!

❌ The Cache-as-Database Trap

Treating an evictable Redis instance with maxmemory LRU policies as your primary persistent database.

Why this causes data loss: Under memory pressure, Redis evicts keys silently according to its LRU policy. If you store business-critical user states exclusively in Redis without an underlying durable database or Write-Behind persistence, your data evaporates into the void! A cache is an acceleration tier, never your primary source of truth.
