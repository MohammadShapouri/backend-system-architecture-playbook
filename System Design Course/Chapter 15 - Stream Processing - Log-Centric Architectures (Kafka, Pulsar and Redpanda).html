Stream Processing Theory

The Log: The Fundamental Primitive of Distributed Streaming

In 2013, LinkedIn engineer and Kafka co-creator Jay Kreps published the seminal essay: "The Log: What every software engineer should know about real-time data's unifying abstraction."

Kreps identified that engineers repeatedly confuse two fundamentally distinct messaging paradigms: **Traditional Queues** versus **Distributed Commit Logs**:

Traditional Message Queue (RabbitMQ / SQS) Destructive Read

Messages are transient. When a worker acknowledges an item, the broker deletes it from disk/memory.

• State: Broker tracks per-message ACK/NACK state
• Concurrency: Multiple workers compete for the same queue head
• Fan-Out: Requires duplicating messages into separate physical queues
• Fatal Limit: Once read, messages cannot be replayed!
Distributed Commit Log (Kafka / Redpanda) Append-Only Immutable

An immutable, append-only sequence of ordered records persisted to disk. Reading is non-destructive.

• State: Broker is dumb; consumers track their own offset pointer
• Fan-Out: 50 independent consumer groups read from the exact same log
• Retention: Messages kept for days, weeks, or forever (S3 tiering)
• Superpower: Time-travel replay of historical streams on demand!

💡 The Real-World Metaphor (Plain English)

Imagine the difference between a box of donuts in a breakroom versus a published history textbook.

A Traditional Queue is the box of donuts. When Employee A takes a donut, that donut ceases to exist in the box. If Employee B walks in 5 minutes later, they cannot eat the donut that Employee A ate.

A Distributed Commit Log is the history textbook. Every historical event is printed in order on numbered pages (Offsets). The Fraud Analyst can read page 14; the Real-Time Dispatcher can read page 892; and the Machine Learning Engineer can re-read the entire book from Page 1 to train an algorithm. Reading a page does not erase the words from the paper!

Distributed Storage Physics

Partitioning Physics: Total Ordering vs. Parallel Scale

Partition Hashing • Sequential Disk I/O • Linux sendfile Zero-Copy

A single commit log file cannot scale beyond the disk bandwidth of one server. To achieve horizontal scalability, streaming platforms divide a **Topic** into multiple parallel append-only files called Partitions:

The Ordering Invariant:

A commit log guarantees total order ONLY within a single partition. There is zero ordering guarantee across different partitions! If driver coordinate updates must arrive in strict chronological order, all updates for a given driver_id must produce the identical partition hash.

The Zero-Copy Magic: Why Kafka & Redpanda Deliver Millions of Records/sec Linux Kernel sendfile

Traditional web servers read data from disk into kernel memory, copy it into user-space application memory, copy it back into kernel socket memory, and finally send it to the NIC (4 context switches + 4 memory copies).

• Page Cache Exploitation: Kafka and Redpanda do not cache messages in application JVM/heap memory. They write to disk segments and rely directly on the Linux OS Page Cache.
• The `sendfile()` Syscall (Zero-Copy): When consumers request records, the broker executes a single kernel instruction: transfer bytes directly from the Page Cache buffer to the Network Interface Card (NIC) DMA buffer. The CPU never touches the data!
Consumer Architecture

Consumer Groups, Offset Commits & Rebalance Storms

Horizontal Scaling • Cooperative Sticky Rebalances • Offset Pitfalls

A Consumer Group is a collection of worker instances cooperating to read a topic. Each partition in the topic is assigned to strictly **one consumer worker** within the group at any given time:

The Partition Cardinality Constraint

If a topic has 10 partitions, you can run at most 10 active consumer pods in a consumer group. If you scale your worker deployment to 20 pods, 10 pods will sit completely idle with zero partitions assigned!

Rule: Number of partitions determines the maximum horizontal consumer parallelism limit.

The Stop-the-World Rebalance Storm

Historically (Eager Rebalance), whenever a consumer joined, crashed, or took longer than max.poll.interval.ms to process a batch, the group coordinator revoked partitions from all workers, pausing all consumption worldwide for seconds!

Cure: Modern **Cooperative Sticky Rebalancing** revokes only the specific reassigned partition while other workers continue processing uninterrupted.

2. Append-Only Commit Log Engine: src/omniroute/streaming/log_engine.py Partitioned Log & Murmur2 Hashing 
# ==============================================================================
# OmniRoute Streaming - Multi-Partition Commit Log Engine
# ==============================================================================

import time
import hashlib
import asyncio
from dataclasses import dataclass
from typing import Dict, List, Optional


@dataclass(frozen=True)
class LogRecord:
    offset: int
    partition_id: int
    key: str
    payload: dict
    timestamp: float


class PartitionLog:
    """A single immutable append-only commit log partition."""
    def __init__(self, partition_id: int):
        self.partition_id = partition_id
        self._records: List[LogRecord] = []
        self._next_offset = 0
        self._lock = asyncio.Lock()

    async def append(self, key: str, payload: dict) -> LogRecord:
        async with self._lock:
            record = LogRecord(
                offset=self._next_offset,
                partition_id=self.partition_id,
                key=key,
                payload=payload,
                timestamp=time.time()
            )
            self._records.append(record)
            self._next_offset += 1
            return record

    def read_from_offset(self, start_offset: int, limit: int = 100) -> List[LogRecord]:
        """Zero-copy slice equivalent: reads immutable records starting at offset."""
        if start_offset >= len(self._records):
            return []
        return self._records[start_offset : start_offset + limit]


class DistributedTopic:
    """
    DISTRIBUTED TOPIC ENGINE:
    Partitions data across N independent append-only commit logs.
    Uses hash(key) % num_partitions to guarantee per-key total ordering.
    """
    def __init__(self, name: str, num_partitions: int = 4):
        self.name = name
        self.num_partitions = num_partitions
        self._partitions = [PartitionLog(i) for i in range(num_partitions)]

    def get_partition_id(self, key: str) -> int:
        """Murmur2-style hash distribution: same key ALWAYS lands on same partition."""
        digest = hashlib.md5(key.encode("utf-8")).hexdigest()
        return int(digest, 16) % self.num_partitions

    async def publish(self, key: str, payload: dict) -> LogRecord:
        pid = self.get_partition_id(key)
        return await self._partitions[pid].append(key, payload)

    def consume(self, partition_id: int, offset: int, limit: int = 100) -> List[LogRecord]:
        if partition_id < 0 or partition_id >= self.num_partitions:
            raise IndexError("Invalid partition ID")
        return self._partitions[partition_id].read_from_offset(offset, limit)

from fastapi import APIRouter, Depends, status, HTTPException
from pydantic import BaseModel, Field
from sqlalchemy.ext.asyncio import AsyncSession
from sqlalchemy import select
from typing import AsyncGenerator

from omniroute.streaming.log_engine import DistributedTopic
from omniroute.streaming.models import ConsumerGroupOffsetModel

router = APIRouter(prefix="/api/v1/stream", tags=["Streaming Commit Logs"])
telemetry_topic = DistributedTopic(name="driver.telemetry.v1", num_partitions=4)


class ProduceTelemetryEventDTO(BaseModel):
    driver_id: str = Field(..., description="Partition Key guaranteeing chronological ordering")
    lat: float
    lng: float
    speed: float


class CommitOffsetRequestDTO(BaseModel):
    group_id: str
    partition_id: int
    offset: int


async def get_session() -> AsyncGenerator[AsyncSession, None]:
    raise NotImplementedError


@router.post(
    "/produce",
    status_code=status.HTTP_201_CREATED,
    summary="Publish Telemetry Event to Partitioned Commit Log"
)
async def produce_stream_event(dto: ProduceTelemetryEventDTO):
    record = await telemetry_topic.publish(
        key=dto.driver_id,
        payload=dto.model_dump()
    )
    return {
        "status": "COMMITTED_TO_LOG",
        "topic": telemetry_topic.name,
        "partition": record.partition_id,
        "offset": record.offset
    }


@router.get(
    "/consume/{group_id}/{partition_id}",
    status_code=status.HTTP_200_OK,
    summary="Poll Records for Consumer Group by Partition"
)
async def consume_stream_events(
    group_id: str,
    partition_id: int,
    limit: int = 50,
    db: AsyncSession = Depends(get_session)
):
    # 1. Look up consumer group's committed offset
    stmt = select(ConsumerGroupOffsetModel).where(
        ConsumerGroupOffsetModel.group_id == group_id,
        ConsumerGroupOffsetModel.topic_name == telemetry_topic.name,
        ConsumerGroupOffsetModel.partition_id == partition_id
    )
    res = await db.execute(stmt)
    offset_record = res.scalar_one_or_none()
    current_offset = offset_record.committed_offset if offset_record else 0

    # 2. Read non-destructively from commit log
    records = telemetry_topic.consume(partition_id=partition_id, offset=current_offset, limit=limit)
    return {
        "group_id": group_id,
        "partition_id": partition_id,
        "read_offset": current_offset,
        "records_returned": len(records),
        "records": [
            {"offset": r.offset, "key": r.key, "payload": r.payload} for r in records
        ]
    }


@router.post(
    "/commit-offset",
    status_code=status.HTTP_200_OK,
    summary="Manually Commit Consumer Group Offset (At-Least-Once)"
)
async def commit_group_offset(
    dto: CommitOffsetRequestDTO,
    db: AsyncSession = Depends(get_session)
):
    stmt = select(ConsumerGroupOffsetModel).where(
        ConsumerGroupOffsetModel.group_id == dto.group_id,
        ConsumerGroupOffsetModel.topic_name == telemetry_topic.name,
        ConsumerGroupOffsetModel.partition_id == dto.partition_id
    )
    res = await db.execute(stmt)
    record = res.scalar_one_or_none()

    if not record:
        record = ConsumerGroupOffsetModel(
            group_id=dto.group_id,
            topic_name=telemetry_topic.name,
            partition_id=dto.partition_id,
            committed_offset=dto.offset
        )
        db.add(record)
    else:
        record.committed_offset = dto.offset

    await db.commit()
    return {"status": "OFFSET_COMMITTED", "group": dto.group_id, "offset": dto.offset}
