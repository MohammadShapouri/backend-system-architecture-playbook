Part 01

Computer Science: The Multi-Tier Latency & Throughput Mandate

When an API gateway or microservice scales to 100,000 requests per second across 50 Kubernetes pods, relying entirely on a centralized Redis cluster becomes a bottleneck.

Even with connection pooling and pipelining, 100k RPS against Redis saturates network switches, exhausts Linux socket file descriptors, and introduces a minimum round-trip penalty of 1.0ms to 2.5ms per query. If a request controller queries 10 cached entities sequentially, network latency alone inflates endpoint response time by 25ms.

The solution adopted by high-throughput tech giants (Meta, Netflix, Stripe) is **Hierarchical Multi-Tier Caching (Near-Caching)**:

The Hierarchical L1/L2 Data Access Cascade

Traversing from CPU Cache lines to Persistent Storage

Tier 1: L1 Near-Cache
In-Process RAM (Striped LRU / ARC)
0.0005ms • 0 Socket IO

Absorbs 85–90% of all lookups

→ on L1 miss →
Tier 2: L2 Remote Cache
Centralized Redis / Dragonfly
1.0ms – 2.0ms • Network Hop

Shared state across all pods

→ on L2 miss →
Tier 3: Database (SoR)
PostgreSQL / MongoDB
15ms – 100ms • Disk Read

System of Record authoritative store

The Mathematical Throughput Advantage:

Assume a service handles 100,000 queries per second. With L2 alone, all 100,000 queries hit Redis over the network. With an L1 Near-Cache achieving an 85% hit ratio, 85,000 queries are resolved entirely inside Python process memory in < 1 microsecond with zero network overhead. Redis traffic drops from 100,000 to 15,000 RPS, protecting network interfaces and eliminating Redis CPU saturation.

Part 02

The Coherency Dilemma: Split-Brain In-Memory Drift Across Replicas

While multi-tier caching delivers phenomenal read velocity, it introduces one of the most treacherous consistency bugs in distributed systems: L1 Cache Desynchronization.

The Multi-Replica L1 Cache Drift Bug
Pod A (Worker 1)
T=0s: Handles POST /user/update
1. Updates PostgreSQL: name="Bob"
2. Deletes from Redis L2: key="user:42"
3. Evicts from local L1: key="user:42"
Centralized L2 Redis
Key "user:42" evicted!
State: Fresh in DB ("Bob")
Next read will fetch "Bob"
Pod B (Worker 2)
T=1s: Handles GET /user/profile
Reads local L1 RAM...
L1 HIT! name="Alice" (STALE!)
✗ Serves stale data for 10 minutes!
⚠ Why Standard Cache-Aside Fails for L1:

Because Pod A has no direct memory access to Pod B's process RAM, Pod B has no idea that the underlying entity was mutated. If a user updates their profile and refreshes the browser, and the load balancer routes request 1 to Pod A and request 2 to Pod B, the user sees their old name reappear!

1. Redis Pub/Sub Invalidation Bus Recommended Standard

Whenever any pod mutates or invalidates an entity, it publishes a lightweight event to a dedicated Redis channel: PUBLISH cf:invalidate "user:42".

  • Sub-Millisecond Eviction: All running application pods listen on a background asynchronous subscriber task and purge the key from their local L1 in under 1ms.
  • Zero Payload Bloat: The bus transmits only the key string, not the payload. Pods evict lazily, preventing broadcast memory storms.
2. RESP3 Client-Side Tracking Redis 6+ Native

Leverages native RESP3 protocol push messages (CLIENT TRACKING on). Redis internally remembers which connection read which key and sends push notifications upon key modification.

  • Server Memory Overhead: Redis must store client tracking tables in RAM. If 1,000 clients track 500,000 keys, Redis server memory balloons significantly.
  • Driver Complexity: Requires full RESP3 push-mode support in the client driver. Pub/Sub remains more transparent and debuggable for most web services.
Part 03

Fault Tolerance: Bounding Inconsistency Drift Under Network Partitions

In distributed systems engineering, one must assume the network will fail. What happens if a network switch blips, and Pod B loses its connection to Redis for 500 milliseconds?

Because Redis Pub/Sub operates on at-most-once delivery (fire-and-forget), messages published while Pod B is disconnected are permanently lost. If an invalidation event for user:42 is missed during that 500ms blip, Pod B will never receive the eviction instruction.

To guarantee system safety, CacheForge enforces the Dual-Control Invalidation Protocol:

The Dual-Control Invalidation Invariant: Pub/Sub Eviction + L1 Safety TTL
\text{L1 Maximum Drift Bound} \le \min(\text{Pub/Sub Latency}, \text{L1 Safety TTL})
While the centralized L2 Redis cache might carry a TTL of 1 hour (3,600s), entries placed into local in-process L1 RAM are constrained by an absolute Safety TTL of 15 to 30 seconds. Under normal operations, Pub/Sub invalidates keys in < 1ms. If a network partition severs Pub/Sub, the maximum possible drift on any pod is mathematically capped at 30 seconds before the entry automatically self-expires!

1. Redis Pub/Sub Invalidation Bus: src/cacheforge/coherency/invalidation_bus.py Real-Time Cluster Eviction Broadcast 
# ==============================================================================
# CacheForge Coherency - Redis Pub/Sub Invalidation Bus (Milestone 06)
# ==============================================================================

import asyncio
import logging
from typing import Callable, Optional
import redis.asyncio as aioredis

logger = logging.getLogger("cacheforge.coherency")

class InvalidationBus:
    """
    REDIS PUB/SUB INVALIDATION BUS:
    Broadcasting key evictions across all distributed application replicas.
    Runs a non-blocking background consumer task to invalidate local L1 RAM.
    """
    def __init__(
        self,
        redis_url: str,
        channel_name: str = "cf:invalidation:events",
        local_evict_callback: Optional[Callable[[str], None]] = None
    ):
        self.redis_url = redis_url
        self.channel_name = channel_name
        self.local_evict_callback = local_evict_callback
        self._pub_client = aioredis.from_url(redis_url, decode_responses=True)
        self._sub_client: Optional[aioredis.Redis] = None
        self._listen_task: Optional[asyncio.Task] = None
        self._running = False

    async def start_listener(self) -> None:
        """Initializes dedicated subscriber connection and starts background task."""
        self._sub_client = aioredis.from_url(self.redis_url, decode_responses=True)
        self._running = True
        self._listen_task = asyncio.create_task(self._consume_invalidations())
        logger.info(f"InvalidationBus listener active on channel '{self.channel_name}'")

    async def _consume_invalidations(self) -> None:
        pubsub = self._sub_client.pubsub()
        await pubsub.subscribe(self.channel_name)

        while self._running:
            try:
                message = await pubsub.get_message(ignore_subscribe_messages=True, timeout=1.0)
                if message and message["type"] == "message":
                    invalidated_key = message["data"]
                    if self.local_evict_callback:
                        self.local_evict_callback(invalidated_key)
            except asyncio.CancelledError:
                break
            except Exception as exc:
                logger.error(f"Error in invalidation listener loop: {exc}")
                await asyncio.sleep(0.5)

    async def publish_invalidation(self, key: str) -> None:
        """Broadcasts a key eviction notification across all connected cluster pods."""
        await self._pub_client.publish(self.channel_name, key)

    async def close(self) -> None:
        self._running = False
        if self._listen_task:
            self._listen_task.cancel()
        if self._sub_client:
            await self._sub_client.aclose()
        await self._pub_client.aclose()
2. Hierarchical Multi-Tier Orchestrator: src/cacheforge/coherency/multitier.py L1 RAM + L2 Redis + Safety TTL 
# ==============================================================================
# CacheForge Coherency - Hierarchical Multi-Tier Cache Manager (Milestone 06)
# ==============================================================================

import time
from typing import Any, Callable, Optional, Awaitable
from cacheforge.core.lru import LRUCache
from cacheforge.storage.remote_client import RemoteCacheDriver
from cacheforge.coherency.invalidation_bus import InvalidationBus

class MultiTierCacheManager:
    """
    HIERARCHICAL L1/L2 CACHE MANAGER:
    - Tier 1 (L1): In-process local RAM (Sub-microsecond read latency).
    - Tier 2 (L2): Centralized Remote Redis (1-2ms shared cluster memory).
    - Invalidation: Real-time broadcast via Redis Pub/Sub bus.
    - Safety Boundary: Enforces max L1 TTL to bound split-brain drift during partitions.
    """
    def __init__(
        self,
        l2_driver: RemoteCacheDriver,
        invalidation_bus: InvalidationBus,
        l1_capacity: int = 5000,
        l1_safety_ttl_seconds: int = 30,  # Maximum staleness bound under network partition
        l2_default_ttl_seconds: int = 3600
    ):
        self.l2 = l2_driver
        self.bus = invalidation_bus
        self.l1_safety_ttl = l1_safety_ttl_seconds
        self.l2_default_ttl = l2_default_ttl_seconds

        # L1 stores tuple: (value, expiration_timestamp)
        self._l1 = LRUCache(capacity=l1_capacity)

        # Wire invalidation callback to local L1 eviction
        self.bus.local_evict_callback = self._evict_l1

    def _evict_l1(self, key: str) -> None:
        """Evicts key from local process RAM upon receiving bus broadcast."""
        self._l1.delete(key)

    async def get(
        self,
        key: str,
        db_loader: Optional[Callable[[], Awaitable[Any]]] = None
    ) -> Optional[Any]:
        now = time.time()

        # ------------------------------------------------------------------
        # STAGE 1: Check L1 Local Process RAM (Sub-microsecond latency)
        # ------------------------------------------------------------------
        l1_entry = self._l1.get(key)
        if l1_entry is not None:
            val, expires_at = l1_entry
            if now < expires_at:
                return val  # L1 HIT! (Zero socket round-trips)
            # L1 safety TTL expired: Evict expired near-cache entry
            self._l1.delete(key)

        # ------------------------------------------------------------------
        # STAGE 2: Check L2 Remote Centralized Redis (1-2ms latency)
        # ------------------------------------------------------------------
        l2_val = await self.l2.get(key)
        if l2_val is not None:
            # Populate local L1 with safety TTL boundary
            self._l1.put(key, (l2_val, now + self.l1_safety_ttl))
            return l2_val

        # ------------------------------------------------------------------
        # STAGE 3: Total Cache Miss → Execute Database Loader
        # ------------------------------------------------------------------
        if db_loader is None:
            return None

        db_data = await db_loader()
        if db_data is not None:
            # Populate L2 with long TTL and L1 with safety TTL
            await self.l2.set(key, db_data, ttl_seconds=self.l2_default_ttl)
            self._l1.put(key, (db_data, now + self.l1_safety_ttl))

        return db_data

    async def set_or_mutate(
        self,
        key: str,
        value: Any,
        db_writer: Optional[Callable[[], Awaitable[None]]] = None
    ) -> None:
        """
        COHERENT MUTATION PROTOCOL:
        1. Write to database (System of Record).
        2. Invalidate/Update L2 Redis cluster.
        3. Evict local L1 RAM immediately.
        4. Broadcast invalidation event over Pub/Sub bus to all peer pods!
        """
        if db_writer:
            await db_writer()

        # Update/Invalidate L2
        await self.l2.set(key, value, ttl_seconds=self.l2_default_ttl)

        # Evict caller's own L1
        self._l1.delete(key)

        # Broadcast invalidation across the cluster bus
        await self.bus.publish_invalidation(key)

import asyncio
import pytest
import pytest_asyncio
from testcontainers.redis import RedisContainer
from cacheforge.storage.remote_client import RemoteCacheDriver
from cacheforge.coherency.invalidation_bus import InvalidationBus
from cacheforge.coherency.multitier import MultiTierCacheManager

@pytest.fixture(scope="session")
def redis_server():
    with RedisContainer("redis:7-alpine") as server:
        yield server


@pytest.mark.integration
class TestMultiTierCoherency:
    """Verifies cross-pod L1 invalidation, L1 hits, and safety TTL bounds."""

    @pytest.mark.asyncio
    async def test_l1_invalidation_bus_evicts_peer_replica_near_cache(self, redis_server):
        url = f"redis://{redis_server.get_container_host_ip()}:{redis_server.get_exposed_port(6379)}/0"

        # Simulate Pod A
        driver_a = RemoteCacheDriver(redis_url=url)
        bus_a = InvalidationBus(redis_url=url, channel_name="test:invalidation")
        manager_a = MultiTierCacheManager(driver_a, bus_a)
        await bus_a.start_listener()

        # Simulate Pod B
        driver_b = RemoteCacheDriver(redis_url=url)
        bus_b = InvalidationBus(redis_url=url, channel_name="test:invalidation")
        manager_b = MultiTierCacheManager(driver_b, bus_b)
        await bus_b.start_listener()

        # Step 1: Prime Pod B's cache with "Alice"
        await manager_b.set_or_mutate("user:100", {"name": "Alice"})
        cached_on_b = await manager_b.get("user:100")
        assert cached_on_b["name"] == "Alice"
        assert "user:100" in manager_b._l1._lookup  # Present in Pod B's local RAM

        # Step 2: Pod A mutates user:100 to "Bob"
        await manager_a.set_or_mutate("user:100", {"name": "Bob"})

        # Step 3: Allow event loop to process Pub/Sub message propagation (< 20ms)
        await asyncio.sleep(0.05)

        # VERIFICATION: Key MUST be evicted from Pod B's local RAM!
        assert "user:100" not in manager_b._l1._lookup

        # Step 4: Next read on Pod B fetches updated "Bob" from L2 Redis!
        refreshed_on_b = await manager_b.get("user:100")
        assert refreshed_on_b["name"] == "Bob"

        # Teardown
        await bus_a.close()
        await bus_b.close()
        await driver_a.close()
        await driver_b.close()
Warning Track

Beginner Pitfalls & Architectural Anti-Patterns

❌ Infinite Local L1 TTLs (Partition Blindness)

Setting keys in local in-process L1 RAM with no expiration under the assumption that "Pub/Sub will always evict it".

Why this causes persistent stale data: Redis Pub/Sub offers at-most-once delivery. If an application pod restarts, experiences a GC pause, or loses network connectivity for 1 second, it misses the invalidation message. Without an automated L1 Safety TTL (15–30s), that pod serves stale data indefinitely until the container is manually killed!

❌ Broadcasting Full Payloads Over Pub/Sub

Publishing the entire updated 50KB JSON document across the invalidation bus: PUBLISH cf:bus "{'user': 42, 'data': ...}".

Why this causes broadcast storms: If 50 pods each publish 50KB updates at 1,000 writes/sec, Redis must broadcast $50\text{KB} \times 1,000 \times 50 = \mathbf{2.5\text{ GB/sec}}$ over the network! Furthermore, 50 pods deserialize payloads for keys their local users may never query. Always broadcast only the key string. Evict lazily on write; load on demand on read.
