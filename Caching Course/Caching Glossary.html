A Index

Active Defragmentation (activedefrag)

Redis • Ch. 9

A background memory compaction subsystem inside Redis. Reallocates scattered values into contiguous physical memory pages on the fly, reducing the mem_fragmentation_ratio back to nominal levels (~1.0–1.2) without downtime.

Adaptive Replacement Cache (ARC)

Algorithm • Ch. 2

A self-tuning eviction algorithm invented by Nimrod Megiddo and Dharmendra S. Modha. Balances recency (T1) and frequency (T2) dynamically using ghost metadata queues (B1, B2), providing scan-resistance without manual capacity tuning.

allkeys-lru (Eviction Policy)

Config • Ch. 9

The standard Redis maxmemory-policy for dedicated caching instances. Approximates LRU across all keys (both persistent and expiring) by sampling candidates, evicting the least recently accessed when memory limits are reached.

ASGI Cache Middleware

ASGI • Ch. 7

A pure ASGI 3.0 middleware executing at the outermost perimeter of the web stack. Intercepts raw response frames to stamp RFC 9111 headers, computes streaming ETags, and short-circuits conditional requests with empty 304 Not Modified frames before buffering memory.

B Index

Belady's Anomaly

Theory • Ch. 1

A counter-intuitive phenomenon in FIFO eviction where allocating more cache slots results in more cache misses for certain access patterns. Proves why stack-based algorithms like LRU are mathematically superior to naive queues.

Blake3 / SHA-256 ETag Hashing

Hashing • Ch. 7

Cryptographic and tree-based hashing algorithms used to compute Strong Entity Tags (ETags) over response bodies. Blake3 processes data at multiple gigabytes per second, enabling zero-latency validation on high-throughput JSON endpoints.

Bloom Filter

Algorithm • Ch. 4

A space-efficient probabilistic data structure that guarantees zero false negatives. Answers whether an element is definitely absent from the database, intercepting malicious non-existent ID queries before they reach SQL storage.

C Index

Cache-Aside (Lazy Loading)

Pattern • Ch. 4

The standard data access pattern where application code directly orchestrates caching: reads check the cache first, querying the DB on miss; writes update the DB and explicitly delete the cache entry.

Cache Avalanche

Outage • Ch. 4

An outage failure mode occurring when hundreds of thousands of keys share the identical expiration deadline. When that second arrives, all keys expire simultaneously, flooding the primary database with an unabsorbable traffic spike.

Cache Breakdown (Hotspot Invalidated)

Outage • Ch. 4, 5

The sudden expiration of a single hyper-popular hot key receiving thousands of requests per second. Simultaneous readers all observe a miss, firing duplicate heavy queries at downstream databases.

Cache-Control (RFC 9111)

HTTP • Ch. 7

The primary HTTP/1.1 and HTTP/2 header field used to express caching directives across browser, CDN, and proxy boundaries (e.g. public, max-age=120, stale-while-revalidate=60).

Cache Hit Ratio (CHR)

Metric • Ch. 1, 9

The percentage of read operations resolved entirely from cache: Hits / (Hits + Misses). A primary SRE golden signal; drops below 90% indicate cache pollution, stampedes, or undersized RAM.

Cache Penetration

Outage • Ch. 4

A failure mode where requests query keys that exist neither in the cache nor in the database (e.g., negative or random IDs). Because no data exists to be cached, 100% of queries punch through directly to the database.

Cache Tagging (Secondary Inverted Index)

Architecture • Ch. 8

Associating cached items with one or more tag sets in Redis (SADD tag:user:42 "key1"). Allows instant cascade invalidation of thousands of related keys without dangerous $O(N)$ wildcard KEYS * scans.

Change Data Capture (CDC)

Architecture • Ch. 8

Streaming committed row mutations directly from database Write-Ahead Logs (WAL) via engines like Debezium. Emits asynchronous invalidation events to message brokers, eliminating dual-write race conditions.

Conditional 304 Not Modified

HTTP • Ch. 7

The HTTP response status returned when a client's If-None-Match header matches the current resource ETag. Carries zero response body payload, saving up to 99% of cloud egress bandwidth.

D Index

Doubly Linked List (Sentinel-Backed)

Data Structure • Ch. 1

A bidirectional node chain initialized with permanent dummy HEAD and TAIL sentinels. Guarantees deterministic $O(1)$ node insertion, removal, and repositioning without null-check edge-case branching.

Dragonfly

Engine • Ch. 3

A modern C++20 drop-in Redis replacement built on a shared-nothing thread-per-core fiber architecture. Achieves millions of QPS per node with zero-fork snapshots and 20–30% lower RAM overhead.

Dual-Write Hazard

Vulnerability • Ch. 8

The distributed race condition that arises when application code attempts to update both a SQL database and a Redis cache sequentially across network boundaries, inevitably causing stale-state corruption upon container crashes or delayed packets.

E Index

Effective Access Time (EAT)

Mathematics • Ch. 1

The mathematical mean latency experienced across all read operations: EAT = (CHR × L_cache) + ((1 - CHR) × L_miss). Shows how slight drops in Hit Ratio cause exponential increases in average response time.

Entity Tag (ETag)

HTTP • Ch. 7

An opaque HTTP response header representing the version of a resource. Classified by RFC 9111 into **Strong ETags** (byte-exact, e.g. "a1b2c3") and **Weak ETags** (semantically equivalent, e.g. W/"v1").

Eviction Velocity

Metric • Ch. 9

The rate (evictions/sec) at which a cache discards unexpired keys to free memory for incoming items. Sustained high eviction velocity proves that working set demand exceeds physical RAM capacity.

F Index

FIFO (First-In, First-Out)

Algorithm • Ch. 1

A naive eviction algorithm that discards elements in the strict order they were inserted, regardless of access recency or frequency. Highly vulnerable to Belady's Anomaly and cache thrashing.

Frequency Decay (Aging)

Algorithm • Ch. 2

The technique of periodically attenuating access frequency counters in LFU caches (e.g., dividing counts by 2 or applying logarithmic time decay). Prevents historical popularity spikes from permanently blocking new items.

Frequency Starvation

Flaw • Ch. 2

The fatal flaw of un-decayed LFU where historically viral items accumulate counts in the hundreds of thousands, resisting eviction indefinitely while newly inserted items (with frequency 1) are evicted immediately.

H Index

Hierarchical Caching (L1/L2 Multi-Tier)

Architecture • Ch. 6

Layering ultra-low-latency in-process local RAM near-caches (L1: < 1μs) in front of distributed network-attached Redis clusters (L2: 1–2ms), resolving up to 90% of requests without socket I/O.

I Index

If-None-Match (Header)

HTTP • Ch. 7

The HTTP request header sent by clients presenting one or more cached ETag identifiers. If matching the server's current ETag, the server short-circuits with 304 Not Modified.

Invalidation Bus

Architecture • Ch. 6

A broadcast messaging channel (backed by Redis Pub/Sub) that broadcasts key eviction instructions across all running API replica pods in real time, purging stale L1 near-caches in under 1 millisecond.

J Index

jemalloc

Memory • Ch. 3, 9

The general-purpose memory allocator used internally by Redis and KeyDB. Employs slab allocation arenas to mitigate fragmentation, but can retain allocated virtual pages if defragmentation is unconfigured.

Jittered TTL

Resilience • Ch. 4

Adding randomized uniform or Gaussian noise ($\pm 10\text{–}20\%$) to cache expiration periods: ttl = base ± random(delta). Disperses mass key expirations over time, eliminating Cache Avalanches.

K Index

KeyDB

Engine • Ch. 3

A multithreaded open-source fork of Redis that scales across multiple CPU cores on a single machine using fine-grained spinlocks, eliminating single-thread CPU bottlenecks on large cloud VM instances.

Kirsch-Mitzenmacher Hashing

Mathematics • Ch. 4

A mathematical optimization proving that $k$ independent hash functions in a Bloom filter can be simulated using only two hash outputs: g_i(x) = (h1(x) + i × h2(x)) mod m with zero loss in asymptotic performance.

L Index

LFU (Least Frequently Used)

Algorithm • Ch. 2

An eviction algorithm tracking cumulative access counts. Implemented in $O(1)$ time using nested doubly linked frequency buckets, protecting popular long-term keys against one-off sequential scans.

Lock Striping

Concurrency • Ch. 2

Partitioning an in-process cache's key space across $N$ independent, lock-isolated stripes (routed via bitwise hash masks). Reduces thread lock contention by a factor of $N$ under heavy concurrent read/write load.

LRU (Least Recently Used)

Algorithm • Ch. 1

The classic eviction algorithm discarding the item unaccessed for the longest duration. Implemented in $O(1)$ time via a Hash Map linked to a Sentinel Doubly Linked List. Exploits temporal locality.

M Index

maxmemory-policy

Redis • Ch. 9

The configuration directive instructing Redis how to behave when allocated RAM ceiling is reached (options: allkeys-lru, volatile-lru, allkeys-lfu, noeviction).

MessagePack (msgpack)

Serialization • Ch. 3

A compact, binary-encoded serialization format offering full JSON data-type compatibility at 30–50% smaller payload sizes and 3× faster parsing speeds in Python C-extensions.

N Index

Near-Cache (L1 Cache)

Architecture • Ch. 6

An in-process cache residing within the application pod's RAM. Delivers sub-microsecond lookups with zero network socket hops, serving as the front-line shield for remote Redis clusters.

Null-Value Sentinel Caching (Negative Caching)

Resilience • Ch. 4

Explicitly writing a sentinel token ("__NULL_VAL__") with a short TTL (30–60s) into the cache when the database returns 0 rows, preventing repeated penetration queries from hitting the DB.

O Index

Outbox Pattern (Transactional Outbox)

Pattern • Ch. 8

A distributed systems pattern where entity mutations and outbox invalidation events are inserted into the database within the same local ACID transaction, guaranteeing that cache eviction messages are never lost if the app crashes.

P Index

Pickle Insecure Deserialization (RCE Hazard)

Security • Ch. 3

A critical vulnerability where caching payloads with Python's pickle allows attackers with Redis access to execute arbitrary shell commands inside application pods via __reduce__ payloads.

Probabilistic Early Expiration

Theory • Ch. 5

A mathematical paradigm where readers dynamically compute a recomputation probability as a key nears expiration. Dispatches background refreshes before key death, guaranteeing 0ms read latency.

R Index

Redis Cluster (Hash Slot Sharding)

Engine • Ch. 3

The distributed horizontal sharding architecture partition keys across 16,384 virtual hash slots using CRC16 checksums, enabling multi-terabyte storage across independent master nodes.

RFC 9111 (HTTP Caching Specification)

Standard • Ch. 7

The current IETF standard (published June 2022, replacing RFC 7234) formalizing HTTP cache freshness, validation algorithms, conditional status headers, and Cache-Control directives.

S Index

Safety TTL (Near-Cache Bound)

Resilience • Ch. 6

A hard upper-bound expiration (e.g. 15–30s) enforced on local in-process L1 cache entries. If a network partition severs the invalidation bus, drift across pods is mathematically guaranteed not to exceed this duration.

Scan Pollution (Sequential Scan Wipeout)

Flaw • Ch. 1, 2

The vulnerability in classic LRU where a large batch query or backup scan accesses cold records once, evicting the entire active hot operational working set and triggering a database collapse.

SingleFlight (Request Coalescing)

Concurrency • Ch. 5

An asynchronous request deduplication pattern. If 100 coroutines query the same key simultaneously on a cache miss, only 1 database query executes; the other 99 latch onto the shared asyncio.Future.

Spatial Locality (Locality in Space)

Physics • Ch. 1

The physical principle dictating that accessing a resource increases the likelihood that contiguous or logically adjacent memory locations will be accessed soon after (exploited by array prefetching and database table pages).

stale-while-revalidate

HTTP • Ch. 7

An RFC 9111 directive allowing caches to serve slightly stale content instantaneously while asynchronously dispatching a background revalidation request to the origin server.

T Index

Temporal Locality (Locality in Time)

Physics • Ch. 1

The fundamental computing law stating that an item referenced at time $t$ is highly likely to be accessed again in the immediate near future ($t + \Delta t$). The foundation of LRU and ARC.

10-Point Staff Production Audit

Audit • Ch. 9

The principal architecture certification checklist verifying bounded memory, Bloom penetration defense, XFetch stampede elimination, multi-tier coherency, and non-blocking ASGI streaming before production rollout.

Thundering Herd (Dogpiling Stampede)

Outage • Ch. 5

The concurrent event where thousands of readers simultaneously observe a cache miss on an expired hotspot key, overwhelming database connection pools with identical queries.

2Q (Two Queue)

Algorithm • Ch. 1

An eviction algorithm using a probationary FIFO queue for first-time accesses, promoting items to an active LRU queue only upon a second access within a time threshold.

V Index

volatile-lru

Config • Ch. 9

Redis eviction policy sampling only keys that have an explicit expiration set. Persistent keys with no TTL are protected from eviction.

W Index

Write-Behind (Write-Back)

Pattern • Ch. 4

A caching pattern where writes update the cache immediately, while a background worker asynchronously aggregates and flushes batched updates to the database on an interval.

Write-Through

Pattern • Ch. 4

A pattern where the application writes to the cache layer, which synchronously persists to the underlying database before returning success, ensuring continuous cache freshness.

X Index

XFetch Algorithm

Algorithm • Ch. 5

The VLDB 2015 optimal probabilistic cache stampede prevention algorithm: now - (β × δ × ln(rand())) > expiry. Triggers early asynchronous recomputation before a key expires, maintaining 0ms read latency under continuous traffic.

Z Index

Zombie Key

Flaw • Ch. 9

An abandoned key stored without an explicit TTL (TTL = -1) that is never accessed again, remaining resident in physical RAM indefinitely and causing silent cluster memory exhaustion.

Zstandard (zstd) Compression

Compression • Ch. 3

A real-time compression algorithm developed by Meta. Applied adaptively to payloads larger than 2KB, shrinking JSON and MessagePack byte streams by 70–85% with microsecond decompression speeds.
