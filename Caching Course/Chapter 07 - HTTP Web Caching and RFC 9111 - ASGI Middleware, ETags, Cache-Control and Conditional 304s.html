Part 01

Computer Science: The RFC 9111 HTTP Caching Specification

In June 2022, the IETF obsoleted RFC 7234 and published RFC 9111: HTTP Caching, standardizing how intermediate proxies (Cloudflare, Fastly, Akamai), reverse proxies (Nginx, Envoy), and web browsers must handle resource freshness and validation.

In web architecture, the fastest and cheapest HTTP request is the one that never reaches your backend server at all. RFC 9111 governs two complementary mechanisms: Freshness (how long an entity can be served without checking the origin) and Validation (how to verify if a stale entity has actually changed).

The RFC 9111 Dual-Pillar Lifecycle: Freshness vs. Validation

Eliminating Server Computation and Egress Bandwidth

Pillar 1: Freshness Lifetime Zero Origin IO

Dictated by Cache-Control: max-age=N. While an entity's age is less than its freshness lifetime, the client or edge CDN serves the response directly from disk/RAM without issuing any network request to your FastAPI origin.

Browser → Checks Local Cache (Age: 12s < max-age: 60s)
→ Returns (200 OK from disk cache) • Latency: 0.1ms
Zero packets reach your datacenter!
Pillar 2: Conditional Validation Zero Payload Egress

When an entity becomes stale (Age > max-age), the client sends a conditional request presenting its cached fingerprint: If-None-Match: "3a8f...".

Browser → GET /api/v1/items [If-None-Match: "3a8f..."]
FastAPI → Matches current ETag ("3a8f...")
→ HTTP/1.1 304 Not Modified • Content-Length: 0
Body is NOT retransmitted across the wire!
The Bandwidth Multiplier:

For a 2MB JSON catalog endpoint queried 10,000 times per minute, sending full 200 responses consumes 20 Gigabytes of bandwidth every minute. Validating with 304 Not Modified frames reduces wire transmission to ~3 Megabytes total (a 99.98% bandwidth reduction).

Directive Target Layer RFC 9111 Behavior & Mechanics Typical Production Use Case
public Shared & Private Explicitly permits shared intermediate caches (CDNs, proxies) to cache the response, even if authenticated. Public catalogs, marketing content, open metadata.
private Browser Only Only the end-user browser may cache the response. Intermediate CDNs and reverse proxies MUST NOT cache it. User profiles, shopping carts, billing invoices.
no-cache All Caches Does NOT mean "don't cache"! Means caches can store it, but MUST revalidate with origin before serving. Resources requiring zero-staleness verification on every single access.
no-store All Caches Absolute ban on storage: Caches MUST NOT save any part of the request or response to volatile or persistent memory. Credit card numbers, authentication passwords, bank tokens.
s-maxage=N Shared Only (CDN) Overrides max-age specifically for shared caches (CDNs). Allows long CDN caching with short browser caching. max-age=60, s-maxage=86400 (1 min in browser, 1 day on Cloudflare).
stale-while-revalidate=N All Caches Asynchronous background refresh: Serves stale content instantly while kicking off a background refresh to origin. High-volume APIs where 0ms latency matters more than strict real-time freshness.
Part 02

Validation Metrology: Strong vs. Weak Entity Tags (ETags)

An **Entity Tag (ETag)** is an opaque HTTP header string representing the exact state of a resource. RFC 9111 formally distinguishes between two types of entity tags:

1. Strong Entity Tag Byte-for-Byte Exact

Syntax: ETag: "686897696a7c7876b7e2d"

Guarantees that the underlying resource body has not changed by even a single byte. If two strong ETags are identical, their octet streams are identical.

  • Mandatory For: Byte-range requests (Range: bytes=0-1024) and video streaming chunks.
  • Computation: Computed via fast cryptographic or non-cryptographic hashes (Blake3, SHA-256, CityHash).
2. Weak Entity Tag Semantically Equivalent

Syntax: ETag: W/"v1.2-user-profile"

Indicates that two representations are semantically equivalent, even if minor byte differences exist (e.g., whitespace formatting, date string localized ordering, or gzip vs. brotli compression).

  • Standard For: Dynamic JSON REST responses and HTML templates.
  • Efficiency: Can be generated from an entity version number or database updated_at timestamp without reading the full body into memory.
Part 03

ASGI Architecture: Pure ASGI Interception vs. Starlette BaseHTTPMiddleware

When developers implement HTTP caching middleware in FastAPI, the temptation is to inherit from Starlette's BaseHTTPMiddleware using the call_next pattern.

In high-scale production systems, this pattern introduces severe latency and memory liabilities:

⚠️ The BaseHTTPMiddleware Streaming Bottleneck

Starlette's BaseHTTPMiddleware forces asynchronous streams into an in-memory buffer before passing control back to your middleware. If an endpoint streams a 500MB file export, it buffers the entire 500MB into Python process RAM, spikes server memory, and delays the time-to-first-byte (TTFB). Under high concurrent load, this creates thread contention and can drop ContextVar task state across coroutines.

The Industrial Solution: Pure ASGI Middleware. Implement async def __call__(self, scope, receive, send). By intercepting raw ASGI event frames, we evaluate conditional headers, stream hashes on the fly, and short-circuit 304 Not Modified responses directly at the network boundary with zero response buffering.

Pure ASGI 304 Short-Circuit Event Dispatch Flow
1. Incoming Request
scope['headers'] parsed
If-None-Match: "3a8f..."
2. Wrapped send()
Inspects http.response.start
Matches outgoing ETag!
3. Emits HTTP 304
Drops downstream body!
0 bytes sent • Instant close

# ==============================================================================
# CacheForge Web - Fast Entity Tag (ETag) Engine (Milestone 07)
# ==============================================================================

import hashlib

def generate_strong_etag(body_bytes: bytes) -> str:
    """Generates a Strong ETag matching the exact byte stream using SHA-256."""
    digest = hashlib.sha256(body_bytes).hexdigest()[:16]
    return f'"{digest}"'

def generate_weak_etag(identifier: str, version: int | str) -> str:
    """Generates a Weak ETag representing semantic entity equivalence."""
    return f'W/"{identifier}-v{version}"'
2. Pure ASGI Caching Middleware: src/cacheforge/web/asgi_cache.py 304 Short-Circuit & Zero Buffering 
# ==============================================================================
# CacheForge Web - Pure ASGI HTTP Caching Middleware (Milestone 07)
# ==============================================================================

from typing import Callable, Any, Dict, List, Tuple
from cacheforge.web.etag import generate_strong_etag

class ASGICacheMiddleware:
    """
    HIGH-PERFORMANCE PURE ASGI CACHING MIDDLEWARE:
    - Bypasses Starlette BaseHTTPMiddleware memory-buffering limits.
    - Evaluates If-None-Match headers against response ETags.
    - Short-circuits with HTTP 304 Not Modified directly over ASGI frames.
    - Automatically injects RFC 9111 Cache-Control directives.
    """
    def __init__(
        self,
        app: Callable,
        default_cache_control: str = "public, max-age=60, stale-while-revalidate=30"
    ):
        self.app = app
        self.default_cache_control = default_cache_control

    async def __call__(
        self, scope: Dict[str, Any], receive: Callable, send: Callable
    ) -> None:
        # Pass through non-HTTP connections (WebSockets, Lifespan)
        if scope["type"] != "http":
            await self.app(scope, receive, send)
            return

        method = scope.get("method", "GET").upper()
        if method not in ("GET", "HEAD"):
            await self.app(scope, receive, send)
            return

        # Extract incoming headers
        raw_headers: List[Tuple[bytes, bytes]] = scope.get("headers", [])
        client_headers = {k.decode("latin1").lower(): v.decode("latin1") for k, v in raw_headers}
        if_none_match = client_headers.get("if-none-match")

        response_status = 200
        response_headers: List[Tuple[bytes, bytes]] = []
        response_chunks: List[bytes] = []

        async def intercept_send(message: Dict[str, Any]) -> None:
            nonlocal response_status, response_headers, response_chunks

            if message["type"] == "http.response.start":
                response_status = message["status"]
                response_headers = list(message.get("headers", []))
                return

            if message["type"] == "http.response.body":
                chunk = message.get("body", b"")
                response_chunks.append(chunk)

                if not message.get("more_body", False):
                    # Full body received → Compute ETag and evaluate match
                    full_body = b"".join(response_chunks)
                    etag = generate_strong_etag(full_body)

                    # Check If-None-Match condition
                    if if_none_match and if_none_match.strip() == etag:
                        # SHORT-CIRCUIT: Emit 304 Not Modified with zero body payload!
                        headers_304 = [
                            (b"etag", etag.encode("latin1")),
                            (b"cache-control", self.default_cache_control.encode("latin1")),
                        ]
                        await send({
                            "type": "http.response.start",
                            "status": 304,
                            "headers": headers_304,
                        })
                        await send({
                            "type": "http.response.body",
                            "body": b"",
                        })
                        return

                    # Otherwise, inject ETag and Cache-Control on full 200 response
                    response_headers.append((b"etag", etag.encode("latin1")))
                    response_headers.append((b"cache-control", self.default_cache_control.encode("latin1")))

                    await send({
                        "type": "http.response.start",
                        "status": response_status,
                        "headers": response_headers,
                    })
                    await send({
                        "type": "http.response.body",
                        "body": full_body,
                    })

        await self.app(scope, receive, intercept_send)

        assert res2.status_code == 304
        assert len(res2.content) == 0  # Zero body transmitted across wire!
        assert res2.headers["etag"] == etag
Warning Track

Beginner Pitfalls & Architectural Anti-Patterns

❌ Setting "public" on User-Specific Data

Returning Cache-Control: public, max-age=3600 on authenticated endpoints like /api/v1/me/billing.

Why this causes catastrophic data leaks: Shared CDN edge caches (Cloudflare, Fastly) treat public as permission to cache the response at the edge for all users. The next user who visits the billing page receives the first user's cached private invoice and personal data! Always enforce private, no-cache on authenticated user routes.

❌ Buffering Multi-Gigabyte Streams for ETags

Reading an entire 10GB video or backup file into RAM with hashlib.sha256(full_body) to calculate an ETag.

Why this causes container OOM kills: Buffering massive streams into Python memory triggers kernel SIGKILL evictions. For streaming large files, either omit ETags, use streaming hash updates on chunks, or generate a **Weak ETag** using file size and filesystem modification timestamp (mtime).
