Part 01

Foundational Mechanics: What is a "Backend"?

At its core, a web server is an infinite loop that listens for electrical pulses or optical signals on a network interface card (NIC), reassembles them into discrete TCP segments, parses an application-level string format called HTTP, and executes application logic based on the requested path.

1 Raw HTTP Over the Wire

When a browser or client communicates with your API, it sends a plain text stream over a TCP socket. An HTTP request is not a Python dictionary; it is raw bytes structured according to RFC standards: 

POST /api/v1/notes?draft=true HTTP/1.1
Host: api.notevault.io
User-Agent: Mozilla/5.0
Content-Type: application/json
Content-Length: 42

{"title": "Ideas", "content": "Learn ASGI"}

The web framework's primary job is to parse this byte-stream: split the start line into Verb, Path, and Protocol, collect the key-value headers, read the body length, and hand off clean objects to your code.

2 From Socket to Handler

How does your Python code actually receive this string? The operating system manages network sockets via system calls:

  1. Bind & Listen: The server process binds to an IP and Port (e.g., 127.0.0.1:8000) via an OS socket.
  2. Kernel Buffer: The OS kernel receives TCP packets, acknowledges them, verifies checksums, and buffers them.
  3. Event Notification: Under Linux, the server uses non-blocking I/O multiplexing primitives like epoll (or kqueue on macOS) to alert the Python event loop that bytes are ready to read.
  4. Deserialization & Dispatch: Bytes are parsed into a normalized Python format and routed to the corresponding route handler function.
Part 02

Server Gateways: Why WSGI Died & ASGI Won

In the era of traditional frameworks (Flask, Django), Python apps relied on the WSGI (Web Server Gateway Interface) specification (PEP 3333). WSGI is strictly synchronous: one worker thread handles exactly one HTTP request from start to finish.

Legacy WSGI (Synchronous Thread-per-Request)

If a worker handles a request that sleeps or queries an external slow API for 3 seconds, that worker is completely frozen. It cannot handle any other client.

Client A ──► [ Worker 1 (BLOCKED 3.0s in I/O) ]
Client B ──► [ Worker 2 (BLOCKED 1.5s in DB) ]
Client C ──► [ QUEUED IN OS SOCKET BUFFER... ] 🛑

Consequence: You need 500 OS threads or processes to handle 500 concurrent slow queries, destroying RAM and thrashing CPU cache via constant context switches.

Modern ASGI (Asynchronous Server Gateway Interface)

FastAPI uses ASGI (powered by Uvicorn or Hypercorn). An ASGI server runs a single thread containing an Event Loop that orchestrates cooperative multitasking.

Client A ──► [ Event Loop: pauses A via `await` ]
Client B ──► [ Event Loop: switches to B instant ]
Client C ──► [ Event Loop: starts C immediately ] 🚀

Consequence: A single process can hold tens of thousands of open connections simultaneously with minimal memory overhead.

What an ASGI Application Actually Looks Like

FastAPI is just a specialized ASGI callable. At the bare-metal level, any valid ASGI 3.0 application is simply an asynchronous function with this exact signature: 

async def simple_asgi_app(scope, receive, send):
    """
    scope:   A dict containing metadata about the connection (HTTP method, path, headers, client IP)
    receive: An async channel to listen for incoming chunks of the request body
    send:    An async channel to push response frames (status, headers, body) back to the server
    """
    assert scope['type'] == 'http'

    # 1. Send the HTTP Response Status and Headers frame
    await send({
        'type': 'http.response.start',
        'status': 200,
        'headers': [[b'content-type', b'text/plain']],
    })

    # 2. Send the HTTP Response Body frame
    await send({
        'type': 'http.response.body',
        'body': b'Hello from bare-metal ASGI! FastAPI wraps this for you.',
    })
Why this matters: FastAPI doesn't replace ASGI; it sits on top of it. Starlette provides the high-level routing, request wrappers, and response classes, while Pydantic handles validation, and FastAPI binds them together seamlessly.

The Exact Dependencies for Milestone 01

Create a file named requirements.txt. We intentionally pin versions using compatible release operators (~=) so your environment receives security patches without breaking major API changes.

# requirements.txt - Milestone 01 Core Stack
fastapi~=0.110.0 # High-performance web framework
uvicorn[standard]~=0.28.0 # Production-grade lightning-fast ASGI server
pydantic~=2.6.0 # Core schema validation engine (Rust-backed)
pydantic-settings~=2.2.0 # 12-Factor App Environment config loader

Why the "[standard]" tag on uvicorn?

Without uvicorn[standard], Uvicorn installs with pure-Python fallbacks. The standard extra compiles C-extensions: uvloop (a lightning-fast event loop replacement for Python's default asyncio built on libuv) and httptools (a fast C-parser for HTTP streams). Always install [standard] in production.

Step 1: Fail-Fast Configuration (app/config.py)

Following the Twelve-Factor App methodology, configuration must be strictly separated from code. Never hardcode credentials or ports in your files. Instead, use pydantic-settings to parse environment variables, cast them into strong types, and crash the server instantly on startup if a required value is missing.

app/config.py
from pydantic_settings import BaseSettings, SettingsConfigDict
from functools import lru_cache

class Settings(BaseSettings):
    # Strong typing: if someone sets PORT=abc, Pydantic raises an error on startup
    APP_NAME: str = "NoteVault API"
    ENVIRONMENT: str = "development"
    DEBUG_MODE: bool = False
    API_V1_PREFIX: str = "/api/v1"

    # Pydantic v2 Settings configuration: read from .env if present
    model_config = SettingsConfigDict(
        env_file=".env",
        env_file_encoding="utf-8",
        case_sensitive=True
    )

# @lru_cache (Least Recently Used Cache) ensures the .env file is read from disk
# only ONCE upon application boot. Every subsequent call returns the cached instance.
@lru_cache
def get_settings() -> Settings:
    return Settings()

settings = get_settings()

Route Decorators, Type Hints & Introspection

When you annotate a function with @app.get("/notes/{note_id}"), what actually happens? FastAPI does not just register your function inside a routing map; it inspects your function signature at startup using Python's standard inspect module and type metadata.

Under the Hood

The 4-Step Route Invocation Pipeline

1. Route Match: Uvicorn receives the HTTP request and checks the URL path against FastAPI's registered Radix-Tree router.
Incoming URL

2. Extraction & Coercion: FastAPI reads path params, query string, and headers. It coerces string representations ("42") to declared Python types (int).

4. Handler Execution & Response Serialization: Clean, typed values are passed into your controller. The return value is auto-serialized into JSON.

How FastAPI Distinguishes Parameters

FastAPI uses a simple, deterministic rule set to differentiate between path variables, query string parameters, and request bodies:

Parameter Syntax Declared Where? Classification Example Invocation
@app.get("/notes/{id}") Inside the Path URL string Path Parameter GET /notes/42
def get_notes(limit: int) In function signature, NOT in URL Query Parameter GET /notes?limit=10
def get_notes(q: str | None = None) In signature, has default value Optional Query Param GET /notes (defaults to None)

Architectural Standard Application Lifespan Protocol: Modern @asynccontextmanager lifespan vs. Deprecated on_event

In older tutorials, you will frequently see event registration written like this:

✗ DEPRECATED: on_event("startup" / "shutdown") 
@app.on_event("startup")
async def startup_event():
    init_db_connection()

@app.on_event("shutdown")
async def shutdown_event():
    close_db_connection()

Disjointed handlers cannot share state safely, fail to handle exceptions across startup/shutdown symmetrically, and are officially deprecated by Starlette.

✓ MODERN: Unified Lifespan Async Context Manager 
from contextlib import asynccontextmanager

@asynccontextmanager
async def lifespan(app: FastAPI):
    # STARTUP: runs before requests arrive
    init_db_connection()
    yield
    # SHUTDOWN: runs on SIGTERM / exit
    close_db_connection()

app = FastAPI(lifespan=lifespan)

A single clean context manager wraps the entire application runtime. Any code before yield runs on boot; code after yield is guaranteed to execute on server shutdown.

app/main.py
# ==============================================================================
# NoteVault Backend - Milestone 01 (Foundation, Routing & Lifespan)
# ==============================================================================

from typing import Optional
from datetime import datetime, timezone
from contextlib import asynccontextmanager
from fastapi import FastAPI, HTTPException, status, Query, Path
from app.config import settings

# 1. Ephemeral In-Memory Storage
# In Chapter 06, we will seamlessly replace this dict with a PostgreSQL database via SQLAlchemy.
NOTE_DATABASE: dict[int, dict] = {
    1: {
        "id": 1,
        "title": "FastAPI Architecture Rules",
        "content": "Always validate input boundaries; keep business logic modular.",
        "tags": ["backend", "python"],
        "created_at": datetime.now(timezone.utc).isoformat(),
        "is_archived": False,
    },
    2: {
        "id": 2,
        "title": "ASGI vs WSGI",
        "content": "ASGI handles asynchronous concurrency without blocking threads.",
        "tags": ["networking"],
        "created_at": datetime.now(timezone.utc).isoformat(),
        "is_archived": False,
    }
}

# 2. Modern Lifespan Context Manager
# Replaces deprecated @app.on_event("startup") and @app.on_event("shutdown")
@asynccontextmanager
async def lifespan(app: FastAPI):
    # --- APPLICATION STARTUP ---
    print(f"[STARTUP] Initializing {settings.APP_NAME} in {settings.ENVIRONMENT} mode...")
    print(f"[STARTUP] Pre-seeded in-memory store with {len(NOTE_DATABASE)} records.")
    
    yield  # Server accepts traffic while paused at yield

    # --- APPLICATION SHUTDOWN ---
    print(f"[SHUTDOWN] Cleaning up resources and shutting down {settings.APP_NAME}...")

# 3. Instantiate the FastAPI Engine with the Lifespan Handler
app = FastAPI(
    title=settings.APP_NAME,
    description="Production-grade personal knowledge vault API.",
    version="1.0.0",
    docs_url="/docs" if settings.ENVIRONMENT == "development" else None,
    redoc_url="/redoc" if settings.ENVIRONMENT == "development" else None,
    lifespan=lifespan,
)

# ==============================================================================
# System & Diagnostic Endpoints
# ==============================================================================

@app.get("/health", tags=["System"], summary="Health Check")
async def health_check():
    """
    Used by orchestrators (Kubernetes, AWS ECS) to verify the process is alive.
    Must always return fast and never hit a slow database.
    """
    return {
        "status": "healthy",
        "environment": settings.ENVIRONMENT,
        "timestamp": datetime.now(timezone.utc).isoformat()
    }

# ==============================================================================
# Note Management Endpoints (CRUD)
# ==============================================================================

@app.get(
    f"{settings.API_V1_PREFIX}/notes",
    tags=["Notes"],
    summary="List & Query Notes",
    status_code=status.HTTP_200_OK
)
async def list_notes(
    # Query parameters declared as optional with metadata validation via Query()
    search: Optional[str] = Query(
        None, 
        min_length=2, 
        max_length=50, 
        description="Case-insensitive search string to match against title or content."
    ),
    include_archived: bool = Query(
        False, 
        description="Whether to return soft-deleted/archived notes."
    ),
    limit: int = Query(
        10, 
        ge=1, 
        le=100, 
        description="Pagination limit (Max 100 per page)."
    )
):
    """
    Fetches notes with automatic query parameter casting and defensive boundaries.
    """
    results = list(NOTE_DATABASE.values())

    # Filter by archive status
    if not include_archived:
        results = [note for note in results if not note["is_archived"]]

    # Filter by search string
    if search:
        query_str = search.lower()
        results = [
            note for note in results 
            if query_str in note["title"].lower() or query_str in note["content"].lower()
        ]

    return results[:limit]


@app.get(
    f"{settings.API_V1_PREFIX}/notes/{note_id}",
    tags=["Notes"],
    summary="Retrieve a specific note by ID"
)
async def get_note(
    note_id: int = Path(..., ge=1, description="The unique numerical primary key of the note.")
):
    # Check if record exists; if not, raise a standard HTTP 404 response
    if note_id not in NOTE_DATABASE:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail=f"Note with ID {note_id} does not exist in the database."
        )
    return NOTE_DATABASE[note_id]


@app.delete(
    f"{settings.API_V1_PREFIX}/notes/{note_id}",
    tags=["Notes"],
    summary="Delete a note",
    status_code=status.HTTP_204_NO_CONTENT
)
async def delete_note(
    note_id: int = Path(..., ge=1)
):
    """
    HTTP 204 No Content: Instructs the client that the record was destroyed,
    and returns an empty response body.
    """
    if note_id not in NOTE_DATABASE:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail=f"Cannot delete note {note_id}: record not found."
        )
    
    del NOTE_DATABASE[note_id]
    return None
Warning Track

Beginner Pitfalls & Anti-Patterns

❌ Never Return Dicts for Errors

Beginners often write: return {"error": "Not Found"}.

Why this is bad: The HTTP response status code is still 200 OK! Frontend clients and mobile apps inspect the HTTP status code first. If you return 200, frontend code thinks the call succeeded. Always raise HTTPException(status_code=404, ...).

❌ Mutable Default Arguments

Never do this: def get_items(tags: list = []).

Why this is bad: In Python, default lists are instantiated once at module load time. Every user request will append to and share that exact same list in memory! Use tags: Optional[list[str]] = None instead.
