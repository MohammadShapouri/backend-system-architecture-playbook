Part 01

Cryptography & Identity: AuthN vs. AuthZ

Many developers conflate Authentication and Authorization. Conflating them leads to severe architectural flaws, such as BOLA (Broken Object Level Authorization), which routinely ranks as the #1 threat on the OWASP API Security Top 10 list.

AuthN

Authentication ("Who are you?")

The process of establishing and verifying identity. The client presents identity claims (e.g., an email address) alongside secret proof (e.g., a raw password, a biometric token, or an MFA one-time passcode). The server validates the proof and issues a session artifact (such as a signed JWT).

Endpoint: POST /api/v1/auth/token → Returns Bearer JWT
AuthZ

Authorization ("What can you do?")

The process of checking whether a verified identity has permission to read or modify a specific resource. Even if Bob proves he is Bob (AuthN), he must not be authorized to view or delete Alice's private notes (AuthZ).

Check: note.owner_id == current_user.id (Row-Level Security)
Cryptographic Primitives: Hashing vs. Encryption
Two-Way Encryption (AES-GCM / RSA)

A reversible operation. Plain text is encrypted into ciphertext using a secret key, and can later be decrypted back into the original plain text using that same key (symmetric) or a private key (asymmetric).

✗ NEVER use encryption for user passwords! If an attacker compromises the server's decryption key, all plain-text passwords across your database are exposed.
One-Way Cryptographic Hashing (Bcrypt / Argon2)

A mathematically irreversible function. Plain text is scrambled into a fixed-length digest. There is no decryption key; it cannot be reversed. To verify a password, the server hashes the incoming attempt with the stored salt and compares the two digests.

✓ The Gold Standard. Even if an attacker dumps your database, they cannot reverse the hashes without massive, cost-prohibitive computing power.
Part 02

Inside Bcrypt: Adaptive Work Factors & The 72-Byte Boundary

Why can't we use standard fast hash functions like MD5 or SHA-256 for passwords? Fast hash functions were engineered for verifying data integrity at high throughput. A modern GPU cluster can compute billions of SHA-256 hashes per second, allowing an attacker to brute-force a leaked database in minutes.

Bcrypt is a Key Derivation Function (KDF) based on the Blowfish cipher. It is slow by design, neutralizing brute-force and dictionary attacks.

Anatomy of a Bcrypt Hash String

When you inspect a stored password hash in NoteVault's database, you will see a 60-character string formatted like this:

$2b$12$n9qXvcv4hkCuv1HsS/d.OOe7cQn0vIsuj6cK6vL5hF6eN8/7C.2eS
$2b$ Algorithm Identifier (Bcrypt specification revision)
12$ Cost/Work Factor (2^12 = 4,096 computation rounds)
n9qXv... (22 chars) Cryptographic Salt (Random 128-bit value defeats Rainbow Tables)
e7cQn... (31 chars) Computed Hash Digest (The final cryptographic output)

⚠️ The 72-Byte Bcrypt Truncation Trap: A Critical Security Boundary

Under the hood, the original Blowfish cipher processes keys in chunks of up to 576 bits (exactly 72 bytes). If a user enters a password with 100 characters, standard Bcrypt silently ignores everything after byte 72!

User Password A: "SuperSecretLongPasswordThatExceedsSeventyTwoBytesLengthByALot111111111"
User Password B: "SuperSecretLongPasswordThatExceedsSeventyTwoBytesLengthByALot222222222"
→ Both produce the EXACT SAME hash because bytes beyond index 71 are ignored!

Defensive Engineering Fix: Always use a Pydantic schema rule on registration: Field(min_length=8, max_length=72), or pre-hash the password with SHA-256 before feeding it to Bcrypt if you require unlimited-length passphrases.

Part 03

Anatomy of a JWT: Stateless Proof of Identity

Traditional server-side sessions store random IDs in cookies and keep session data in a database (like Redis). On every single incoming API call, the server must query the session database to identify the user.

A JSON Web Token (JWT) is stateless. The user's identity, permissions, and expiration timestamp are encoded directly inside the token. The server verifies the token's validity using a cryptographic signature, eliminating the need for a database lookup on every request.

RFC 7519 Token Structure

Three Base64URL-encoded JSON segments separated by dots

eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTYiLCJ1c2VybmFtZSI6ImFsaWNlIiwiZXhwIjoxNzkzNDQ4MDAwfQ.4T8_x6dI_WwN1X9eZp_4_7A6B8C9D0E1F2G3H4I5J6K
1. Header 
{
  "alg": "HS256",
  "ty": "JWT"
}

Specifies the cryptographic signing algorithm (e.g., HMAC with SHA-256).

2. Payload (Claims) 
{
  "sub": "1",
  "email": "alice@notevault.io",
  "exp": 1793448000
}

Contains registered claims: sub (subject/user ID) and exp (Unix expiration timestamp).

3. Signature 
HMACSHA256(
  base64(header) + "." +
  base64(payload),
  SECRET_KEY
)

Ensures data integrity. If a client tampers with the payload, the signature verification fails and the request is rejected.

Security Note: JWTs are SIGNED, NOT ENCRYPTED!

Anyone can paste a JWT into a tool like jwt.io to read the decoded payload. Never store sensitive data (like plain passwords, API keys, or credit card numbers) in a JWT payload. The signature guarantees integrity (the data has not been altered), not secrecy.

Part 04

Production Architecture: Custom Auth vs. Turnkey Solutions

Implementing the basic password-hashing and token-signing flow below is essential for understanding security mechanics. However, building an enterprise-grade auth system involves significantly more complexity:

1. Token Revocation

Because JWTs are stateless, you cannot "log out" a stolen token until it expires. True revocation requires keeping a distributed blocklist in Redis or using short-lived access tokens (15 mins) paired with rotating refresh tokens.

2. Account Recovery & MFA

Production applications require secure email verification, password reset tokens with single-use expirations, rate-limiting on login routes to prevent brute forcing, and TOTP (Time-based One-Time Password) MFA support.

3. The Production Choice

For commercial SaaS backends, consider using battle-tested libraries like FastAPI-Users, or offloading authentication to dedicated Identity Providers (IdPs) like Supabase Auth, Auth0, or Clerk via OAuth2/OIDC.

1. Cryptographic Utilities: app/security.py Bcrypt & PyJWT Logic 
# ==============================================================================
# NoteVault Backend - Cryptographic Security Layer (Milestone 07)
# ==============================================================================

from datetime import datetime, timedelta, timezone
from typing import Optional
import jwt
from passlib.context import CryptContext
from app.config import settings

# 1. Password Hashing Context
# Uses bcrypt with automatic salt generation and work-factor management
pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

# 2. Token Configuration
JWT_SECRET_KEY = getattr(settings, "JWT_SECRET_KEY", "insecure_dev_secret_change_in_production_32bytes")
ALGORITHM = getattr(settings, "ALGORITHM", "HS256")
ACCESS_TOKEN_EXPIRE_MINUTES = getattr(settings, "ACCESS_TOKEN_EXPIRE_MINUTES", 30)

def hash_password(raw_password: str) -> str:
    """Hashes a plain-text password using Bcrypt with a secure salt."""
    return pwd_context.hash(raw_password)

def verify_password(raw_password: str, hashed_password: str) -> bool:
    """Verifies a plain-text attempt against a stored Bcrypt hash string."""
    return pwd_context.verify(raw_password, hashed_password)

def create_access_token(data: dict, expires_delta: Optional[timedelta] = None) -> str:
    """
    Generates an RFC 7519 compliant JSON Web Token signed with HMAC-SHA256.
    Ensures an explicit UTC expiration timestamp ('exp') is included.
    """
    to_encode = data.copy()
    expire = datetime.now(timezone.utc) + (expires_delta or timedelta(minutes=ACCESS_TOKEN_EXPIRE_MINUTES))
    to_encode.update({"exp": expire})
    
    encoded_jwt = jwt.encode(to_encode, JWT_SECRET_KEY, algorithm=ALGORITHM)
    return encoded_jwt

from typing import Optional, List
from datetime import datetime, timezone
from sqlalchemy import String, Text, Integer, Boolean, DateTime, JSON, ForeignKey
from sqlalchemy.orm import Mapped, mapped_column, relationship
from app.database import Base

class UserModel(Base):
    """Physical database table representing users."""
    __tablename__ = "users"

    id: Mapped[int] = mapped_column(Integer, primary_key=True, autoincrement=True)
    email: Mapped[str] = mapped_column(String(255), unique=True, index=True, nullable=False)
    hashed_password: Mapped[str] = mapped_column(String(255), nullable=False)
    is_active: Mapped[bool] = mapped_column(Boolean, default=True, nullable=False)
    created_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True),
        default=lambda: datetime.now(timezone.utc),
        nullable=False
    )

    # Relationship: One user has many notes
    notes: Mapped[List["NoteModel"]] = relationship(back_populates="owner", cascade="all, delete-orphan")


class NoteModel(Base):
    """Updated Note model with Foreign Key binding to the owner user."""
    __tablename__ = "notes"

    id: Mapped[int] = mapped_column(Integer, primary_key=True, autoincrement=True)
    title: Mapped[str] = mapped_column(String(120), nullable=False, index=True)
    content: Mapped[str] = mapped_column(Text, nullable=False)
    tags: Mapped[List[str]] = mapped_column(JSON, default=list, nullable=False)
    priority: Mapped[int] = mapped_column(Integer, default=1, nullable=False)
    is_archived: Mapped[bool] = mapped_column(Boolean, default=False, nullable=False, index=True)
    created_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True),
        default=lambda: datetime.now(timezone.utc),
        nullable=False
    )

    # FOREIGN KEY LINK: Binds every note row to an authentic user
    owner_id: Mapped[int] = mapped_column(Integer, ForeignKey("users.id", ondelete="CASCADE"), index=True, nullable=False)
    
    # Relationship traversal
    owner: Mapped[UserModel] = relationship(back_populates="notes")

Abuse Defense Rate Limiting: Defending Login Endpoints Against Brute-Force & CPU Exhaustion

Because Bcrypt is intentionally slow and computationally expensive (taking 50ms–200ms of CPU time per hash check), the /api/v1/auth/token login route is the #1 target for Denial-of-Service (DoS) and credential stuffing. An attacker sending 50 concurrent requests per second can easily pin all CPU cores to 100%, taking down the entire backend.

FastAPI backends defend against this using Rate Limiting (via libraries like slowapi or Redis-backed token buckets), throttling requests by client IP address: 

from slowapi import Limiter, _rate_limit_exceeded_handler
from slowapi.util import get_remote_address
from slowapi.errors import RateLimitExceeded

# 1. Instantiate Limiter keyed by client IP address (stored in memory or Redis)
limiter = Limiter(key_func=get_remote_address)
app.state.limiter = limiter
app.add_exception_handler(RateLimitExceeded, _rate_limit_exceeded_handler)

# 2. Apply strict rate limit to the CPU-heavy login route
@router.post("/token")
@limiter.limit("5/minute")  # Allows max 5 login attempts per minute per IP!
def login_for_access_token(request: Request, ...):
    ...

If an attacker exceeds 5 attempts in a minute, FastAPI immediately short-circuits the call and returns an HTTP 429 Too Many Requests response without calculating any expensive Bcrypt hashes.

4. Auth Router with Rate Limiting: app/routers/auth.py Registration & Token Issuance 
# ==============================================================================
# NoteVault Backend - Authentication Router (Milestone 07)
# ==============================================================================

from fastapi import APIRouter, HTTPException, status, Depends, Request
from fastapi.security import OAuth2PasswordRequestForm
from sqlalchemy import select
from slowapi import Limiter
from slowapi.util import get_remote_address

from app.database import SessionLocal
from app.models import UserModel
from app.schemas import UserCreate, UserResponse, Token
from app.security import hash_password, verify_password, create_access_token
from app.dependencies import DbSession

limiter = Limiter(key_func=get_remote_address)
router = APIRouter(prefix="/api/v1/auth", tags=["Authentication"])

@router.post("/register", response_model=UserResponse, status_code=status.HTTP_201_CREATED)
def register_user(payload: UserCreate, db: DbSession):
    # Check if email is already registered
    existing_user = db.scalar(select(UserModel).where(UserModel.email == payload.email))
    if existing_user:
        raise HTTPException(
            status_code=status.HTTP_409_CONFLICT,
            detail="An account with this email address already exists."
        )

    # Create and persist the user with their salted Bcrypt hash
    new_user = UserModel(
        email=payload.email,
        hashed_password=hash_password(payload.password),
        is_active=True
    )
    db.add(new_user)
    db.commit()
    db.refresh(new_user)
    return new_user


@router.post("/token", response_model=Token)
@limiter.limit("5/minute")  # RATE LIMIT: Blocks brute-force password guessing & CPU starvation
def login_for_access_token(
    request: Request,
    db: DbSession,
    form_data: OAuth2PasswordRequestForm = Depends()
):
    """
    Standard OAuth2 specification login endpoint.
    form_data.username contains the user's submitted email address.
    """
    user = db.scalar(select(UserModel).where(UserModel.email == form_data.username))
    
    # Constant-time mitigation against timing attacks: Always run password verification
    if not user or not verify_password(form_data.password, user.hashed_password):
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Incorrect email or password.",
            headers={"WWW-Authenticate": "Bearer"},
        )
    
    if not user.is_active:
        raise HTTPException(status_code=400, detail="Inactive user account.")

    # Issue the signed JWT with user ID as the subject ('sub')
    access_token = create_access_token(data={"sub": str(user.id)})
    return {"access_token": access_token, "token_type": "bearer"}
5. Guard Dependency: app/dependencies.py Authenticating Route Invocations 
# Append to app/dependencies.py:
from fastapi.security import OAuth2PasswordBearer
import jwt
from app.security import JWT_SECRET_KEY, ALGORITHM
from app.models import UserModel
from sqlalchemy import select

# Informs Swagger UI (/docs) that the token is acquired from /api/v1/auth/token
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="/api/v1/auth/token")

def get_current_user(
    token: Annotated[str, Depends(oauth2_scheme)],
    db: DbSession
) -> UserModel:
    """
    Validates the JWT signature and extracts the user.
    If the token is invalid or expired, raises an HTTP 401 error immediately.
    """
    credentials_exception = HTTPException(
        status_code=status.HTTP_401_UNAUTHORIZED,
        detail="Could not validate credentials.",
        headers={"WWW-Authenticate": "Bearer"},
    )
    try:
        payload = jwt.decode(token, JWT_SECRET_KEY, algorithms=[ALGORITHM])
        user_id_str: str = payload.get("sub")
        if user_id_str is None:
            raise credentials_exception
        user_id = int(user_id_str)
    except (jwt.PyJWTError, ValueError):
        raise credentials_exception

    user = db.scalar(select(UserModel).where(UserModel.id == user_id))
    if user is None or not user.is_active:
        raise credentials_exception
    return user

# Type alias for clean route parameter declarations
CurrentUser = Annotated[UserModel, Depends(get_current_user)]

# In app/routers/notes.py:
from app.dependencies import DbSession, CurrentUser

@router.post("", response_model=NoteResponse, status_code=status.HTTP_201_CREATED)
def create_note(
    payload: NoteCreate,
    db: DbSession,
    current_user: CurrentUser  # GUARD: Requires valid JWT; injects authenticated user
):
    # BIND TO AUTHENTICATED USER: Automatically links owner_id to current_user.id
    new_note = NoteModel(
        title=payload.title,
        content=payload.content,
        tags=payload.tags,
        priority=payload.priority,
        owner_id=current_user.id
    )
    db.add(new_note)
    db.commit()
    db.refresh(new_note)
    return new_note


@router.get("", response_model=List[NoteResponse])
def list_notes(
    db: DbSession,
    current_user: CurrentUser,
    limit: int = 10,
    skip: int = 0
):
    # MULTI-TENANT ISOLATION: A user can ONLY query notes they own!
    stmt = (
        select(NoteModel)
        .where(NoteModel.owner_id == current_user.id)
        .where(NoteModel.is_archived == False)
        .offset(skip)
        .limit(limit)
    )
    return db.scalars(stmt).all()


@router.delete("/{note_id}", status_code=status.HTTP_204_NO_CONTENT)
def delete_note(
    note_id: int,
    db: DbSession,
    current_user: CurrentUser
):
    # AUTHORIZATION CHECK: Must match both note_id AND owner_id
    stmt = select(NoteModel).where(NoteModel.id == note_id, NoteModel.owner_id == current_user.id)
    note = db.scalar(stmt)
    if not note:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail="Note not found or unauthorized to delete."
        )
    
    note.is_archived = True
    db.commit()
    return None
Warning Track

Beginner Pitfalls & Anti-Patterns

❌ Broken Object Level Authorization (BOLA)

Writing select(NoteModel).where(NoteModel.id == note_id) without verifying that note.owner_id == current_user.id.

Why this is catastrophic: Any authenticated user can access, modify, or delete any other user's private data simply by changing the ID in the URL. Always scope every query by the authenticated user's ID.

❌ Hardcoding Secrets in Version Control

Committing JWT_SECRET_KEY = "my_super_secret_key" directly into your Git repository.

Why this happens: Automated scrapers scan public commits on GitHub for hardcoded strings. If an attacker discovers your secret key, they can forge valid admin tokens without ever knowing user passwords. Always load keys from environment variables or a secrets manager.
