Part 01

Design Patterns: Inversion of Control (IoC)

In traditional procedural software, a function directly instantiates its own dependencies. If function get_notes() needs a database, it imports the database driver and opens a socket. This approach is called tight coupling.

✗ Tightly Coupled (The Anti-Pattern)

The controller assumes full responsibility for creating, maintaining, and closing external resources: 

@router.get("/notes")
def read_notes():
    # Direct instantiation inside the controller
    db = PostgresDatabasePool.get_connection()
    notes = db.query(...)
    db.close()
    return notes

Fatal Flaws:

  • Untestable: You cannot run a unit test without launching a live PostgreSQL instance.
  • Leaky: If db.query() raises an exception, db.close() never executes, leaking network sockets.
  • Rigid: You cannot swap storage backends without modifying all your route files.

✓ Inversion of Control (The DI Way)

The controller declares its requirements in its function parameters. The framework injects the dependency from the outside: 

@router.get("/notes")
def read_notes(db: NoteStore = Depends(get_db)):
    # The route only cares about using the store
    return db.get_all()

Architectural Benefits:

  • Single Responsibility: The route focuses strictly on HTTP handling and response formatting.
  • Guaranteed Cleanup: The framework manages setup and teardown, even if crashes occur.
  • Mockable: In test files, get_db can be swapped for an in-memory test double without altering production code.
Part 02

Under the Hood: The Directed Acyclic Graph (DAG)

FastAPI’s dependency injection system is hierarchical. Dependencies can themselves depend on other dependencies. When a request arrives, FastAPI inspects the route's parameters using Python's standard inspect module, builds a Directed Acyclic Graph (DAG), and resolves dependencies from the bottom up.

Dependency Resolution Tree

FastAPI builds and executes this graph for each incoming request

Target Route Handler: update_note(...) Receives fully resolved: (note_id, current_user, db_session)
↑ Injects resolved values
get_current_user Depends on: token, db_session
get_db_session Depends on: engine connection pool
↑ Resolves dependencies first
oauth2_scheme Parses Authorization header
get_settings Cached config (LRU Cache)

FastAPI computes the topological sort of this graph, guaranteeing that prerequisite tasks (such as token extraction or connection acquisition) execute in the correct order.

Documentation Note Per-Request Dependency Result Caching (use_cache=True)

Notice in our DAG that both update_note and get_current_user require get_db_session. Does FastAPI execute get_db_session() twice?

No. By default, FastAPI calls dependencies with Depends(dependency, use_cache=True). During a single HTTP request lifecycle, the first time get_db_session executes, FastAPI caches its return value in an internal dictionary scoped to that request. Subsequent references within the same request retrieve the cached instance, preventing duplicate database sessions.

Part 03

Resource Lifecycles: The yield Context Manager

Standard functions use return to return a value and terminate execution. However, stateful backend resources (like database sessions, network sockets, or file locks) require a two-phase lifecycle: setup before the request runs, and cleanup after the response is sent.

// Anatomy of a Yielding Dependency
def get_db_session():
    # =========================================================================
    # PHASE 1: SETUP (Executes BEFORE your route controller logic runs)
    # =========================================================================
    session = SessionFactory()  # Check out a session from the connection pool
    try:
        # FastAPI pauses get_db_session right here!
        # It hands 'session' to your route and lets the route execute.
        yield session
    finally:
        # =====================================================================
        # PHASE 2: TEARDOWN (GUARANTEED to run AFTER the route finishes)
        # =====================================================================
        # Code inside finally runs even if your controller raises an uncaught exception!
        session.close()  # Returns connection back to pool for other requests

⚠️ The Connection Pooling Trap: Sessions vs. Engines

A common mistake among backend engineers is confusing a Database Engine (Pool) with a Database Session (Transaction Sandbox).

Opening a physical TCP connection to PostgreSQL or MySQL takes 20 to 100 milliseconds due to the TCP handshake and TLS negotiation. If your dependency creates a brand-new create_engine() inside get_db() on every HTTP request, your database will quickly reject connections with FATAL: too many connections under load.

Rule: The Engine and Connection Pool must be created once at application startup. Your yielding dependency should only check out a lightweight Session from that shared pool, and return it inside finally: session.close().

1. Dependency Registry: app/dependencies.py Decoupled Repository & Providers 
# ==============================================================================
# NoteVault Backend - Dependencies & Repositories (Milestone 05)
# ==============================================================================

from typing import Annotated, Generator, Optional, List, Dict
from datetime import datetime, timezone
from fastapi import Depends, Query

# ------------------------------------------------------------------------------
# 1. NoteRepository: Encapsulates storage logic (The Unit of Work pattern)
# In Chapter 06, this class will interface directly with SQLAlchemy Sessions.
# ------------------------------------------------------------------------------
class NoteRepository:
    # Module-level storage simulation
    _datastore: Dict[int, dict] = {
        1: {
            "id": 1,
            "title": "FastAPI Architecture Rules",
            "content": "Always validate input boundaries; keep business logic modular.",
            "tags": ["backend", "python"],
            "priority": 2,
            "created_at": datetime.now(timezone.utc),
            "updated_at": None,
            "is_archived": False,
        }
    }
    _id_counter: int = 1

    def list_notes(
        self, 
        search: Optional[str] = None, 
        include_archived: bool = False, 
        limit: int = 10, 
        skip: int = 0
    ) -> List[dict]:
        records = list(self._datastore.values())
        if not include_archived:
            records = [r for r in records if not r["is_archived"]]

        if search:
            q = search.lower()
            records = [
                r for r in records 
                if q in r["title"].lower() or q in r["content"].lower()
            ]
        return records[skip : skip + limit]

    def get_by_id(self, note_id: int) -> Optional[dict]:
        return self._datastore.get(note_id)

    def create(self, data: dict) -> dict:
        self._id_counter += 1
        new_record = {
            **data,
            "id": self._id_counter,
            "is_archived": False,
            "created_at": datetime.now(timezone.utc),
            "updated_at": None,
        }
        self._datastore[self._id_counter] = new_record
        return new_record

    def update(self, note_id: int, updates: dict) -> Optional[dict]:
        record = self._datastore.get(note_id)
        if not record:
            return None
        for k, v in updates.items():
            record[k] = v
        record["updated_at"] = datetime.now(timezone.utc)
        self._datastore[note_id] = record
        return record


# ------------------------------------------------------------------------------
# 2. Dependency Providers with Lifecycle Hooks
# ------------------------------------------------------------------------------
def get_note_repo() -> Generator[NoteRepository, None, None]:
    """
    Yields an active repository handle.
    Guarantees clean exit block execution upon request termination.
    """
    repo = NoteRepository()
    try:
        yield repo
    finally:
        # Future: session.close(), metrics increment, audit log flushes
        pass


# ------------------------------------------------------------------------------
# 3. Composite Query Parameter Dependency
# Encapsulates reusable pagination parameters across any listing endpoint
# ------------------------------------------------------------------------------
class PaginationParams:
    def __init__(
        self,
        skip: int = Query(0, ge=0, description="Number of records to skip."),
        limit: int = Query(10, ge=1, le=100, description="Max records to return.")
    ):
        self.skip = skip
        self.limit = limit


# ------------------------------------------------------------------------------
# 4. Modern Python 3.10+ Annotated Dependency Aliases
# Cleans up route signatures, avoiding verbose `= Depends(...)` repetition
# ------------------------------------------------------------------------------
NoteRepoDep = Annotated[NoteRepository, Depends(get_note_repo)]
PaginationDep = Annotated[PaginationParams, Depends()]
2. Refactored Router: app/routers/notes.py Clean Controller Inversion 
# ==============================================================================
# NoteVault Backend - Notes API Router (Milestone 05)
# ==============================================================================

from typing import Optional, List
from fastapi import APIRouter, HTTPException, status, Query, Path
from app.schemas import NoteCreate, NoteUpdate, NoteResponse
from app.dependencies import NoteRepoDep, PaginationDep

router = APIRouter()

@router.post(
    "",
    response_model=NoteResponse,
    status_code=status.HTTP_201_CREATED,
    summary="Create a new note"
)
async def create_note(payload: NoteCreate, repo: NoteRepoDep):
    """
    The route controller is now decoupled from the storage layer.
    The repository is injected into 'repo' via NoteRepoDep.
    """
    new_note = repo.create(payload.model_dump())
    return new_note


@router.get(
    "",
    response_model=List[NoteResponse],
    summary="List notes with injected pagination"
)
async def list_notes(
    repo: NoteRepoDep,
    pagination: PaginationDep,
    search: Optional[str] = Query(None, min_length=2, max_length=50),
    include_archived: bool = Query(False),
):
    # Reusable pagination parameters injected seamlessly
    return repo.list_notes(
        search=search,
        include_archived=include_archived,
        limit=pagination.limit,
        skip=pagination.skip
    )


@router.get("/{note_id}", response_model=NoteResponse)
async def get_note(
    note_id: int = Path(..., ge=1),
    repo: NoteRepoDep = ...
):
    record = repo.get_by_id(note_id)
    if not record:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail=f"Note {note_id} does not exist."
        )
    return record


@router.patch("/{note_id}", response_model=NoteResponse)
async def update_note(
    note_id: int = Path(..., ge=1),
    payload: NoteUpdate = ...,
    repo: NoteRepoDep = ...
):
    updates = payload.model_dump(exclude_unset=True)
    updated = repo.update(note_id, updates)
    if not updated:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail=f"Note {note_id} does not exist."
        )
    return updated
Part 05

Testing: Hot-Swapping with dependency_overrides

The primary reason enterprise engineering teams adopt Dependency Injection is isolated testability. FastAPI applications expose a dictionary called app.dependency_overrides. During a test suite run, you can override any production dependency with a mock or test double without modifying your route code.

How Pytest Swaps the Database in Memory

from fastapi.testclient import TestClient
from app.main import app
from app.dependencies import get_note_repo, NoteRepository

# 1. Define an isolated, ephemeral mock repository for the test suite
class MockNoteRepository(NoteRepository):
    def __init__(self):
        # Fresh, isolated sandbox state for each test run
        self._datastore = {
            999: {"id": 999, "title": "Mock Test", "content": "Test doubles in action", "tags": [], "priority": 1, "is_archived": False}
        }
        self._id_counter = 999

def override_get_note_repo():
    return MockNoteRepository()

# 2. Tell FastAPI to swap the production dependency for our mock
app.dependency_overrides[get_note_repo] = override_get_note_repo

client = TestClient(app)

def test_read_note_mocked():
    response = client.get("/api/v1/notes/999")
    assert response.status_code == 200
    assert response.json()["title"] == "Mock Test"

# 3. Clean up overrides after testing finishes
app.dependency_overrides.clear()

Notice the Separation:

The test verifies the HTTP routing, serialization, and status codes, but runs entirely in memory without writing to a live database or making external network calls.

Warning Track

Beginner Pitfalls & Anti-Patterns

❌ Omitting the Try...Finally Block

Writing def get_db(): db = Session(); yield db; db.close() without wrapping it in a try...finally.

Why this is dangerous: If an exception is raised inside your route handler or a response serialization fails, Python jumps out of the execution context immediately. Any cleanup lines placed after a bare yield are skipped. Always wrap the yield statement in a try...finally block to ensure cleanup runs.

❌ Calling Dependencies Directly in Routes

Writing async def read_notes(): db = get_db() inside a route handler.

Why this fails: Calling a yielding dependency function directly simply returns a Python generator object (<generator object get_db at 0x...>). It bypasses FastAPI’s DI engine, so the dependency isn't resolved, cached, or cleaned up. Always declare dependencies in parameters using Depends().
