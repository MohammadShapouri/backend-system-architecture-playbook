Architecture Fundamentals

Interception & Recursive Aggregation in Modern Systems

As applications scale, two major structural tensions emerge:

  1. Cross-Cutting Pollution: When security checks, telemetry, audit hashing, or caching leak directly into business models, classes swell into unmaintainable monsters violating the Single Responsibility Principle.
  2. Hierarchical Asymmetry: When systems manage items grouped into containers (e.g., individual stocks grouped into sub-funds, grouped into regional trusts, grouped into parent conglomerates), codebases often end up riddled with brittle isinstance(node, Leaf) checks and nested loops.
// The Structural Interception & Aggregation Triad:

Decorator layers new behavior dynamically while maintaining the identical contract. Proxy controls and guards access to an object behind the identical contract. Composite enables clients to treat singular objects and recursive hierarchies identically through a unified contract.

Design Pattern #09

Pattern Name: Decorator (Wrapper)

Formal Classification: Structural Pattern • Gang of Four (GoF) Reference p. 175

💡 The Real-World Metaphor (Plain English)

Imagine stepping outside on a freezing winter day. You start with your base clothing: a basic t-shirt.

If it starts raining, you don't undergo surgery to replace your skin with waterproof scales. You slip on a sweater. If the wind starts howling, you slip a waterproof windbreaker jacket over the sweater. If it gets dark, you strap on a reflective safety vest over the jacket.

Each garment (Decorator) wraps around you, adds a specific capability (insulation, water resistance, visibility), and preserves your core identity: you are still a person who can walk, run, and enter buildings. You can layer garments on and peel them off in any combination at runtime.

The Problem: Modifying Core Classes or Incurring Inheritance Sprawl

In NexusCore, we have an OrderExecutor that sends trades directly to market clearing venues. Suddenly, compliance demands three new requirements:

  • Log an immutable audit trail for every executed trade.
  • Record real-time execution latency metrics in Prometheus.
  • Encrypt sensitive client order payloads using HMAC signatures.

If an engineer uses inheritance to address this, they face a massive subclass explosion: AuditedOrderExecutor, MetricAuditedOrderExecutor, EncryptedMetricAuditedOrderExecutor. Alternatively, modifying the core class directly pollutes clean business logic with telemetry and cryptography dependencies: 

# ------------------------------------------------------------------------------
# ANTI-PATTERN: Polluting Core Execution with Every Cross-Cutting Concern
# ------------------------------------------------------------------------------

class MonolithicOrderExecutor:
    def execute_order(self, order_id: str, symbol: str, amount: float):
        # 1. Prometheus Metrics logic glued into core trading logic:
        start_time = time.perf_counter()
        
        # 2. Cryptographic encryption logic glued into core trading logic:
        encrypted_sig = hmac.new(b"sec", f"{order_id}:{amount}".encode(), hashlib.sha256).hexdigest()
        
        # 3. Actual trading logic (buried under noise!):
        wire_payload = {"id": order_id, "sym": symbol, "sig": encrypted_sig}
        success = send_to_clearing_house(wire_payload)
        
        # 4. Audit logging logic glued into core trading logic:
        audit_file.write(f"EXECUTED:{order_id}:{amount}:{time.time()}\n")
        metrics_counter.inc()
        
        # Result: Violates Single Responsibility. Cannot test execution in isolation!
        return success
Deep Concept: GoF Object Decorator vs. Python `@decorator` Syntax

In Python, the word "decorator" often refers to function annotations: @audit_log. While conceptually related, there is a fundamental architectural distinction:

Python Function Decorators (@wrap)

Applied at module load time (compile time) to a function signature. Every single invocation of that function will execute the decorator wrapper statically. Difficult to conditionally remove or rearrange dynamically per customer/session.

Gang of Four Object Decorator

Applied at runtime via object composition. You take an active object and dynamically wrap it: executor = MetricsDecorator(AuditDecorator(BaseExecutor())). Different sessions can configure different stacks on the fly.

The GoF Decorator Wrapping Pipeline
Outermost Wrapper MetricsOrderDecorator
Measures execution δt
→ delegates to →
Middle Wrapper AuditLogOrderDecorator
Writes tamper-evident hash
→ delegates to →
Core Component RealOrderExecutor
Pure order wire dispatch
Total Interface Transparency:

Every single wrapper implements the exact same base interface (IOrderExecutor). The caller simply calls executor.execute(order), completely oblivious to whether 0, 1, or 5 decorators are silently wrapping the invocation!

✔ When to Use Decorator
  • You need to add responsibilities to individual objects dynamically and transparently at runtime without affecting other objects.
  • You want to assign cross-cutting concerns (logging, encryption, rate limiting, caching) without cluttering domain logic.
  • Extension by subclassing is impractical because combinations of independent features would cause an exponential class explosion.
✘ When NOT to Use Decorator
  • The component's interface has dozens of methods. Wrapping a 40-method class requires forwarding 39 methods manually, creating massive boilerplate.
  • Code relies heavily on concrete object identity (isinstance(obj, RealClass)), since decorators wrap instances in an outer shell.
Design Pattern #10

Pattern Name: Proxy (Surrogate)

Formal Classification: Structural Pattern • Gang of Four (GoF) Reference p. 207

💡 The Real-World Metaphor (Plain English)

Imagine a debit card. A debit card is a Proxy for your actual physical bank vault.

When you purchase a coffee, you do not hire armed guards to wheel a 500-pound steel safe filled with gold bullion into the café. You tap your plastic debit card. The card implements the exact same financial transaction interface as cash: it can settle debts.

However, the card controls access: it prompts for a PIN (Protection Proxy), connects to the remote banking network across the country on demand (Remote Proxy), and defers moving actual physical reserves until the end of the day (Virtual Proxy).

The Three Enterprise Proxy Archetypes

While a Decorator focuses on adding new capabilities, a **Proxy focuses on controlling and managing access** to the underlying object:

1. Virtual Proxy (Lazy) On-Demand Init

Defers instantiating an expensive object until the exact moment a method is first called. Prevents slow server startup and avoids allocating unused socket connections.

2. Protection Proxy (RBAC) Access Gatekeeper

Validates permissions, authentication tokens, or tenant identity before forwarding the call to the real service. Raises security exceptions transparently.

3. Remote Proxy (RPC) Network Camouflage

Hides the fact that the actual service is running on another machine across gRPC or TCP sockets. Handles network serialization while looking like a local Python method call.

1. Caller

→ invokes →

1. Verifies TRADER role
2. Lazily connects TCP socket

Heavy, connected client
Executes live order
✔ When to Use Proxy
  • You have an expensive heavyweight service (e.g. database connection pool, high-memory ML model) that should only initialize if and when called.
  • You need strict security and role-based access control checking prior to invoking domain logic.
  • You want to maintain a local representation of a remote gRPC or HTTP microservice without leaking network I/O boilerplate into caller code.
✘ When NOT to Use Proxy
  • The target object is lightweight, fast, and already in memory. Adding a proxy layer just adds useless call overhead.
  • You are introducing remote proxies that hide high network latency and intermittent network failures behind synchronous method calls (leads to unhandled timeout crashes).
Design Pattern #11

Pattern Name: Composite (Object Tree)

Formal Classification: Structural Pattern • Gang of Four (GoF) Reference p. 163

💡 The Real-World Metaphor (Plain English)

Imagine calculating the total shipping weight of an order in an Amazon warehouse.

A shipment consists of a giant master cardboard crate. Inside that crate are two smaller boxes and an unwrapped hammer (a leaf item). Inside one of the smaller boxes are three tiny gift boxes, and inside each gift box is a watch.

To compute the total weight, you don't write complex code that unpacks every box individually with different rules for small vs. large boxes. You simply pick up any container or item and call .get_weight(). A box recursively sums the weight of its contents; a single hammer simply returns its own weight. The caller treats boxes and hammers identically!

The Problem: Modeling Institutional Asset Portfolios

In institutional finance, a global wealth holding is never a flat list. It is a deeply nested tree:

Global Hedge Fund Portfolio (Root Composite)
├── North America Fund (Composite)
│ ├── Tech Growth Account (Composite)
│ │ ├── StockHolding: AAPL ($1,500,000) [Leaf]
│ │ └── StockHolding: NVDA ($2,400,000) [Leaf]
│ └── Commodity Hedge (Composite)
│ └── GoldContract ($800,000) [Leaf]
└── European Mutual Trust (Composite)
└── CashReserve: EUR ($500,000) [Leaf]

Without the Composite Pattern, writing a function to compute total valuation or calculate portfolio risk requires ugly, brittle conditional loops checking whether an object is a list, a folder, or a holding: 

# ------------------------------------------------------------------------------
# ANTI-PATTERN: Brittle Recursive Type Checking
# ------------------------------------------------------------------------------

def calculate_total_value(node):
    total = 0.0
    if isinstance(node, StockHolding):
        return node.shares * node.market_price
    elif isinstance(node, CashReserve):
        return node.fiat_balance
    elif isinstance(node, PortfolioGroup):
        for child in node.sub_items:
            # Ugly recursion with endless isinstance checks:
            total += calculate_total_value(child)
    return total
    # Every time a new asset type (e.g. BondHolding, Crypto) is added, this function breaks!
The Composite Pattern Structural Uniformity
IPortfolioComponent
.get_market_value() • .get_risk_score()
↓ implemented by both ↓
Leaf: AssetHolding

Represents individual base items (Stocks, Bonds, Cash). Has zero children. Returns its own exact calculated market value.

Composite: PortfolioGroup

Holds an internal collection of List[IPortfolioComponent]. Recursively sums values of children without caring if they are leaves or nested groups!

The Recursive Polymorphism Invariant:

The caller can execute root_portfolio.get_market_value() on a portfolio containing 50,000 sub-accounts. The entire tree traverses itself polymorphically in a single call with zero isinstance branches!

Structural Pattern Core Intent Internal Structure Child/Target Relationship
Decorator Adds responsibilities dynamically to an object without altering its interface. Holds 1 reference to an instance of the identical interface. Linear chain (Wrapper around wrapper).
Proxy Controls and manages access to an object without altering its interface. Holds 1 reference to an instance of the identical interface (often lazily initialized). Surrogate / Gatekeeper to a single real subject.
Composite Treats individual objects and hierarchical compositions uniformly. Holds a collection (List/Set) of child instances sharing the component interface. Recursive tree hierarchy (Root → Branches → Leaves).

1. Execution Decorators: src/nexuscore/execution/decorators.py GoF Decorator Pattern 
# ==============================================================================
# NexusCore Execution - GoF Decorator Implementations for Cross-Cutting Concerns
# ==============================================================================

import time
import hashlib
from abc import ABC, abstractmethod
from typing import Dict, Any, List
from nexuscore.orders.models import TradeOrder

# ------------------------------------------------------------------------------
# Base Component Interface
# ------------------------------------------------------------------------------
class IOrderExecutionService(ABC):
    """Common interface implemented by both concrete executor and all decorators."""
    @abstractmethod
    def execute_order(self, order: TradeOrder) -> Dict[str, Any]:
        pass


# ------------------------------------------------------------------------------
# Concrete Component (Core Business Logic)
# ------------------------------------------------------------------------------
class BaseOrderExecutionService(IOrderExecutionService):
    """The clean, pure business executor. Has ZERO logging or telemetry bloat."""
    def execute_order(self, order: TradeOrder) -> Dict[str, Any]:
        # Simulates dispatching to high-frequency exchange matching engine
        return {
            "status": "FILLED",
            "order_id": order.order_id,
            "symbol": order.symbol,
            "executed_qty": order.quantity,
            "fill_price": order.price
        }


# ------------------------------------------------------------------------------
# Base Decorator (Maintains IOrderExecutionService contract)
# ------------------------------------------------------------------------------
class BaseOrderExecutionDecorator(IOrderExecutionService):
    """Holds reference to the wrapped component and delegates calls by default."""
    def __init__(self, wrapped: IOrderExecutionService):
        self._wrapped = wrapped

    def execute_order(self, order: TradeOrder) -> Dict[str, Any]:
        return self._wrapped.execute_order(order)


# ------------------------------------------------------------------------------
# Concrete Decorator 1: Cryptographic Audit Trail Logger
# ------------------------------------------------------------------------------
class AuditTrailDecorator(BaseOrderExecutionDecorator):
    """Assigns SHA-256 tamper-evident audit records without touching core executor."""
    def __init__(self, wrapped: IOrderExecutionService, audit_sink: List[str]):
        super().__init__(wrapped)
        self.audit_sink = audit_sink

    def execute_order(self, order: TradeOrder) -> Dict[str, Any]:
        res = self._wrapped.execute_order(order)
        
        # Compute immutable cryptographic ledger hash
        digest = hashlib.sha256(f"{order.order_id}:{order.notional_value}:{time.time()}".encode()).hexdigest()
        self.audit_sink.append(f"AUDIT_RECORD:{order.order_id}:{digest}")
        
        res["audit_hash"] = digest
        return res


# ------------------------------------------------------------------------------
# Concrete Decorator 2: Microsecond Telemetry & Latency Tracker
# ------------------------------------------------------------------------------
class TelemetryMetricsDecorator(BaseOrderExecutionDecorator):
    """Measures microsecond latency and attaches telemetry metrics to response."""
    def execute_order(self, order: TradeOrder) -> Dict[str, Any]:
        t0 = time.perf_counter()
        res = self._wrapped.execute_order(order)
        duration_ms = (time.perf_counter() - t0) * 1000
        
        res["latency_ms"] = round(duration_ms, 4)
        return res
2. Gateways & Access Proxies: src/nexuscore/execution/proxies.py Virtual & Protection Proxy Patterns 
# ==============================================================================
# NexusCore Execution - Virtual & Protection Proxy Implementations
# ==============================================================================

from abc import ABC, abstractmethod
from typing import Dict, Any, Optional
from nexuscore.orders.models import TradeOrder

# ------------------------------------------------------------------------------
# Gateway Interface
# ------------------------------------------------------------------------------
class IExchangeGateway(ABC):
    @abstractmethod
    def dispatch_to_market(self, order: TradeOrder) -> str:
        pass


# ------------------------------------------------------------------------------
# Heavy Real Subject
# ------------------------------------------------------------------------------
class RealExchangeGateway(IExchangeGateway):
    """Heavy Real Subject: Spawns TCP sockets, authenticates, and initializes memory."""
    def __init__(self, venue_url: str):
        self.venue_url = venue_url
        self.is_connected = True

    def dispatch_to_market(self, order: TradeOrder) -> str:
        return f"ACK_{order.symbol}_{order.order_id}"


# ------------------------------------------------------------------------------
# Virtual & Protection Proxy
# ------------------------------------------------------------------------------
class SecureLazyExchangeProxy(IExchangeGateway):
    """
    DUAL-ROLE PROXY:
    1. Protection Proxy: Validates caller role before granting access.
    2. Virtual Proxy: Defers RealExchangeGateway allocation until first valid dispatch.
    """
    def __init__(self, venue_url: str, user_role: str):
        self.venue_url = venue_url
        self.user_role = user_role
        # Virtual Proxy: Subject starts as None! Zero connection cost on boot!
        self._real_subject: Optional[RealExchangeGateway] = None

    def dispatch_to_market(self, order: TradeOrder) -> str:
        # 1. Protection Proxy Gate: Enforce Role-Based Access Control
        if self.user_role != "LICENSED_TRADER":
            raise PermissionError(f"Unauthorized: Role '{self.user_role}' cannot access live market gateway.")

        # 2. Virtual Proxy Gate: Lazy-instantiate subject on demand
        if self._real_subject is None:
            self._real_subject = RealExchangeGateway(self.venue_url)

        return self._real_subject.dispatch_to_market(order)
3. Institutional Asset Tree: src/nexuscore/portfolio/composite.py Composite Pattern 
# ==============================================================================
# NexusCore Portfolio - Recursive Institutional Composite Tree Hierarchy
# ==============================================================================

from abc import ABC, abstractmethod
from typing import List

# ------------------------------------------------------------------------------
# Base Component Interface
# ------------------------------------------------------------------------------
class IPortfolioComponent(ABC):
    """Common interface for both leaf holdings and composite container groups."""
    @abstractmethod
    def get_market_value(self) -> float:
        pass

    @abstractmethod
    def count_holdings(self) -> int:
        pass


# ------------------------------------------------------------------------------
# Leaf Node (Singular Asset Holding)
# ------------------------------------------------------------------------------
class AssetHolding(IPortfolioComponent):
    """LEAF NODE: Holds a specific asset balance. Has ZERO child components."""
    def __init__(self, symbol: str, units: float, unit_price: float):
        self.symbol = symbol
        self.units = units
        self.unit_price = unit_price

    def get_market_value(self) -> float:
        return self.units * self.unit_price

    def count_holdings(self) -> int:
        return 1


# ------------------------------------------------------------------------------
# Composite Node (Recursive Portfolio Container)
# ------------------------------------------------------------------------------
class PortfolioGroup(IPortfolioComponent):
    """
    COMPOSITE NODE:
    Can contain both singular AssetHoldings and nested child PortfolioGroups.
    Evaluates aggregations recursively with zero type-checking logic.
    """
    def __init__(self, name: str):
        self.name = name
        self._children: List[IPortfolioComponent] = []

    def add(self, component: IPortfolioComponent) -> None:
        self._children.append(component)

    def remove(self, component: IPortfolioComponent) -> None:
        self._children.remove(component)

    def get_market_value(self) -> float:
        # Recursively aggregates market value across the entire subtree:
        return sum(child.get_market_value() for child in self._children)

    def count_holdings(self) -> int:
        return sum(child.count_holdings() for child in self._children)

from nexuscore.orders.builder import OrderBuilder

class TestStructuralWrappersAndTrees:
    """Verifies Decorator layering, Virtual/Protection Proxy barriers, and Composite trees."""

    def test_decorator_stacking_preserves_interface_and_adds_behavior(self):
        order = OrderBuilder().for_instrument("NVDA", OrderSide.BUY).with_sizing(10, 200.0).build()
        audit_sink = []

        # Dynamically stack 2 decorators around base executor at runtime
        core_executor = BaseOrderExecutionService()
        audited_executor = AuditTrailDecorator(core_executor, audit_sink)
        telemetry_executor = TelemetryMetricsDecorator(audited_executor)

        # Execute transparently through the outer decorator
        res = telemetry_executor.execute_order(order)

        assert res["status"] == "FILLED"
        assert "latency_ms" in res          # From TelemetryMetricsDecorator
        assert "audit_hash" in res          # From AuditTrailDecorator
        assert len(audit_sink) == 1
        assert order.order_id in audit_sink[0]

    def test_proxy_blocks_unauthorized_roles_and_lazily_initializes(self):
        order = OrderBuilder().for_instrument("BTC/USD", OrderSide.BUY).with_sizing(1, 50000.0).build()

        # 1. Protection Proxy: REJECT unauthorized role
        unauthorized_proxy = SecureLazyExchangeProxy("tcp://live-exchange", user_role="GUEST_USER")
        with pytest.raises(PermissionError, match="Unauthorized"):
            unauthorized_proxy.dispatch_to_market(order)

        # 2. Virtual Proxy: Verify subject is None initially
        authorized_proxy = SecureLazyExchangeProxy("tcp://live-exchange", user_role="LICENSED_TRADER")
        assert authorized_proxy._real_subject is None  # Zero socket allocation!

        # First dispatch lazily connects
        ack = authorized_proxy.dispatch_to_market(order)
        assert authorized_proxy._real_subject is not None
        assert authorized_proxy._real_subject.is_connected is True
        assert "ACK_BTC/USD_" in ack

    def test_composite_portfolio_recursive_aggregation(self):
        # Level 3: Leaf Assets
        aapl = AssetHolding("AAPL", units=100, unit_price=150.0)    # $15,000
        nvda = AssetHolding("NVDA", units=50, unit_price=200.0)     # $10,000
        gold = AssetHolding("GOLD", units=5, unit_price=2000.0)     # $10,000

        # Level 2: Sub-Funds
        tech_fund = PortfolioGroup("Tech Fund")
        tech_fund.add(aapl)
        tech_fund.add(nvda)
        assert tech_fund.get_market_value() == 25000.0
        assert tech_fund.count_holdings() == 2

        hedge_fund = PortfolioGroup("Hedge Fund")
        hedge_fund.add(gold)

        # Level 1: Master Conglomerate
        global_master = PortfolioGroup("Global Master Trust")
        global_master.add(tech_fund)
        global_master.add(hedge_fund)

        # Polymorphic recursive evaluation
        assert global_master.get_market_value() == 35000.0  # 25,000 + 10,000
        assert global_master.count_holdings() == 3
Warning Track

Beginner Pitfalls & Architectural Anti-Patterns

❌ The Invisible RPC Network Illusion (Proxy Trap)

Writing a Remote Proxy that makes remote HTTP/gRPC calls look like an instantaneous local Python method call without timeouts, retries, or error models.

Why this causes production crashes: Local method calls execute in 10 nanoseconds and never experience network partitions. Remote calls take 50ms and can fail due to socket drops. If callers treat a remote proxy as a local object, they omit circuit breakers and timeouts, leading to thread pool exhaustion when network blips occur!

❌ Recursive Stack Overflows in Composite Trees

Allowing circular references in Composite parent-child assignments (e.g. adding Group A into Group B, then accidentally adding Group B into Group A).

Why this crashes the process: Calling get_market_value() will enter an infinite recursive loop until Python throws RecursionError: maximum recursion depth exceeded. Always validate that child additions do not create directed cycles in composite hierarchies.
