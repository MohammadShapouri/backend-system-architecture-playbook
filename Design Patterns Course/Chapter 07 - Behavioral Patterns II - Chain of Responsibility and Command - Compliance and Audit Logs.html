Architecture Fundamentals

Decoupling Senders, Receivers & Action Invocations

In tightly coupled applications, the component initiating a request directly invokes the component executing the request. For example, an API endpoint function directly invokes database.execute_update(...).

This direct coupling creates severe structural liabilities:

  • Sender-Receiver Entanglement: The sender must know the exact concrete class, constructor arguments, and method signatures of every handler that might process the request.
  • Loss of Temporal Flexibility: When an action is directly executed as a method call, it cannot be queued, logged to disk, delayed, retried later, or undone upon failure.
// The Two Architectural Solutions:

Chain of Responsibility decouples the sender from multiple potential receivers by passing the request along a pipeline until a handler resolves it. Command decouples the sender from the receiver by packaging the request, its receiver, and its execution parameters into an independent object that can be passed around, queued, or reversed.

Design Pattern #16

Pattern Name: Chain of Responsibility

Formal Classification: Behavioral Pattern • Gang of Four (GoF) Reference p. 223

💡 The Real-World Metaphor (Plain English)

Imagine passing through an international airport security checkpoint before boarding an overseas flight.

You do not enter an office where a single security officer checks your passport, operates an X-ray scanner, conducts a metal detector wand search, inspects customs declarations, and tests for hazardous chemicals all at once.

Instead, you pass through a sequential chain of specialized checkpoints: Officer 1 checks passport validity; if valid, you move to Officer 2 at the metal detector; if clear, you pass to Officer 3 at luggage inspection. If Officer 1 finds a forged passport, you are stopped immediately (short-circuited), and no subsequent officers waste time scanning your bags!

The Problem: The Monolithic Validation Monolith

In enterprise finance, trade compliance involves verifying international sanctions lists, checking user KYC tiers, testing transaction size against anti-money laundering thresholds, and verifying daily trading velocity.

Without Chain of Responsibility, developers write a monolithic function containing dozens of nested checks. Adding a new rule or reordering checks requires modifying a massive file, risking regressions in working validation code: 

# ------------------------------------------------------------------------------
# ANTI-PATTERN: The Monolithic Hardcoded Compliance Function
# ------------------------------------------------------------------------------

class MonolithicComplianceService:
    def verify_trade(self, user_id: str, amount: float, country: str) -> bool:
        # Check 1: Sanctions check
        if country in ["NORTH_KOREA", "IRAN"]:
            return False
            
        # Check 2: KYC Level check
        kyc_level = db.get_user_kyc(user_id)
        if amount > 10000 and kyc_level < 2:
            return False

        # Check 3: Daily volume limit check
        daily_spent = db.get_daily_volume(user_id)
        if daily_spent + amount > 50000:
            return False
            
        # Every time legal or risk adds a new rule, this monolithic method grows!
        # You cannot reorder checks, disable one for VIPs, or test each check in isolation.
        return True

Short-Circuiting Invariant:

If any handler in the chain encounters a violation (e.g. SanctionsCheck fails), it terminates the chain immediately and returns a rejection result. Handlers 2 and 3 are never invoked, saving database lookups and network calls.

✔ When to Use Chain of Responsibility
  • More than one object may handle a request, and the exact handler isn't known beforehand (or should be determined dynamically).
  • You want to issue a request to one of several objects without specifying the receiver explicitly.
  • The set of objects that can handle a request, or their order of execution, should be specified dynamically at runtime.
✘ When NOT to Use Chain of Responsibility
  • Every single handler in the pipeline must execute unconditionally without short-circuiting (Consider an observer or composite instead).
  • The sequence has strict, rigid, unchangeable dependencies where later steps directly need variables produced by earlier steps (Consider Template Method or Pipeline).
Design Pattern #17

Pattern Name: Command (Action / Transaction)

Formal Classification: Behavioral Pattern • Gang of Four (GoF) Reference p. 233

💡 The Real-World Metaphor (Plain English)

Imagine placing an order at a diner restaurant.

You do not barge into the kitchen, grab the chef's spatula, and instruct them verbally: "Cook 2 eggs over-easy and toast 1 bagel."

Instead, the waiter writes your request down on an Order Pad (The Command). The order slip is an independent object: it contains all necessary parameters (table number, items, special requests), it can sit in an incoming order queue, it can be passed to whichever chef is available, it can be logged in the accounting register, and if you change your mind 10 seconds later, the waiter can pull the slip off the clip and cancel it (Undo)!

The Problem: Transient Method Calls

When you call a method directly (ledger.transfer(from_acc, to_acc, 5000)), that operation evaporates from memory as soon as the stack frame pops. If a distributed multi-step transaction fails on step 3 of 4, how do you undo steps 1 and 2?

The Command Pattern solves this by packaging the receiver, the action, and the parameters into a first-class object that implements two critical methods: execute() and undo().

Audit & Replayability Guarantee:

Because commands are standalone objects, they can be serialized to a persistent database table or Kafka topic. If the server crashes, NexusCore restarts, reads the command log, and replays all commands sequentially to rebuild identical account balances!

✔ When to Use Command
  • You need to support undo/redo operations or transactional rollbacks.
  • You want to parameterize objects with operations, queue requests, or execute them asynchronously.
  • You need to log changes to disk so that system state can be reconstructed following a crash (audit log / event sourcing foundation).
✘ When NOT to Use Command
  • You have simple synchronous operations where undo, queuing, and serialization are never required.
  • Creating a command class for every simple getter or single-line operation introduces unnecessary class sprawl.

1. Compliance Verification Chain: src/nexuscore/compliance/chain.py Chain of Responsibility Pattern 
# ==============================================================================
# NexusCore Compliance - Chain of Responsibility for Trade Inspection
# ==============================================================================

from abc import ABC, abstractmethod
from dataclasses import dataclass
from typing import Optional, Set


@dataclass(frozen=True)
class TradeContext:
    """Request payload passing through the compliance pipeline."""
    user_id: str
    country_code: str
    kyc_level: int
    amount: float
    currency: str


@dataclass(frozen=True)
class ComplianceResult:
    """Evaluation result issued by handlers."""
    passed: bool
    rejected_by: Optional[str] = None
    reason: Optional[str] = None


# ------------------------------------------------------------------------------
# BASE HANDLER
# ------------------------------------------------------------------------------
class AbstractComplianceHandler(ABC):
    """
    CHAIN OF RESPONSIBILITY BASE HANDLER:
    Maintains a reference to the next handler in the pipeline.
    Provides standard handle() propagation with short-circuiting on failure.
    """
    def __init__(self):
        self._next_handler: Optional["AbstractComplianceHandler"] = None

    def set_next(self, handler: "AbstractComplianceHandler") -> "AbstractComplianceHandler":
        """Enables fluent chaining: handler_a.set_next(handler_b).set_next(handler_c)"""
        self._next_handler = handler
        return handler

    def handle(self, context: TradeContext) -> ComplianceResult:
        # Execute self check:
        result = self._check(context)
        if not result.passed:
            # SHORT-CIRCUIT: Do not proceed further down the chain!
            return result

        # If check passed and there is a next handler, delegate:
        if self._next_handler:
            return self._next_handler.handle(context)

        # End of chain reached successfully:
        return ComplianceResult(passed=True)

    @abstractmethod
    def _check(self, context: TradeContext) -> ComplianceResult:
        """Subclasses implement specific regulatory logic."""
        pass


# ------------------------------------------------------------------------------
# CONCRETE HANDLERS
# ------------------------------------------------------------------------------
class SanctionsListHandler(AbstractComplianceHandler):
    """Handler 1: Verifies international OFAC / UN sanctions."""
    def __init__(self, blocked_countries: Optional[Set[str]] = None):
        super().__init__()
        self._blocked = blocked_countries or {"PRK", "IRN", "SYR"}

    def _check(self, context: TradeContext) -> ComplianceResult:
        if context.country_code.upper() in self._blocked:
            return ComplianceResult(
                passed=False,
                rejected_by="SanctionsListHandler",
                reason=f"Jurisdiction '{context.country_code}' is sanctioned."
            )
        return ComplianceResult(passed=True)


class KycTierLimitHandler(AbstractComplianceHandler):
    """Handler 2: Enforces trade volume ceiling based on customer KYC level."""
    def _check(self, context: TradeContext) -> ComplianceResult:
        # Tier 1 users cannot trade over $1,000; Tier 2 over $100,000
        limits = {1: 1_000.0, 2: 100_000.0, 3: 10_000_000.0}
        max_allowed = limits.get(context.kyc_level, 0.0)

        if context.amount > max_allowed:
            return ComplianceResult(
                passed=False,
                rejected_by="KycTierLimitHandler",
                reason=f"Amount ${context.amount:,.2f} exceeds KYC Tier {context.kyc_level} limit of ${max_allowed:,.2f}."
            )
        return ComplianceResult(passed=True)


class AmlThresholdHandler(AbstractComplianceHandler):
    """Handler 3: Flags single transactions over $500,000 for compliance review."""
    def _check(self, context: TradeContext) -> ComplianceResult:
        if context.amount >= 500_000.0:
            return ComplianceResult(
                passed=False,
                rejected_by="AmlThresholdHandler",
                reason="Transaction exceeds single-operation AML threshold of $500,000."
            )
        return ComplianceResult(passed=True)
2. Reversible Transaction Commands: src/nexuscore/commands/transaction.py Command Pattern 
# ==============================================================================
# NexusCore Commands - Reversible Transaction Commands & Audit Journal
# ==============================================================================

from abc import ABC, abstractmethod
import time
import uuid
from typing import List, Dict, Any
from nexuscore.ledger.bridge import LedgerAccount


# ------------------------------------------------------------------------------
# THE COMMAND INTERFACE
# ------------------------------------------------------------------------------
class ITransactionCommand(ABC):
    """
    COMMAND INTERFACE:
    Encapsulates an action, its arguments, and its rollback logic.
    """
    @property
    @abstractmethod
    def command_id(self) -> str:
        pass

    @abstractmethod
    def execute(self) -> bool:
        """Executes the forward transaction."""
        pass

    @abstractmethod
    def undo(self) -> bool:
        """Rolls back / compensates the transaction exactly."""
        pass

    @abstractmethod
    def to_audit_dict(self) -> Dict[str, Any]:
        """Serializes state for persistence and replayability."""
        pass


# ------------------------------------------------------------------------------
# CONCRETE COMMAND: Deposit / Credit Command
# ------------------------------------------------------------------------------
class DepositFundsCommand(ITransactionCommand):
    """Concrete Command to credit an account."""
    def __init__(self, account: LedgerAccount, amount: float, reference: str):
        self._command_id = f"cmd_dep_{uuid.uuid4().hex[:8]}"
        self.account = account
        self.amount = amount
        self.reference = reference
        self._executed = False

    @property
    def command_id(self) -> str:
        return self._command_id

    def execute(self) -> bool:
        # Credits positive amount to ledger:
        success = self.account.post_transaction(self._command_id, self.amount, self.reference)
        self._executed = success
        return success

    def undo(self) -> bool:
        if not self._executed:
            return False
        # Reverses credit by deducting the exact amount:
        undo_ref = f"UNDO:{self._command_id}"
        return self.account.post_transaction(f"rev_{self._command_id}", -self.amount, undo_ref)

    def to_audit_dict(self) -> Dict[str, Any]:
        return {
            "command_id": self._command_id,
            "type": "DEPOSIT",
            "account_id": self.account.account_id,
            "amount": self.amount,
            "reference": self.reference
        }


# ------------------------------------------------------------------------------
# CONCRETE COMMAND: Inter-Account Transfer Command
# ------------------------------------------------------------------------------
class TransferFundsCommand(ITransactionCommand):
    """Concrete Command transferring funds between two LedgerAccount receivers."""
    def __init__(self, from_account: LedgerAccount, to_account: LedgerAccount, amount: float):
        self._command_id = f"cmd_xfer_{uuid.uuid4().hex[:8]}"
        self.from_account = from_account
        self.to_account = to_account
        self.amount = amount
        self._executed = False

    @property
    def command_id(self) -> str:
        return self._command_id

    def execute(self) -> bool:
        # 1. Deduct from sender:
        self.from_account.post_transaction(f"deb_{self._command_id}", -self.amount, f"Transfer to {self.to_account.account_id}")
        # 2. Credit to recipient:
        self.to_account.post_transaction(f"crd_{self._command_id}", self.amount, f"Transfer from {self.from_account.account_id}")
        self._executed = True
        return True

    def undo(self) -> bool:
        if not self._executed:
            return False
        # Exact compensation reversal:
        self.to_account.post_transaction(f"und_crd_{self._command_id}", -self.amount, "Reversal: deduct transfer")
        self.from_account.post_transaction(f"und_deb_{self._command_id}", self.amount, "Reversal: refund transfer")
        return True

    def to_audit_dict(self) -> Dict[str, Any]:
        return {
            "command_id": self._command_id,
            "type": "TRANSFER",
            "from_account": self.from_account.account_id,
            "to_account": self.to_account.account_id,
            "amount": self.amount
        }


# ------------------------------------------------------------------------------
# THE INVOKER & JOURNAL
# ------------------------------------------------------------------------------
class TransactionJournalInvoker:
    """
    THE INVOKER:
    Executes commands, maintains an execution stack for point-in-time rollbacks (Undo),
    and logs an audit trail.
    """
    def __init__(self):
        self._history: List[ITransactionCommand] = []
        self._audit_log: List[Dict[str, Any]] = []

    def execute_command(self, command: ITransactionCommand) -> bool:
        success = command.execute()
        if success:
            self._history.append(command)
            entry = command.to_audit_dict()
            entry["timestamp"] = time.time()
            self._audit_log.append(entry)
        return success

    def undo_last_command(self) -> bool:
        """Rolls back the most recent command in LIFO order."""
        if not self._history:
            return False
        command = self._history.pop()
        return command.undo()

    def get_audit_log(self) -> List[Dict[str, Any]]:
        return list(self._audit_log)
3. Verification Test Battery: tests/test_chain_and_command.py PyTest Suite 
import pytest
from nexuscore.compliance.chain import (
    TradeContext, SanctionsListHandler, KycTierLimitHandler, AmlThresholdHandler
)
from nexuscore.ledger.bridge import InMemoryLedgerStorage, StandardRetailAccount
from nexuscore.commands.transaction import (
    DepositFundsCommand, TransferFundsCommand, TransactionJournalInvoker
)

class TestChainAndCommandSuite:
    """Verifies Chain of Responsibility short-circuiting and Command undo journaling."""

    def test_chain_approves_fully_compliant_trade(self):
        # Build Chain: Sanctions → KYC → AML
        sanctions = SanctionsListHandler()
        kyc = KycTierLimitHandler()
        aml = AmlThresholdHandler()
        sanctions.set_next(kyc).set_next(aml)

        valid_trade = TradeContext(
            user_id="user_101",
            country_code="DEU",
            kyc_level=2,
            amount=5000.0,
            currency="USD"
        )
        res = sanctions.handle(valid_trade)
        assert res.passed is True
        assert res.rejected_by is None

    def test_chain_short_circuits_on_sanctions_violation(self):
        sanctions = SanctionsListHandler()
        kyc = KycTierLimitHandler()
        sanctions.set_next(kyc)

        sanctioned_trade = TradeContext(
            user_id="bad_actor",
            country_code="PRK",  # North Korea
            kyc_level=3,
            amount=500.0,
            currency="USD"
        )
        res = sanctions.handle(sanctioned_trade)
        assert res.passed is False
        assert res.rejected_by == "SanctionsListHandler"
        assert "is sanctioned" in res.reason

    def test_chain_rejects_unqualified_kyc_tier(self):
        sanctions = SanctionsListHandler()
        kyc = KycTierLimitHandler()
        sanctions.set_next(kyc)

        unverified_trade = TradeContext(
            user_id="newbie",
            country_code="USA",
            kyc_level=1,          # Tier 1 max: $1,000
            amount=25000.0,       # $25,000 exceeds limit
            currency="USD"
        )
        res = sanctions.handle(unverified_trade)
        assert res.passed is False
        assert res.rejected_by == "KycTierLimitHandler"

    def test_command_execution_and_undo_reversal(self):
        storage = InMemoryLedgerStorage()
        acc_a = StandardRetailAccount("ACC_A", storage)
        acc_b = StandardRetailAccount("ACC_B", storage)

        invoker = TransactionJournalInvoker()

        # 1. Deposit funds into Account A via Command
        dep_cmd = DepositFundsCommand(acc_a, 1000.0, "Payroll")
        invoker.execute_command(dep_cmd)
        assert acc_a.get_current_balance() == 1000.0

        # 2. Transfer $400 from A to B via Command
        xfer_cmd = TransferFundsCommand(acc_a, acc_b, 400.0)
        invoker.execute_command(xfer_cmd)
        assert acc_a.get_current_balance() == 600.0
        assert acc_b.get_current_balance() == 400.0

        # 3. Undo transfer command: Balances must revert exactly!
        invoker.undo_last_command()
        assert acc_a.get_current_balance() == 1000.0
        assert acc_b.get_current_balance() == 0.0

        # 4. Verify audit log integrity
        audit = invoker.get_audit_log()
        assert len(audit) == 2
        assert audit[0]["type"] == "DEPOSIT"
        assert audit[1]["type"] == "TRANSFER"
Warning Track

Beginner Pitfalls & Architectural Anti-Patterns

❌ The Broken Chain (Silent Request Drops)

Writing a Chain of Responsibility where a handler neither resolves the request nor calls super().handle(context).

Why this causes silent failures: If a handler forgets to pass control to the next handler, requests fall off the end of the chain into the void. The caller receives None, leading to silent bugs where validation checks are omitted without raising an error! Always enforce explicit return contracts in base handlers.

❌ Asymmetric Undo in Commands

Implementing a Command whose undo() method does not restore the receiver's state to the exact pre-execution state.

Why this corrupts state: If execute() charges an exchange fee or mutates an account status, but undo() only refunds the principal amount without refunding the fee or restoring status, the ledger becomes mathematically desynchronized. Undo must be the exact mathematical inverse of execute!
