Architecture Fundamentals

Why Object Creation Matters: The Physics of Couplings

In software engineering, every time your code contains the keyword ClassInstantiation() (such as calling a class constructor directly: StripeGateway(api_key="sk_live_...")), you create a tight compile-time / import-time coupling between the caller and that specific concrete implementation.

When you hardcode object creation inside your business services:

  • You violate the Open-Closed Principle (OCP): To add a new provider (e.g., PayPal or Adyen), you must open and rewrite existing business service files, risking regressions in working code.
  • You break testing isolation: You cannot easily swap out real network-calling payment providers for lightweight in-memory stubs without monkey-patching or complex test setup.
  • You scatter configuration logic: API keys, timeouts, retry rules, and endpoint paths become duplicated across every controller that constructs a gateway.
Coupling Comparison: Direct Constructor Calls vs. Factory Abstraction
1. Direct Constructor Coupling (Rigid) High Friction

Caller explicitly imports and instantiates concrete classes:

CheckoutService → imports StripeGateway
CheckoutService → imports SepaGateway
CheckoutService → calls new StripeGateway(cfg)
✗ Adding Adyen requires modifying CheckoutService!

Result: High coupling. The business layer must know all implementation details, imports, and configuration mechanics of every vendor.

2. Factory Abstraction (Decoupled) Standard Architecture

Caller interacts purely with an abstract contract:

CheckoutService → depends only on IPaymentGateway
CheckoutService → calls factory.create_gateway()
Factory decides: returns Stripe, SEPA, or Mock
✓ Zero changes to CheckoutService when adding vendors!

Result: Loose coupling. The business service focuses strictly on processing transactions, unaware of how vendors are constructed.

Design Pattern #01

Pattern Name: Factory Method

Formal Classification: Creational Pattern • Gang of Four (GoF) Reference p. 107

💡 The Real-World Metaphor (Plain English)

Imagine ordering a meal at a fast-food drive-through window. You pull up to the speaker and order a "Value Meal". You don't walk into the kitchen, turn on the deep fryer, calibrate the grill temperature, or choose which specific cardboard box holds the burger.

The restaurant staff acts as the Factory Method: you request a product by specifying an abstract order, and the kitchen encapsulates the complex creation steps, handing you a finished meal that satisfies the standard "Food Item" contract. Your car never touches the kitchen equipment.

The Problem: Hardcoded Conditional Instantiation

Here is what real-world code looks like when an entry-level engineer handles multiple payment providers without a creational pattern. Notice how the core business function becomes a dumping ground for vendor credentials, imports, and giant conditional branches: 

# ------------------------------------------------------------------------------
# ANTI-PATTERN: The Hardcoded Conditional Constructor
# ------------------------------------------------------------------------------

class OrderProcessor:
    def process_payment(self, order_id: str, amount: float, provider: str, currency: str):
        # The business processor is directly coupled to every vendor's initialization!
        if provider == "stripe":
            # Stripe requires secret keys and API version configurations
            gateway = StripeGateway(api_key="sk_live_998822", api_version="2023-10-16")
        elif provider == "sepa":
            # SEPA requires bank identifier codes, IBAN formatters, and clearing IDs
            gateway = SepaGateway(creditor_id="DE98ZZZ0999", bic="MARKDEF1")
        elif provider == "paypal":
            # PayPal requires OAuth client ID, client secret, and sandbox booleans
            gateway = PayPalGateway(client_id="id_123", client_secret="sec_456", sandbox=False)
        else:
            raise ValueError(f"Unknown provider: {provider}")

        # If PayPal changes their constructor tomorrow, this business file breaks!
        # If we want to unit test this class, we are forced to mock 3 different vendors!
        return gateway.charge(amount, currency)
Factory Method Architectural Topology
Caller Service Calls factory.get_gateway()
→ invokes →
GatewayFactory Resolves configuration & instantiates concrete gateway
→ returns →
IPaymentGateway Common polymorphic interface (.charge())
✔ When to Use Factory Method
  • You don't know ahead of time the exact types and dependencies of the objects your code needs to work with.
  • You want to provide users of your library or framework with a way to extend its internal components by substituting custom subclasses.
  • You want to centralize complex initialization logic (reading credentials, pooling network connections) into a single place.
✘ When NOT to Use Factory Method
  • The object has simple instantiation logic (e.g., standard Python dataclasses with 2 primitive fields). Direct construction is cleaner.
  • Your system will only ever have one single implementation of an object and you have no business requirements for swapping or mocking.
  • You are introducing an abstract class and factory just to satisfy dogma ("Patternitis").
Design Pattern #02

Pattern Name: Abstract Factory

Formal Classification: Creational Pattern • Gang of Four (GoF) Reference p. 87

💡 The Real-World Metaphor (Plain English)

Imagine furnishing an office. You decide you want a specific interior design theme: either a "Modern Minimalist" theme or an "Antique Victorian" theme.

If you buy a Modern desk, you must also buy a Modern chair and a Modern lamp so the furniture matches. You don't want to accidentally mix an ornate Victorian carved oak desk with an ultra-modern neon plastic chair!

An Abstract Factory is the furniture showroom that guarantees consistency: when you select the Modern Furniture Factory, calling create_chair(), create_desk(), and create_lamp() guarantees that all items belong to the identical matching family.

The Problem in Multi-Provider Gateways

A real-world payment integration involves more than charging money. A full vendor integration requires a family of matching, co-dependent components:

  1. A Payment Gateway: Executes authorization and capture over the wire.
  2. A Settlement Invoicer: Generates regulatory invoices formatted for that provider's tax jurisdiction.
  3. A Webhook Dispatcher: Decodes, cryptographically verifies, and parses asynchronous callback events from that specific vendor.

If an application initiates a payment via Stripe, but accidentally passes the transaction callback to the SEPA Webhook Parser, the cryptographic signature check fails and the invoice is issued with the wrong tax identifiers. Abstract Factory guarantees family compatibility at instantiation time.

Abstract Factory Component Family Structure
Family 1: StripeProviderFactory
• create_gateway() → StripeGateway
• create_invoicer() → StripeInvoicer
• create_webhook_verifier() → StripeWebhookVerifier
Family 2: SepaProviderFactory
• create_gateway() → SepaGateway
• create_invoicer() → SepaInvoicer
• create_webhook_verifier() → SepaWebhookVerifier
The client application accepts an IPaymentProviderFactory instance and creates compatible components with zero danger of cross-family pollution!
Dimension Factory Method Abstract Factory
Primary Intent Creates a single object whose exact concrete class is determined by subclasses or parameters. Creates families of related or dependent objects without specifying their concrete classes.
Creation Mechanism Relies on inheritance or a dedicated parameterized creation function/method. Relies on object composition: factory itself is an object passed into client code.
Output Scope One product interface (e.g., IPaymentGateway). Multiple product interfaces (e.g., Gateway + Invoicer + Verifier).

1. Abstract Domain Contracts: src/nexuscore/payments/contracts.py Pure Interfaces 
# ==============================================================================
# NexusCore Core - Payment & Settlement Domain Contracts
# ==============================================================================

from abc import ABC, abstractmethod
from dataclasses import dataclass
from typing import Optional


@dataclass(frozen=True)
class PaymentResult:
    """
    Immutable value object encapsulating the outcome of a financial charge attempt.
    """
    success: bool
    transaction_id: str
    amount: float
    currency: str
    provider_name: str
    error_message: Optional[str] = None


@dataclass(frozen=True)
class Invoice:
    """
    Immutable representation of an official regulatory invoice issued by a provider.
    """
    invoice_number: str
    tax_jurisdiction: str
    gross_amount: float


# ------------------------------------------------------------------------------
# Product Interface 1: Payment Gateway
# ------------------------------------------------------------------------------
class IPaymentGateway(ABC):
    """
    Abstract Contract for initiating charges against remote banking systems.
    Every provider (Stripe, SEPA, PayPal) MUST adhere to this exact interface.
    """
    @abstractmethod
    def charge(self, amount: float, currency: str, source_token: str) -> PaymentResult:
        """Executes a financial charge."""
        pass


# ------------------------------------------------------------------------------
# Product Interface 2: Invoicer
# ------------------------------------------------------------------------------
class IInvoicer(ABC):
    """
    Abstract Contract for generating tax invoices tailored to regional regulatory rules.
    """
    @abstractmethod
    def generate_invoice(self, transaction_id: str, amount: float) -> Invoice:
        """Produces a formal tax invoice document."""
        pass


# ------------------------------------------------------------------------------
# Product Interface 3: Webhook Verifier
# ------------------------------------------------------------------------------
class IWebhookVerifier(ABC):
    """
    Abstract Contract for validating HMAC/cryptographic signatures on incoming callbacks.
    """
    @abstractmethod
    def verify_signature(self, payload: bytes, signature_header: str) -> bool:
        """Validates cryptographic integrity of a vendor callback."""
        pass

# ==============================================================================
# NexusCore Providers - Concrete Vendor Implementations
# ==============================================================================

import uuid
from nexuscore.payments.contracts import (
    IPaymentGateway, IInvoicer, IWebhookVerifier, PaymentResult, Invoice
)

# ==============================================================================
# 1. STRIPE FAMILY (US / International Credit Cards)
# ==============================================================================

class StripeGateway(IPaymentGateway):
    def __init__(self, api_key: str, endpoint: str = "https://api.stripe.com/v1"):
        # Encapsulates Stripe-specific configuration
        self._api_key = api_key
        self._endpoint = endpoint

    def charge(self, amount: float, currency: str, source_token: str) -> PaymentResult:
        # In production: Performs HTTP POST to Stripe with Bearer token
        tx_id = f"ch_stripe_{uuid.uuid4().hex[:8]}"
        return PaymentResult(
            success=True,
            transaction_id=tx_id,
            amount=amount,
            currency=currency.upper(),
            provider_name="Stripe"
        )

class StripeInvoicer(IInvoicer):
    def generate_invoice(self, transaction_id: str, amount: float) -> Invoice:
        return Invoice(
            invoice_number=f"INV-STRIPE-{transaction_id}",
            tax_jurisdiction="US-CA",
            gross_amount=amount
        )

class StripeWebhookVerifier(IWebhookVerifier):
    def verify_signature(self, payload: bytes, signature_header: str) -> bool:
        # Validates Stripe HMAC-SHA256 signature
        return signature_header.startswith("t=") and len(payload) > 0


# ==============================================================================
# 2. SEPA FAMILY (European Direct Debit Bank Clearing)
# ==============================================================================

class SepaGateway(IPaymentGateway):
    def __init__(self, creditor_id: str, bic: str):
        # Encapsulates European Banking Union BIC and Creditor Identifiers
        self._creditor_id = creditor_id
        self._bic = bic

    def charge(self, amount: float, currency: str, source_token: str) -> PaymentResult:
        # Enforces Euro-only regulatory rule
        if currency.upper() != "EUR":
            return PaymentResult(
                success=False,
                transaction_id="",
                amount=amount,
                currency=currency,
                provider_name="SEPA",
                error_message="SEPA only clears transactions in EUR"
            )

        tx_id = f"sepa_debit_{uuid.uuid4().hex[:8]}"
        return PaymentResult(
            success=True,
            transaction_id=tx_id,
            amount=amount,
            currency="EUR",
            provider_name="SEPA"
        )

class SepaInvoicer(IInvoicer):
    def generate_invoice(self, transaction_id: str, amount: float) -> Invoice:
        return Invoice(
            invoice_number=f"EU-VAT-SEPA-{transaction_id}",
            tax_jurisdiction="EU-GERMANY",
            gross_amount=amount
        )

class SepaWebhookVerifier(IWebhookVerifier):
    def verify_signature(self, payload: bytes, signature_header: str) -> bool:
        # Validates banking certificate public key
        return signature_header.startswith("sha256-rsa=")


# ==============================================================================
# 3. MOCK FAMILY (Zero Network IO for Fast Unit Testing)
# ==============================================================================

class MockGateway(IPaymentGateway):
    def charge(self, amount: float, currency: str, source_token: str) -> PaymentResult:
        return PaymentResult(
            success=True,
            transaction_id=f"mock_tx_{uuid.uuid4().hex[:6]}",

3. Factory Implementation: src/nexuscore/payments/factories.py Factory Method & Abstract Factory 
# ==============================================================================
# NexusCore Factories - Factory Method & Abstract Factory Engines
# ==============================================================================

from abc import ABC, abstractmethod
from typing import Dict, Type
from nexuscore.payments.contracts import IPaymentGateway, IInvoicer, IWebhookVerifier
from nexuscore.payments.providers import (
    StripeGateway, StripeInvoicer, StripeWebhookVerifier,
    SepaGateway, SepaInvoicer, SepaWebhookVerifier,
    MockGateway, MockInvoicer, MockWebhookVerifier
)

# ------------------------------------------------------------------------------
# PATTERN 1: FACTORY METHOD (Parameterized / Registry-Driven)
# ------------------------------------------------------------------------------
class PaymentGatewayFactory:
    """
    FACTORY METHOD PATTERN:
    Responsible for creating single IPaymentGateway objects.
    Decouples callers from constructor signatures, credentials, and API versions.
    Open-Closed: New providers can be registered dynamically via 'register_provider'!
    """
    _registry: Dict[str, Type[IPaymentGateway]] = {
        "stripe": StripeGateway,
        "sepa": SepaGateway,
        "mock": MockGateway,
    }

    @classmethod
    def register_provider(cls, name: str, gateway_cls: Type[IPaymentGateway]) -> None:
        """Dynamically register a new provider without modifying this class (OCP)."""
        cls._registry[name.lower()] = gateway_cls

    @classmethod
    def create(cls, provider_name: str, **kwargs) -> IPaymentGateway:
        """
        The Factory Method: Resolves, configures, and instantiates the gateway.
        """
        normalized_name = provider_name.strip().lower()
        if normalized_name not in cls._registry:
            raise ValueError(f"Unknown payment provider: '{provider_name}'. Registered: {list(cls._registry.keys())}")

        gateway_cls = cls._registry[normalized_name]

        # Factory encapsulates configuration mapping for specific providers
        if gateway_cls is StripeGateway:
            api_key = kwargs.get("api_key", "sk_live_default_credential")
            return StripeGateway(api_key=api_key)

        elif gateway_cls is SepaGateway:
            creditor_id = kwargs.get("creditor_id", "DE99ZZZ00000001")
            bic = kwargs.get("bic", "MARKDEF1XXX")
            return SepaGateway(creditor_id=creditor_id, bic=bic)

        elif gateway_cls is MockGateway:
            return MockGateway()

        # Fallback instantiation for dynamically registered providers
        return gateway_cls(**kwargs)


# ------------------------------------------------------------------------------
# PATTERN 2: ABSTRACT FACTORY (Family of Related Components)
# ------------------------------------------------------------------------------
class IPaymentProviderFactory(ABC):
    """
    ABSTRACT FACTORY CONTRACT:
    Guarantees that an entire family of components (Gateway + Invoicer + Verifier)
    always belongs to the exact same vendor ecosystem. Prevents mismatched components.
    """
    @abstractmethod
    def create_gateway(self) -> IPaymentGateway:
        pass

    @abstractmethod
    def create_invoicer(self) -> IInvoicer:
        pass

    @abstractmethod
    def create_webhook_verifier(self) -> IWebhookVerifier:
        pass


class StripeProviderFactory(IPaymentProviderFactory):
    def __init__(self, api_key: str):
        self._api_key = api_key

    def create_gateway(self) -> IPaymentGateway:
        return StripeGateway(api_key=self._api_key)

    def create_invoicer(self) -> IInvoicer:
        return StripeInvoicer()

    def create_webhook_verifier(self) -> IWebhookVerifier:
        return StripeWebhookVerifier()


class SepaProviderFactory(IPaymentProviderFactory):
    def __init__(self, creditor_id: str, bic: str):
        self._creditor_id = creditor_id
        self._bic = bic

    def create_gateway(self) -> IPaymentGateway:
        return SepaGateway(creditor_id=self._creditor_id, bic=self._bic)

    def create_invoicer(self) -> IInvoicer:
        return SepaInvoicer()

    def create_webhook_verifier(self) -> IWebhookVerifier:
        return SepaWebhookVerifier()


class MockProviderFactory(IPaymentProviderFactory):
    def create_gateway(self) -> IPaymentGateway:
        return MockGateway()

    def create_invoicer(self) -> IInvoicer:
        return MockInvoicer()

    def create_webhook_verifier(self) -> IWebhookVerifier:
        return MockWebhookVerifier()

# ==============================================================================
# NexusCore Service - High-Level Decoupled Checkout Service
# ==============================================================================

from typing import Dict, Any
from nexuscore.payments.contracts import IPaymentGateway, PaymentResult, Invoice
from nexuscore.payments.factories import PaymentGatewayFactory, IPaymentProviderFactory

class OrderCheckoutService:
    """
    BUSINESS SERVICE DEMONSTRATING DECOUPLING:
    This class has ZERO imports of StripeGateway, SepaGateway, or concrete classes!
    It relies entirely on factories and contracts.
    """
    
    # --------------------------------------------------------------------------
    # Usage 1: Consuming Factory Method
    # --------------------------------------------------------------------------
    def checkout_with_provider_name(
        self,
        order_id: str,
        amount: float,
        currency: str,
        provider_name: str,
        token: str
    ) -> PaymentResult:
        # The factory method creates the proper polymorphic gateway
        gateway: IPaymentGateway = PaymentGatewayFactory.create(provider_name)
        return gateway.charge(amount, currency, source_token=token)

    # --------------------------------------------------------------------------
    # Usage 2: Consuming Abstract Factory (Full Family Coherency)
    # --------------------------------------------------------------------------
    def execute_complete_order_lifecycle(
        self,
        factory: IPaymentProviderFactory,
        amount: float,
        currency: str,
        token: str
    ) -> Dict[str, Any]:
        # Client receives a factory family and constructs consistent components
        gateway = factory.create_gateway()
        invoicer = factory.create_invoicer()

        # 1. Execute Charge
        result: PaymentResult = gateway.charge(amount, currency, token)
        if not result.success:
            return {"status": "FAILED", "error": result.error_message}

        # 2. Issue Invoice using matching invoicer
        invoice: Invoice = invoicer.generate_invoice(result.transaction_id, amount)

        return {
            "status": "COMPLETED",
            "transaction_id": result.transaction_id,
            "invoice_number": invoice.invoice_number,
            "tax_region": invoice.tax_jurisdiction
        }

Warning Track

Beginner Pitfalls & Architectural Anti-Patterns

❌ The Factory of Factories (Over-Abstraction)

Writing PaymentGatewayFactoryProducerProviderManager to create a factory that creates a factory that returns a simple string formatter.

Why this harms codebases: Excessive layers of indirection obscure straightforward logic. If your application only has one static configuration and a single payment vendor that will never change, a simple function or constructor is much more readable. Use factories when polymorphism, dynamic provider resolution, or test isolation is genuinely required.

❌ Leaking Concrete Types in Type Annotations

Defining a Factory Method that returns an abstract interface, but annotating caller code with concrete types: gateway: StripeGateway = factory.create("stripe").

Why this defeats the pattern: If the caller declares a concrete type, your static type checker (mypy) and developer mental model remain tightly coupled to Stripe. If you swap the factory to return SepaGateway, type checking breaks! Always annotate with the Abstract Interface (gateway: IPaymentGateway).
