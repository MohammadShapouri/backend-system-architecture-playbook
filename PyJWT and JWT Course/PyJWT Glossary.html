A Index

Algorithm Confusion Exploit

Exploit • Ch. 1

A critical vulnerability where an attacker changes a token's header from an asymmetric algorithm (RS256) to a symmetric one (HS256) and signs it using the target server's known public key as the HMAC secret. Prevented in PyJWT by explicitly constraining allowed algorithms in jwt.decode(..., algorithms=["RS256"]).

Asymmetric Cryptography (Public-Key)

Crypto • Ch. 1, 4

A cryptographic paradigm utilizing a mathematically linked keypair: a Private Key kept confidential by the identity issuer to sign tokens, and a Public Key distributed to microservices to verify signatures locally without network hops.

aud (Audience Claim)

RFC 7519 • Ch. 2, 4

An RFC 7519 registered claim identifying the intended recipients of the JWT (e.g. "clearing-engine-service"). Verifiers must reject any token where their specific service identifier is absent from the audience list.

Audience Confusion Exploit

Exploit • Ch. 2, 4

A cross-service replay attack occurring when an attacker takes a valid token minted for an unprivileged service (like a public forum) and submits it to a sensitive internal microservice (like a payment engine) because the receiving service verified the signature but omitted the aud claim check.

AuthenticatedPrincipal

TokenForge • Ch. 4

The immutable, type-safe Python dataclass in TokenForge injected into protected FastAPI route controllers. Holds verified subject identity, parsed authorization scopes, and raw claims extracted from a validly decoded token.

B Index

Base64URL Encoding

Encoding • Ch. 1, 3

A modification of Base64 defined in RFC 7515 for URL and HTTP header safety: replaces + with -, replaces / with _, and strips trailing = padding characters. Not encryption.

Bearer Token Scheme (RFC 6750)

Security • Ch. 4

The standard HTTP authorization framework where possession of the token grant conveys access rights. Transmitted via the Authorization: Bearer <token> request header and extracted in FastAPI via OAuth2PasswordBearer.

Blast Radius (Key Compromise)

Architecture • Ch. 1

The scope of damage caused if a service is compromised. For symmetric keys (HS256), the blast radius is total across all services. For asymmetric keys (RS256), a downstream verifier breach leaks only public keys, preventing systemic forgery.

C Index

Circuit Breaker Key Fetching

Resilience • Ch. 1, 4

A resilience pattern guarding downstream microservices when fetching updated public keys from an IAM JWKS endpoint. Trips to OPEN if the IAM network fails repeatedly, preventing API threads from locking up.

Claims Taxonomy (RFC 7519)

RFC 7519 • Ch. 2

The three classifications of JWT payload keys: Registered (IETF reserved 3-letter codes like sub, exp), Public (collision-resistant names registered in the IANA registry), and Private (bespoke agreements between services like tenant_id).

Clock Skew (NTP Drift)

Systems • Ch. 2

The slight time difference (often 1–5 seconds) across servers in a cluster due to physical hardware clock drift and asynchronous NTP syncing. Can cause freshly issued tokens to be rejected prematurely unless mitigated by PyJWT's leeway.

cryptography Library Backend

Library • Ch. 1

The underlying C-backed cryptographic engine installed via pyjwt[crypto]. Interfaces with OpenSSL to handle high-speed RSA, ECDSA, and Ed25519 mathematical calculations, PEM serialization, and PKCS#8 parsing.

D Index

Diagnostic Inspection (Unverified)

CLI • Ch. 3

Decoding and viewing token headers and payload segments without evaluating signatures via options={"verify_signature": False}. Permissible strictly for CLI debugging tools (tokenforge inspect); hazardous if used in app auth logic.

Dual-Mode Key Engine

Architecture • Ch. 1, 4

An architectural design pattern built into TokenForge allowing a single token client to seamlessly operate in either symmetric (HS256) or asymmetric (RS256) mode based on environment configuration while preventing algorithm mismatch.

E Index

ES256 (ECDSA P-256 with SHA-256)

Crypto • Ch. 1

An asymmetric signature algorithm based on Elliptic Curve Cryptography. Offers equivalent cryptographic security to a 3072-bit RSA key using only 256 bits, resulting in significantly shorter JWT strings and faster signing performance.

exp (Expiration Time Claim)

RFC 7519 • Ch. 2, 4

The RFC 7519 registered claim denoting the exact Unix epoch second after which the token must be rejected. Production standard mandates short expiration windows (e.g. 5–15 minutes) for access tokens to limit replay risk upon token theft.

ExpiredSignatureError

PyJWT • Ch. 2, 3

A specific PyJWT exception raised when jwt.decode() evaluates a token whose exp timestamp is in the past (accounting for configured leeway). Maps to HTTP 401 Unauthorized or CLI exit code 3.

F Index

Fermat Public Exponent (65537)

Crypto • Ch. 1

The standard mathematical prime constant ($F_4 = 2^{16} + 1 = 65537$) used during RSA key generation. Provides optimal resistance against Coppersmith attacks while offering efficient modular exponentiation during signature verification.

Filesystem POSIX Permissions (0o600)

Security • Ch. 3

The Unix permission mode (-rw-------) enforced atomically when generating private PEM keys to disk. Restricts read and write operations strictly to the file owner, preventing unauthorized daemons or local users from stealing signing credentials.

H Index

HMAC (Hash-based MAC)

Crypto • Ch. 1

A symmetric cryptographic construction combining a secret key with an underlying cryptographic hash function (such as SHA-256). Verifies both data integrity and the authenticity of a message.

HS256 (HMAC with SHA-256)

Algorithm • Ch. 1, 4

The most widely used symmetric signing algorithm for JWTs. Uses a single shared secret key of at least 256 bits (32 bytes). Efficient for single-server monoliths, but hazardous when shared across distributed microservices.

HTTP 431 (Header Fields Too Large)

HTTP • Ch. 2

An HTTP error returned by web servers and reverse proxies (Nginx, Cloudflare) when incoming headers exceed buffer limits (often 8KB). A direct consequence of the anti-pattern of embedding large database objects or relational states inside JWT payloads.

I Index

iat (Issued At Claim)

RFC 7519 • Ch. 2

The RFC 7519 registered claim recording the exact Unix epoch second when the token was created. Crucial for auditing token age and implementing global token invalidation for sessions issued prior to a user password reset.

ImmatureSignatureError

PyJWT • Ch. 2

A PyJWT exception raised when a token is processed before its nbf (Not Before) timestamp has arrived according to the current UTC clock (factoring in configured leeway).

Inter-Service Token Federation

Architecture • Ch. 4

A zero-trust identity topology where an IAM service issues signed tokens using an asymmetric private key, and independent microservices verify the token locally in memory using the public key with zero synchronous network callbacks.

InvalidAlgorithmError

PyJWT • Ch. 1, 2

A PyJWT exception raised when a token specifies an algorithm header that does not match the strict whitelist passed to algorithms=[...]. Acts as the primary defensive barrier against algorithm confusion exploits.

InvalidAudienceError

PyJWT • Ch. 2

A PyJWT exception raised when the token's aud claim does not contain the expected audience string passed to jwt.decode(..., audience="..."). Defends against cross-service token replay.

InvalidIssuerError

PyJWT • Ch. 2

A PyJWT exception raised when the token's iss claim does not match the trusted authority identifier specified in jwt.decode(..., issuer="..."), blocking tokens minted by unauthorized foreign issuers.

InvalidSignatureError

PyJWT • Ch. 2, 3

A PyJWT exception raised when cryptographic verification fails. Indicates that the token payload, header, or signature was modified in transit, or that the token was signed by an unrecognized key.

iss (Issuer Claim)

RFC 7519 • Ch. 2, 4

The RFC 7519 registered claim identifying the trusted security principal or authority that generated and signed the token (e.g. "https://iam.tokenforge.internal"). Verified to prevent spoofed token generation.

J Index

jti (JWT ID Claim)

RFC 7519 • Ch. 2

The RFC 7519 registered claim providing a globally unique string identifier (often a UUIDv4) for the token. Acts as a cryptographic nonce to prevent replay attacks and allows distributed architectures to record individual token revocations.

JWKS (JSON Web Key Set - RFC 7517)

RFC 7517 • Ch. 4

A JSON-based standard for publishing public cryptographic keys. Identity providers expose a /.well-known/jwks.json endpoint allowing downstream microservices to discover, verify, and rotate signing keys automatically.

JWS (JSON Web Signature - RFC 7515)

RFC 7515 • Ch. 1

The underlying IETF specification that defines cryptographic signing for JSON objects. Standard JWTs are JWS structures consisting of Header, Payload, and Signature segments separated by periods.

JWT (JSON Web Token - RFC 7519)

Standard • Ch. 1–4

A compact, URL-safe means of representing claims to be transferred between two parties. Encoded as a three-part Base64URL string containing Header, Payload, and cryptographic Signature. Signed, but unencrypted by default.

jwt.get_unverified_header()

PyJWT • Ch. 3

A PyJWT function that extracts and parses only the first Base64URL segment of a JWT string into a dictionary. Essential for reading the Key ID (kid) to determine which public key to load prior to verifying the signature.

K Index

kid (Key ID Header Parameter)

RFC 7515 • Ch. 3, 4

An optional header parameter defined in RFC 7515 indicating which specific key was used to sign the token. Enables seamless cryptographic key rotation without invalidating active tokens signed with older keys.

KeyManager

TokenForge • Ch. 1, 3

The cryptographic helper class built in TokenForge Milestone 01. Responsible for generating 2048-bit RSA keypairs, serializing PKCS#8 private keys and SubjectPublicKeyInfo public keys to PEM formats, and validating bit-depth.

L Index

leeway (PyJWT Parameter)

PyJWT • Ch. 2

A parameter passed to jwt.decode() (accepting an integer number of seconds or a timedelta). Adds a temporal tolerance buffer to exp and nbf checks to absorb clock skew between microservice nodes.

Lifespan Key Preloading

FastAPI • Ch. 4

The practice of loading and parsing PEM cryptographic keys from disk once during FastAPI startup using @asynccontextmanager lifespan, caching the parsed RSA keys in memory to prevent repeated disk I/O on every request.

M Index

Microservice Introspection Anti-Pattern

Anti-Pattern • Ch. 4

Configuring downstream microservices to make a synchronous HTTP introspection call back to the IAM server on every incoming request. Doubles latency, introduces a single point of failure, and defeats the performance benefits of JWTs.

MissingRequiredClaimError

PyJWT • Ch. 2

A PyJWT exception raised when a decoded payload omits a claim configured as mandatory in options={"require": ["exp", "sub", ...]}, ensuring tokens without expirations or subjects are immediately rejected.

N Index

nbf (Not Before Claim)

RFC 7519 • Ch. 2

The RFC 7519 registered claim identifying the exact Unix epoch second before which the token must not be accepted for processing. Used for deferred token activation schedules.

NIST Key Length Standards

Security • Ch. 1

Cryptographic security guidelines published by NIST: mandates a minimum of 2048 bits for RSA keys and at least 256 bits (32 bytes) of random entropy for HMAC symmetric secrets to prevent offline brute-force cracking.

NumericDate (RFC 7519)

RFC 7519 • Ch. 2

The standard integer or floating-point representation of seconds elapsed since 1970-01-01T00:00:00Z UTC (Unix epoch). Used strictly by claims such as exp, nbf, and iat.

O Index

OAuth2PasswordBearer

FastAPI • Ch. 4

A FastAPI security utility that extracts Bearer token strings from incoming Authorization headers and registers the token acquisition endpoint (tokenUrl) in Swagger UI documentation.

options={"require": [...]}

PyJWT • Ch. 2

The PyJWT decoding option mapping a list of required claim strings. Guarantees that jwt.decode() raises an error if an incoming token is missing critical attributes like exp or sub.

options={"verify_signature": False}

PyJWT • Ch. 2, 3

A PyJWT option disabling signature verification. Hazardous if used in production application controllers because it allows arbitrary forged claims to pass; permissible strictly for offline CLI triage and inspection.

P Index

PEM (Privacy-Enhanced Mail)

Encoding • Ch. 1, 3

The standard text-based format for storing cryptographic keys and certificates. Wraps Base64-encoded DER binary data between human-readable header and footer delimiters (e.g. -----BEGIN RSA PRIVATE KEY-----).

PKCS#8 (Private-Key Syntax)

Standard • Ch. 1

The modern, algorithm-agnostic standard (RFC 5208) for serializing private keys. Replaces legacy PKCS#1 structures, using header -----BEGIN PRIVATE KEY-----.

Private Key (Asymmetric)

Crypto • Ch. 1, 3, 4

The confidential half of an asymmetric keypair held exclusively by the authentication authority. Used to create mathematical digital signatures for tokens. Must never be shared or distributed to microservices.

Public Key (Asymmetric)

Crypto • Ch. 1, 3, 4

The non-confidential half of an asymmetric keypair distributed freely to microservices and clients. Used to verify token digital signatures locally in memory. Cannot be used to sign or forge new tokens.

pyjwt[crypto]

Packaging • Ch. 1

The PyJWT installation target that bundles the underlying cryptography library. Required when working with asymmetric algorithms like RS256 or ES256.

R Index

Refresh Token Rotation (RTR)

Security • Ch. 2

A security pattern pairing short-lived access tokens (15 mins) with longer-lived, single-use refresh tokens stored in database or Redis. Every refresh request invalidates the old refresh token and issues a new pair, detecting stolen token replays.

RequireScopes Guard

FastAPI • Ch. 4

The parameterizable authorization dependency class in TokenForge. Inspects the authenticated principal's token claims and raises HTTP 403 Forbidden if required permission scopes are missing.

Revocation Strategy

Architecture • Ch. 2

Methods for invalidating stateless tokens before their exp lapses: storing revoked jti IDs in a Redis cache with a matching TTL or maintaining a distributed Bloom filter.

RS256 (RSA Signature with SHA-256)

Algorithm • Ch. 1, 4

The gold standard asymmetric algorithm for microservices. Signs tokens using an RSA private key and verifies them using an RSA public key. Recommended key size is 2048 or 4096 bits.

S Index

Scope Claims (scope / scp)

Claims • Ch. 2, 4

A space-separated string or array embedded in the token payload (e.g. "settlement:execute ledger:read") representing coarse-grained permissions granted to the principal.

Shared Secret Trap (Microservices)

Anti-Pattern • Ch. 1, 4

Sharing a single symmetric HS256 secret string across multiple microservices. If any single service leaks the secret, attackers can forge administrator tokens for the entire ecosystem.

Signing vs. Encryption

Crypto • Ch. 1

The critical distinction: Signing (JWS) guarantees payload integrity and authenticity, but anyone can decode and read the claims. Encryption (JWE) hides the payload from unauthorized viewers. Standard JWTs are signed, not encrypted.

sub (Subject Claim)

RFC 7519 • Ch. 2, 4

The RFC 7519 registered claim identifying the principal that is the subject of the JWT (e.g. User ID, machine client ID). Must be locally unique within the context of the issuer.

SubjectPublicKeyInfo (X.509)

Standard • Ch. 1

The standard X.509 structure (RFC 5280) for serializing public keys. Encoded in PEM format with header -----BEGIN PUBLIC KEY-----, used by PyJWT to import public keys.

Symmetric vs. Asymmetric Signing

Architecture • Ch. 1

Symmetric uses one shared secret for both signing and verifying (best for monoliths). Asymmetric uses a private key for signing and a public key for verifying (mandatory for microservices and zero-trust ecosystems).

T Index

Token Replay Attack

Security • Ch. 2

An attack where an adversary intercepts a valid token transmitted across the wire and resubmits it repeatedly to gain unauthorized access. Mitigated by short exp lifetimes, TLS, and recording unique jti nonces.

TokenEngine

TokenForge • Ch. 1, 3

The central cryptographic engine built in TokenForge Milestone 01. Encapsulates signing and verification logic, validates key bit-depths, and enforces single-algorithm whitelists to neutralize algorithm confusion attacks.

TokenForge Project

Project • Ch. 1–4

The continuous institutional federated identity and cryptographic token engineering project built incrementally across the four chapters to demonstrate RS256 signing, claims validation, CLI operator utilities, and FastAPI microservice federation.

TokenSecurityError

TokenForge • Ch. 1, 2

The base domain exception class in TokenForge. Parent to all specific token violations including TokenExpiredError, AudienceMismatchError, and AlgorithmMismatchError.

TokenValidator

TokenForge • Ch. 2, 4

The defensive validation pipeline service built in TokenForge Milestone 02. Enforces mandatory RFC 7519 registered claims, validates expected audiences and issuers, absorbs clock skew via leeway, and returns typed ValidatedToken objects.

U Index

UNIX Exit Codes in Security CLI

CLI • Ch. 3

Standardized process return codes implemented in TokenForge CLI: 0 (Valid), 1 (General/Syntax Error), 2 (Cryptographic Tampering), and 3 (Token Expired). Essential for bash script automation.

V Index

ValidatedToken

TokenForge • Ch. 2, 4

An immutable value object produced by TokenValidator upon successful decoding. Exposes strongly typed fields (subject, issuer, audience, expires_at) and a raw claims dictionary.

W Index

WWW-Authenticate Header (RFC 6750)

RFC 6750 • Ch. 4

A mandatory HTTP response header returned alongside status 401 Unauthorized (e.g. WWW-Authenticate: Bearer error="invalid_token"). Informs client applications and proxies which authentication scheme is expected.

Z Index

Zero-Network-Hop Verification

Architecture • Ch. 4

The architectural capability of downstream microservices to verify token signatures and claims locally in memory in ~0.1ms using a cached RSA public key, eliminating synchronous network calls back to the central IAM identity authority.
