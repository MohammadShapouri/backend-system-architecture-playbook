Part 01

Computer Science: Cryptographic Signing vs. Encryption

Before examining library interfaces, engineers must master the fundamental cryptographic objective of a JSON Web Token (RFC 7519). A standard JWT is a JWS (JSON Web Signature), not a JWE (JSON Web Encryption).

Signing provides Integrity (proving the claims have not been altered in transit) and Authenticity (proving the claims were generated by a trusted entity). It provides zero Confidentiality. Anyone who intercepts the token can decode the Base64URL string and read the payload.

Cryptographic Topologies: Symmetric Secrets vs. Asymmetric Keypairs

Analyzing Trust Boundaries Across Distributed Services

1. Symmetric Signing (HS256) Shared Secret

A single shared binary secret is used for both generation and validation:

IAM Service: Uses secret_key to SIGN token
Billing Service: Needs secret_key to VERIFY token
Reporting Service: Needs secret_key to VERIFY token
→ If Reporting Service is hacked, attacker steals secret_key!
  • Blast Radius: Catastrophic. Any verifier can forge valid administrator tokens.
  • Key Distribution: Complex and dangerous across cloud infrastructure.
  • Best For: Small monolithic backends with no external consumers.
2. Asymmetric Signing (RS256) Public/Private Pair

Two mathematically linked keys: a Private Signing Key and a Public Verifying Key:

IAM Service: Keeps PRIVATE key secret • SIGNS tokens
Billing Service: Has PUBLIC key only • VERIFIES locally
Reporting Service: Has PUBLIC key only • VERIFIES locally
→ Reporting Service breach leaks only public info. Zero forgery!
  • Blast Radius: Contained. Compromised services cannot issue or forge tokens.
  • Key Distribution: Safe. Public keys can be exposed via open JWKS endpoints.
  • Best For: Modern microservices, distributed SaaS, and mobile API backends.
Part 02

Under the Hood: The Algorithm Confusion Exploit

One of the most severe historical vulnerabilities in JWT implementations is the Algorithm Confusion Attack (also known as the Key Confusion Vulnerability). Understanding this exploit is mandatory for any senior engineer designing token-based systems.

The Anatomy of an Algorithm Confusion Breach
1. Attacker Action Takes known RSA Public Key • Changes JWT Header from "RS256" to "HS256"
→ signs with HMAC →
2. Forged Token Created Attacker uses public key string as symmetric secret • Generates valid HS256 signature
→ dispatches to backend →
3. Vulnerable Verifier Naive decoder reads header "HS256" • Uses server's public key variable as HMAC secret • Signature MATCHES!
⚠ Why This Happens in Naive Code:

If a developer writes jwt.decode(token, public_key) without explicitly specifying the algorithms=["RS256"] whitelist, an older or poorly configured library reads the algorithm from the unverified token header. It switches to symmetric mode, treating the text of the public key as the secret password! Since the attacker already knows the public key, they have effectively forged administrative credentials.

The Defensive PyJWT Mandate: Explicit Algorithm Constraints

PyJWT mitigates this vulnerability by strictly requiring an explicit list of algorithms in jwt.decode(). If an incoming token specifies an algorithm not present in the allowed list, PyTest and PyJWT raise an immediate jwt.exceptions.InvalidAlgorithmError.

# SENIOR STANDARD: Always pass algorithms as an explicit single-item list
payload = jwt.decode(token, public_key, algorithms=["RS256"])
Part 03

Cryptographic Key Management: Generating & Serializing PEMs

Asymmetric keys are represented as abstract mathematical structures (prime factors and modular exponents). In production software, these structures are serialized into standardized text representations known as PEM (Privacy-Enhanced Mail) files, bounded by headers like -----BEGIN RSA PRIVATE KEY-----.

PyJWT delegates all asymmetric cryptography to the industrial-strength Python cryptography library. Below is the exact production sequence for generating and serializing an RSA-2048 keypair in memory:

// Pure Python Key Generation & Serialization (PKCS#8 & SubjectPublicKeyInfo):
from cryptography.hazmat.primitives.asymmetric import rsa
from cryptography.hazmat.primitives import serialization

def generate_rsa_keypair() -> tuple[str, str]:
    # 1. Generate private key using Fermat's public exponent (65537) and 2048-bit modulus
    private_key = rsa.generate_private_key(
        public_exponent=65537,
        key_size=2048,
    )

    # 2. Serialize Private Key to PEM format (PKCS#8 standard)
    private_pem = private_key.private_bytes(
        encoding=serialization.Encoding.PEM,
        format=serialization.PrivateFormat.PKCS8,
        encryption_algorithm=serialization.NoEncryption()  # In prod, protect with passphrases
    ).decode("utf-8")

    # 3. Extract and Serialize Public Key to PEM format (SubjectPublicKeyInfo standard)
    public_pem = private_key.public_key().public_bytes(
        encoding=serialization.Encoding.PEM,
        format=serialization.PublicFormat.SubjectPublicKeyInfo
    ).decode("utf-8")

    return private_pem, public_pem

2. Cryptographic Token Engine: src/tokenforge/core/crypto.py Symmetric & Asymmetric Implementation 
# ==============================================================================
# TokenForge Core - Cryptographic Token Engine (Milestone 01)
# ==============================================================================

import jwt
from datetime import datetime, timezone
from typing import Any, Dict, Optional, Tuple
from cryptography.hazmat.primitives.asymmetric import rsa
from cryptography.hazmat.primitives import serialization

class TokenSecurityError(Exception):
    """Base exception for TokenForge security and cryptographic violations."""
    pass

class InvalidKeyError(TokenSecurityError):
    """Raised when cryptographic key formatting or bit-depth is invalid."""
    pass

class AlgorithmMismatchError(TokenSecurityError):
    """Raised when token algorithm deviates from strict allowed whitelist."""
    pass


class KeyManager:
    """Generates, parses, and validates cryptographic keys for token operations."""

    @staticmethod
    def generate_rsa_keypair(key_size: int = 2048) -> Tuple[str, str]:
        """
        Generates an industrial-grade RSA Keypair using FIPS compliant public exponent.
        Returns: (private_pem_string, public_pem_string)
        """
        if key_size < 2048:
            raise InvalidKeyError("RSA key size must be at least 2048 bits for secure operation.")

        private_key = rsa.generate_private_key(
            public_exponent=65537,
            key_size=key_size,
        )

        private_pem = private_key.private_bytes(
            encoding=serialization.Encoding.PEM,
            format=serialization.PrivateFormat.PKCS8,
            encryption_algorithm=serialization.NoEncryption()
        ).decode("utf-8")

        public_pem = private_key.public_key().public_bytes(
            encoding=serialization.Encoding.PEM,
            format=serialization.PublicFormat.SubjectPublicKeyInfo
        ).decode("utf-8")

        return private_pem, public_pem


class TokenEngine:
    """
    Core token issuing and verification engine.
    Enforces strict algorithm encapsulation to eliminate Key Confusion exploits.
    """
    def __init__(
        self,
        algorithm: str = "RS256",
        signing_key: Optional[str] = None,
        verification_key: Optional[str] = None
    ):
        self.algorithm = algorithm
        self.signing_key = signing_key
        self.verification_key = verification_key

        # Defensive sanity: enforce key strength for symmetric algorithms
        if self.algorithm.startswith("HS") and self.signing_key:
            if len(self.signing_key.encode("utf-8")) < 32:
                raise InvalidKeyError("HMAC secrets must be at least 32 bytes (256 bits) long.")

    def issue_token(self, payload: Dict[str, Any], headers: Optional[Dict[str, Any]] = None) -> str:
        """
        Signs a payload into an RFC 7519 JSON Web Token string.
        Requires signing_key (Private Key for RS256, Shared Secret for HS256).
        """
        if not self.signing_key:
            raise TokenSecurityError("Signing key is not configured on this TokenEngine instance.")

        token = jwt.encode(
            payload=payload,
            key=self.signing_key,
            algorithm=self.algorithm,
            headers=headers
        )
        return token

    def verify_token(self, token: str) -> Dict[str, Any]:
        """
        Verifies token signature and extracts claims.
        Crucial Defense: Enforces algorithms=[self.algorithm] to block algorithm switching!
        """
        key = self.verification_key or self.signing_key
        if not key:
            raise TokenSecurityError("Verification key is not configured on this TokenEngine instance.")

        try:
            decoded_claims = jwt.decode(
                jwt=token,
                key=key,
                # CRITICAL SECURITY INVARIANT: Must pass algorithms as explicit list
                algorithms=[self.algorithm],
                options={"verify_signature": True}
            )
            return decoded_claims
        except jwt.exceptions.InvalidAlgorithmError as err:
            raise AlgorithmMismatchError(f"Token algorithm does not match required {self.algorithm}") from err
        except jwt.PyJWTError as err:
            raise TokenSecurityError(f"Cryptographic verification failed: {str(err)}") from err

4. Cryptographic Test Suite: tests/unit/test_crypto.py Verifying Security & Exploits 
# ==============================================================================
# TokenForge Test Suite - Cryptographic Engine Verification (Milestone 01)
# ==============================================================================

import jwt
import pytest
from tokenforge.core.crypto import (
    TokenEngine, 
    KeyManager, 
    InvalidKeyError, 
    AlgorithmMismatchError, 
    TokenSecurityError
)

class TestCryptographicEngine:
    """Unit tests asserting signature generation, verification, and exploit defense."""

    def test_symmetric_hs256_issue_and_verify_cycle(self):
        # Enforces 32-byte secret
        secret = "super_secret_key_exceeding_32_bytes_length!"
        engine = TokenEngine(algorithm="HS256", signing_key=secret)

        token = engine.issue_token({"sub": "user_123", "role": "analyst"})
        claims = engine.verify_token(token)

        assert claims["sub"] == "user_123"
        assert claims["role"] == "analyst"

    def test_asymmetric_rs256_issue_with_private_verify_with_public(self, rsa_keypair):
        # Producer uses Private Key
        issuer_engine = TokenEngine(algorithm="RS256", signing_key=rsa_keypair["private"])
        token = issuer_engine.issue_token({"sub": "svc_orders", "scope": "orders:write"})

        # Consumer uses Public Key ONLY
        consumer_engine = TokenEngine(algorithm="RS256", verification_key=rsa_keypair["public"])
        claims = consumer_engine.verify_token(token)

        assert claims["sub"] == "svc_orders"
        assert claims["scope"] == "orders:write"

    def test_tampered_payload_fails_signature_verification(self, rsa_keypair):
        issuer_engine = TokenEngine(algorithm="RS256", signing_key=rsa_keypair["private"])
        token = issuer_engine.issue_token({"sub": "user_123", "is_admin": False})

        # Attacker modifies the payload segment in transit
        parts = token.split(".")
        tampered_token = f"{parts[0]}.eyJzdWIiOiAidXNlcl8xMjMiLCAiaXNfYWRtaW4iOiB0cnVlfQ.{parts[2]}"

        consumer_engine = TokenEngine(algorithm="RS256", verification_key=rsa_keypair["public"])
        with pytest.raises(TokenSecurityError, match=r"verification failed"):
            consumer_engine.verify_token(tampered_token)

    def test_algorithm_confusion_exploit_is_blocked(self, rsa_keypair):
        """
        CRITICAL EXPLOIT REPRODUCTION:
        Attacker signs token with HS256 using the target server's public key string as secret.
        The TokenEngine MUST reject the token because its algorithm whitelist is strictly RS256!
        """
        public_pem_as_hmac_secret = rsa_keypair["public"]
        malicious_forged_token = jwt.encode(
            payload={"sub": "admin", "role": "superuser"},
            key=public_pem_as_hmac_secret,
            algorithm="HS256"
        )

        # Target server is expecting RS256
        server_verifier = TokenEngine(algorithm="RS256", verification_key=rsa_keypair["public"])

        with pytest.raises(AlgorithmMismatchError):
            server_verifier.verify_token(malicious_forged_token)
Warning Track

Beginner Pitfalls & Architectural Anti-Patterns

❌ The Shared Secret Across Microservices Trap

Using a single symmetric HS256 secret string distributed across 15 separate microservice repositories.

Why this causes systemic outages: Every service that needs to verify a token has the power to issue tokens. If a vulnerability is discovered in an internal reporting microservice, an attacker extracts the shared secret and can immediately issue valid administrator tokens across payment and account systems. Always use RS256 or ES256 across service boundaries!

❌ Short Symmetric Secrets

Using short passwords like secret = "my_app_secret" for HS256 signing.

Why this is cracked in minutes: JWTs are completely public. Anyone holding a token can run offline dictionary attacks using GPU hash-cracking tools (such as Hashcat or John the Ripper) directly against the signature string. Modern standards mandate a minimum of 256 bits (32 high-entropy bytes).
