A Index

ACID Guarantees

Database • Ch. 4

The four non-negotiable guarantees of transactional relational storage: Atomicity (all operations commit or all rollback), Consistency (invariants and check constraints are preserved), Isolation (concurrent transactions cannot view partial state), and Durability (committed writes survive system crashes via WAL logs).

aiosqlite

Driver • Ch. 1, 9

An asynchronous driver for SQLite using the URI protocol sqlite+aiosqlite:///. Runs SQLite operations in a separate worker threadpool to emulate non-blocking behavior for local testing alongside async engines.

Alembic

Database • Ch. 8, 11

The official schema migration framework for SQLAlchemy. Inspects ORM model metadata, compares it against the live physical database catalog, and compiles versioned Python upgrade and downgrade scripts without deleting existing production data.

alembic_version Table

Alembic • Ch. 8

A single-row metadata table automatically created and maintained by Alembic inside your relational database. Contains the single column version_num, designating the exact migration revision node the database is currently synchronized to.

async_sessionmaker

Async • Ch. 9

The asynchronous session factory in SQLAlchemy 2.0. Binds to an AsyncEngine and produces isolated AsyncSession instances per request, typically configured with expire_on_commit=False.

AsyncAdaptedQueuePool

Connection Pool • Ch. 9

The default connection pool implementation used by asynchronous engines. Adapts the standard bounded-queue pooling logic to integrate cleanly with non-blocking event loops, managing warm connection checkouts across concurrent asyncio tasks.

AsyncEngine & create_async_engine()

Async • Ch. 9

The non-blocking factory construct in SQLAlchemy. Connects to drivers using async protocols (postgresql+asyncpg). Replaces threadpool offloading with true Linux epoll OS socket multiplexing on Python's event loop.

asyncpg

Driver • Ch. 1, 9

A high-speed, non-blocking PostgreSQL driver built directly on the PostgreSQL binary frontend/backend protocol. Operates without libpq dependencies, delivering industry-leading query throughput under high concurrency.

AsyncSession

Async • Ch. 9

The asynchronous proxy wrapper around SQLAlchemy's Unit of Work. Replaces blocking method calls with coroutines requiring explicit await expressions (await session.execute(), await session.commit()).

B Index

back_populates

Relationships • Ch. 6

The explicit 2.0 configuration parameter establishing a bidirectional relationship between two models. Synchronizes changes made in memory (e.g. appending a transaction to account.transactions automatically updates transaction.account).

Base (DeclarativeBase)

Architecture • Ch. 2, 3

The common ancestor class for all declarative ORM entities in SQLAlchemy 2.0. Holds the shared MetaData collection that catalogues all tables, columns, indexes, and constraint naming conventions.

batch_alter_table (Alembic)

Alembic • Ch. 8

An Alembic context manager (with op.batch_alter_table("accounts") as batch_op:) that provides cross-database safety. Essential for SQLite: creates a temporary table, copies existing rows, drops the old table, and renames the new table to emulate native DDL alters.

before_cursor_execute / after_cursor_execute

Telemetry • Ch. 11

Core engine event hooks fired immediately before and after a SQL statement is dispatched to the DBAPI driver cursor. Used to stamp monotonic start times and log slow queries exceeding production latency thresholds.

begin_nested() (Savepoints)

Transactions • Ch. 4

A session context manager emitting a database SAVEPOINT. Allows isolated sub-actions (e.g. attempting to charge an optional fee) to fail and rollback cleanly (ROLLBACK TO SAVEPOINT) without aborting the parent outer transaction.

Bulk Operations (Core insert().values())

Performance • Ch. 7

Executing bulk inserts, updates, or deletes using raw Core statements (session.execute(insert(Model), list_of_dicts)). Bypasses ORM object instantiation and Identity Map registration, achieving massive ingestion throughput with a flat memory footprint.

C Index

Cartesian Product Trap

Anti-Pattern • Ch. 6

A severe performance hazard caused by applying joinedload() across multiple one-to-many collections simultaneously. SQL outer joins multiply row counts (e.g. 1 parent × 50 child A × 20 child B = 1,000 returned rows), duplicating parent data and exhausting network bandwidth.

Cascades (delete-orphan vs. passive_deletes)

Relationships • Ch. 6

ORM cascade rules (cascade="all, delete-orphan") instruct SQLAlchemy to track and delete detached child instances in Python memory. Database cascades (ondelete="CASCADE") with passive_deletes=True delegate deletion to the RDBMS engine directly for optimal performance.

CheckConstraint

DDL • Ch. 2, 3

A database-level constraint enforcing boolean business rules on physical columns (e.g. CheckConstraint("balance >= 0")). Acts as the ultimate defensive backstop against software bugs or race conditions attempting to write corrupt state.

commit() vs. flush()

Transactions • Ch. 4

flush() emits buffered SQL (INSERT/UPDATE) to the database connection buffer, assigning primary keys and checking constraints without ending the transaction. commit() issues a physical COMMIT, writing to the Write-Ahead Log (WAL), releasing database locks, and terminating the transaction.

Common Table Expressions (cte())

Core Query • Ch. 7

Temporary, named query result sets compiled using the SQL WITH clause (select(...).cte("summary")). Enables clean, modular multi-stage analytical aggregations without deep subquery nesting.

compare_type=True

Alembic • Ch. 8

A critical configuration flag in alembic/env.py. By default, Alembic autogenerate ignores alterations to column types. Enabling this flag forces Alembic to detect column length, precision, and type changes (e.g. String(50) → String(100)).

Connection (Level 2 Primitive)

Architecture • Ch. 1

An active, checked-out socket wrapper acquired from the Engine pool (with engine.connect() as conn:). Represents a direct channel to the database used for executing raw SQL statements or Core expressions outside of the ORM Unit of Work.

contains_eager()

Loader Strategy • Ch. 6

A specialized loader strategy used when a query explicitly joins a related table (often to apply WHERE filters). Instructs SQLAlchemy to populate the relationship collection directly from the joined rows without emitting a redundant second query or outer join.

create_engine()

Core • Ch. 1

The central singleton factory in SQLAlchemy. Parses the database connection URI, loads the target dialect compiler, instantiates the connection pool, and manages socket lifecycles. Must be instantiated exactly once per application process.

D Index

Database Dialect

Architecture • Ch. 1

SQLAlchemy’s database-specific compiler layer. Translates Python expressions into dialect-specific SQL syntax, handling variance across RDBMS implementations (such as PostgreSQL sequences vs MySQL auto-increment, or JSONB vs JSON).

DBAPI (Python Enhancement Proposal 249)

Specification • Ch. 1

The standardized interface specification for Python database drivers. Mandates uniform Connection and Cursor classes across low-level drivers like psycopg, asyncpg, and sqlite3.

Deadlock & Deterministic Lock Ordering

Concurrency • Ch. 5

A concurrency failure where Transaction 1 locks Row A and requests Row B, while Transaction 2 locks Row B and requests Row A. Mathematically eliminated by Deterministic Lock Ordering: always acquiring row locks in ascending primary key ID order (order_by(Model.id.asc())).

DeclarativeBase

SQLAlchemy 2.0 • Ch. 2

The modern 2.0 foundation class for declaring ORM models. Subclassed by class Base(DeclarativeBase): pass, replacing legacy 1.x declarative_base() and enabling type-annotated Mapped[] column mapping.

Detached State & DetachedInstanceError

ORM State • Ch. 4, 6

The state of an entity whose originating Session has closed. The object still has a database primary key in RAM, but attempting to access un-loaded relationship attributes crashes with DetachedInstanceError because no database connection exists to fetch the child data.

Discriminator Column (polymorphic_on)

Inheritance • Ch. 3

The physical table column (such as transaction_type) that stores string identifiers indicating which subclass an individual row represents, allowing polymorphic queries to instantiate the correct child class in memory.

E Index

Eager Loading

Performance • Ch. 6

Loading parent entities and related child collections upfront in the initial query or in a batch using selectinload() or joinedload(). Neutralizes N+1 query bottlenecks and ensures attributes remain accessible outside the session.

Engine (Level 1 Singleton)

Architecture • Ch. 1

The application-wide singleton holding the dialect compiler and the active connection pool. Does not maintain persistent user transaction state; checks out transient Connection sockets to sessions upon demand.

engine.dispose()

DevOps • Ch. 11

Closes all underlying open database socket connections currently held inside the connection pool. Called inside application lifespan shutdown blocks upon receiving SIGTERM to prevent orphaned connections from exhausting RDBMS slot limits during rolling deployments.

Entity Lifecycle States (4 States)

ORM State • Ch. 4

The four phases an ORM instance traverses in Python memory: Transient (new in RAM, no session), Pending (session.add(), not yet flushed), Persistent (flushed or queried, bound to session with a DB identity), and Detached (session closed).

Enum & SQLEnum (native_enum=False)

Types • Ch. 2

Mapping Python enum.Enum classes to database columns. Setting native_enum=False creates a portable VARCHAR column backed by a check constraint, ensuring identical validation behavior across both SQLite and PostgreSQL.

event.listens_for (SQLAlchemy Event Bus)

Telemetry • Ch. 11

The decorator used to register listeners across SQLAlchemy’s internal publish-subscribe Event Bus. Attaches hooks to engines, sessions, or mappers to execute auditing, modify statements, or benchmark slow SQL queries.

exclude_unset=True (PATCH Updates)

Web Pattern • Ch. 10

A Pydantic serialization setting essential for safe HTTP PATCH endpoints. Dumps only the fields explicitly provided in the request payload, ignoring default null values so untouched database columns are not overwritten.

expire_on_commit=False

Sessionmaker • Ch. 4, 9

A configuration flag on sessionmaker. When set to False, committed instances retain their attribute values in RAM rather than expiring them. Critical in FastAPI to prevent DetachedInstanceError or MissingGreenlet during response serialization.

F Index

Floating-Point Trap (Float vs. Numeric)

Anti-Pattern • Ch. 2

The danger of storing monetary balances in binary Float columns. Base-2 binary arithmetic cannot represent numbers like $0.10$ exactly, resulting in fractional rounding drift (0.30000000000000004). Fixed via base-10 Numeric types.

flush()

Transactions • Ch. 4

Emits pending SQL statements to the database transaction buffer over the active connection. Obtains database-generated primary key IDs and fires check constraints, but does not commit or release transaction locks.

func.now() vs. server_default

DDL • Ch. 3

SQLAlchemy’s SQL function compiler generating CURRENT_TIMESTAMP. When used inside server_default=func.now(), timestamps are assigned directly by the central database engine clock, eliminating distributed app-server clock drift.

G Index

get_bind() (Primary/Replica Routing)

Routing • Ch. 10

A core method on SQLAlchemy’s Session that resolves which database engine to execute a query against. Overridden in enterprise routing sessions to dynamically route SELECT queries to Read-Replicas and mutation statements to the Primary writer.

Greenlet & greenlet_spawn

Async • Ch. 9

A C-extension micro-threading library used by SQLAlchemy to bridge synchronous ORM logic with asynchronous Python event loops. Spawns an internal execution frame that suspends itself when I/O is reached and yields control to asyncio.

I Index

Identity Map

Architecture • Ch. 4

A dictionary maintained inside each Session that maps (Model, primary_key) to an in-memory instance. Ensures querying the same primary key multiple times in a single request always returns the exact same Python object pointer in RAM.

Identity Map Memory Tax

Performance • Ch. 7

The performance and RAM penalty of instantiating thousands of individual ORM model objects inside an active session. Managing InstanceState and dirty-tracking structures across 10,000 objects consumes 100MB+ of RAM. Bypassed via Core bulk operations.

Object-Relational Impedance Mismatch

Computer Science • Ch. 1

The conceptual conflict between object-oriented programming (rich graphs, references, methods) and relational databases (two-dimensional tables, foreign keys, set theory). Bridged by ORM frameworks.

J Index

joinedload()

Loader Strategy • Ch. 6

An eager loader strategy that emits a SQL LEFT OUTER JOIN to fetch parent and child entities in a single network round-trip. Optimal for many-to-one and one-to-one relations, but hazardous when applied to multiple collections due to Cartesian products.

Joined-Table Inheritance (JTI)

Inheritance • Ch. 3

A normalized ORM inheritance strategy where common attributes reside in a base table, and subclass attributes are stored in separate child tables sharing the same primary key as a foreign key. Allows strict NOT NULL constraints on child fields.

L Index

Lazy Loading (lazy="select")

Anti-Pattern • Ch. 6, 9

The default relationship loading mode where child data is not fetched until the attribute is accessed in Python. Causes N+1 query bottlenecks in loops, triggers DetachedInstanceError if the session has closed, and causes fatal MissingGreenlet exceptions in async applications.

LedgerCore Project

Project • Ch. 1–11

The continuous double-entry financial ledger and transaction system built across the curriculum to demonstrate exact decimal calculations, concurrency locking, polymorphic movements, and cloud database deployment.

Lost Update Anomaly

Concurrency • Ch. 5

A concurrency race condition where two simultaneous transactions execute a Read-Modify-Write cycle on the same row. Transaction B commits after Transaction A, silently overwriting Transaction A’s modification. Defended via row-level locking.

M Index

Mapped[]

SQLAlchemy 2.0 • Ch. 2

The type-hinting container representing ORM-mapped attributes in 2.0. Informs static typecheckers (Mypy) of attribute types and automatically infers database nullability (e.g. Mapped[str] produces NOT NULL, while Mapped[Optional[str]] produces NULL).

mapped_column()

SQLAlchemy 2.0 • Ch. 2

The 2.0 declarative column generator. Replaces legacy Column(), accepting DDL metadata such as primary keys, database types, default values, check constraints, and foreign key definitions.

MetaData & naming_convention (5 Keys)

Schema Design • Ch. 3, 8

The enterprise dictionary defining explicit naming rules for anonymous constraints: ix, uq, ck, fk, pk. Prevents autogenerated nameless constraints that cause Alembic to crash during drop or alter operations.

MissingGreenlet Exception

Async • Ch. 9

A runtime crash thrown when application code accesses an unloaded relationship attribute in an async context without eager loading. Because Python properties cannot be implicitly awaited, the driver cannot yield to the event loop and raises a fatal exception.

Mixins (TimestampMixin & SoftDeleteMixin)

Design Pattern • Ch. 3

Reusable, uninstantiated Python classes that bundle common columns, indexes, and table configurations. Composed into target models via Python's Method Resolution Order (MRO) to eliminate repetitive boilerplate.

Multi-Tenancy & Sharding

Architecture • Ch. 10

Architectural patterns for isolating corporate tenant data: either by dynamically setting PostgreSQL's search_path to tenant-specific schema namespaces, or by dynamically resolving the active session to a physically sharded engine pool based on request headers.

N Index

N+1 Query Problem

Performance • Ch. 6

A performance defect where loading $N$ parent records results in 1 initial query plus $N$ individual child queries, amplifying network round-trip latency. Solved by eager loading via selectinload().

NullPool

Connection Pool • Ch. 1, 8

A connection pool class that disables pooling completely, opening a fresh database socket upon checkout and closing it immediately upon checkin. Standard for one-off CLI operations and Alembic migration scripts.

Numeric(precision, scale)

Types • Ch. 2

The fixed-point numeric type (e.g. Numeric(14, 4)) mapping directly to Python's decimal.Decimal. Stores scaled base-10 integers to guarantee exact precision without floating-point rounding corruption.

O Index

Optimistic Concurrency Control (OCC)

Concurrency • Ch. 5

A concurrency control mechanism where no database row locks are held during read phases. Instead, rows include an integer version counter (version_id_col). When committing, SQLAlchemy verifies that the database version matches the loaded version, raising StaleDataError if a conflict occurred.

P Index

passive_deletes=True

Relationships • Ch. 6

A relationship configuration setting informing SQLAlchemy that the database server will automatically handle child row deletions via foreign key cascades (ondelete="CASCADE"), preventing the ORM from wasting memory loading children into RAM before emitting parent deletes.

Pending State

ORM State • Ch. 4

The state of an entity that has been registered with a session (session.add()) but has not yet been flushed to the database. It is tracked by the Unit of Work but does not yet possess an active database identity.

PendingRollbackError

Exception • Ch. 4

An exception raised when application code attempts to execute queries on a session whose transaction previously encountered a SQL error. When PostgreSQL encounters an error, it rejects all further commands until session.rollback() is explicitly called.

Persistent State

ORM State • Ch. 4

The state of an entity that is bound to an active session, tracked in the Identity Map, and has a corresponding row and primary key in the database. Attribute changes made to persistent objects are automatically marked "dirty".

Pessimistic Locking (with_for_update)

Concurrency • Ch. 5

Acquiring exclusive row-level database locks during reads via SELECT ... FOR UPDATE (select(Model).with_for_update()). Forces concurrent transactions attempting to read or write the same rows to queue, neutralizing race conditions.

polymorphic_on & polymorphic_identity

Inheritance • Ch. 3

Configuration arguments in __mapper_args__. polymorphic_on identifies the discriminator column on the base class; polymorphic_identity specifies the unique discriminator value that instantiates that specific child subclass.

pool_pre_ping=True

Connection Pool • Ch. 1, 11

A production engine setting that executes an ultra-fast SELECT 1 heartbeat query immediately before handing a pooled connection to an application request. Catches and discards stale sockets dropped by cloud firewalls without crashing the request.

pool_recycle

Connection Pool • Ch. 1, 11

An engine parameter (typically set to 1800 seconds / 30 minutes) instructing the pool to close and re-open physical connections that have exceeded an age threshold, preventing server-side timeouts from severing idle connections.

pool_size & max_overflow

Connection Pool • Ch. 1, 11

pool_size defines the constant number of warm connections held open in the pool. max_overflow sets the upper ceiling of temporary burst connections spawned during sudden traffic spikes.

Q Index

QueuePool

Connection Pool • Ch. 1

The standard connection pool implementation for synchronous relational engines. Maintains an in-memory queue of connections, blocking calling threads up to a configured timeout (pool_timeout=30) when capacity is exhausted before raising an error.

R Index

raiseload("*")

Loader Strategy • Ch. 6

A defensive compiler guard option passed to select().options(raiseload("*")). Throws an InvalidRequestError immediately if any code attempts to access an unloaded relationship attribute, mathematically guaranteeing zero accidental lazy queries.

Read-Replica Routing

Microservice Scale • Ch. 10

An architectural pattern splitting traffic between a Primary database engine (handling write mutations: INSERT/UPDATE/DELETE) and one or more Read-Only Replicas (handling read queries: SELECT), protecting write capacity from analytical contention.

Replication Lag

Distributed Systems • Ch. 10

The delay between a write committing on the Primary engine and being replayed on a Read-Replica. Causes Read-After-Write anomalies where a user writes data and immediately queries a replica, seeing stale or missing data. Defended by pinning recent writers to the primary.

Revision DAG (Alembic)

Alembic • Ch. 8

The Directed Acyclic Graph formed by Alembic migration files linking revision to down_revision. Diverges into multiple heads when concurrent branches merge, and re-unifies into a single path via alembic merge.

rollback()

Transactions • Ch. 4

The session method that issues an atomic ROLLBACK to the database connection. Discards all pending in-memory and buffered SQL changes, releasing locks and resetting the session to a clean state after an unhandled error.

run_sync() (Async Alembic Bridge)

Async • Ch. 8, 9

An asynchronous connection method (await connection.run_sync(fn)) that allows synchronous callable routines (like Alembic’s DDL migration runner) to execute over an asynchronous database driver without blocking the event loop.

S Index

Savepoints (begin_nested)

Transactions • Ch. 4

A database transaction boundary within an active transaction. Created via session.begin_nested(), allowing isolated sub-operations to fail and roll back without causing the outer parent transaction to abort.

select() & scalars()

Querying • Ch. 2, 6, 7

The core query construction syntax in SQLAlchemy 2.0. select(Model) constructs a typed executable expression; session.scalars() unwraps row tuples directly into individual ORM entity instances.

selectinload()

Loader Strategy • Ch. 6

The gold-standard eager loading strategy for one-to-many collections. Emits a second query using an IN (...) clause on parent primary keys. Avoids Cartesian product duplications and is completely safe with query pagination (limit/offset).

server_default (vs. default)

DDL • Ch. 3

Specifies a default value in the database table DDL (DEFAULT CURRENT_TIMESTAMP). Unlike Python client-side default=, server defaults are evaluated by the RDBMS engine at commit time, guaranteeing consistency across disparate services and migrations.

Session & sessionmaker (Level 3 Sandbox)

Architecture • Ch. 1, 4

The primary ORM interaction interface. Acts as a transaction-scoped sandbox implementing the Unit of Work and Identity Map patterns. Tracks object state modifications in RAM and flushes SQL changes inside transactions.

Single-Table Inheritance (STI)

Inheritance • Ch. 3

An ORM inheritance pattern where all classes in a hierarchy are persisted into a single wide table with a discriminator column. Provides fast reads without joins, but creates sparse tables because subclass columns must be declared nullable=True.

StaleDataError

Exception • Ch. 5

An exception raised by SQLAlchemy during Optimistic Concurrency Control commits. Occurs when an UPDATE statement targeting an expected version_id modifies 0 rows because a concurrent transaction updated the record first.

StaticPool

Connection Pool • Ch. 1

A connection pool that maintains exactly one persistent connection across all checkouts. Mandatory when using SQLite in-memory databases (:memory:) to prevent data from vanishing when a session closes.

T Index

target_metadata (Alembic)

Alembic • Ch. 8

The variable in alembic/env.py bound to your application’s Base.metadata. Provides Alembic’s autogenerate engine with the complete catalogue of models and columns to compare against the physical database.

text() Construct

Core • Ch. 1

A core SQLAlchemy construct used to declare raw SQL strings safely. SQLAlchemy 2.0 strictly disallows passing bare string literals to execute() to defend against SQL injection; all textual statements must be wrapped in text("SELECT ...").

Three-Step Data Migration Pattern

Alembic • Ch. 8

The zero-downtime pattern for adding non-nullable columns to populated production tables: 1) Add column as nullable=True, 2) Execute an inline SQL backfill updating historical rows with default data, 3) Alter the column constraint to nullable=False.

TimestampMixin

Mixin • Ch. 3

A standardized declarative mixin class providing created_at and updated_at audit columns. Configured with server_default=func.now() and DateTime(timezone=True) to eliminate timezone and clock drift errors.

Transient State

ORM State • Ch. 4

The initial state of an entity instantiated using its standard Python constructor (acc = Account(...)). Exists strictly in Python RAM, is not associated with any database session, and has no database primary key identity.

U Index

Unit of Work Pattern

Design Pattern • Ch. 4

Martin Fowler’s pattern implemented by SQLAlchemy's Session. Maintains a list of business objects affected by a business transaction and coordinates writing out changes by computing minimal, ordered SQL changesets upon commit.

UUIDv4 vs. UUIDv7 (B-Tree Health)

Database Indexing • Ch. 2

Random UUIDv4 identifiers cause random insertions throughout B-Tree index pages, causing expensive page splits and high disk I/O under heavy write volume. Time-ordered UUIDv7 and sequential BigIntegers append cleanly to the rightmost leaf node, preserving index density.

V Index

version_id_col

Concurrency • Ch. 5

The model configuration argument in __mapper_args__ enabling native Optimistic Concurrency Control. Designates an integer column that SQLAlchemy increments on each update, validating that another transaction has not modified the record in the interim.

W Index

Window Functions (func.over())

Analytics • Ch. 7

SQL analytical functions declared via func.sum().over(partition_by=..., order_by=...). Calculates cumulative aggregates (such as running account balances over historical ledger entries) directly inside the database engine without looping in Python.

with_for_update()

Concurrency • Ch. 5

The query method compiling into SELECT ... FOR UPDATE. Acquires exclusive row-level database locks, preventing concurrent transactions from reading or mutating targeted rows until the locking transaction commits. Supports nowait=True and skip_locked=True.

Z Index

Zero-Downtime Migration Rollout

DevOps • Ch. 8, 11

The operational discipline of executing schema migrations without service interruption. Follows the expand-and-contract pattern and isolates alembic upgrade head into a single-execution pre-deploy release phase or Kubernetes Job, avoiding multi-pod container lock collisions.
