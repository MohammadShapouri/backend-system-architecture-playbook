A Index

act (Local Actions CLI)

CLI • Ch. 6

An open-source utility that reads .github/workflows/ and runs GitHub Actions locally by launching Docker containers matching the runner environment, allowing pipeline debugging without pushing commits.

actions/cache@v4

Actions • Ch. 7

A production GitHub Action that caches dependency directories (e.g., ~/.cache/pip, node_modules) using content-addressable cryptographic keys computed via hashFiles().

actions/checkout@v4

Actions • Ch. 6, 7

The standard official action that checks out your Git repository to the runner's $GITHUB_WORKSPACE so that subsequent steps can access, test, and build the code.

Atomic Commit

Methodology • Ch. 2

A core version control principle where each commit represents a single, self-contained, compilable change. Ensures every commit in history passes tests and can be rolled back or cherry-picked independently without breaking the build.

B Index

Blob (Binary Large Object)

Git Primitives • Ch. 1

One of the four immutable Git object types stored in .git/objects/. Stores raw compressed file contents only, omitting filenames, paths, and permissions (which are stored separately in Tree objects).

Branch (Git Reference)

Git Architecture • Ch. 2

A lightweight, movable text pointer stored in .git/refs/heads/<name> that contains the 40-character SHA of the branch's latest commit. It is not a container of files, making branch creation instantaneous.

Branch Protection Rules (Rulesets)

Governance • Ch. 5

GitHub security policies applied to branches like main that block direct pushes, require passing CI status checks, enforce peer code review approvals, and require linear history.

BREAKING CHANGE (SemVer)

Convention • Ch. 2

In Conventional Commits, a declaration denoted by an exclamation mark (feat!: ...) or a footer (BREAKING CHANGE: ...) indicating an incompatible API change that triggers a Major version increment.

C Index

CODEOWNERS (.github/CODEOWNERS)

Governance • Ch. 5

A configuration file defining which individuals or teams automatically receive review requests when a pull request modifies code in designated directory paths (e.g., /src/auth/ @security-team).

Commit Object

Git Primitives • Ch. 1

An immutable node in the Git DAG stored in .git/objects/. Bundles a top-level Tree hash pointer, parent commit hashes, author/committer identities, timestamps, and the semantic commit message.

concurrency (Actions Directive)

Actions • Ch. 6

A workflow directive configured with cancel-in-progress: true that automatically cancels older in-flight CI builds for the same branch or PR when a developer pushes new commits, saving runner compute minutes.

Content-Addressable Storage

Computer Science • Ch. 1

A datastore architecture where data is retrieved by its cryptographic hash key rather than a filename or path. In Git, hashing header + content produces the SHA key used to write and look up objects in .git/objects/.

Conventional Commits 1.0

Standards • Ch. 2

A lightweight specification on commit messages providing explicit formatting rules (<type>(<scope>): <description>) that integrate directly with automated semantic changelogs and version release tools.

D Index

Detached HEAD State

Git Internals • Ch. 2

The state where HEAD points directly to a specific commit hash rather than a named branch reference. Commits made here risk becoming orphaned and garbage-collected once you switch branches without creating a new branch.

Directed Acyclic Graph (DAG)

Computer Science • Ch. 1

The mathematical data structure underlying Git history: commits are directed nodes pointing back toward their parent(s), containing no closed circular loops (acyclic).

Draft Pull Request

GitHub • Ch. 5

A pull request mode indicating active development. Triggers automated CI workflows for early feedback while disabling the merge button and suppressing notifications to designated code reviewers.

drop (Interactive Rebase Command)

History Surgery • Ch. 4

An instruction in a git rebase -i todo list that excises a specific commit node entirely when the rebase chain is replayed onto the base.

E Index

edit (Interactive Rebase Command)

History Surgery • Ch. 4

An interactive rebase instruction that halts the replay execution at that commit, leaving your working directory and staging index at that exact historical moment to split or amend files before resuming with git rebase --continue.

Expressions Engine (${{ ... }})

Actions • Ch. 6

The evaluation engine in GitHub Actions used to inject context values, evaluate booleans, evaluate functions like hashFiles(), and evaluate status check conditions (success(), failure()).

F Index

Fast-Forward Merge

Git Integration • Ch. 2

A merge operation that occurs when the target branch has received no new commits since the feature branch diverged. Git merely moves the target branch pointer forward to point to the latest feature commit without creating a merge commit.

fixup (Interactive Rebase Command)

History Surgery • Ch. 4

An interactive rebase directive that combines a commit's diff directly into the preceding commit while silently discarding the fixup commit's log message, creating a clean atomic commit without prompting.

G Index

git add -p (Patch Staging)

Staging • Ch. 1

Interactive patch mode that presents modified code hunks one by one, allowing developers to review and stage specific parts of a file while leaving other changes in the working directory for atomic commits.

git commit --amend

History Surgery • Ch. 3

Replaces the latest tip commit by generating a brand-new commit object that combines staged changes and allows updating the commit message, abandoning the previous commit to the reflog.

git-filter-repo

Security • Ch. 4

The modern, official Python-based tool that replaces the deprecated git filter-branch. Surgically purges leaked secrets, files, or sensitive directories permanently across all historical commit trees and tags.

git reflog (Reference Log)

Forensics • Ch. 3

The local journal (.git/logs/HEAD) recording every movement of HEAD across commits, checkouts, and resets. Serves as a 30-to-90 day time-travel safety net to recover deleted branches or undo hard resets.

git reset (--soft, --mixed, --hard)

State Surgery • Ch. 3

Moves the current branch pointer backward: --soft retains working files and staged state; --mixed clears the index while preserving working files; --hard overwrites both the index and working directory on disk.

git rm --cached

Tracking • Ch. 1

Removes a file or directory from Git's Staging Index (.git/index) so that it ceases to be tracked, while leaving the physical copy on local disk untouched.

git stash (-u, pop, apply)

State Management • Ch. 3

Stores dirty working directory and staged index modifications as multi-parent commit objects referenced in .git/refs/stash, resetting your working tree so you can perform clean emergency context switches.

GITHUB_TOKEN

Security • Ch. 6

An ephemeral authentication credential automatically provisioned by GitHub for each workflow job. Best practices require restricting its scope using explicit permissions: blocks in the workflow YAML.

.gitkeep

Convention • Ch. 1

A community convention using an empty placeholder file to anchor an otherwise empty directory in the repository, overcoming Git's inability to track empty directories that contain no leaf blobs.

.gitignore

Config • Ch. 1

A repository configuration file specifying glob patterns of untracked files and directories that Git should ignore and omit from git status and git add operations.

H Index

hashFiles() (Actions Function)

Actions • Ch. 7

A built-in Actions function that computes a SHA-256 hash of one or more matching files (such as hashFiles('**/pyproject.toml')) to create deterministic cache keys that invalidate automatically when dependencies change.

HEAD Pointer

Git Architecture • Ch. 1, 2

The special reference file at .git/HEAD designating the currently checked-out branch or commit. In normal states, it stores a symbolic reference (e.g., ref: refs/heads/main).

I Index

Index (Staging Area)

Three Trees • Ch. 1

The binary cache file at .git/index recording file paths, permission modes, and SHA-1 blob hashes. Represents the proposed next snapshot that will be written when git commit executes.

Interactive Rebase (git rebase -i)

History Surgery • Ch. 4

A command providing an editable instruction script that allows developers to reorder, squash, reword, edit, or drop local commits before publishing branches to a shared upstream repository.

J Index

Job (GitHub Actions)

Actions • Ch. 6

A discrete execution unit composed of sequential steps that run inside a freshly provisioned virtual machine container. By default, separate jobs run in parallel unless linked with the needs: keyword.

L Index

Linear History

Architecture • Ch. 2, 5

A Git DAG topology devoid of diverging and intersecting merge bubble commits. Enforced through branch rulesets that require PRs to be integrated via Squash and Merge or Rebase and Merge.

M Index

Matrix Strategy (strategy.matrix)

Actions • Ch. 7

An Actions configuration block that computes the Cartesian product of provided variables (such as OS and runtime versions), provisioning dedicated parallel runner VMs for each combination simultaneously.

Merge Commit (Three-Way Merge)

Git Integration • Ch. 2

A commit node generated when reconciling two diverged branches using their common ancestor. Uniquely contains two parent pointer hashes, documenting the exact historical intersection of the branches.

N Index

needs: (Actions Job Dependency)

Actions • Ch. 6, 7

A job-level configuration key establishing an explicit sequential dependency. Forces downstream jobs (e.g. deployment) to pause until listed prerequisite jobs (e.g. test suites) complete successfully.

O Index

on: (Workflow Trigger Block)

Actions • Ch. 6

The top-level workflow block specifying which webhook events (push, pull_request), manual actions (workflow_dispatch), or scheduled cron intervals initiate the workflow.

P Index

permissions: (Workflow Security)

Security • Ch. 6

The Actions configuration key used to apply the Principle of Least Privilege to the runner's GITHUB_TOKEN, granting only minimal required scopes (e.g., contents: read, pull-requests: write).

PULL_REQUEST_TEMPLATE.md

GitHub • Ch. 5

A standardized markdown template located in .github/ that automatically prepopulates pull request descriptions with checklists, issue tracker links, and testing verification headers.

push --force-with-lease

Safety • Ch. 4

A defensive alternative to --force. It instructs the remote to reject your forced update if another developer pushed commits to the remote branch that you haven't integrated locally yet.

Q Index

Quality Gate (CI Pattern)

Architecture • Ch. 6

An initial fast-failing CI job executing static analysis, code format verification (Black), and security AST scans (Bandit) before triggering heavier compilation or test matrix jobs.

R Index

Rebase (git rebase)

Git Integration • Ch. 2, 4

The operation of lifting a feature branch's unique commits and sequentially reapplying them onto the tip of another base commit, synthesizing new commit objects to produce a clean, linear history.

Remote-Tracking Branch

Git Architecture • Ch. 2

A read-only local reference (refs/remotes/origin/main) representing the state of the remote branch at the time of the last git fetch or network operation.

restore-keys (Cache Fallbacks)

Actions • Ch. 7

An ordered list of prefix strings configured in actions/cache used to restore a partial or older cache if an exact primary key match misses.

reword (Interactive Rebase Command)

History Surgery • Ch. 4

An interactive rebase command that applies a commit's diff unchanged while pausing execution to allow editing the commit message (e.g., standardizing older commits to Conventional Commits).

Runner (GitHub Actions)

Compute • Ch. 6

The compute host VM or container executing the runner agent. Can be cloud-managed by GitHub (ubuntu-latest, macos-latest) or hosted on private infrastructure (self-hosted).

S Index

Semantic Versioning (SemVer)

Standards • Ch. 2

The three-part version numbering convention (MAJOR.MINOR.PATCH) denoting breaking changes, backward-compatible feature additions, or bug fixes.

ShipForge Project

Project • Ch. 1–7

The continuous microservice repository engineered across this seven-chapter curriculum to master the Git object model, tracking mechanics, history rewrites, PR governance, and enterprise GitHub Actions automation.

Squash and Merge (GitHub PR)

Integration • Ch. 5

A pull request integration strategy that combines all commits on the feature branch into a single atomic commit appended directly onto the target base branch, maintaining clean linearity.

squash (Interactive Rebase Command)

History Surgery • Ch. 4

An interactive rebase instruction that melds a commit's diff into the previous commit while pausing to allow combining and editing both commit messages in an editor.

Status Check Functions (Actions)

Actions • Ch. 6

Built-in workflow functions (success(), failure(), always(), cancelled()) used inside if: statements to control whether steps execute after earlier step errors.

Suggested Changes (```suggestion)

Review • Ch. 5

A GitHub markdown syntax block used in pull request code reviews allowing reviewers to write replacement code that authors can apply directly as a commit with a single click.

T Index

Three Trees Architecture

Computer Science • Ch. 1

The tripartite state model governing Git: the physical Working Directory on disk, the binary cached Staging Area (Index), and the historical snapshot at HEAD.

timeout-minutes

Actions • Ch. 6

A job-level Actions setting establishing a hard maximum execution time (e.g., timeout-minutes: 10) to prevent hung scripts from consuming organizational billing allowances.

Tree Object

Git Primitives • Ch. 1

An immutable Git object in .git/objects/ representing a directory snapshot. Maps filenames, directory modes (permissions), and SHA pointers to child blobs or sub-trees.

U Index

Untracked File

Git States • Ch. 1

A file physically present on the local working disk that is absent from both the Staging Index (.git/index) and the current commit snapshot.

Upstream Tracking (-u)

Remotes • Ch. 2

Configuring an explicit link between a local branch and a remote branch via git push -u origin <branch>, allowing subsequent git pull and git push invocations without arguments.

W Index

Workflow (GitHub Actions)

Actions • Ch. 6

A configurable automated process defined in a YAML file in .github/workflows/ that triggers on specified events and executes one or more jobs.

workflow_dispatch

Actions • Ch. 6

An Actions event trigger that enables manual execution of a workflow on-demand via the GitHub Web UI or GitHub CLI (gh workflow run) with optional custom input parameters.

Working Directory (Working Tree)

Three Trees • Ch. 1

The physical files, directories, and assets unpacked on local disk where developers author code before staging into the index or committing to the DAG.
