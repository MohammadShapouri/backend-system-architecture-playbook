A Section

ACID Properties

Database • Part 4

The four non-negotiable guarantees of relational database transactions: Atomicity (all steps succeed or all rollback), Consistency (rules enforced), Isolation (concurrent transactions don't peek at partial data), and Durability (committed data survives server crashes).

AJAX

Frontend • Parts 1, 6

Asynchronous JavaScript and XML. The technique of using client-side JavaScript (via fetch()) to send and receive data from a server in the background without requiring a full browser page reload.

API (Application Programming Interface)

Architecture • Part 2

A standardized contract or rulebook that allows two separate programs to communicate without knowing each other's internal source code. Over the web, Web APIs exchange structured data (usually JSON) over HTTP.

ASGI

Backend • Part 8

Asynchronous Server Gateway Interface. The modern Python standard enabling web frameworks (like FastAPI) to handle asynchronous coroutines, concurrent connections, and WebSockets at high performance. Implemented by servers like Uvicorn.

Asynchronous Execution (Non-Blocking)

Programming • Part 6

A programming paradigm where long-running operations (like network requests or database queries) run in the background without freezing the execution thread. Managed with async/await and Promises.

Authentication (AuthN)

Security • Part 7

The security process that answers: "Who are you?" Verifies identity using passwords, biometric checks, or tokens. Failure triggers status code 401 Unauthorized.

Authorization (AuthZ)

Security • Part 7

The security process that answers: "Are you allowed to perform this action?" Checks user permissions, roles (e.g. Admin vs Member), and access rights. Failure triggers status code 403 Forbidden.

B Section

Backend

Architecture • Parts 1, 3

The private engine room running on a remote server. It handles business rules, processes calculations, connects to databases, manages authentication, and answers incoming HTTP requests from frontends.

Bcrypt

Security • Part 7

An industry-standard, slow, cryptographic hashing algorithm designed specifically to protect passwords. It incorporates a random salt to defend against rainbow table and brute-force cracking attacks.

Browser (Client Runtime)

Foundations • Part 1

The software on a user's device (e.g. Chrome, Safari) responsible for parsing HTML, calculating CSS layouts, rendering pixels, and running the client-side JavaScript engine.

C Section

Caching (HTTP Caching)

Networking • Part 1

Saving a local copy of static files (CSS, images, JS) on the browser or edge server to avoid downloading unchanged assets repeatedly. Validated using ETags and the 304 Not Modified status code.

CDN (Content Delivery Network)

DevOps • Part 8

A globally distributed network of edge proxy servers (e.g. Cloudflare, CloudFront) that cache and deliver static assets (HTML, CSS, images) from the geographical data center closest to the visiting user.

Client

Foundations • Part 1

The requester in a distributed system. The hardware device and application (browser, phone app) that captures human user actions, issues requests over the network, and displays results.

Component-Based Architecture

Frontend • Part 5

Designing graphical user interfaces by assembling modular, reusable "Lego block" units (Components) that bundle their own HTML structure, CSS styling, and JavaScript behavior into an isolated function.

Controller (MVC)

Architecture • Part 1

The coordinator in the MVC pattern. It receives the incoming HTTP request, validates parameters, queries the Model for data, feeds that data into the View template, and returns the finished response.

Cookie (HTTP Cookie)

Backend • Part 3

A small key-value string sent by the server via Set-Cookie that the browser stores locally and automatically attaches to every future request sent to that same domain.

CORS (Cross-Origin Resource Sharing)

Security • Part 6

A browser security mechanism that blocks scripts on one origin (e.g. localhost:3000) from reading data from another origin (e.g. localhost:8000) unless the backend explicitly approves it via headers.

CRUD

Data • Part 2

The four fundamental database operations: Create (POST), Read (GET), Update (PUT/PATCH), and Delete (DELETE).

CSR (Client-Side Rendering)

Frontend • Part 5

A rendering strategy where the server delivers an empty HTML file and a JavaScript bundle. The user's browser executes the JavaScript locally to construct HTML elements and fetch JSON data dynamically.

D Section

Database (DBMS)

Data • Part 4

A dedicated, non-volatile software system designed to store, index, query, and modify permanent information on disk while guaranteeing concurrency safety and crash recovery.

Database Migrations

Data • Part 4

Version control for database schemas. Structured script files that alter tables (adding columns, constraints) over time without destroying existing production records.

Deserialization (Parsing)

Data • Part 2

Converting a raw incoming text string (such as a JSON payload received over the network) back into native in-memory objects (like Python dictionaries and lists).

Django

Framework • Part 3

A high-level, "batteries-included" Python web framework. It provides a built-in ORM, admin dashboard, user authentication, and HTML template engine out of the box.

DNS (Domain Name System)

Networking • Part 1

The internet's phonebook directory. Translates human-readable domain names (e.g. google.com) into computer-routable numerical IP addresses (e.g. 142.250.190.46).

Docker & Containers

DevOps • Part 8

A containerization platform that packages application code along with its exact OS runtime, libraries, and system dependencies into a lightweight, isolated container that runs identically on any computer.

DOM (Document Object Model)

Frontend • Part 1

The browser's live, in-memory tree representation of an HTML document. JavaScript manipulates the DOM to dynamically add, delete, or modify elements on screen.

Dynamic Routing (Path Parameters)

Backend • Part 3

URL routes containing variable wildcards (e.g. /users/{user_id}). The backend router captures the variable segment and delivers it as an argument to the controller function.

E Section

Environment Variables (.env)

Security • Part 7

Dynamic key-value pairs stored in the operating system environment (or inside a local .env file). Keeps database credentials and private API keys out of Git repositories.

ETag (Entity Tag)

Networking • Part 1

A unique hash or fingerprint assigned to a specific version of a file. Browsers send this hash back to the server to check if an asset has changed without downloading it again.

F Section

FastAPI

Framework • Parts 1, 2, 3

A modern, high-performance Python web framework based on standard Python type hints. Features automatic JSON serialization, async execution, and automatic interactive Swagger documentation.

Foreign Key (FK)

Data • Part 4

A column in a relational database table that points to the Primary Key of another table, establishing a verifiable relationship (e.g., linking an order to a user ID).

Frontend

Architecture • Parts 1, 5

The visible layer of a web application running inside the client's web browser. Composed of HTML for layout, CSS for appearance, and JavaScript for interactivity and state.

G Section

GET (HTTP Method)

HTTP • Parts 1, 2

The safe, read-only HTTP verb used to request a copy of a resource from a server. It must not alter the server's database state.

Gunicorn

DevOps • Part 8

A production process manager for Python web applications. It forks and supervises multiple worker processes to distribute incoming traffic across all CPU cores.

H Section

Headers (HTTP Headers)

HTTP • Parts 1, 2

Key-value metadata pairs accompanying an HTTP request or response. They describe data formats (Content-Type), authentication tokens, cookies, and caching instructions.

HTTP & HTTPS

Protocol • Part 1

HyperText Transfer Protocol. The universal request-response language of the web. HTTPS encrypts this traffic using TLS on port 443 so attackers cannot snoop on passwords or private data.

Hydration

Frontend • Part 5

In Server-Side Rendering (SSR), the process where client-side JavaScript boots up, reads the pre-rendered HTML sent by the server, and attaches click listeners and state to make buttons interactive.

I Section

IP Address

Networking • Part 1

A unique numerical address assigned to every device connected to the internet (e.g. 142.250.190.46). Used by routers to physically deliver data packets.

J Section

Jinja2

Backend • Part 1

A popular Python template engine. It takes an HTML file with placeholder slots like {{ username }} and injects live Python variables into it before sending it to the client.

JSON (JavaScript Object Notation)

Data • Part 2

The dominant lightweight data format of the modern web. Human-readable text representing nested key-value objects and lists. Natively supported across Python, JavaScript, and every modern programming language.

JWT (JSON Web Token)

Security • Part 3

A compact, URL-safe, digitally signed token containing user claims (e.g. user ID and role). Allows backends to verify a user's identity statelessly without querying a database on every request.

L Section

Localhost (127.0.0.1)

Networking • Part 8

The standard hostname pointing back to your own computer's local loopback network interface. Used for building and testing web applications locally before deployment.

M Section

Managed Database

DevOps • Part 8

A cloud database service (e.g. AWS RDS, Supabase, Neon) where the cloud vendor automatically manages hardware, disk scaling, automated daily backups, and security patches.

Middleware

Backend • Part 3

A pipeline of modular software layers that intercept every HTTP request before it reaches a controller, and inspect every response before it leaves the server. Used for authentication, logging, and CORS headers.

Model (MVC)

Architecture • Parts 1, 4

The data layer in MVC. It represents the structure of your data, enforces validation rules, and interacts directly with the database to read, create, and update records.

MPA (Multi-Page Application)

Architecture • Part 5

A traditional web application architecture where every user interaction or link navigation triggers a full browser reload, fetching a brand-new HTML document from the server.

MVC (Model-View-Controller)

Architecture • Part 1

An architectural design pattern that isolates backend responsibilities into three distinct layers: the Model (data & database rules), the View (presentation & visual templates), and the Controller (request routing & traffic orchestration).

N Section

Next.js

Framework • Part 5

A production React framework that adds full-stack capabilities: Server-Side Rendering (SSR), Static Site Generation (SSG), automatic file-based routing, and backend API routes.

Nginx

DevOps • Part 8

A high-speed reverse proxy and web server. Sits in front of Python application servers to handle SSL termination, load balancing, rate limiting, and static file caching.

NoSQL (Document Databases)

Data • Part 4

Non-relational database systems (e.g. MongoDB) that store data in flexible, nested JSON-like documents rather than rigid tabular rows and columns.

O Section

ORM (Object-Relational Mapping)

Data • Part 4

A library (such as SQLAlchemy or Django ORM) that maps Python classes to SQL database tables. Allows developers to create, query, and update records using native Python objects while automatically defending against SQL injection.

Origin

Security • Part 6

The unique combination of Protocol (http://), Domain (example.com), and Port (:3000). If any of the three differs, requests cross an origin boundary.

P Section

PaaS (Platform as a Service)

DevOps • Part 8

Cloud platforms (e.g. Render, Railway, Heroku) that manage underlying virtual machines, networking, and OS patching for you, allowing you to deploy apps simply by connecting a Git repo.

Password Salt

Security • Part 7

A unique, random cryptographic string blended with a user's plaintext password before hashing. Ensures that identical passwords yield completely different final hashes, rendering pre-computed rainbow tables useless.

Payload (HTTP Body)

HTTP • Parts 1, 2

The actual data content carried inside an HTTP request or response (the "letter inside the envelope"), such as a JSON document submitted in a POST request or HTML text returned by the server.

Polling (HTTP Short & Long Polling)

Networking • Part 6

An older technique for simulating real-time updates by having the client repeatedly ask the server: "Any new messages yet?" on a timer. Creates significant bandwidth overhead compared to WebSockets.

Port

Networking • Part 1

A numbered virtual doorway on a computer (e.g. Port 80 for HTTP, Port 443 for HTTPS, Port 5432 for Postgres) allowing the operating system to route incoming packets to the correct application process.

POST (HTTP Method)

HTTP • Parts 1, 2

The HTTP verb used to submit new data to the server (e.g. submitting a signup form or creating a new database record). Usually returns status code 201 Created.

Preflight Request (OPTIONS)

Security • Part 6

An automatic preliminary HTTP request sent by a browser using the OPTIONS method to verify whether a cross-origin server allows custom headers or destructive actions before sending the actual request.

Primary Key (PK)

Data • Part 4

A column (or set of columns) in a relational database table whose value is strictly unique for every row (e.g. user ID 1), guaranteeing that each record can be distinctly referenced.

Promise

Programming • Part 6

A JavaScript object representing the eventual completion (or failure) of an asynchronous background task. It can be unpacked using await or .then().

Props

Frontend • Part 5

Short for Properties. Read-only input values passed downwards from a parent component into a child component (analogous to passing arguments into a Python function).

PUT & PATCH (HTTP Methods)

HTTP • Parts 1, 2

HTTP verbs used to update records. PUT completely replaces the entire item with the new payload; PATCH applies a partial update modifying only specified fields.

Q Section

Query Parameters

API • Part 2

Optional key-value pairs appended to the end of a URL after a ? mark (e.g. /products?category=shoes&limit=10). Used for searching, filtering, and pagination.

R Section

RAM (Volatile Memory)

Hardware • Part 4

Ultra-fast, temporary computer memory where executing programs and Python variables reside. All data in RAM is erased instantly if the computer is turned off or the server process restarts.

React

Library • Part 5

A declarative JavaScript library developed by Meta for building interactive user interfaces out of reusable components. Automatically updates the DOM whenever state changes occur.

Relational Database (SQL)

Data • Part 4

A database that organizes information into strict, tabular rows and columns with enforced relationships (Foreign Keys) and mathematical relational integrity.

Request–Response Lifecycle

Foundations • Part 1

The universal web conversation pattern: a client crafts and dispatches an HTTP request; the server processes it and returns exactly one HTTP response envelope; the connection then closes.

REST (Representational State Transfer)

Architecture • Part 2

An architectural style for designing APIs. Mandates treating entities as resources named by nouns (/users) and manipulating them using standard HTTP verbs (GET, POST, PUT, DELETE) in a stateless manner.

Reverse Proxy

DevOps • Part 8

An intermediary web server (like Nginx) that stands between the public internet and your private backend applications to terminate SSL encryption, distribute traffic, and buffer attacks.

Router (URL Dispatcher)

Backend • Part 3

The internal backend component that pattern-matches incoming URL paths and HTTP verbs against registered endpoints to invoke the appropriate Python handler function.

S Section

Same-Origin Policy (SOP)

Security • Part 6

A foundational browser sandbox rule preventing client-side scripts running on one origin from accessing cookies, storage, or DOM resources on a completely different origin.

Serialization

Data • Part 2

The process of converting in-memory Python objects (like dicts and lists) into a standardized, transportable text string (like JSON) so it can be transmitted across the network.

Server

Foundations • Part 1

A computer running continuously in a secure data center that listens on network ports, protects application secrets, runs business logic, and responds to client requests.

Session (Session-Based Auth)

Backend • Part 3

A stateful authentication method where the server stores user session data in server memory or Redis, and gives the client only an opaque session_id cookie (the "coat-check ticket").

SPA (Single-Page Application)

Architecture • Part 5

A modern web app architecture where the browser loads only one initial HTML shell. Navigation and view updates happen dynamically via JavaScript without full browser reloads.

SQL (Structured Query Language)

Data • Part 4

The standardized programming language used by relational database systems (Postgres, MySQL, SQLite) to create tables, query rows, and perform transactional updates.

SQL Injection (SQLi)

Security • Part 7

A critical vulnerability where unvalidated user input is concatenated directly into a SQL query string, allowing an attacker to manipulate query syntax and hijack the database.

SQLAlchemy

Library • Part 4

The leading Object-Relational Mapping (ORM) toolkit for Python. Translates Python model classes into database tables and provides a clean, secure query API.

SQLite

Data • Part 4

A lightweight, zero-configuration SQL database engine that stores entire databases inside a single file on disk. Perfect for local development and embedded systems.

SSG (Static Site Generation)

Frontend • Part 5

A rendering strategy where every HTML page is compiled in advance during the build process. Pages are cached on a global CDN for instant delivery.

SSR (Server-Side Rendering)

Frontend • Part 5

A rendering strategy where the server generates the full HTML for a page on every incoming request, ensuring optimal SEO and fast first content display before client-side hydration.

State (Frontend State)

Frontend • Part 5

The internal memory of a user interface (e.g. is the modal open, shopping cart count). When state changes, reactive frameworks (like React) automatically re-render the affected elements on screen.

Statelessness

HTTP • Parts 2, 3

The architectural principle that the server does not retain memory of previous requests. Every incoming request must carry all the credentials and data required to complete the action.

Status Codes (HTTP Status)

HTTP • Parts 1, 2

Standard 3-digit response codes from the server: 200s (Success), 300s (Redirection / Cache), 400s (Client error, e.g. 404 Not Found), and 500s (Server error / crash).

T Section

Template Hydration / Interpolation

Backend • Part 1

The server-side process where a template engine swaps out placeholders (like {{ price }}) inside an HTML file with real values queried from a database.

Transaction (Database Transaction)

Data • Part 4

A bundle of multiple database operations treated as one atomic unit. If any individual operation fails, the transaction is rolled back (ROLLBACK) to protect data integrity.

U Section

Uvicorn

DevOps • Parts 1, 8

A lightning-fast ASGI application server for Python. Acts as the execution bridge that listens for incoming HTTP requests on a socket and invokes your FastAPI code.

V Section

View (MVC)

Architecture • Part 1

The visual blueprint layer in MVC (often an HTML template). Contains the graphical layout and placeholders for dynamic data without directly handling database queries.

W Section

WebSockets (ws:// and wss://)

Networking • Part 6

A persistent, bidirectional, full-duplex TCP communication protocol. After an initial HTTP upgrade handshake, the tunnel remains open, allowing either the server or client to push messages instantly.

WSGI

Backend • Part 8

Web Server Gateway Interface. The legacy synchronous Python standard used by frameworks like standard Django and Flask to talk to web servers like Gunicorn.

X Section

XML (Extensible Markup Language)

Data • Part 2

An older markup format with custom opening and closing tags (e.g. <user>Alice</user>). Heavier and more verbose than JSON.

XSS (Cross-Site Scripting)

Security • Part 7

A browser-side security vulnerability where an attacker injects malicious JavaScript into user-submitted content (like comments). When other users view the page, their browsers execute the script, potentially stealing their auth cookies.
