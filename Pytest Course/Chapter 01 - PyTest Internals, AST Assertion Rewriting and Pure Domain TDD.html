Part 01

Computer Science: Test Discovery & The src/ Layout Boundary

When you invoke pytest from your terminal, PyTest does not simply execute Python scripts. It initializes a deterministic discovery protocol, parsing directories into a recursive composite tree of collection nodes:

The PyTest Collection Protocol Invariant

PyTest crawls the directory tree starting from the rootdir (resolved via pyproject.toml). By default, it collects:

1. File Identification

Matches test_*.py or *_test.py files. Ignores standard scripts.

2. Class Scoping

Collects classes prefixed with Test* that omit an __init__ constructor.

3. Item Invocation

Identifies test functions and methods prefixed with test_*.

Architectural Vulnerability: The Flat Layout vs. The Modern src/ Layout

Why Local Directory Imports Create Illusory Green Test Suites

1. Flat Layout (The Import Illusion) Unsafe for CI
my_project/
├── vaultflow/ ← Local module sits in current working directory
│ └── core.py
└── tests/
└── test_core.py

When PyTest runs, Python automatically prepends the current working directory to sys.path. Tests import directly from the raw directory, not from the packaged wheel.

✗ Failure Mode: Tests pass completely on your laptop, but deployment crashes in production because you forgot to package an asset, manifest file, or C-extension!

2. Modern src/ Layout (Packaging Isolation) Production Standard
my_project/
├── src/
│ └── vaultflow/ ← Cannot be accidentally imported directly!
│ └── core.py
└── tests/
└── test_core.py

Because vaultflow lives inside src/, running pytest forces you to install the package in editable mode (pip install -e .).

✓ Total Parity: Tests are executed strictly against the installed distribution artifact, matching the exact binary state deployed to production containers.

Part 02

Under the Hood: Abstract Syntax Tree (AST) Assertion Rewriting

In standard Python, the assert keyword is a primitive language construct designed for internal sanity checks. If an expression evaluates to False, Python raises an uninformative AssertionError with no contextual metadata. Worse, if Python executes with optimization flags (python -O), assertion statements are completely stripped from compiled bytecode!

Legacy frameworks like unittest worked around this by inventing dozens of verbose assertion methods: self.assertEqual(), self.assertDictEqual(), self.assertSequenceEqual(). PyTest abandoned this boilerplate entirely by implementing AST Assertion Rewriting.

The PyTest AST Bytecode Transformation Pipeline
1. Raw Source Code assert account.balance == expected
→ Meta Path Hook →
2. PyTest AssertionRewriter Traverses AST, mutates Compare nodes, injects stack frame inspectors
→ Bytecode Execution →
3. Introspective Failure Rich Diff: Values, types, operand values, and visual diffs
// What happens under the hood when PyTest imports test modules:

PyTest installs a custom PEP 302 import hook at the head of sys.meta_path. When a test module or conftest.py is imported, PyTest reads its source, compiles it into an Abstract Syntax Tree (ast.parse), and invokes _pytest.assertion.rewrite.AssertionRewriter.

The rewriter replaces every ast.Assert node with complex conditional bytecode: capturing each sub-expression (the left-hand value, the right-hand value, intermediate operations), storing them in temporary variables, and only executing the string formatting if the assertion fails.

Systems Deep Dive Engineering Custom Failure Explanations: pytest_assertrepr_compare

When comparing complex domain objects (such as two multi-currency ledger accounts or matrix vectors), standard string representations fail to explain *why* the assertion failed. PyTest exposes an internal hook specification in conftest.py allowing senior engineers to intercept equality comparisons and format visual diff reports:

# In tests/conftest.py: Intercept equality failures between Money domain objects def pytest_assertrepr_compare(config, op, left, right): from vaultflow.core.money import Money if isinstance(left, Money) and isinstance(right, Money) and op == "==": return [ "Financial Money comparison mismatch:", f" Left operand: {left.amount} {left.currency}", f" Right operand: {right.amount} {right.currency}", f" Currency match: {left.currency == right.currency}", f" Delta balance: {abs(left.amount - right.amount)}", ] return None # Fall back to standard PyTest AST diffing for other types
Part 03

Test-Driven Development (TDD): The Immutable Cycle

Test-Driven Development is not an academic philosophy; it is a defensive engineering strategy that forces clear interface contracts before implementation details cloud architectural judgment. When engineering high-frequency financial platforms, TDD prevents **Speculative Generality** and forces boundary handling for rounding modes, nullability, and invariants upfront.

The Strict TDD State Machine
1. RED PHASE Must Fail

Write an atomic test asserting desired domain behavior before writing a single line of production code.

pytest → FAIL: ModuleNotFoundError or AssertionError
2. GREEN PHASE Make it Pass

Write the absolute minimal production code required to satisfy the failing assertion. No speculative features!

pytest → 1 passed in 0.01s!
3. REFACTOR Clean Architecture

Eliminate duplication, enforce immutability, optimize algorithmic performance, and add type annotations while under the green safety net.

pytest → Suite remains 100% green!
Part 04

Defensive Exception Verification: pytest.raises

In a financial ledger, how your application rejects invalid operations is just as vital as how it processes valid transactions. If an engineer attempts to sum $100.00 USD with €50.00 EUR without passing through an explicit FX clearing house, the application must abort instantly with a deterministic domain exception.

PyTest provides the pytest.raises() context manager. In production suites, testing for raw exception classes alone is considered an anti-pattern; you must assert against specific error regex patterns and verify custom exception attributes:

// Anatomy of Defensive Exception Verification:
import pytest
from decimal import Decimal
from vaultflow.core.money import Money, CurrencyMismatchError

def test_cross_currency_addition_raises_deterministic_domain_error():
    usd = Money(Decimal("100.0000"), "USD")
    eur = Money(Decimal("50.0000"), "EUR")

    # 1. Capture the exact exception and enforce regex validation on the message
    with pytest.raises(
        CurrencyMismatchError, 
        match=r"^Cannot operate across distinct currencies: USD vs EUR$"
    ) as exc_info:
        _ = usd + eur

    # 2. Senior Pattern: Inspect structured payload attributes on the exception itself!
    assert exc_info.value.source_currency == "USD"
    assert exc_info.value.target_currency == "EUR"
    assert exc_info.type is CurrencyMismatchError

2. Financial Domain Value Object: src/vaultflow/core/money.py The Implementation Core 
# ==============================================================================
# VaultFlow Core Domain - Immutable Money Value Object (Milestone 01)
# ==============================================================================

from dataclasses import dataclass
from decimal import Decimal, ROUND_HALF_EVEN, InvalidOperation
from typing import Union

# Standard ISO-4217 Currency Code Registry
SUPPORTED_CURRENCIES = {"USD", "EUR", "GBP", "JPY", "CHF"}
# Quantization Mask: 4 decimal places for micro-cent settlement accuracy
FINANCIAL_PRECISION = Decimal("0.0001")


class FinancialDomainError(Exception):
    """Base exception for all VaultFlow financial invariant violations."""
    pass


class CurrencyMismatchError(FinancialDomainError):
    """Raised when arithmetic is attempted across distinct un-cleared currencies."""
    def __init__(self, source_currency: str, target_currency: str):
        self.source_currency = source_currency
        self.target_currency = target_currency
        super().__init__(
            f"Cannot operate across distinct currencies: {source_currency} vs {target_currency}"
        )


class InvalidCurrencyError(FinancialDomainError):
    """Raised when an unapproved ISO currency symbol is initialized."""
    pass


@dataclass(frozen=True, slots=True)
class Money:
    """
    IMMUTABLE FINANCIAL VALUE OBJECT:
    Enforces exact fixed-point arithmetic using Python's Decimal.
    Uses banker's rounding (ROUND_HALF_EVEN) to eliminate statistical bias.
    """
    amount: Decimal
    currency: str

    def __post_init__(self):
        # 1. Enforce strict type safety: reject float completely!
        if isinstance(self.amount, float):
            raise TypeError(
                "Floating-point numbers are prohibited in financial modeling. Use Decimal or str."
            )

        # 2. Coerce string or integer amounts safely into quantized Decimal
        try:
            quantized_val = Decimal(str(self.amount)).quantize(
                FINANCIAL_PRECISION, rounding=ROUND_HALF_EVEN
            )
            # Bypass frozen dataclass mutation restriction during post-init
            object.__setattr__(self, "amount", quantized_val)
        except (InvalidOperation, TypeError) as err:
            raise FinancialDomainError(f"Invalid monetary amount provided: {self.amount}") from err

        # 3. Validate ISO Currency Code
        sanitized_curr = self.currency.strip().upper()
        if sanitized_curr not in SUPPORTED_CURRENCIES:
            raise InvalidCurrencyError(f"Unsupported ISO-4217 currency: {self.currency}")
        object.__setattr__(self, "currency", sanitized_curr)

    def __add__(self, other: "Money") -> "Money":
        self._assert_same_currency(other)
        return Money(self.amount + other.amount, self.currency)

    def __sub__(self, other: "Money") -> "Money":
        self._assert_same_currency(other)
        return Money(self.amount - other.amount, self.currency)

    def __mul__(self, scalar: Union[Decimal, int, str]) -> "Money":
        if isinstance(scalar, float):
            raise TypeError("Cannot multiply Money by floating-point scalar.")
        decimal_scalar = Decimal(str(scalar))
        return Money(self.amount * decimal_scalar, self.currency)

    def __lt__(self, other: "Money") -> bool:
        self._assert_same_currency(other)
        return self.amount < other.amount

    def __le__(self, other: "Money") -> bool:
        self._assert_same_currency(other)
        return self.amount <= other.amount

    def _assert_same_currency(self, other: "Money") -> None:
        if not isinstance(other, Money):
            raise TypeError(f"Operand must be an instance of Money. Got: {type(other)}")
        if self.currency != other.currency:
            raise CurrencyMismatchError(self.currency, other.currency)

from typing import Optional, List
from vaultflow.core.money import Money

def pytest_assertrepr_compare(config, op: str, left: object, right: object) -> Optional[List[str]]:
    """
    PYTEST HOOK SPECIFICATION:
    Intercepts equality assertion failures between Money value objects
    and formats an institutional audit diff detailing exact discrepancies.
    """
    if isinstance(left, Money) and isinstance(right, Money) and op == "==":
        return [
            "─── FINANCIAL VALUE OBJECT EQUALITY FAILURE ───",
            f"  Left Spec:     {left.amount} [{left.currency}]",
            f"  Right Spec:    {right.amount} [{right.currency}]",
            f"  Currency Match: {left.currency == right.currency}",
            f"  Variance Delta: {abs(left.amount - right.amount)}",
            "──────────────────────────────────────────────"
        ]
    return None
4. Domain Unit Test Suite: tests/unit/test_money.py The TDD Verification Battery 
# ==============================================================================
# VaultFlow Test Suite - Pure Domain Money Tests (Milestone 01)
# ==============================================================================

import pytest
from decimal import Decimal
from dataclasses import FrozenInstanceError
from vaultflow.core.money import (
    Money, 
    CurrencyMismatchError, 
    InvalidCurrencyError
)

@pytest.mark.unit
class TestMoneyDomainCore:
    """Unit tests asserting financial precision, immutability, and boundary constraints."""

    def test_valid_money_initialization_with_quantized_precision(self):
        # String representation must normalize to 4 decimal places
        m = Money(Decimal("100.5"), "usd")
        assert m.amount == Decimal("100.5000")
        assert m.currency == "USD"

    def test_floating_point_instantiation_raises_type_error(self):
        # Reject binary IEEE 754 floats unconditionally
        with pytest.raises(TypeError, match=r"Floating-point numbers are prohibited"):
            _ = Money(100.50, "USD")  # type: ignore

    def test_invalid_iso_currency_rejection(self):
        with pytest.raises(InvalidCurrencyError, match=r"Unsupported ISO-4217 currency: BITCOIN"):
            _ = Money(Decimal("10.0000"), "BITCOIN")

    def test_immutable_dataclass_prevents_state_tampering(self):
        m = Money(Decimal("500.0000"), "USD")
        # Value objects must be completely immutable to guarantee ledger integrity
        with pytest.raises(FrozenInstanceError):
            m.amount = Decimal("1000.0000")  # type: ignore

    def test_same_currency_addition_and_subtraction(self):
        m1 = Money(Decimal("1500.2500"), "USD")
        m2 = Money(Decimal("499.7500"), "USD")
        
        summed = m1 + m2
        assert summed == Money(Decimal("2000.0000"), "USD")
        
        diff = m1 - m2
        assert diff == Money(Decimal("1000.5000"), "USD")

    def test_cross_currency_math_raises_custom_domain_error(self):
        usd = Money(Decimal("100.0000"), "USD")
        eur = Money(Decimal("100.0000"), "EUR")

        with pytest.raises(CurrencyMismatchError) as exc_info:
            _ = usd + eur

        assert exc_info.value.source_currency == "USD"
        assert exc_info.value.target_currency == "EUR"

    def test_bankers_rounding_half_even_preservation(self):
        # Banker's rounding rounds half to nearest even digit
        # 2.5 rounds to 2; 3.5 rounds to 4. Prevents systemic inflation drift!
        m_even = Money(Decimal("0.00025"), "USD")  # 2 is even -> rounds to 0.0002
        m_odd = Money(Decimal("0.00035"), "USD")   # 3 is odd -> rounds to 0.0004

        assert m_even.amount == Decimal("0.0002")
        assert m_odd.amount == Decimal("0.0004")
Warning Track

Beginner Pitfalls & Architectural Anti-Patterns

❌ The "Assert Catching" Anti-Pattern

Writing try: assert x() except AssertionError: pass inside tests.

Why this destroys test harnesses: Manually catching AssertionError defeats PyTest’s reporting, silences AST stack introspection, and produces false positives. If the method crashes with an unexpected AttributeError, the test fails for the wrong reason. Always use pytest.raises().

❌ Defining __init__.py in the Project Root

Placing an empty __init__.py in the repository root directory next to pyproject.toml.

Why this causes package collision: Creating a root-level __init__.py forces Python to treat the entire workspace folder as a root package. In CI pipelines, tests start resolving imports from untracked root files rather than the isolated src/ tree, causing silent packaging defects to bypass validation.
