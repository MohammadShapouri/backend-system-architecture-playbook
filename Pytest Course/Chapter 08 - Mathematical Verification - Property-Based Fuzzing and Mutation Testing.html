Part 01

Computer Science: Example-Based Testing vs. Property Invariants

Traditional tests are example-based: an engineer picks an input $x = 10$, calls the system $f(x)$, and asserts that the output matches an expected constant $y = 20$. The vulnerability is obvious: what happens when $x = -0.0001$, $x = 2^{63}-1$, $x = \text{NaN}$, or when the input contains non-printable Unicode characters?

Property-Based Testing (PBT) inverts this relationship. Instead of testing arbitrary specific values, you formulate universal mathematical invariants that must hold true across the entire domain space:

1. Round-Trip Symmetry

Serializing and deserializing data must restore the identical state:

deserialize(serialize(ledger)) == ledger
2. Conservation Laws

Total wealth across accounts must remain strictly constant after transfers:

sum(balances_after) == sum(balances_before)
3. Idempotent Stability

Executing an idempotent settlement operation twice yields the identical state:

settle(settle(batch)) == settle(batch)

The Shrinking Invariant:

When a test fails under Hypothesis, you are never handed a 5,000-line randomized trace. Hypothesis runs a shrinking algorithm (binary reduction, integer subtraction, string simplification) to find the absolute smallest input that still causes the assertion to fail. Furthermore, Hypothesis records the failing example in a local SQLite database (.hypothesis/examples/) to guarantee deterministic replay on subsequent runs!

Part 02

Authoring Custom Composite Strategies: @st.composite

Standard Hypothesis strategies like st.integers() or st.text() generate unconstrained data. Passing unconstrained strings to VaultFlow will merely trigger constructor validation errors (e.g., invalid ISO currency codes) rather than testing deep financial logic.

Using @st.composite, we can author domain-aware generators that compose primitive strategies into valid Money, Account, and balanced multi-leg postings:

// Building Domain Strategies in tests/property/test_ledger_invariants.py:
from decimal import Decimal
from hypothesis import strategies as st
from vaultflow.core.money import Money, SUPPORTED_CURRENCIES

# 1. Custom strategy for valid, bounded financial Decimals
monetary_decimals = st.decimals(
    min_value=Decimal("0.0001"),
    max_value=Decimal("1000000000.0000"),
    places=4,
    allow_nan=False,
    allow_infinity=False
)

# 2. Composite strategy generating valid Money value objects
@st.composite
def money_strategy(draw) -> Money:
    amount = draw(monetary_decimals)
    currency = draw(st.sampled_from(sorted(SUPPORTED_CURRENCIES)))
    return Money(amount, currency)

# 3. Composite strategy generating a perfectly balanced multi-leg transfer
@st.composite
def balanced_split_transfer_strategy(draw):
    currency = draw(st.sampled_from(sorted(SUPPORTED_CURRENCIES)))
    total_debit_amount = draw(monetary_decimals)
    
    # Split total credit amount across 2 destination legs cleanly
    split_ratio = draw(st.fractions(min_value=Decimal("0.01"), max_value=Decimal("0.99")))
    credit_1_amount = (total_debit_amount * Decimal(str(split_ratio))).quantize(Decimal("0.0001"))
    credit_2_amount = total_debit_amount - credit_1_amount

    return {
        "total_debit": Money(total_debit_amount, currency),
        "credit_leg_1": Money(credit_1_amount, currency),
        "credit_leg_2": Money(credit_2_amount, currency),
    }
Part 03

Stateful Model-Checking: RuleBasedStateMachine

Stateless property tests verify single function calls. However, real-world financial corruption emerges from sequences of state transitions: an account is opened, credited, converted via FX, partially debited, frozen, reopened, and debited again.

Hypothesis provides RuleBasedStateMachine. It generates sequences of operations, maintains a parallel simplified "mental model" of the world, and checks that after every single transition, the invariant holds true:

The Stateful Ledger Model-Checking Engine
@rule: create_account Spawns Asset / Liability accounts
@rule: deposit_funds Debits Cash, Credits Deposit
@rule: transfer_funds Atomic multi-account transfer
@invariant: check_zero_sum ∑ Debits == ∑ Credits

Hypothesis executes hundreds of randomized action chains (e.g., 50 actions in sequence). If an action chain creates a micro-cent discrepancy, Hypothesis intercepts the failure, shrinks the sequence down to the minimal 2 actions that caused the leak, and outputs the exact reproduction script!

Part 04

Mutation Testing: Evaluating Test Quality with mutmut

Code coverage metrics (like 95% line coverage from pytest-cov) create a false sense of security. A test can execute 100% of your lines of code without making a single assertion!

Mutation Testing inverts the inspection: it alters your production code by introducing small synthetic defects (mutants) and runs your test suite against each mutation. If your test suite fails, the mutant is killed (✓ Good). If your test suite passes, the mutant survived (✗ Bad, revealing an assertion blind spot).

How mutmut Mutates Production AST Nodes
Production Code:
if source.balance < amount:
    raise InsufficientFundsError()
balance -= amount
Synthesized Mutants:
Mutant 1: if source.balance <= amount: # Operator flipped
Mutant 2: if False: # Check removed
Mutant 3: balance += amount # Sign inverted
The Mutation Score Indicator (MSI) Formula:
MSI = (Killed Mutants / Total Mutants) × 100%

In enterprise clearing engines, a mutation score below 85% is unacceptable. Every surviving mutant represents a logic bug that can be introduced into production without a single test failing!

# ==============================================================================
# VaultFlow Test Suite - Property-Based Invariant Verification (Milestone 08)
# ==============================================================================

from decimal import Decimal
import pytest
from hypothesis import given, settings, HealthCheck, strategies as st
from hypothesis.stateful import (
    RuleBasedStateMachine, 
    rule, 
    initialize, 
    invariant
)

from vaultflow.core.money import Money, SUPPORTED_CURRENCIES
from vaultflow.core.ledger import (
    Ledger, 
    Account, 
    AccountType, 
    Posting, 
    JournalEntry, 
    UnbalancedJournalError
)

# Custom Strategy for precision financial amounts
monetary_decimals = st.decimals(
    min_value=Decimal("0.0001"),
    max_value=Decimal("1000000.0000"),
    places=4,
    allow_nan=False,
    allow_infinity=False
)

@pytest.mark.property
class TestStatelessLedgerInvariants:
    """Stateless property tests asserting mathematical conservation laws."""

    @given(
        amount=monetary_decimals,
        currency=st.sampled_from(sorted(SUPPORTED_CURRENCIES))
    )
    def test_zero_sum_balanced_entry_always_conserves_wealth(self, amount: Decimal, currency: str):
        ledger = Ledger(supported_currencies=SUPPORTED_CURRENCIES)
        source = Account("SRC", AccountType.ASSET, Money(amount, currency))
        dest = Account("DST", AccountType.LIABILITY, Money(Decimal("0.0000"), currency))
        
        ledger.register_account(source)
        ledger.register_account(dest)

        initial_total = source.balance.amount + dest.balance.amount

        transfer_money = Money(amount, currency)
        entry = JournalEntry(
            reference_id="PROP-TX",
            postings=[
                Posting(account=source, amount=transfer_money, is_debit=False),
                Posting(account=dest, amount=transfer_money, is_debit=True),
            ]
        )
        ledger.commit_entry(entry)

        # Universal Invariant: Net balance is strictly conserved across all generated Decimals!
        final_total = source.balance.amount + dest.balance.amount
        assert final_total == initial_total


# ==============================================================================
# STATEFUL MODEL CHECKER: Simulates arbitrary randomized action sequences
# ==============================================================================
class LedgerStateMachine(RuleBasedStateMachine):
    def __init__(self):
        super().__init__()
        self.ledger = Ledger(supported_currencies={"USD"})
        self.accounts: dict[str, Account] = {}
        self.total_minted = Decimal("0.0000")

    @initialize()
    def setup_vault_reserve(self):
        vault = Account("VAULT_RESERVE", AccountType.ASSET, Money(Decimal("0.0000"), "USD"))
        self.ledger.register_account(vault)
        self.accounts["VAULT_RESERVE"] = vault

    @rule(acc_id=st.integers(min_value=1, max_value=5))
    def create_customer_account(self, acc_id: int):
        num = f"CUST_{acc_id}"
        if num not in self.accounts:
            acc = Account(num, AccountType.LIABILITY, Money(Decimal("0.0000"), "USD"))
            self.ledger.register_account(acc)
            self.accounts[num] = acc

    @rule(
        acc_id=st.integers(min_value=1, max_value=5),
        amount=monetary_decimals
    )
    def deposit_funds(self, acc_id: int, amount: Decimal):
        num = f"CUST_{acc_id}"
        if num in self.accounts:
            cust = self.accounts[num]
            vault = self.accounts["VAULT_RESERVE"]
            money = Money(amount, "USD")

            entry = JournalEntry(
                reference_id=f"DEP-{len(self.ledger.journal_entries)}",
                postings=[
                    Posting(account=vault, amount=money, is_debit=True),
                    Posting(account=cust, amount=money, is_debit=False),
                ]
            )
            self.ledger.commit_entry(entry)
            self.total_minted += amount

    @invariant()
    def balance_conservation_invariant(self):
        # INVARIANT CHECKED AFTER EVERY RANDOM ACTION:
        # Total Vault Cash Assets == Total Customer Deposit Liabilities
        vault_cash = self.accounts["VAULT_RESERVE"].balance.amount
        total_customer_deposits = sum(
            acc.balance.amount for k, acc in self.accounts.items() if k != "VAULT_RESERVE"
        )
        assert vault_cash == total_customer_deposits == self.total_minted

Warning Track

Beginner Pitfalls & Architectural Anti-Patterns

❌ The "Random Seed Flakiness" Trap

Using Python's standard random.choice() inside standard unit tests.

Why this destroys test engineering: When a failure occurs, the random state is lost forever. You cannot reproduce the bug locally, and the failure disappears on the next CI run. Fix: Use Hypothesis. It manages deterministic seeds, logs reproduction hashes, and automatically shrinks inputs!

❌ Assertion-Free Test Suites (100% Coverage Illusion)

Writing tests that invoke complex functions but contain zero assert statements.

Why this passes coverage gates: Line coverage tools celebrate that 100% of lines executed. But when mutmut flips an arithmetic operator from + to -, the test still passes! The mutant survives, proving your test asserts nothing. Fix: Enforce a minimum Mutation Score Indicator (MSI) gate in CI.
