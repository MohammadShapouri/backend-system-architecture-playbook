A Index

addopts

Config • Ch. 1, 10

A configuration directive in pyproject.toml under [tool.pytest.ini_options] specifying default command-line flags (e.g. -ra -q --strict-markers) applied automatically to every test execution without manual typing.

ASGITransport (HTTPX)

Web Testing • Ch. 7

An HTTPX transport mechanism that dispatches HTTP requests directly into an ASGI callable (e.g. a FastAPI application) inside Python memory. Enables sub-millisecond integration testing with zero open network sockets and zero port collisions.

asyncio_mode (strict vs. auto)

Asyncio • Ch. 5

A pytest-asyncio setting. "auto" wraps all async def functions implicitly, while "strict" (the enterprise standard) mandates explicit @pytest.mark.asyncio decorators to prevent unintended third-party coroutine execution.

AssertionRewriter (AST)

Compiler • Ch. 1

Pytest's internal AST transformer. Intercepts test module imports via PEP 302/451 hooks, mutates ast.Assert nodes into intermediate sub-expression inspectors, and produces rich failure diffs without requiring legacy self.assertEqual() methods.

autouse=True

Fixtures • Ch. 2, 6

A fixture flag that activates the fixture automatically for every test in scope without requiring it to be named in the test function signature. Used for global invariants like connection pool leak sentinels and environment sanitizers.

autospec=True

Mocking • Ch. 4

A parameter for mocker.patch that inspects the real class signature, raising immediate AttributeError or TypeError if tests call methods or pass arguments that do not exist on the real object, preventing "mock drift."

B Index

Banker's Rounding (ROUND_HALF_EVEN)

Precision • Ch. 1

The IEEE 754 standard financial rounding mode where fractions of 0.5 round to the nearest even integer (e.g. 2.5 rounds to 2, 3.5 rounds to 4). Eliminates cumulative statistical inflation drift across millions of ledger transactions.

Blind Retries (--reruns Anti-Pattern)

Anti-Pattern • Ch. 10

Using --reruns 3 globally in CI to turn failing builds green. Masks real production concurrency deadlocks, race conditions, and memory leaks instead of quarantining and fixing the root cause.

Branch Coverage (--cov-branch)

Metrology • Ch. 10

A strict coverage metrology metric in pytest-cov. Measures whether every branch of conditional statements (if/else, try/except) was exercised, proving line coverage alone is insufficient.

C Index

capfd

Built-in Fixture • Ch. 7

A built-in Pytest fixture that captures output at the operating system file descriptor level (FD 1 and FD 2). Unlike capsys, capfd captures output emitted by compiled C-extensions and subprocesses.

caplog

Built-in Fixture • Ch. 7

A built-in Pytest fixture that intercepts Python's standard logging library records. Allows tests to assert on log messages, warning levels, and regulatory audit entries emitted during execution.

capsys

Built-in Fixture • Ch. 7

A built-in Pytest fixture that captures text written to Python's sys.stdout and sys.stderr streams via capsys.readouterr(), enabling assertions on CLI terminal tables and messages.

Cartesian Product Stacking

Parametrization • Ch. 3

Stacking multiple @pytest.mark.parametrize decorators on a single test function. Pytest calculates the product ($A \times B$), executing every permutation as an isolated, distinct test node.

Circuit Breaker Testing

Boundary • Ch. 4

Testing state transitions across CLOSED, OPEN, and HALF_OPEN boundary states under synthetic 503 or 429 errors using mocker.spy to verify failover routing without live network costs.

CliRunner (Typer / Click)

CLI Testing • Ch. 7

An in-process execution harness for Click and Typer CLI applications. Invokes terminal commands directly inside Python without spawning OS subprocesses, returning exit codes and stream buffers.

conftest.py

Core Engine • Ch. 1, 2, 9

Pytest's local per-directory plugin and fixture registry. Fixtures and hooks defined in a conftest.py are automatically available to all tests in its directory and subdirectories without explicit imports.

Connection Pool Leak Sentinel

Database • Ch. 6

An autouse=True fixture that inspects SQLAlchemy's internal pool metrics (pool.checkedout()) before and after every test, failing immediately if a test leaks physical database sockets.

D Index

dependency_overrides (FastAPI)

Web Testing • Ch. 7

FastAPI's testing dictionary (app.dependency_overrides) allowing tests to swap production dependencies (e.g. database sessions, auth checks) with test doubles. Must be cleared during fixture teardown.

--dist=load vs. --dist=loadscope

xdist • Ch. 10

--dist=load assigns individual test functions randomly to workers. --dist=loadscope groups all tests in a class or module onto the same worker process, preventing database deadlock collisions.

Dummy (Test Double)

Test Double • Ch. 4

A test double passed into a function simply to fill required parameter slots (e.g. an unreferenced correlation ID), but whose methods and attributes are never actually called or inspected during test execution.

--durations=N

Profiling • Ch. 2, 5

A Pytest CLI flag that profiles the $N$ slowest test functions and fixture setup/teardown phases, identifying hidden CPU latency bottlenecks, disk I/O leaks, and sleep delays.

Dynamic Test Generation

Metaprogramming • Ch. 3

Generating test items at collection time via pytest_generate_tests(metafunc) by reading external datasets (JSON/YAML regulatory test vectors) rather than hardcoding static decorator tuples.

E Index

Ephemeral Postgres Container

Database • Ch. 6

A real PostgreSQL database provisioned programmatically in Docker via testcontainers for the duration of a test session. Runs on a randomized port and is automatically destroyed upon test completion.

Event Loop Scope

Asyncio • Ch. 5

The lifecycle boundary of the asyncio event loop during testing. Default function scoping guarantees that unclosed tasks do not leak across tests, while session scoping keeps connections alive across an entire run.

Example-Based Testing

Paradigm • Ch. 8

The traditional testing paradigm where developers manually choose specific input values and assert specific output constants. Limited by human cognitive bias; contrasted with property-based testing.

F Index

Factory Fixture Pattern

Fixtures • Ch. 2

A fixture that returns an internal callable generator (Callable[..., T]). Enables tests to dynamically instantiate custom entities with sensible defaults while overriding parameters, eliminating static fixture bloat.

Fake (Test Double)

Test Double • Ch. 4

A fully functioning in-memory implementation of a production protocol (e.g. FakeRatesProvider storing rates in a dict). Executes business logic with zero network latency, zero costs, and zero mock drift.

filterwarnings = ["error"]

Config • Ch. 1, 5

A Pytest configuration directive in pyproject.toml that escalates Python runtime warnings into hard test failures. Crucial for catching un-awaited async coroutines (RuntimeWarning) that would otherwise pass silently.

FixtureDef (Internal Pytest)

Core Engine • Ch. 2

Pytest's internal data structure representing a registered fixture definition. Tracks the fixture's scope, parameter names, caching slot, generator state, and finalizer teardown callbacks.

FixtureManager (DAG Resolver)

Core Engine • Ch. 2

The internal Pytest dependency injection coordinator. Inspects test function parameters via reflection, constructs the fixture Directed Acyclic Graph (DAG), executes a topological sort, and guarantees setup/teardown order.

FixtureRequest (request fixture)

Fixtures • Ch. 2, 3

A built-in fixture providing dynamic reflection into the test currently invoking the fixture. Allows fixtures to read custom markers via request.node.get_closest_marker() and inspect parameters via request.param.

Flaky Test Quarantine Architecture

Architecture • Ch. 10

Isolating non-deterministic tests with @pytest.mark.quarantine into a non-blocking secondary CI lane with repetition (--count=50). Protects PR velocity while engineers eliminate the underlying race condition.

H Index

@pytest.hookimpl (pluggy)

pluggy • Ch. 9

The pluggy decorator used to implement concrete callback logic for a registered Pytest hook specification. Can configure execution ordering via tryfirst, trylast, or hookwrapper.

@hookspec (pluggy)

pluggy • Ch. 9

The pluggy decorator declaring an abstract extension point signature. Defines function arguments and return types that downstream hookimpl handlers must satisfy.

hookwrapper=True

pluggy • Ch. 9

A hook implementation modifier that turns the handler into a generator. Executes setup logic, calls outcome = yield to execute other hooks, and resumes execution to inspect or modify the finalized TestReport.

Hypothesis (Property Testing)

Property • Ch. 8

A library for Python that generates hundreds of randomized edge-case inputs to verify universal mathematical invariants, automatically shrinking failures to the minimal reproducible counterexample.

I Index

ids (Parametrization Naming)

Parametrization • Ch. 3

A parameter on @pytest.mark.parametrize (accepting a list of strings or a formatting callable) that gives human-readable names to matrix cases (e.g. Tier:INSTITUTIONAL) instead of opaque indexes.

Idempotency Testing

Architecture • Ch. 5

Testing that executing a financial transaction with an identical idempotency key twice commits the transaction once and rejects the duplicate replay, preventing double-spending under concurrent network retries.

indirect=True

Parametrization • Ch. 3

An argument in @pytest.mark.parametrize that routes parameters into a fixture's request.param rather than directly into the test function, dynamically reconfiguring collaborator instances.

In-Memory ASGI Testing

Web Testing • Ch. 7

Dispatching HTTP requests directly into FastAPI’s asynchronous callable scope in RAM via httpx.ASGITransport. Tests full routing, middleware, and serialization in ~0.9ms with zero network overhead.

L Index

LIFO Fixture Teardown

Fixtures • Ch. 2

The Last-In, First-Out stack unwinding order Pytest uses to clean up fixtures. If Fixture A depends on Fixture B, B initializes first, but A executes its post-yield teardown first, mirroring context manager lifecycles.

M Index

metafunc

Metaprogramming • Ch. 3

The argument passed to pytest_generate_tests. Exposes metafunc.fixturenames and provides metafunc.parametrize() to programmatically generate test items during discovery.

Mock (Test Double)

Test Double • Ch. 4

A test double programmed with expectations about which calls it should receive. Fails tests if calls occur out of order or with invalid arguments. Best reserved for side-effect boundaries like sending emails.

Mock Drift

Risk • Ch. 4

The divergence between a mock object and real production code over time. Tests pass green against an outdated mock signature, but live code fails in production. Defended with autospec=True and typing.Protocol.

mocker.patch (pytest-mock)

Mocking • Ch. 4

A fixture method from pytest-mock that wraps unittest.mock.patch with automatic teardown cleanup, ensuring patches never leak across tests even if assertion errors occur.

mocker.spy (pytest-mock)

Mocking • Ch. 4

A method from pytest-mock that wraps a real object method. Lets production code run unmodified while recording call counts, arguments, and return values for assertions.

Mutable Session Fixture Poisoning

Anti-Pattern • Ch. 2

Mutating a scope="session" fixture inside a function-level test. The mutation persists in memory for all subsequent tests, causing order-dependent cascading failures in randomized or parallel test runs.

mutmut & Mutation Testing

Mutation • Ch. 8

A mutation testing tool for Python. Injects deliberate synthetic defects (mutants) into production source code and executes the test suite. If tests fail, the mutant is "killed"; if tests pass, it "survived."

Mutation Score Indicator (MSI)

Mutation • Ch. 8

The percentage of synthesized mutants killed by the test suite: (Killed / Total) × 100%. Evaluates assertion strength better than line coverage by proving tests detect logic regressions.

Mystery Guest Anti-Pattern

Anti-Pattern • Ch. 2

Tests that rely on hidden fixture setup code in separate files without explicitly declaring the required state. When assertions fail, engineers cannot determine where the data originated. Defended with Factory Fixtures.

N Index

Namespace Lookup Rule (Patching)

Mocking • Ch. 4

The rule: "Patch where an object is looked up, not where it is defined." If service.py imports from httpx import AsyncClient, you must patch service.AsyncClient, not httpx.AsyncClient.

Network Socket Blocking

Security • Ch. 4

A test harness policy (via pytest-socket) that crashes tests immediately if code attempts an unmocked live network call, ensuring tests never hit paid APIs or fail due to network drops in CI.

P Index

@pytest.mark.parametrize

Parametrization • Ch. 3

Pytest's primary data-driven testing decorator. Generates isolated, individually reported test nodes for each parameter tuple in a list, avoiding internal for-loops and assertion masking.

pytest.param

Parametrization • Ch. 3

A wrapper for individual parameter values in @pytest.mark.parametrize allowing developers to attach custom string IDs (id="...") and specific markers (such as xfail or skip) to individual matrix cells.

pluggy

Architecture • Ch. 9

The hook management library that powers Pytest's plugin architecture. Orchestrates multicast hook calls, priority execution (tryfirst, trylast), and bidirectional lifecycle wrappers (hookwrapper).

Property-Based Testing (PBT)

Property • Ch. 8

A testing paradigm where code is tested against universal mathematical invariants (e.g. conservation of money, idempotence) across hundreds of auto-generated inputs rather than human-chosen examples.

Protocol (typing.Protocol)

Python Stdlib • Ch. 4

Python's structural subtyping (static duck typing) mechanism. Used to define interface boundaries at I/O edges, allowing in-memory Fakes and live clients to be verified by Mypy without mock drift.

pytest.raises

Exceptions • Ch. 1

A context manager used to assert that code raises an expected exception. Best practice requires using match=r"..." to validate error messages and inspecting attributes via as exc_info.

pytest_addoption(parser)

Hook • Ch. 9

A configuration hook used in plugins or conftest.py to register custom command-line options and INI configuration settings parsed by Pytest on startup.

pytest_assertrepr_compare

Hook • Ch. 1

A low-level hook that intercepts failed equality comparisons between specific domain types, allowing developers to format custom visual diffs (e.g. balance discrepancies) in terminal reports.

pytest_collection_modifyitems

Hook • Ch. 9

A collection hook invoked after all test items are discovered. Allows plugins to reorder tests, filter out items, or abort test runs if mandatory compliance markers are missing.

pytest_configure(config)

Hook • Ch. 9

An initialization hook invoked after command-line options and configuration files are parsed. Used to register custom markers programmatically via config.addinivalue_line().

pytest_generate_tests

Hook • Ch. 3

A discovery hook that inspects collected functions and enables dynamic custom parameterization at collection time using metafunc.parametrize(), useful for data-driven testing from external files.

pytest_runtest_makereport

Hook • Ch. 9

A protocol hook called to construct a TestReport for each test phase (setup, call, teardown). Wrapped with hookwrapper=True to intercept results and generate audit logs.

pytest_terminal_summary

Hook • Ch. 9

A reporting hook called after all tests complete. Used by plugins to write custom terminal summary sections and export external artifacts, such as compliance audit ledgers with cryptographic seals.

pytest-asyncio

Plugin • Ch. 5

The official asynchronous testing plugin for Pytest. Enables testing async def functions and provides support for asynchronous yield fixtures on the event loop.

pytest-cov

Plugin • Ch. 10

The standard test coverage plugin for Pytest. Integrates Coverage.py to measure statement and branch coverage (--cov-branch) and enforce minimum coverage gates (--cov-fail-under=95) in CI.

pytest-mock

Plugin • Ch. 4

A Pytest wrapper around standard library unittest.mock. Provides the mocker fixture, guaranteeing that all patches and spies are cleaned up during fixture teardown.

pytest-xdist

Plugin • Ch. 10

A distributed testing plugin for Pytest. Spawns multiple worker processes across CPU cores (-n auto) communicating over IPC sockets, executing tests concurrently to reduce CI execution time.

pytest11 (Entry Point)

Packaging • Ch. 9

The standard Python packaging entry-point group (project.entry-points.pytest11 in pyproject.toml) used to expose installable third-party Pytest plugins to the discovery loader.

R Index

Red-Green-Refactor

TDD • Ch. 1

The core TDD iteration cycle: write a failing test demonstrating a requirement (Red), write the minimal code to satisfy the assertion (Green), and optimize structure under test protection (Refactor).

request.addfinalizer

Fixtures • Ch. 2

A method on pytest.FixtureRequest that registers teardown cleanup callbacks. Finalizers are guaranteed to execute even if subsequent setup lines inside the fixture fail.

respx

Boundary • Ch. 4

An HTTP transport interception library for HTTPX. Intercepts outgoing HTTP calls at the in-memory transport layer, enabling zero-cost testing of rate-limited or paid APIs with simulated status codes.

RuleBasedStateMachine

Hypothesis • Ch. 8

Hypothesis's stateful model-checker class. Executes generated sequences of randomized actions (@rule) and asserts invariants (@invariant) after every step.

S Index

Savepoint Rollback Pattern

Database • Ch. 6

An isolation pattern where every test executes inside a subtransaction (SAVEPOINT). In teardown, Pytest issues a ROLLBACK TO SAVEPOINT, resetting the database state in ~0.8ms without table truncations.

Scopes (Fixture Lifecycles)

Fixtures • Ch. 2

The 5 lifecycle caching boundaries for Pytest fixtures: function (default), class, module, package, and session. Broader scopes must never depend on narrower scopes.

Shrinking Engine (Hypothesis)

Hypothesis • Ch. 8

Hypothesis's reduction algorithm. When a random input fails an assertion, the shrinking engine prunes unnecessary elements to find the minimal failing counterexample.

Sleep-and-Pray Anti-Pattern

Anti-Pattern • Ch. 5

Using await asyncio.sleep(0.1) to wait for background workers. Fails under CPU load in CI and slows suites down. Replaced by asyncio.Event coordination.

Spy (Test Double)

Test Double • Ch. 4

A test double that wraps a real object. Real business logic executes while the spy records invocation counts, arguments, and return values for assertions.

src/ Layout Architecture

Packaging • Ch. 1

The project directory standard where source code resides in a src/ subdirectory. Prevents tests from importing uninstalled local code, forcing validation against installed packages.

@st.composite (Hypothesis)

Hypothesis • Ch. 8

A decorator from Hypothesis used to build custom domain strategies. Uses a draw callable to compose primitive strategies into valid domain objects (e.g. Money).

--strict-markers

Config • Ch. 1, 9

A Pytest configuration flag that treats unregistered markers as hard errors. Catches typos (e.g. typing @pytest.mark.smok instead of smoke) that would otherwise skip tests without warning.

Stub (Test Double)

Test Double • Ch. 4

A test double that returns hardcoded canned responses to calls made during the test. Used to provide indirect inputs without asserting interaction call counts.

T Index

TaskGroup (asyncio)

Asyncio • Ch. 5

Python 3.11+'s structured concurrency context manager. Manages child tasks, cancels remaining tasks if one fails, and raises an ExceptionGroup to guarantee no orphaned tasks escape into subsequent tests.

10-Point Staff Test Suite Audit

Audit • Ch. 10

The enterprise certification checklist verifying packaging isolation, fixed-point precision, immutable fixtures, zero-cost network mocks, virtual clocks, sub-millisecond database rollbacks, and branch coverage.

Test Double Taxonomy (Meszaros)

Theory • Ch. 4

The five categories of test doubles formalized by Gerard Meszaros: Dummy, Stub, Spy, Mock, and Fake. Categorizes roles based on indirect inputs vs. outputs and behavior verification.

testcontainers-python

Database • Ch. 6

A Python library that manages Docker containers for testing. Provisions real PostgreSQL or Redis instances on randomized ports on demand without manual Docker Compose setups.

time-machine (Virtual Clock)

Determinism • Ch. 5

A Python C-extension that mocks system clocks (time.time, datetime.now). Warps time forward by hours or days in sub-millisecond CPU time without flaky sleep calls.

tmp_path (pathlib.Path)

Built-in Fixture • Ch. 7

A built-in Pytest fixture providing a unique, isolated temporary directory as a pathlib.Path object for each test function, preventing file-access collisions during parallel test runs.

Topological Sort (Fixture DAG)

Core Engine • Ch. 2

The algorithm Pytest uses to resolve fixture execution order. Guarantees that dependencies are resolved from the bottom up and detects circular dependency errors during setup.

V Index

VaultFlow Financial Engine

Project • Ch. 1–10

The high-throughput institutional clearinghouse and FX settlement project built incrementally across the 10 chapters to demonstrate financial math, double-entry ledgers, async workers, and PostgreSQL repositories.

Virtual Clocks

Determinism • Ch. 5

The practice of intercepting operating system time routines to advance time deterministically in tests. Allows testing multi-day rate limits and sliding TTLs without burning real wall-clock time.

W Index

with_for_update() (Row-Level Locking)

Database • Ch. 6

SQLAlchemy's method compiling to SQL SELECT ... FOR UPDATE. Acquires an exclusive row-level lock on account records during transfers, tested in Chapter 06 to prove double-spend rejection.

X Index

@pytest.mark.xfail

Markers • Ch. 3

A Pytest marker indicating a test is expected to fail (e.g. tracking a known edge-case bug). When paired with strict=True, Pytest fails the suite if the test unexpectedly passes.

Y Index

yield Fixtures (Two-Phase Lifecycle)

Fixtures • Ch. 2, 5

The standard Pytest generator pattern for fixtures. Code before the yield executes during the setup phase; code after yield executes as teardown cleanup, even if tests fail.

Z Index

Zero-Sum Invariant (∑ Debits − ∑ Credits ≡ 0)

Domain • Ch. 2, 8

The primary financial law enforced in VaultFlow. Proves that money can neither be created nor destroyed through rounding or currency conversions across all multi-leg transactions.
