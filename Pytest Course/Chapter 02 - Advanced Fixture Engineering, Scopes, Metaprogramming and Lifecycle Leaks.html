Part 01

Computer Science: The Fixture Resolution DAG & Injection Mechanics

In classical xUnit frameworks (such as Python's legacy unittest or JUnit 4), test setup is fundamentally bound to class inheritance via monolithic setUp() and tearDown() methods. This forces an all-or-nothing inheritance tax: subclasses inherit fixtures they do not need, and composing independent dependencies requires complex multiple inheritance hierarchies.

PyTest implements a pure Dependency Injection (DI) Container based on a Directed Acyclic Graph (DAG). When a test function declares arguments, PyTest's FixtureManager inspects function signatures via reflection (inspect.signature), maps parameter names to registered FixtureDef nodes, resolves dependencies recursively, and calculates an execution schedule using a topological sort:

The Fixture Dependency Injection Directed Acyclic Graph (DAG)

Topological Resolution Schedule for an Accounting Journal Test

currency_registry [Scope: session] Instantiated ONCE • Immutable master chart of ISO currencies • Shared across workers
↓ injects into ↓
source_account [Scope: function] Asset account initialized with $10,000 USD
destination_account [Scope: function] Liability account initialized with $0 USD
↓ composed into ↓
empty_ledger [Scope: function] Injects currency_registry • Initializes fresh in-memory journal book
↓ delivered to test signature ↓
test_atomic_transfer_balances_ledger(empty_ledger, source_account, destination_account)
PyTest resolves DAG → Instantiates nodes in strict topological order → Executes test body → Runs post-yield teardowns in reverse order!
⚠ The Topological Invariant:

If Fixture A depends on Fixture B, B is guaranteed to initialize before A enters its body. During teardown, PyTest unwinds the call stack in strict LIFO (Last-In, First-Out) order: Fixture A cleans up before Fixture B executes its post-yield teardown.

Part 02

The 5 Scopes: Lifecycle Cache Slots & Memory Retention

Every fixture is annotated with a scope controlling its instantiation boundary and cache lifetime. Selecting an improper scope is the single most common cause of test suite memory bloat, non-deterministic cross-test contamination, and slow execution times.

function Default

Created anew for every single test function. Destroyed and garbage collected immediately after the test completes.

Max Isolation • Safe for mutable state
class Class-Bound

Created once before the first test method of a TestClass runs. Teardown occurs after the final method finishes.

Shared across methods in a single class
module File-Bound

Created once per test_*.py file. Shared across all test functions and classes within that module.

Excellent for read-only mock servers
package Pkg-Bound

Created once per directory package containing an __init__.py. Survives across multiple test modules.

Rarely used • Subsystem integration
session Global Run

Created once when PyTest boots. Remains resident in RAM across the entire test run until the final test concludes.

MUST BE IMMUTABLE • Zero state mutation
// The Golden Scope Hierarchy Constraint

In PyTest, a broader-scoped fixture can NEVER depend on a narrower-scoped fixture. A session fixture cannot request a function fixture. If this were permitted, the session fixture would either hold stale references to destroyed objects or force the function fixture to survive beyond its intended lifecycle, causing catastrophic memory leaks:

ScopeMismatch: You tried to access the function scoped fixture 'db_connection' with a session scoped request object...

✓ Legal: function → class → module → package → session (Narrow depends on Broad).

Part 03

Two-Phase Lifecycles: yield vs. request.addfinalizer

PyTest fixtures manage setup and teardown within a single cohesive generator function via Python's yield keyword. However, in enterprise environments where fixtures allocate external OS resources (file descriptors, TCP sockets, temporary schemas), relying solely on standard yield can lead to leaked resources if an error occurs during the setup phase.

Standard Pattern

1. Generator Yield

Code before yield is the setup phase; code after yield is teardown: 

@pytest.fixture
def managed_resource():
    res = allocate_resource()  # Setup
    yield res                  # Injected into test
    res.cleanup()              # Teardown

Vulnerability: If an exception occurs inside allocate_resource() before reaching the yield statement, the post-yield cleanup code never executes! Any partially allocated socket is orphaned.

Defensive Staff Pattern

2. request.addfinalizer Callback

Registers cleanup callbacks immediately upon acquiring individual handles: 

@pytest.fixture
def bulletproof_resource(request):
    res = allocate_first()
    # Registered immediately! Executes even if step 2 crashes
    request.addfinalizer(res.cleanup)
    
    res.allocate_second()
    return res

Guarantee: Registered finalizers are guaranteed to execute even if subsequent lines within the fixture itself crash with an unhandled exception.

Part 04

The Dynamic Factory Fixture Pattern (Defeating the Mystery Guest)

In complex financial applications, tests frequently require domain entities with slightly varied parameters: an account with $50.00 USD, an account with negative balance, a frozen Japanese Yen account.

A junior engineer's instinct is to create dozens of distinct static fixtures: funded_usd_account, empty_eur_account, frozen_jpy_account. This creates fixture bloat and triggers the Mystery Guest Anti-Pattern—where the reader must jump across multiple files to understand what balance or state an entity holds.

The enterprise solution is the Factory Fixture Pattern: a fixture that returns an internal generator callable configured with production-grade defaults:

// The Canonical Factory Fixture Pattern:
@pytest.fixture
def account_factory():
    """
    FACTORY FIXTURE: Returns a dynamic generator function.
    Encapsulates defaults while permitting surgical test-specific overrides.
    """
    spawned_accounts = []

    def _create_account(
        account_number: Optional[str] = None,
        account_type: AccountType = AccountType.ASSET,
        initial_balance: Optional[Decimal] = None,
        currency: str = "USD",
        is_active: bool = True
    ) -> Account:
        acc = Account(
            account_number=account_number or f"ACC-{uuid.uuid4().hex[:8].upper()}",
            account_type=account_type,
            balance=Money(initial_balance if initial_balance is not None else Decimal("0.0000"), currency),
            is_active=is_active
        )
        spawned_accounts.append(acc)
        return acc

    yield _create_account

    # Centralized teardown: Verify no accounts remain in un-reconciled states
    spawned_accounts.clear()
Part 05

Context Metaprogramming via pytest.FixtureRequest

PyTest exposes a built-in fixture named request (an instance of pytest.FixtureRequest). The request object provides dynamic reflection into the test currently invoking the fixture:

1. Marker Inspection

Read metadata attached to the test function via custom decorators:

marker = request.node.get_closest_marker("initial_funds")
funds = marker.args[0] if marker else 0
2. Indirect Parametrization

Access raw parameter objects when fixtures are parameterized indirectly:

# Accesses parameter passed via @pytest.mark.parametrize
currency = request.param
3. Dynamic Introspection

Access test function names, module filepaths, and class definitions:

test_name = request.node.name
calling_module = request.module.__name__

1. Double-Entry Accounting Core: src/vaultflow/core/ledger.py Stateful Domain Logic 
# ==============================================================================
# VaultFlow Core Domain - Double-Entry Ledger Engine (Milestone 02)
# ==============================================================================

import uuid
from dataclasses import dataclass, field
from decimal import Decimal
from enum import Enum
from typing import List, Dict, Optional
from vaultflow.core.money import Money, FinancialDomainError, CurrencyMismatchError

class AccountType(str, Enum):
    ASSET = "ASSET"          # Normal Debit balance (e.g., Vault Cash, Bank Reserves)
    LIABILITY = "LIABILITY"  # Normal Credit balance (e.g., Customer Deposits)
    EQUITY = "EQUITY"        # Normal Credit balance (e.g., Retained Earnings)
    REVENUE = "REVENUE"      # Normal Credit balance (e.g., Clearing Fees)
    EXPENSE = "EXPENSE"      # Normal Debit balance (e.g., Network Fees)


class UnbalancedJournalError(FinancialDomainError):
    """Raised when journal debits do not equal journal credits."""
    def __init__(self, total_debits: Money, total_credits: Money):
        self.total_debits = total_debits
        self.total_credits = total_credits
        super().__init__(
            f"Journal Entry unbalanced! Debits: {total_debits.amount} {total_debits.currency} != "
            f"Credits: {total_credits.amount} {total_credits.currency}"
        )


class InactiveAccountError(FinancialDomainError):
    """Raised when operations are attempted against frozen/closed accounts."""
    pass


@dataclass
class Account:
    account_number: str
    account_type: AccountType
    balance: Money
    is_active: bool = True

    def apply_posting(self, posting_amount: Money, is_debit: bool) -> None:
        if not self.is_active:
            raise InactiveAccountError(f"Account {self.account_number} is inactive/frozen.")
        
        # Directional balance accounting rules:
        # ASSET / EXPENSE: Debits increase (+), Credits decrease (-)
        # LIABILITY / EQUITY / REVENUE: Credits increase (+), Debits decrease (-)
        if self.account_type in (AccountType.ASSET, AccountType.EXPENSE):
            if is_debit:
                self.balance = self.balance + posting_amount
            else:
                self.balance = self.balance - posting_amount
        else:
            if is_debit:
                self.balance = self.balance - posting_amount
            else:
                self.balance = self.balance + posting_amount


@dataclass(frozen=True)
class Posting:
    account: Account
    amount: Money
    is_debit: bool


@dataclass
class JournalEntry:
    reference_id: str
    postings: List[Posting] = field(default_factory=list)
    is_posted: bool = False

    def validate_balance(self) -> None:
        if not self.postings:
            raise FinancialDomainError("Cannot balance an empty journal entry.")

        first_currency = self.postings[0].amount.currency
        total_debits = Money(Decimal("0.0000"), first_currency)
        total_credits = Money(Decimal("0.0000"), first_currency)

        for p in self.postings:
            if p.amount.currency != first_currency:
                raise CurrencyMismatchError(first_currency, p.amount.currency)
            if p.is_debit:
                total_debits = total_debits + p.amount
            else:
                total_credits = total_credits + p.amount

        if total_debits != total_credits:
            raise UnbalancedJournalError(total_debits, total_credits)


class Ledger:
    """Coordinates account management and atomic double-entry journal postings."""
    def __init__(self, supported_currencies: set[str]):
        self.supported_currencies = supported_currencies
        self.accounts: Dict[str, Account] = {}
        self.journal_entries: List[JournalEntry] = []

    def register_account(self, account: Account) -> None:
        if account.balance.currency not in self.supported_currencies:
            raise FinancialDomainError(f"Currency {account.balance.currency} not supported by ledger.")
        if account.account_number in self.accounts:
            raise FinancialDomainError(f"Account {account.account_number} already registered.")
        self.accounts[account.account_number] = account

    def commit_entry(self, entry: JournalEntry) -> None:
        # 1. Enforce mathematical balance invariant
        entry.validate_balance()

        # 2. Mutate balances atomically
        for posting in entry.postings:
            posting.account.apply_posting(posting.amount, posting.is_debit)

        entry.is_posted = True
        self.journal_entries.append(entry)
2. Hierarchical Fixtures & Dynamic Factories: tests/conftest.py Dependency Injection Graph

# VaultFlow Test Harness - Root Fixtures & Factory Providers (Milestone 02)
# ==============================================================================

import uuid
import pytest
from decimal import Decimal
from typing import Optional, Callable, Generator, Set
from vaultflow.core.money import Money
from vaultflow.core.ledger import Account, AccountType, Ledger

# ------------------------------------------------------------------------------
# SESSION SCOPE: Instantiated ONCE across the entire test session. Must be IMMUTABLE.
# ------------------------------------------------------------------------------
@pytest.fixture(scope="session")
def currency_registry() -> Set[str]:
    """Immutable master registry of currencies sanctioned for clearing."""
    return {"USD", "EUR", "GBP", "JPY", "CHF"}

# ------------------------------------------------------------------------------
# FUNCTION SCOPE: Fresh, isolated ledger state per test.
# ------------------------------------------------------------------------------
@pytest.fixture(scope="function")
def empty_ledger(currency_registry: Set[str]) -> Generator[Ledger, None, None]:
    """Yields a blank ledger and asserts zero memory leaks upon teardown."""
    ledger = Ledger(supported_currencies=currency_registry)
    yield ledger
    # Teardown assertion: verify all ledger books finalize cleanly
    ledger.accounts.clear()
    ledger.journal_entries.clear()

# ------------------------------------------------------------------------------
# FACTORY FIXTURE PATTERN: Dynamic generator eliminating static fixture bloat.
# ------------------------------------------------------------------------------
@pytest.fixture(scope="function")
def account_factory(request: pytest.FixtureRequest) -> Callable[..., Account]:
    """
    Generates customized Account entities on demand with sensible production defaults.
    Uses request.addfinalizer for bulletproof cleanup.
    """
    created_accounts: list[Account] = []

    def _builder(
        account_number: Optional[str] = None,
        account_type: AccountType = AccountType.ASSET,
        balance: Optional[Decimal] = None,
        currency: str = "USD",
        is_active: bool = True
    ) -> Account:
        acc = Account(
            account_number=account_number or f"ACC-{uuid.uuid4().hex[:8].upper()}",
            account_type=account_type,
            balance=Money(balance if balance is not None else Decimal("0.0000"), currency),
            is_active=is_active
        )
        created_accounts.append(acc)
        return acc

    def _cleanup():
        created_accounts.clear()

    # Defensive finalizer registered on the request context
    request.addfinalizer(_cleanup)
    return _builder

# VaultFlow Test Suite - Double-Entry Ledger Verification (Milestone 02)
# ==============================================================================

import pytest
from decimal import Decimal
from vaultflow.core.money import Money, CurrencyMismatchError
from vaultflow.core.ledger import (
    AccountType, 
    Posting, 
    JournalEntry, 
    UnbalancedJournalError, 
    InactiveAccountError
)

@pytest.mark.unit
class TestDoubleEntryLedger:
    """Verifies atomic journal postings and double-entry mathematical invariants."""

    def test_balanced_transfer_updates_account_balances_atomically(
        self, 
        empty_ledger, 
        account_factory
    ):
        # 1. Arrange: Use factory fixtures to construct test state with zero mystery guests
        vault_cash = account_factory(
            account_number="ACC-VAULT-01",
            account_type=AccountType.ASSET,
            balance=Decimal("10000.0000"),
            currency="USD"
        )
        customer_deposit = account_factory(
            account_number="ACC-CUST-99",
            account_type=AccountType.LIABILITY,
            balance=Decimal("0.0000"),
            currency="USD"
        )
        empty_ledger.register_account(vault_cash)
        empty_ledger.register_account(customer_deposit)

        transfer_amount = Money(Decimal("2500.0000"), "USD")

        # 2. Act: Construct balanced multi-leg journal entry
        entry = JournalEntry(
            reference_id="TX-SETTLE-001",
            postings=[
                Posting(account=vault_cash, amount=transfer_amount, is_debit=True),
                Posting(account=customer_deposit, amount=transfer_amount, is_debit=False),
            ]
        )
        empty_ledger.commit_entry(entry)

        # 3. Assert: Verify directional account mutations
        assert vault_cash.balance == Money(Decimal("12500.0000"), "USD")
        assert customer_deposit.balance == Money(Decimal("2500.0000"), "USD")
        assert entry.is_posted is True
        assert len(empty_ledger.journal_entries) == 1

    def test_unbalanced_journal_entry_raises_deterministic_exception(
        self, 
        empty_ledger, 
        account_factory
    ):
        acc_a = account_factory(balance=Decimal("100.0000"))
        acc_b = account_factory(balance=Decimal("100.0000"))

        # Unbalanced: $50 Debit vs $40 Credit
        entry = JournalEntry(
            reference_id="TX-UNBALANCED-01",
            postings=[
                Posting(account=acc_a, amount=Money(Decimal("50.0000"), "USD"), is_debit=True),
                Posting(account=acc_b, amount=Money(Decimal("40.0000"), "USD"), is_debit=False),
            ]
        )

        with pytest.raises(UnbalancedJournalError) as exc_info:
            empty_ledger.commit_entry(entry)

        assert exc_info.value.total_debits == Money(Decimal("50.0000"), "USD")
        assert exc_info.value.total_credits == Money(Decimal("40.0000"), "USD")
        assert len(empty_ledger.journal_entries) == 0

    def test_posting_against_inactive_account_fails_atomically(
        self, 
        empty_ledger, 
        account_factory
    ):
        active_acc = account_factory(balance=Decimal("500.0000"))
        frozen_acc = account_factory(balance=Decimal("500.0000"), is_active=False)

        entry = JournalEntry(
            reference_id="TX-FROZEN-FAIL",
            postings=[
                Posting(account=active_acc, amount=Money(Decimal("100.0000"), "USD"), is_debit=True),
                Posting(account=frozen_acc, amount=Money(Decimal("100.0000"), "USD"), is_debit=False),
            ]
        )

        with pytest.raises(InactiveAccountError, match=r"is inactive/frozen"):
            empty_ledger.commit_entry(entry)

    def test_cross_currency_postings_in_single_entry_rejected(
        self, 
        account_factory
    ):
        usd_acc = account_factory(currency="USD")
        eur_acc = account_factory(currency="EUR")

        entry = JournalEntry(
            reference_id="TX-CROSS-REJECT",
            postings=[
                Posting(account=usd_acc, amount=Money(Decimal("100.0000"), "USD"), is_debit=True),
                Posting(account=eur_acc, amount=Money(Decimal("100.0000"), "EUR"), is_debit=False),
            ]
        )

        with pytest.raises(CurrencyMismatchError):
            entry.validate_balance()
Warning Track

Beginner Pitfalls & Architectural Anti-Patterns

❌ The "Mutable Session Fixture Poisoning" Trap

Annotating a mutable ledger with @pytest.fixture(scope="session") and calling ledger.register_account() inside test functions.

Why this causes catastrophic test flakiness: When Test 1 commits a transaction, the session-scoped ledger retains that mutation in memory. When Test 4 runs, the account already holds altered balances! Tests pass when run in isolation, but fail intermittently when run in randomized batches or parallel workers (`pytest-xdist`). Rule: Session fixtures must be 100% read-only and immutable!

❌ The "Mystery Guest" Anti-Pattern

Writing fixtures that invisibly instantiate 15 database records in the background without the calling test referencing them explicitly.

Why this destroys maintainability: When an assertion fails with assert user.balance == 50, the engineer reviewing the test has no idea where the initial balance came from because it was set inside a hidden fixture 4 directories away. Use Factory Fixtures to make parameters visible inside the test function itself.
